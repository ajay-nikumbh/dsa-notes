# 15. 3Sum

| Difficulty | Pattern | LeetCode | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Medium** | Two Pointers + Sorting | [15. 3Sum](https://leetcode.com/problems/3sum/) | `O(n^2)` | `O(1)` extra` |

## 1. Problem Statement

Given an integer array `nums`, return all the triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, and `j != k`, and `nums[i] + nums[j] + nums[k] == 0`.

Notice that the solution set must not contain duplicate triplets.

### Examples

```text
Input:  nums = [-1,0,1,2,-1,-4]
Output: [[-1,-1,2],[-1,0,1]]
Explanation:
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0.
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0.
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0.
The distinct triplets are [-1,0,1] and [-1,-1,2].
Notice that the order of the output and the order of the triplets does not matter.
```

```text
Input:  nums = [0,1,1]
Output: []
Explanation: The only possible triplet does not sum up to 0.
```

```text
Input:  nums = [0,0,0]
Output: [[0,0,0]]
Explanation: The only possible triplet sums up to 0.
```

### Constraints

- `3 <= nums.length <= 3000`
- `-10^5 <= nums[i] <= 10^5`

## 2. Core Theory

**The technique.** 3Sum is the canonical *sort + fix one + converging two pointers* problem, and it is really a `kSum` reduction. You sort once, then peel off one index with an outer loop and solve the remaining `2Sum`-on-a-sorted-array in linear time. The general shape is: reduce a `k`-element search to a `(k-1)`-element search by fixing an index, until you reach `k = 2`, where sortedness gives you an `O(n)` scan. Each peel costs a factor of `n`, so `kSum` on a sorted array is `O(n^(k-1))`.

**Why sorting makes each pointer move safe.** Fix `nums[i]` and let `need = -nums[i]`. You are searching the sorted window `nums[left..right]` for a pair summing to `need`. Look at `total = nums[left] + nums[right]`:

```text
If total < need:
    nums[right] is the LARGEST value left in the window.
    So nums[left] + nums[j] <= nums[left] + nums[right] = total < need
    for every j in [left+1, right].
    => nums[left] can never reach need with ANY remaining partner.
    => discarding left loses no answer. Move left += 1.

If total > need:
    nums[left] is the SMALLEST value left in the window.
    So nums[j] + nums[right] >= nums[left] + nums[right] = total > need
    for every j in [left, right-1].
    => nums[right] can never reach need with ANY remaining partner.
    => discarding right loses no answer. Move right -= 1.

If total == need:
    record the triplet, then move BOTH inward, since each of
    nums[left] and nums[right] has now been fully resolved.
```

Every move therefore eliminates exactly one element, and it eliminates it only after proving that element is dead for the entire remaining window. Because no valid pair is ever skipped, the scan is exhaustive; because each step retires one index, it is `O(n)`. This is the whole correctness argument, and it is what an interviewer is listening for.

**Why uniqueness comes for free from sorting.** After sorting, equal values are adjacent. Two triplets are duplicates exactly when they have the same multiset of values, and since the output triplet is written in sorted order `(nums[i], nums[left], nums[right])`, duplicates arise only from re-choosing an equal value at the same *role*. So three guards suffice: skip an `i` equal to `nums[i-1]`, and after recording a hit, advance `left` past values equal to the one just used and retreat `right` past values equal to the one just used. No hash set is needed.

**Recognising the pattern.**

| Signal | Response |
|:---|:---|
| "find all pairs/triplets summing to a target" | Sort, then fix `k-2` indices and converge two pointers |
| "the solution set must not contain duplicates" | Sort and skip adjacent equals, rather than deduping with a set afterwards |
| Order of the output does not matter | You are free to sort the input destructively |
| You need *indices*, not values | Sorting destroys indices — use a hash map instead |

## 3. Problem Explanation

You are given an integer array `nums`.

You need to find all **unique triplets**:

```text
[nums[i], nums[j], nums[k]]
```

such that:

```text
i != j != k
nums[i] + nums[j] + nums[k] == 0
```

Important:

```text
The answer must not contain duplicate triplets.
```

### Example

```text
Input:
nums = [-1, 0, 1, 2, -1, -4]

Output:
[[-1, -1, 2], [-1, 0, 1]]
```

Valid triplets are:

```text
-1 + -1 + 2 = 0
-1 +  0 + 1 = 0
```

So answer is:

```text
[[-1, -1, 2], [-1, 0, 1]]
```

## 4. Key Observation

This problem is an extension of **Two Sum**.

For every fixed number `nums[i]`, we need two other numbers such that:

```text
nums[i] + nums[left] + nums[right] = 0
```

Rearrange:

```text
nums[left] + nums[right] = -nums[i]
```

So after fixing one number, the problem becomes:

```text
Find two numbers whose sum is -nums[i]
```

## 5. Important Duplicate Problem

Input:

```text
nums = [-1, 0, 1, 2, -1, -4]
```

After sorting:

```text
[-4, -1, -1, 0, 1, 2]
```

The triplet `[-1, 0, 1]` can be found more than once because `-1` appears twice.

But output should contain it only once.

So we must skip duplicates carefully.

## 6. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Fewer than three elements | `[]`, `[0]`, `[0,0]` | `[]` | `range(n - 2)` must not misbehave; with `n < 3` it yields nothing, which is correct. |
| All zeros | `[0,0,0,0]` | `[[0,0,0]]` | Classic trap — must emit the triplet exactly **once**, not three or four times. Tests both the `i` guard and the `left`/`right` guards. |
| Exactly three zeros | `[0,0,0]` | `[[0,0,0]]` | The `nums[i] > 0` early break must not fire on `0`; use `>`, not `>=`. |
| No triplet exists | `[0,1,1]` | `[]` | Loop must terminate cleanly and return an empty list, not `None`. |
| All positive | `[1,2,3,4]` | `[]` | The `nums[i] > 0: break` optimisation exits on the first index. |
| All negative | `[-1,-2,-3]` | `[]` | Sum can never reach zero; confirms no false positives from the negative side. |
| Duplicates producing one triplet | `[-2,0,0,2,2]` | `[[-2,0,2]]` | Duplicates sit on **both** `left` and `right`; skipping only `i` would emit it twice. |
| Duplicates in the fixed slot | `[-1,0,1,2,-1,-4]` | `[[-1,-1,2],[-1,0,1]]` | `-1` appears twice, so the `i` guard is what prevents a repeated `[-1,0,1]`. |
| Two identical values form the triplet | `[-1,-1,2]` | `[[-1,-1,2]]` | A value may legitimately appear twice *within* one triplet — do not over-skip. |
| Large magnitudes | `[-100000,50000,50000]` | `[[-100000,50000,50000]]` | No overflow in Python, but worth naming in languages with fixed-width ints. |
| Many identical non-zero values | `[1,1,1,1]` | `[]` | Ensures duplicate skipping cannot loop forever or step `left` past `right`. |

## 7. Brute Force Solution

### Intuition

Try every possible triplet.

If the sum is `0`, store the sorted triplet in a set to avoid duplicates.

### Approach

1. Use three loops.
2. Pick indices `i`, `j`, and `k`.
3. Check if sum is `0`.
4. Sort the triplet.
5. Add it into a set.
6. Convert set back to list.

### Dry Run

```text
nums = [-1, 0, 1, 2, -1, -4]
```

Some checked triplets:

```text
[-1, 0, 1]  -> sum = 0
[-1, 2, -1] -> sum = 0
```

After sorting triplets:

```text
[-1, 0, 1]
[-1, -1, 2]
```

Answer:

```text
[[-1, -1, 2], [-1, 0, 1]]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def threeSum(self, nums: List[int]) -> List[List[int]]:

        # Store the size of the array
        n = len(nums)

        # Use a set to avoid duplicate triplets
        unique_triplets = set()

        # Pick first element
        for i in range(n):

            # Pick second element after i
            for j in range(i + 1, n):

                # Pick third element after j
                for k in range(j + 1, n):

                    # Check if current triplet sum is zero
                    if nums[i] + nums[j] + nums[k] == 0:

                        # Sort the triplet so duplicate combinations look same
                        triplet = tuple(sorted([nums[i], nums[j], nums[k]]))

                        # Add triplet to set
                        unique_triplets.add(triplet)

        # Convert set of tuples into list of lists
        result = [list(triplet) for triplet in unique_triplets]

        # Return all unique triplets
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^3)` | Because we use three nested loops. |
| **Space** | `O(number of unique triplets)` | Because we store triplets in a set. |

## 8. Better Solution: Hash Set for Two Sum

### Intuition

Fix one number `nums[i]`.

Then find two numbers after `i` whose sum is:

```text
-nums[i]
```

We can use a hash set for the two-sum part.

### Approach

1. For every index `i`, fix `nums[i]`.
2. Create an empty set called `seen`.
3. For every index `j > i`, need third number:

```text
third = -(nums[i] + nums[j])
```

4. If `third` is in `seen`, we found a triplet.
5. Sort triplet and add to set to avoid duplicates.
6. Add `nums[j]` to `seen`.

### Dry Run

```text
nums = [-1, 0, 1, 2, -1, -4]
```

Fix:

```text
nums[i] = -1
```

Now we need two numbers with sum:

```text
1
```

Scan remaining elements:

```text
j = 1, nums[j] = 0
third = -(-1 + 0) = 1
seen = {}
1 not found
add 0

j = 2, nums[j] = 1
third = -(-1 + 1) = 0
seen = {0}
0 found
triplet = [-1, 1, 0] -> sorted [-1, 0, 1]
```

Valid triplet found.

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def threeSum(self, nums: List[int]) -> List[List[int]]:

        # Store the size of the array
        n = len(nums)

        # Set to store unique sorted triplets
        unique_triplets = set()

        # Fix one element at a time
        for i in range(n):

            # Set to store values seen after fixed index i
            seen = set()

            # Traverse elements after i
            for j in range(i + 1, n):

                # Calculate required third value to make sum zero
                third = -(nums[i] + nums[j])

                # If required third value was seen before
                if third in seen:

                    # Create sorted triplet to avoid duplicate order issues
                    triplet = tuple(sorted([nums[i], nums[j], third]))

                    # Add triplet to set
                    unique_triplets.add(triplet)

                # Add current value to seen for future pairs
                seen.add(nums[j])

        # Convert set of tuples to list of lists
        result = [list(triplet) for triplet in unique_triplets]

        # Return unique triplets
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Because we fix one element and scan the remaining array. |
| **Space** | `O(n)` + output space | Because `seen` can store up to n elements, and the result stores triplets. |

This is better, but still uses extra set for duplicates.

## 9. Most Optimal Solution: Sorting + Two Pointers

### Core Intuition

Sort the array.

Then fix one number and use two pointers to find the other two numbers.

After sorting:

```text
nums = [-4, -1, -1, 0, 1, 2]
```

Fix one number:

```text
nums[i]
```

Then use:

```text
left  = i + 1
right = n - 1
```

Calculate:

```text
total = nums[i] + nums[left] + nums[right]
```

If:

```text
total == 0
```

we found a triplet.

If:

```text
total < 0
```

we need a bigger sum, so move `left` forward.

If:

```text
total > 0
```

we need a smaller sum, so move `right` backward.

## 10. Why Sorting Helps

Sorting helps in two ways:

### 1. Two pointer movement becomes possible

If sum is too small:

```text
move left rightward to increase sum
```

If sum is too large:

```text
move right leftward to decrease sum
```

### 2. Duplicate skipping becomes easier

If current number is same as previous number, skip it.

Example:

```text
[-4, -1, -1, 0, 1, 2]
```

When `i = 1`, `nums[i] = -1`.

When `i = 2`, `nums[i] = -1` again.

We skip `i = 2` because it would create duplicate triplets.

## 11. Duplicate Skipping Rules

### Skip duplicate fixed number

```python
if i > 0 and nums[i] == nums[i - 1]:
    continue
```

This avoids repeating triplets with same first value.

### Skip duplicate left and right after finding triplet

After we find a valid triplet:

```text
[nums[i], nums[left], nums[right]]
```

Move `left` over duplicates:

```python
while left < right and nums[left] == nums[left - 1]:
    left += 1
```

Move `right` over duplicates:

```python
while left < right and nums[right] == nums[right + 1]:
    right -= 1
```

This avoids repeated second and third values.

## 13. Early Break Optimization

After sorting, if:

```text
nums[i] > 0
```

then all numbers after it are also positive.

So sum can never become `0`.

Therefore:

```python
if nums[i] > 0:
    break
```

Example:

```text
[1, 2, 3, 4]
```

No triplet can sum to zero.

## 14. Optimal Code

```python
# Define the class solution
class Solution:

    # Define the method
    def threeSum(self, nums: List[int]) -> List[List[int]]:

        # Sort the array to enable two pointers and duplicate skipping
        nums.sort()

        # Store final unique triplets
        result = []

        # Store the length of the array
        n = len(nums)

        # Fix one number at a time
        for i in range(n - 2):

            # If fixed number is greater than zero, no future triplet can sum to zero
            if nums[i] > 0: break

            # Skip duplicate fixed numbers to avoid duplicate triplets
            if i > 0 and nums[i] == nums[i - 1]: continue

            # Left pointer starts after fixed index
            left = i + 1

            # Right pointer starts from end
            right = n - 1

            # Search for pairs using two pointers
            while left < right:

                # Calculate current triplet sum
                total = nums[i] + nums[left] + nums[right]

                # If sum is zero, we found a valid triplet
                if total == 0:

                    # Add triplet to result
                    result.append([nums[i], nums[left], nums[right]])

                    # Move left pointer forward
                    left += 1

                    # Move right pointer backward
                    right -= 1

                    # Skip duplicate values for left pointer
                    while left < right and nums[left] == nums[left - 1]: left += 1

                    # Skip duplicate values for right pointer
                    while left < right and nums[right] == nums[right + 1]: right -= 1

                # If sum is less than zero, we need a larger value
                elif total < 0:

                    # Move left pointer forward to increase sum
                    left += 1

                # If sum is greater than zero, we need a smaller value
                else:

                    # Move right pointer backward to decrease sum
                    right -= 1

        # Return all unique triplets
        return result
```

## 15. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Skipping duplicates for `i` but forgetting to skip them for `left`/`right` after recording a triplet | `[-2,0,0,2,2]` records `[-2,0,2]` twice, because the next `(left, right)` pair holds the same values. | After appending, run both `while left < right and nums[left] == nums[left - 1]: left += 1` and `while left < right and nums[right] == nums[right + 1]: right -= 1`. |
| Writing the `i` guard as `if nums[i] == nums[i + 1]: continue` | Skips the *first* occurrence rather than the repeats, so `[-1,-1,2]` is never found — and it reads out of range at `i == n - 1`. | Compare backwards: `if i > 0 and nums[i] == nums[i - 1]: continue`. |
| Using `if nums[i] >= 0: break` for the early exit | Kills the all-zeros case: `[0,0,0]` breaks at `i = 0` and returns `[]` instead of `[[0,0,0]]`. | The break condition is strictly `nums[i] > 0`. |
| Skipping duplicates *before* moving the pointers | Comparing `nums[left] == nums[left - 1]` while `left` still points at the recorded element compares it with the wrong neighbour and can skip a valid pair. | Move `left += 1` / `right -= 1` first, *then* skip equals. |
| Forgetting to sort | The two-pointer decision rule has no basis — `total < 0` no longer implies `nums[left]` is dead, so answers are silently missed. | `nums.sort()` before the outer loop; it also enables the duplicate guards. |
| Returning indices instead of values | LeetCode 15 wants the values, and sorting has already destroyed the original indices. | Append `[nums[i], nums[left], nums[right]]`. |
| Omitting `left < right` in the duplicate-skip loops | On `[0,0,0,0]` the skip walks `left` past `right` and off the array. | Guard both skip loops with `left < right`. |
| Using a `set` of triplets on top of the two-pointer scan | Not wrong, but it silently hides a broken skip and adds `O(k)` space — an interviewer reads it as "I do not trust my own invariant". | Rely on the adjacency guards; the sorted order makes them sufficient. |

## 17. Important Interview Mistakes

### Mistake 1: Not sorting first

Without sorting, two pointers cannot decide whether to move `left` or `right`.

### Mistake 2: Not skipping duplicate fixed values

Without this:

```python
if i > 0 and nums[i] == nums[i - 1]:
    continue
```

You may add duplicate triplets.

### Mistake 3: Moving `left` and `right` before saving triplet incorrectly

Correct order after finding triplet:

```text
1. Add triplet
2. Move left and right
3. Skip duplicates
```

### Mistake 4: Returning indices

LeetCode 15 asks for values, not indices.

So return:

```text
[[-1, -1, 2], [-1, 0, 1]]
```

not index positions.

## 18. Interview Follow-ups

**Q: Extend this to 4Sum, and then to general kSum. What is the complexity?**

A: The same reduction recurses. For 4Sum you fix two indices with nested loops and run the two-pointer scan inside, giving `O(n^3)` time. In general `kSum` on a sorted array is `O(n^(k-1))` time and `O(k)` recursion space (excluding output): you peel indices with nested loops until `k = 2`, then converge two pointers. The duplicate guards apply identically at every level — skip an index whose value equals its predecessor at the same depth. Two useful prunes at each level: break if `nums[i] * k > target` (the smallest remaining values already overshoot) and skip if `nums[i] + nums[n-1] * (k-1) < target` (the largest remaining values cannot reach it).

**Q: Can you beat `O(n^2)` for 3Sum?**

A: Not by any known practical algorithm. 3Sum is the canonical *3SUM-hard* problem, and the 3SUM conjecture holds that no `O(n^(2-ε))` algorithm exists for the general integer case. There are slightly sub-quadratic results in restricted models (roughly `O(n^2 / log n)` factors), but nothing an interview expects. If the value range is small you can do better with an FFT-based convolution over a bitmask of the values, which is `O(U log U)` in the universe size `U` rather than in `n`.

**Q: What if you had to return the indices of the triplets instead of the values?**

A: Sorting destroys the original positions, so pair each value with its index before sorting (`sorted(enumerate(nums), key=lambda p: p[1])`) and carry the index through, emitting the stored indices. But note the duplicate rule changes meaning: distinct index triples with equal values are now *different* answers, so you would drop the value-based skip guards entirely — and the output can then be exponential in size (`[0]*n` yields `C(n,3)` triplets), which is worth flagging to the interviewer before you code.

**Q: What if you only need to know whether *any* triplet sums to zero, or just how many there are?**

A: Existence uses the identical scan but returns `True` on the first hit, so the constant factor drops though the worst case is still `O(n^2)`. Counting is different: when `total == 0` you must count *all* pairs with those two values, so count the run of equal values at `left` (say `a`) and at `right` (say `b`) and add `a * b`; if `nums[left] == nums[right]` the whole block is one value and you add `C(len, 2)` instead, then jump both pointers past the block.

**Q: The array does not fit in memory — say a billion integers on disk. How would you adapt?**

A: Sort externally with a merge sort over disk-backed runs. The outer loop streams `i` forward, but the inner two-pointer scan needs simultaneous access to both ends, so you keep two buffered readers, one moving forward and one backward, each reading a block at a time. That keeps memory at `O(block size)` and I/O sequential in both directions. If the value range is bounded, a far better route is to bucket by value and work on the distinct values with their counts.

**Q: How does 3Sum Closest (LeetCode 16) differ?**

A: Structurally it is the same sort-plus-two-pointer scan, but you never stop early on a match against a target sum — you track `best` by `abs(total - target)` and move `left` or `right` by the sign of `total - target`. You also drop all the duplicate-skipping logic, since duplicates cannot change the closest value. It stays `O(n^2)`.

## 19. Interview Explanation

> I sort the array first. Then I fix one element at a time and use two pointers on the remaining right side to find two numbers whose sum with the fixed element is zero. If the sum is too small, I move the left pointer forward. If the sum is too large, I move the right pointer backward. I skip duplicate fixed values and duplicate left/right values after finding a valid triplet to ensure unique triplets. This gives `O(n^2)` time.

## 20. Verify
```python
from typing import List


def three_sum(nums: List[int]) -> List[List[int]]:
    nums = sorted(nums)
    result = []
    n = len(nums)

    for i in range(n - 2):
        if nums[i] > 0:
            break
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        left = i + 1
        right = n - 1

        while left < right:
            total = nums[i] + nums[left] + nums[right]

            if total == 0:
                result.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
            elif total < 0:
                left += 1
            else:
                right -= 1

    return result
```
