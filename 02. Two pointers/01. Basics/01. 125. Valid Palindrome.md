# 125. Valid Palindrome

| Difficulty | Pattern | LeetCode | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Two Pointers | [125. Valid Palindrome](https://leetcode.com/problems/valid-palindrome/) | `O(n)` | `O(1)` |

## 1. Problem Statement

A phrase is a **palindrome** if, after converting all uppercase letters into lowercase letters and removing all non-alphanumeric characters, it reads the same forward and backward. Alphanumeric characters include letters and numbers.

Given a string `s`, return `true` if it is a **palindrome**, or `false` otherwise.

### Examples

```text
Input:  s = "A man, a plan, a canal: Panama"
Output: true
Explanation: "amanaplanacanalpanama" is a palindrome.
```

```text
Input:  s = "race a car"
Output: false
Explanation: "raceacar" is not a palindrome.
```

```text
Input:  s = " "
Output: true
Explanation: s is an empty string "" after removing non-alphanumeric
characters. Since an empty string reads the same forward and backward,
it is a palindrome.
```

### Constraints

- `1 <= s.length <= 2 * 10^5`
- `s` consists only of printable ASCII characters.

## 2. Core Theory

**The technique.** This is the *converging two pointers* (opposite-ends) pattern. You place `left` at index `0` and `right` at the last index, then walk them toward each other until they cross. It applies whenever the answer depends on a relationship between a pair of positions taken from opposite ends, and each comparison lets you safely retire at least one position. Because every iteration advances `left` or retreats `right`, the total work is bounded by the array length, giving `O(n)` time with `O(1)` space.

**Why it is correct here.** A palindrome is defined by a set of mirrored pairs: position `k` from the front must match position `k` from the back, counted over *valid* characters only. The two-pointer walk enumerates exactly those pairs, in order, and nothing else. Skipping a non-alphanumeric character is safe because such characters are not part of the cleaned string at all, so they can never participate in a pair. The moment one mirrored pair disagrees, the whole string is disqualified, so returning `False` early loses no information.

**Why filtering in place is safe.** The naive route builds a cleaned copy and compares it with its reverse. The two-pointer route computes the *same* comparison lazily: the `k`-th valid character from the left and the `k`-th valid character from the right are found by skipping, and are compared as soon as both are known. The sequence of comparisons is identical, so the two methods agree on every input, but the second never materialises the cleaned string.

**Recognising the pattern.** Reach for converging pointers when you see any of these signals:

| Signal in the problem | What it suggests |
|:---|:---|
| "reads the same forwards and backwards" | Mirrored-pair comparison from both ends |
| Input is sorted and you need a pair/sum | Opposite ends, move by comparison to target |
| "maximise/minimise something over a pair `(i, j)`" | Start widest, shrink while discarding a provably dominated side |
| "ignore characters of type X" | Skip loops inside the pointer walk, not a pre-pass |

**The one trap.** Every skip loop must re-check `left < right`. Without it, a string of only punctuation walks a pointer off the end of the string and indexes out of range.

## 3. Problem Explanation

You are given a string `s`.

You need to check whether it is a **palindrome** after:

1. Removing all non-alphanumeric characters.
2. Ignoring uppercase and lowercase differences.

A palindrome means the string reads the same from left to right and right to left.

### Example

```text
Input:
s = "A man, a plan, a canal: Panama"

After cleaning:
"amanaplanacanalpanama"

Reverse:
"amanaplanacanalpanama"

Output:
true
```

```text
Input:
s = "race a car"

After cleaning:
"raceacar"

Reverse:
"racaecar"

Output:
false
```

## 4. Intuition

A normal palindrome check compares:

```text
first character  with last character
second character with second last character
third character  with third last character
...
```

But here we have extra rules:

```text
Ignore spaces
Ignore commas
Ignore colons
Ignore symbols
Ignore uppercase/lowercase difference
```

So instead of cleaning the string separately, we can use **two pointers**:

```text
left pointer  -> starts from beginning
right pointer -> starts from end
```

Then:

```text
If left character is not alphanumeric, skip it.
If right character is not alphanumeric, skip it.
Otherwise compare both lowercase characters.
```

## 5. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Empty after cleaning | `" "` | `True` | An empty string is trivially a palindrome; the loop must never execute. |
| Only punctuation | `",.:"` | `True` | Both skip loops run to exhaustion — without the `left < right` guard inside them you index out of range. |
| Single character | `"a"` | `True` | `left == right` immediately, so the `while left < right` condition is false at entry. |
| Digits present | `"0P"` | `False` | Using `isalpha()` instead of `isalnum()` would drop `0` and wrongly return `True`. |
| All identical characters | `"aaaa"` | `True` | Every pair matches; confirms the loop terminates rather than spinning. |
| Digits-only palindrome | `"1221"` | `True` | Confirms digits are compared, not filtered out. |
| Mixed case | `"Aa"` | `True` | Comparison must be case-insensitive on both sides, not just one. |
| Odd valid length | `"aba"` | `True` | The middle character pairs with itself and needs no comparison. |
| Underscore is not alphanumeric | `"a_a"` | `True` | `_` is skipped; note Python's `isalnum()` treats `_` as non-alphanumeric (unlike `\w` in regex). |
| Negative-looking input | `"-1-"` | `True` | `-` is skipped, leaving `"1"`; there are no negative *numbers* here, only symbols. |

## 6. Brute Force Approach

### Idea

First create a new cleaned string that contains only lowercase alphanumeric characters.

Then check whether this cleaned string is equal to its reverse.

### Steps

```text
s = "A man, a plan, a canal: Panama"

Cleaned string:
"amanaplanacanalpanama"

Reverse cleaned string:
"amanaplanacanalpanama"

Both are equal, so answer is true.
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | We traverse the string once to clean it, and reversing also takes `O(n)`. |
| **Space** | `O(n)` | Because we create a new cleaned string. |

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def isPalindrome(self, s: str) -> bool:

        # Create an empty list to store only valid lowercase characters
        cleaned_chars = []

        # Traverse every character in the input string
        for ch in s:

            # Check whether the current character is alphanumeric
            if ch.isalnum():

                # Convert the character to lowercase and store it
                cleaned_chars.append(ch.lower())

        # Convert the list of characters into a string
        cleaned_string = ''.join(cleaned_chars)

        # Compare the cleaned string with its reversed version
        return cleaned_string == cleaned_string[::-1]
```

## 7. Better Approach Using Two Pointers

### Idea

Instead of creating a new cleaned string, we can directly check the original string using two pointers.

- One pointer starts from the beginning.
- One pointer starts from the end.
- We skip invalid characters from both sides.
- Then we compare valid characters.

### Why this is better?

Brute force uses extra space:

```text
cleaned string = O(n)
```

Two pointer method avoids that. It only uses:

```text
left pointer
right pointer
```

So space becomes:

```text
O(1)
```

## 8. Most Optimal Solution — Two Pointers

### Core Intuition

We only care about valid alphanumeric characters.

So we move from both ends:

```text
left  = 0
right = len(s) - 1
```

Then:

```text
If s[left] is not alphanumeric:
    left++

If s[right] is not alphanumeric:
    right--

Otherwise:
    compare lowercase s[left] and lowercase s[right]
```

If at any point characters do not match, return `False`.

If all matching characters pass, return `True`.

## 9. Working Example

```text
s = "A man, a plan, a canal: Panama"
```

Initial pointers:

```text
left  = 0  -> 'A'
right = 29 -> 'a'
```

Compare:

```text
'a' == 'a'
```

Move both:

```text
left++
right--
```

Now:

```text
left points to ' '
```

Space is not alphanumeric, so skip it.

Continue this process. Eventually every valid character matches.

So output is:

```text
true
```

### Smaller Example

```text
s = "race a car"
```

Clean valid comparison:

```text
r  == r
a  == a
c  != a
```

At mismatch:

```text
return False
```

## 10. Time and Space Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Each character is visited at most once by either `left` or `right`. |
| **Space** | `O(1)` | No extra string or array is created. |

## 11. Optimal Code

```python
# Define the class solution
class Solution:

    # Define the method
    def isPalindrome(self, s: str) -> bool:

        # Start the left pointer from the beginning of the string
        left = 0

        # Start the right pointer from the end of the string
        right = len(s) - 1

        # Continue checking while left pointer is before right pointer
        while left < right:

            # Skip characters from the left side that are not alphanumeric
            while left < right and not s[left].isalnum():

                # Move left pointer to the next character
                left += 1

            # Skip characters from the right side that are not alphanumeric
            while left < right and not s[right].isalnum():

                # Move right pointer to the previous character
                right -= 1

            # Compare lowercase version of both valid characters
            if s[left].lower() != s[right].lower():

                # If characters do not match, string is not a palindrome
                return False

            # Move left pointer forward after successful comparison
            left += 1

            # Move right pointer backward after successful comparison
            right -= 1

        # If all valid character pairs matched, string is a palindrome
        return True
```

## 12. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Using `isalpha()` instead of `isalnum()` | Silently drops digits, so `"0P"` cleans to `"P"` and wrongly returns `True`. | Use `isalnum()`, which keeps letters *and* digits. |
| Omitting `left < right` inside the skip loops | On input like `",.:"` the inner `while` runs past the end of the string and raises `IndexError`. | Guard every skip loop: `while left < right and not s[left].isalnum()`. |
| Lowercasing only one side | `"Aa"` compares `'A'` against `'a'` and returns `False`. | Call `.lower()` on both characters, or lowercase the whole string once up front. |
| Using `if` instead of `while` for skipping | Only one invalid character is skipped per iteration, so `"a,,,a"` compares `'a'` against `','`. | Skipping must loop until a valid character is found. |
| Forgetting to advance after a successful match | `left` and `right` never move past an equal pair, producing an infinite loop. | Always do `left += 1` and `right -= 1` after the comparison. |
| Comparing `s[left] == s[right]` on raw characters | Case differences cause false negatives even when the letters match. | Normalise case before comparing. |

## 14. Interview Follow-ups

**Q: How would you handle Unicode input instead of printable ASCII?**

A: Python's `str.isalnum()` and `str.lower()` are already Unicode-aware, so the same code accepts `"Ä"` or Devanagari digits. The real subtleties are (a) *case folding* — `str.casefold()` is stricter than `lower()` and correctly maps the German `ß` to `"ss"`, and (b) *combining characters*, where `"é"` may be one code point or `e` plus a combining accent. For correctness you would `unicodedata.normalize("NFC", s)` first so that visually identical strings compare equal, then walk with two pointers over the normalised string.

**Q: What if you had to return the longest palindromic substring instead of a yes/no answer?**

A: That is a different problem (LeetCode 5) and the converging-pointer trick no longer suffices. The standard approach is *expand around centre*: for each of the `2n - 1` centres, push two pointers outward while the characters match, and keep the longest span. That is `O(n^2)` time, `O(1)` space. Manacher's algorithm gets it to `O(n)` but is rarely expected in an interview.

**Q: Can you do this if the input is a singly linked list instead of a string?**

A: Yes, but you lose random access from the back. The usual recipe is: find the midpoint with slow/fast pointers, reverse the second half in place, walk the two halves forward in lockstep comparing values, then (politely) reverse the second half back to restore the input. That is `O(n)` time and `O(1)` space.

**Q: What if you were allowed to delete at most one character (LeetCode 680)?**

A: Walk normally with two pointers. On the first mismatch you have exactly two candidate repairs: delete `s[left]` or delete `s[right]`. Check whether either `s[left+1..right]` or `s[left..right-1]` is a plain palindrome with a helper, and return `True` if either is. You never need to consider a second deletion, so it stays `O(n)`.

**Q: The string is 10 GB and arrives as a stream. Now what?**

A: Two pointers require random access from both ends, which a forward-only stream cannot give. If the data is on disk you can seek from both ends and keep two small buffers, preserving `O(1)` memory. If it is a genuine one-pass stream, you cannot answer exactly without buffering; the practical answer is to store a rolling hash of the forward pass and compare it against a hash of the reverse pass in a second pass, accepting a negligible collision probability.

## 15. Interview Explanation

> I will use two pointers, one from the start and one from the end. Since the problem says to ignore non-alphanumeric characters, I will skip them from both sides. Once both pointers are on valid characters, I will compare them in lowercase. If they mismatch, I return false. If all pairs match, I return true. This avoids building a cleaned string and gives O(n) time with O(1) space.

## 16. Verify
```python
def is_palindrome(s: str) -> bool:
    left = 0
    right = len(s) - 1
    while left < right:
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True
```
