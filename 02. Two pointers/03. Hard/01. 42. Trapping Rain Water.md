# 42. Trapping Rain Water

| Difficulty | Pattern | LeetCode | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Hard** | Two Pointers / Monotonic Stack | [42. Trapping Rain Water](https://leetcode.com/problems/trapping-rain-water/) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given `n` non-negative integers representing an elevation map where the width of each bar is `1`, compute how much water it can trap after raining.

### Examples

```text
Input:  height = [0,1,0,2,1,0,1,3,2,1,2,1]
Output: 6
Explanation: The above elevation map (black section) is represented by
array [0,1,0,2,1,0,1,3,2,1,2,1]. In this case, 6 units of rain water
(blue section) are being trapped.
```

```text
Input:  height = [4,2,0,3,2,5]
Output: 9
```

### Constraints

- `n == height.length`
- `1 <= n <= 2 * 10^4`
- `0 <= height[i] <= 10^5`

## 2. Core Theory

**The technique.** Trapping Rain Water is the classic demonstration that two pointers can replace precomputed auxiliary arrays. The underlying idea is *converging pointers carrying running extremes*: instead of storing `prefix_max` and `suffix_max` for every index, you keep just `left_max` and `right_max` as scalars and process whichever side is currently provably decidable. The general lesson is that you can drop an `O(n)` table to `O(1)` whenever, at each step, one side's answer is already fully determined by the information you have accumulated so far.

**The per-index formula.** Water standing above index `i` is `min(prefix_max[i], suffix_max[i]) - height[i]`, clamped at zero. The bar at `i` sits in a basin whose walls are the tallest bar to its left and the tallest bar to its right; water rises to the lower of the two walls and then spills over it. The whole difficulty is computing that `min` without building both tables.

**Why `height[left] <= height[right]` means `left_max` alone determines the water at `left`.** This is the crux of the problem and the thing to prove out loud.

Let `left_max = max(height[0..left])` and `right_max = max(height[right..n-1])`, which is exactly what the running scalars hold. Suppose the test `height[left] <= height[right]` passes. Then:

```text
1. right_max >= height[right]
       right_max is the max over a range that CONTAINS index right.

2. height[right] >= height[left]
       this is the branch condition we just tested.

3. left_max >= height[left]
       left_max is the max over a range that CONTAINS index left.

The true right wall for index `left` is
       true_right = max(height[left+1 .. n-1])
and since `right` lies in that range,
       true_right >= height[right] >= height[left].

Now compare the two walls for index `left`:
       true_left  = left_max            (already fully known: the whole
                                         prefix 0..left has been scanned)
       true_right >= height[right] >= height[left]

Case A: left_max <= height[left].
       Then height[left] IS the prefix maximum, so left_max is updated
       to height[left] and the water here is 0 — correct, since a bar
       that is its own prefix max cannot be submerged from the left.

Case B: left_max > height[left].
       Then true_right >= height[right] >= height[left], but that alone
       is not enough — we need true_right >= left_max OR the min to be
       left_max. Two sub-cases:
         - If true_right >= left_max, then
               min(left_max, true_right) = left_max.
         - If true_right < left_max, then the tallest bar in the whole
               suffix is shorter than left_max, and in particular
               height[right] <= true_right < left_max. But the pointers
               have converged from both ends with the SMALLER side always
               advancing, which guarantees that whenever we process the
               left side, some bar at or beyond `right` is at least as
               tall as height[left]; the binding wall is therefore never
               shorter than what left_max already accounts for at this
               index.
       In both sub-cases the water is exactly left_max - height[left].
```

The compact way to say it in an interview: **we do not need the exact value of the right wall, only the guarantee that it is at least as tall as the left wall.** The condition `height[left] <= height[right]` supplies precisely that guarantee, because `height[right]` is a *witness* — a real bar on the right that is at least as tall as `height[left]` — so the true right maximum is at least that tall too. Once `min(left_max, true_right)` is pinned to `left_max`, the water at `left` is settled and the index can be retired. The symmetric argument handles the `else` branch with `right_max`.

**Why the shorter side is always the safe side.** The scan processes whichever boundary is lower, and that is not an arbitrary choice: the lower boundary is the one whose wall is *guaranteed to be matched* by the opposite side. Processing the taller side would be unsound, because you would have no witness that the far side reaches high enough.

**Comparison of the four standard approaches.**

| Approach | Time | Space | Idea |
|:---|:---:|:---:|:---|
| Brute force | `O(n^2)` | `O(1)` | Rescan left and right maxima for every index |
| Prefix/suffix arrays | `O(n)` | `O(n)` | Precompute both tables, then one pass |
| Monotonic stack | `O(n)` | `O(n)` | Fill water layer by layer, horizontally |
| Two pointers | `O(n)` | `O(1)` | Keep running maxima, process the lower side |

**Recognising the pattern.** Look for: an objective at each index that depends on a prefix extreme *and* a suffix extreme; a natural `min`/`max` of two boundaries; and a comparison that lets you prove one boundary is currently binding. When all three are present, the prefix/suffix tables can usually collapse into two scalars.

## 3. Problem Explanation

We are given an array `height`.

Each value represents the height of a vertical bar.

We need to calculate how much rain water can be trapped between these bars.

Example:

```text
height = [0,1,0,2,1,0,1,3,2,1,2,1]
```

Output:

```text
6
```

Water trapped = 6 units.

## 4. Core Intuition

Water can be trapped at an index only if there is a taller bar on the **left** and a taller bar on the **right**.

For every index `i`, water above that bar depends on:

```text
left_max  = tallest bar from left side up to i
right_max = tallest bar from right side up to i
```

Water trapped at index `i`:

```text
min(left_max, right_max) - height[i]
```

Why minimum?

Because water overflows from the shorter boundary.

Example:

```text
left_max  = 3
right_max = 2
height[i] = 1
```

Water level can only go up to 2, not 3. So:

```text
water = min(3, 2) - 1 = 1
```

## 5. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Empty array | `[]` | `0` | `right = n - 1` becomes `-1`; without a guard the loop is skipped anyway, but the shorter variant that seeds `left_max = height[left]` would raise `IndexError`. |
| Single bar | `[5]` | `0` | One wall cannot hold water; `left == right` at entry. |
| Two bars | `[5,5]` | `0` | No index lies *between* the walls, so nothing can be trapped. |
| All identical heights | `[3,3,3,3]` | `0` | A flat surface traps nothing; every bar equals its own prefix max. |
| All zeros | `[0,0,0,0]` | `0` | Degenerate flat case; must not produce negative water. |
| Monotonically increasing | `[1,2,3,4,5]` | `0` | Classic trap — every bar is its own prefix maximum, so `height[left] >= left_max` fires every time and nothing accumulates. |
| Monotonically decreasing | `[5,4,3,2,1]` | `0` | Mirror case, exercised through the `else` branch. |
| Valley between two walls | `[3,0,3]` | `3` | The minimal genuine basin; `min(3,3) - 0 = 3`. |
| Unequal walls | `[5,0,3]` | `3` | Water rises to the **lower** wall, `min(5,3) = 3`, not to `5`. |
| Deep single pit | `[5,0,0,0,5]` | `15` | Three submerged cells at depth `5`. |
| Two separate basins | `[3,0,3,0,3]` | `6` | Confirms the scan accumulates across multiple independent pools. |
| Plateau bottom | `[4,1,1,1,4]` | `9` | Equal-height floor bars; the `>=` versus `>` comparison must not double count. |
| Tall spike in the middle | `[4,2,0,3,2,5]` | `9` | The interior `3` is itself partly submerged — bars can be both floor and wall. |
| Canonical example | `[0,1,0,2,1,0,1,3,2,1,2,1]` | `6` | The standard case with several nested basins. |
| Note on negatives | n/a | n/a | Constraints give `0 <= height[i]`, so heights are never negative — a negative bar has no physical meaning. If negatives were allowed you would need to clamp water at `max(0, ...)` per index. |

## 6. Brute Force Approach

### Idea

For every index:

1. Find the maximum height on its left.
2. Find the maximum height on its right.
3. Water at that index is:

```text
min(left_max, right_max) - height[i]
```

### Example

```text
height = [4, 2, 0, 3, 2, 5]
```

For index 2, value 0:

```text
left side max  = max(4, 2, 0) = 4
right side max = max(0, 3, 2, 5) = 5

water = min(4, 5) - 0 = 4
```

For index 3, value 3:

```text
left side max  = max(4, 2, 0, 3) = 4
right side max = max(3, 2, 5) = 5

water = min(4, 5) - 3 = 1
```

### Complexity

For every index, we scan left and right.

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Scanning both sides for every index. |
| **Space** | `O(1)` | Ignoring output variables. |

### Code

```python
# Define the class solution
class Solution:

    # Function to calculate trapped rain water
    def trap(self, height: List[int]) -> int:

        # Store length of height array
        n = len(height)

        # Store total trapped water
        total_water = 0

        # Traverse every index
        for i in range(n):

            # Store maximum height on the left side including current index
            left_max = 0

            # Find left maximum from index 0 to i
            for left in range(i + 1):

                # Update left maximum
                left_max = max(left_max, height[left])

            # Store maximum height on the right side including current index
            right_max = 0

            # Find right maximum from index i to n - 1
            for right in range(i, n):

                # Update right maximum
                right_max = max(right_max, height[right])

            # Water at current index depends on smaller boundary
            water_at_current = min(left_max, right_max) - height[i]

            # Add current trapped water to total
            total_water += water_at_current

        # Return total trapped water
        return total_water
```

## 7. Better Solution Using Prefix and Suffix Arrays

### Idea

Instead of calculating `left_max` and `right_max` again and again, precompute them.

Create two arrays:

```text
prefix_max[i] = maximum height from index 0 to i
suffix_max[i] = maximum height from index i to n - 1
```

Then for every index:

```text
water = min(prefix_max[i], suffix_max[i]) - height[i]
```

### Example

```text
height = [4, 2, 0, 3, 2, 5]
```

Prefix max:

```text
[4, 4, 4, 4, 4, 5]
```

Suffix max:

```text
[5, 5, 5, 5, 5, 5]
```

Now water:

```text
i = 0 -> min(4,5)-4 = 0
i = 1 -> min(4,5)-2 = 2
i = 2 -> min(4,5)-0 = 4
i = 3 -> min(4,5)-3 = 1
i = 4 -> min(4,5)-2 = 2
i = 5 -> min(5,5)-5 = 0
```

Total:

```text
0 + 2 + 4 + 1 + 2 + 0 = 9
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Three linear passes. |
| **Space** | `O(n)` | Because we use prefix and suffix arrays. |

### Code

```python
# Define the class solution
class Solution:

    # Function to calculate trapped rain water
    def trap(self, height: List[int]) -> int:

        # Store length of height array
        n = len(height)

        # If there are less than 3 bars, water cannot be trapped
        if n < 3:
            return 0

        # prefix_max[i] stores maximum height from 0 to i
        prefix_max = [0] * n

        # suffix_max[i] stores maximum height from i to n - 1
        suffix_max = [0] * n

        # First prefix max is first height
        prefix_max[0] = height[0]

        # Build prefix maximum array
        for i in range(1, n):

            # Maximum so far from left side
            prefix_max[i] = max(prefix_max[i - 1], height[i])

        # Last suffix max is last height
        suffix_max[n - 1] = height[n - 1]

        # Build suffix maximum array
        for i in range(n - 2, -1, -1):

            # Maximum so far from right side
            suffix_max[i] = max(suffix_max[i + 1], height[i])

        # Store total trapped water
        total_water = 0

        # Traverse every index
        for i in range(n):

            # Water level is decided by smaller of left max and right max
            water_level = min(prefix_max[i], suffix_max[i])

            # Water above current bar
            water_at_current = water_level - height[i]

            # Add current water to total
            total_water += water_at_current

        # Return total trapped water
        return total_water
```

## 8. Optimal Solution Using Two Pointers

### Deep Intuition

The prefix/suffix solution uses extra arrays.

Can we avoid them? Yes.

Use two pointers:

```text
left  = 0
right = n - 1
```

Maintain:

```text
left_max  = maximum height seen from left side
right_max = maximum height seen from right side
```

At every step, compare:

```text
height[left] and height[right]
```

If:

```text
height[left] <= height[right]
```

Then the left side is the limiting side. So we can safely calculate water at `left`.

Why?

Because if `height[left] <= height[right]`, then there is at least one right boundary tall enough to support water on the left side. So water at `left` depends on `left_max`.

Similarly, if:

```text
height[right] < height[left]
```

Then right side is the limiting side, and water at `right` depends on `right_max`.

## 9. Two Pointer Logic

For left pointer:

```text
If height[left] >= left_max:
    update left_max
Else:
    water += left_max - height[left]
```

For right pointer:

```text
If height[right] >= right_max:
    update right_max
Else:
    water += right_max - height[right]
```

## 10. Most Optimal Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Each index is visited once. |
| **Space** | `O(1)` | Only variables are used. |

## 11. Optimal Code

```python
# Define the class solution
class Solution:

    # Function to calculate trapped rain water
    def trap(self, height: List[int]) -> int:

        # Store length of height array
        n = len(height)

        # If less than 3 bars exist, water cannot be trapped
        if n < 3:
            return 0

        # Left pointer starts from beginning
        left = 0

        # Right pointer starts from end
        right = n - 1

        # Maximum height seen so far from left side
        left_max = 0

        # Maximum height seen so far from right side
        right_max = 0

        # Store total trapped water
        total_water = 0

        # Continue until both pointers meet
        while left < right:

            # If left bar is smaller or equal, process left side
            if height[left] <= height[right]:

                # If current left bar is greater than or equal to left_max
                if height[left] >= left_max:

                    # Update left_max because this becomes new left boundary
                    left_max = height[left]

                # Otherwise water can be trapped above current left bar
                else:

                    # Add trapped water at current left index
                    total_water += left_max - height[left]

                # Move left pointer one step right
                left += 1

            # If right bar is smaller, process right side
            else:

                # If current right bar is greater than or equal to right_max
                if height[right] >= right_max:

                    # Update right_max because this becomes new right boundary
                    right_max = height[right]

                # Otherwise water can be trapped above current right bar
                else:

                    # Add trapped water at current right index
                    total_water += right_max - height[right]

                # Move right pointer one step left
                right -= 1

        # Return total trapped water
        return total_water
```

### Alternate Shorter Version

```python
class Solution:

    # Define the method
    def trap(self, height: List[int]) -> int:

        # Handle the edge case
        if not height: return 0

        # Declare the result for storing the final result
        result = 0

        # Define the 2 pointer's
        left = 0
        right = len(height) - 1

        # Declare the leftmax and rightmax
        left_max = height[left]
        right_max = height[right]

        # Loop till the condition fails
        while left < right:

            # If the left_max is less then the right_max then shift the left pointer
            if left_max < right_max:

                # Increment the left pointer by 1
                left += 1

                # Update the left_max
                left_max = max(left_max, height[left])

                # Update the result
                result += left_max - height[left]

            # Else if the right_max is less then the left_max then shift the right pointer
            else:

                # Increment the right pointer by 1
                right -= 1

                # Update the right_max
                right_max = max(right_max, height[right])

                # Update the result
                result += right_max - height[right]

        # Finally return the result
        return result
```

## 12. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Processing the **taller** side instead of the shorter one | You lose the witness that the opposite wall is high enough, so `left_max` is no longer guaranteed to be the binding wall and the water is over-counted. On `[4,2,0,3,2,5]` this over-reports. | Branch on `if height[left] <= height[right]` and process the **left** (shorter-or-equal) side. |
| Updating `left_max` *after* adding the water, unconditionally | You add `left_max - height[left]` even when `height[left] > left_max`, producing negative contributions that silently cancel real water. | Use the if/else: update `left_max` when `height[left] >= left_max`, otherwise add the difference. The two branches are mutually exclusive. |
| Using `min(left_max, right_max)` inside the two-pointer loop | It looks like the brute-force formula, but `right_max` is only the maximum of the *scanned* suffix, not the true suffix maximum — so the `min` can be too small and water is under-counted. | Do not take a `min` at all. The branch condition already proves which single maximum is binding; use `left_max` alone on the left branch. |
| Seeding `left_max = height[0]` but forgetting the empty-array guard | The shorter variant reads `height[left]` before checking `n`, so `[]` raises `IndexError`. | Guard with `if not height: return 0` (or `if n < 3: return 0`) before touching the array. |
| Writing `while left <= right` | The final iteration processes one index twice as both pointers sit on it, adding phantom water on inputs like `[3,0,3]`. | `while left < right`. |
| Forgetting to advance the pointer inside a branch | If the `if height[left] >= left_max` branch updates `left_max` but the `left += 1` sits only in the `else`, the loop never terminates on an increasing array. | Put `left += 1` after the inner if/else, so it runs on both paths. |
| Assuming a bar cannot be both floor and wall | On `[4,2,0,3,2,5]` the bar of height `3` traps `1` unit above itself *and* serves as a local wall. Treating walls as exempt under-counts. | The per-index formula handles this automatically; never special-case "peaks". |
| In the stack solution, popping without checking for an empty stack | After popping the bottom, if no left boundary remains there is no basin, and `stack[-1]` raises `IndexError`. | `if not stack: break` immediately after the pop. |

## 15. Stack-Based Solution

Since this is also a stack topic, we should know the monotonic stack solution.

### Stack Intuition

We keep a stack of indexes with decreasing heights.

When we find a bar taller than the stack top, it means we found a **right boundary**.

Then the popped bar becomes the **bottom** of trapped water.

Formula:

```text
distance = current_index - left_boundary_index - 1
bounded_height = min(height[current_index], height[left_boundary_index]) - height[bottom]
water = distance * bounded_height
```

### Stack Example

```text
height = [4, 2, 0, 3, 2, 5]
```

At height 3, we can trap water over bars 0 and 2 using 4 as left boundary and 3 as right boundary.

At height 5, we trap more water using previous bars as bottom.

### Stack Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Each index is pushed and popped at most once. |
| **Space** | `O(n)` | For stack. |

### Code

```python
# Define the class solution
class Solution:

    # Function to calculate trapped rain water using monotonic stack
    def trap(self, height: List[int]) -> int:

        # Store total trapped water
        total_water = 0

        # Stack stores indexes of bars
        stack = []

        # Traverse every bar by index
        for current_index in range(len(height)):

            # While current bar is taller than bar at stack top
            while stack and height[current_index] > height[stack[-1]]:

                # Popped index is the bottom of water container
                bottom_index = stack.pop()

                # If stack becomes empty, no left boundary exists
                if not stack:

                    # Stop processing
                    break

                # Left boundary index is now stack top
                left_boundary_index = stack[-1]

                # Width between left boundary and current right boundary
                distance = current_index - left_boundary_index - 1

                # Height of water is limited by smaller boundary minus bottom height
                bounded_height = min(height[current_index], height[left_boundary_index]) - height[bottom_index]

                # Add trapped water for this bounded region
                total_water += distance * bounded_height

            # Push current index into stack
            stack.append(current_index)

        # Return total trapped water
        return total_water
```

## 18. Interview Follow-ups

**Q: What changes for Trapping Rain Water II, the 2D version (LeetCode 407)?**

A: Almost everything. In 1D the water level at a cell is decided by just two walls, so a linear sweep works. In 2D water can escape in any of four directions, so the level at a cell is set by the *lowest point along the best escape path to the boundary* — a min-max path problem, not a left/right `min`. The standard solution is a priority-queue flood fill: push every border cell into a min-heap, then repeatedly pop the lowest cell, and for each unvisited neighbour add `max(0, current_level - neighbour_height)` water and push it with height `max(current_level, neighbour_height)`. It runs in `O(m * n * log(m * n))` time and `O(m * n)` space. The intuition is that water always spills over the lowest rim first, which is exactly what the heap gives you — it is Dijkstra with `max` as the path cost instead of `sum`.

**Q: Compare the two-pointer and monotonic-stack solutions. When would you pick each?**

A: They compute the same total in opposite geometries. Two pointers accumulate water **vertically**, column by column, and give `O(n)` time with `O(1)` space — the best answer for this problem in isolation. The stack accumulates water **horizontally**, in flat rectangular layers, and costs `O(n)` space, but it generalises: the same structure solves Largest Rectangle in Histogram, Next Greater Element, and Sum of Subarray Minimums, and it handles a streaming left-to-right input, which two pointers cannot. In an interview I would code two pointers and then mention the stack to show pattern breadth.

**Q: Could you solve it in one pass if the bars arrived as a stream?**

A: Not with two pointers, which need both ends simultaneously. The monotonic stack is the right tool: it consumes the input strictly left to right and settles water as soon as a taller right boundary arrives. Memory is the stack depth, `O(n)` worst case (a strictly decreasing stream) but small in practice. There is a caveat: water above bars still on the stack at end-of-stream is never trapped, which is correct — those bars have no right boundary yet.

**Q: What if you had to return *where* the water sits, not just the total?**

A: Return a per-index array `water[i] = min(prefix_max[i], suffix_max[i]) - height[i]`. The two-pointer version can fill this array as it goes, since each index is finalised exactly once at the moment it is processed, but you have now spent `O(n)` space on the output and may as well use the clearer prefix/suffix solution. If you instead need the *pools* as contiguous regions, the monotonic stack is the natural fit, because each pop already delimits one rectangular slab with known left and right boundaries.

**Q: What if bars had non-unit widths, or you could remove one bar to maximise trapped water?**

A: Non-unit widths are easy: multiply each index's water by its width, and the whole argument is unchanged since the per-index level calculation never used the width. Removing one bar is much harder — removing an interior floor bar adds water directly above it, but removing a *wall* can drain a whole basin. The tractable approach is to precompute `prefix_max` and `suffix_max`, compute the baseline total, and then for each index evaluate the delta in `O(1)` for floor bars, falling back to a recomputation only for the `O(n)` bars that are prefix or suffix records. In practice that is `O(n)` amortised for most inputs and `O(n^2)` worst case.

**Q: How would you parallelise this across many machines for a very large array?**

A: Split the array into chunks. Each chunk can compute its local maximum and its internal water *conditionally* on the eventual left and right wall heights supplied by its neighbours. Do a parallel prefix-scan (a `max`-scan, which is associative) to give every chunk the true `prefix_max` at its start and `suffix_max` at its end, then each chunk computes its water independently in a second pass. That is two parallel passes, `O(n / p + log p)` span — the standard prefix-scan decomposition, which works precisely because `max` is associative.

## 19. Interview Key Points

Say this in interview:

> Water at any index depends on the smaller of the maximum height on its left and right. The brute force approach recalculates these maximums for every index. We can optimize using prefix and suffix maximum arrays. Further, we can reduce space using two pointers by processing the side with the smaller height, because that side determines the water level. This gives `O(n)` time and `O(1)` space.

For stack-specific explanation:

> I can also solve it using a monotonic decreasing stack. When a current bar is taller than the stack top, the popped bar becomes the bottom, the current bar becomes the right boundary, and the new stack top becomes the left boundary. Then I calculate trapped water using width and bounded height.

## 20. Verify
```python
from typing import List


def trap(height: List[int]) -> int:
    # Store length of height array
    n = len(height)

    # If less than 3 bars exist, water cannot be trapped
    if n < 3:
        return 0

    # Left pointer starts from beginning
    left = 0

    # Right pointer starts from end
    right = n - 1

    # Maximum height seen so far from left side
    left_max = 0

    # Maximum height seen so far from right side
    right_max = 0

    # Store total trapped water
    total_water = 0

    # Continue until both pointers meet
    while left < right:
        # If left bar is smaller or equal, process left side
        if height[left] <= height[right]:
            # If current left bar is greater than or equal to left_max
            if height[left] >= left_max:
                # Update left_max because this becomes new left boundary
                left_max = height[left]
            # Otherwise water can be trapped above current left bar
            else:
                # Add trapped water at current left index
                total_water += left_max - height[left]
            # Move left pointer one step right
            left += 1
        # If right bar is smaller, process right side
        else:
            # If current right bar is greater than or equal to right_max
            if height[right] >= right_max:
                # Update right_max because this becomes new right boundary
                right_max = height[right]
            # Otherwise water can be trapped above current right bar
            else:
                # Add trapped water at current right index
                total_water += right_max - height[right]
            # Move right pointer one step left
            right -= 1

    # Return total trapped water
    return total_water


# Prefix/suffix reference, used to cross-check the two-pointer version
def trap_reference(height: List[int]) -> int:
    # Store length of height array
    n = len(height)

    # If less than 3 bars exist, water cannot be trapped
    if n < 3:
        return 0

    # Prepare prefix and suffix maximum arrays
    prefix = [0] * n
    suffix = [0] * n

    # Seed the prefix maximum with the first bar
    prefix[0] = height[0]

    # Fill the prefix maximum from left to right
    for i in range(1, n):
        prefix[i] = max(prefix[i - 1], height[i])

    # Seed the suffix maximum with the last bar
    suffix[n - 1] = height[n - 1]

    # Fill the suffix maximum from right to left
    for i in range(n - 2, -1, -1):
        suffix[i] = max(suffix[i + 1], height[i])

    # Sum water trapped at each index using the smaller boundary
    return sum(min(prefix[i], suffix[i]) - height[i] for i in range(n))
```
