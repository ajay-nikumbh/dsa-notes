# 01. 131. Palindrome Partitioning

| Difficulty | Pattern | Source | Time | Space |

## 1. Problem Statement

Given a string `s`, partition `s` such that every substring of the partition is a palindrome. Return all possible palindrome partitions of `s`.

### Examples

```text
Input:  s = "aab"
Output: [["a","a","b"],["aa","b"]]
```

```text
Input:  s = "a"
Output: [["a"]]
```

### Constraints

- `1 <= s.length <= 16`
- `s` contains only lowercase English letters.

## 2. Core Theory

Palindrome Partitioning belongs to the same backtracking family as subsequence problems, but the "choice" at each recursion level is different in shape. In pick/not-pick problems (subsets, subsequences) each level is a binary decision: include this single element or skip it. Here, at each level we instead choose the **length of the next piece** — we try every possible prefix of the remaining string and only commit to the ones that are valid.

Formally, `backtrack(start)` means: *everything before `start` has already been split into valid palindromes; now partition the suffix `s[start:]`.* At that call we loop `end` from `start` to `len(s) - 1`, treating `s[start:end+1]` as a candidate next piece:

```text
for end in range(start, len(s)):
    if is_palindrome(s[start:end+1]):
        choose s[start:end+1]
        backtrack(end + 1)
        undo (pop the choice)
```

The base case is `start == len(s)`: every character has been consumed by some palindrome piece, so the current `path` is a complete, valid partition and gets copied into the answer.

**Why this is a variant of pick/not-pick.** Think of the `n - 1` gaps between characters as `n - 1` binary switches: cut here or don't. That view gives `2^(n-1)` raw partitions before any pruning, matching subsequence-style counting. The difference is that the recursion doesn't walk switch-by-switch; it collapses runs of "don't cut" into one substring choice and validates that whole substring at once. So the shape is the same exponential search space, just parameterized by substring length instead of a single bit.

**The palindrome-check helper.** A substring `s[left:right+1]` is a palindrome if its outer characters match and the inside is also a palindrome:

```python
def is_palindrome(left, right):
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True
```

This costs `O(length)` per call. Since backtracking may re-ask "is this substring a palindrome?" for overlapping ranges across different branches, the naive version repeats work.

**DP precomputation optimization.** Because there are only `O(n^2)` distinct substrings, we can precompute `pal[i][j]` = "is `s[i:j+1]` a palindrome" for every pair once, bottom-up, in `O(n^2)`:

```text
pal[i][j] = (s[i] == s[j]) and (j - i <= 1 or pal[i + 1][j - 1])
```

Building it requires `pal[i+1][j-1]` (a shorter, more "inward" substring) to already be known, so the outer loop runs `i` from `n - 1` down to `0`, and the inner loop runs `j` from `i` up to `n - 1`. After this table exists, every palindrome check inside backtracking becomes an `O(1)` array lookup instead of an `O(length)` scan. This does not change the exponential nature of the search (we must still enumerate every valid partition), it only removes redundant palindrome recomputation.

Recursion tree for `s = "aab"` — branches that fail the palindrome check are pruned immediately:


**Why `end + 1` and not `start + 1`.** The chosen substring `s[start:end+1]` occupies indices `start..end` inclusive, so the next unprocessed index is `end + 1`. Recursing on `start + 1` would re-process characters already committed to the current piece.

**Why no `used[]` array is needed.** Unlike permutations, where elements can be picked in arbitrary order, here we always move strictly left to right. The `start` index alone fully describes which characters remain, so there is nothing else to track.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---|:---|
| Single character | `s = "a"` | `[["a"]]` | Smallest input; loop runs once, immediately hits base case |
| All-palindrome string | `s = "aaaa"` | 6 partitions (every cut pattern valid) | Pruning does nothing; exercises the full `2^(n-1)` search space |
| No multi-char palindrome substring | `s = "abc"` | `[["a","b","c"]]` | Every `end > start` fails the palindrome check, forcing single-character pieces |
| Two-character palindrome | `s = "aa"` | `[["a","a"],["aa"]]` | First place a length-2 palindrome choice appears |
| Mixed valid/invalid prefix | `s = "aab"` | `[["a","a","b"],["aa","b"]]` | The worked example; exercises both prune and recurse in one tree |

## 4. Solution 1: Backtracking with On-the-Fly Palindrome Check

### Intuition

At every index `start`, try every possible next piece by extending `end` from `start` to the last index. Only recurse into a piece that is currently a palindrome — this is the pruning step that keeps the search from wasting time on partitions that could never be valid.

### Approach

1. Maintain `path` (the partition being built) and `answer` (all completed partitions).
2. `backtrack(start)`: if `start == len(s)`, the whole string is consumed — append a **copy** of `path` to `answer` and return.
3. Otherwise, for `end` from `start` to `len(s) - 1`:
   - If `s[start:end+1]` is a palindrome: append it to `path`, recurse with `backtrack(end + 1)`, then pop it back off (`path.pop()`).
4. Start with `backtrack(0)`.

### Dry Run

```text
s = "aab"

backtrack(0):
  end=0 -> "a" palindrome -> choose "a", path=["a"]
    backtrack(1):
      end=1 -> "a" palindrome -> choose "a", path=["a","a"]
        backtrack(2):
          end=2 -> "b" palindrome -> choose "b", path=["a","a","b"]
            backtrack(3): start == len(s) -> save ["a","a","b"]
          pop "b" -> path=["a","a"]
      pop "a" -> path=["a"]
      end=2 -> "ab" not palindrome -> skip
    (backtrack(1) done)
  pop "a" -> path=[]
  end=1 -> "aa" palindrome -> choose "aa", path=["aa"]
    backtrack(2):
      end=2 -> "b" palindrome -> choose "b", path=["aa","b"]
        backtrack(3): start == len(s) -> save ["aa","b"]
      pop "b" -> path=["aa"]
  pop "aa" -> path=[]
  end=2 -> "aab" not palindrome -> skip

answer = [["a","a","b"], ["aa","b"]]
```

### Code

```python
# Define the class solution
class Solution:

    # Return every valid palindrome partition of s
    def partition(self, s: str) -> List[List[str]]:

        # Store all complete valid partitions
        answer = []

        # Store the partition currently being built
        path = []

        # Check whether s[left:right+1] is a palindrome
        def is_palindrome(left, right):

            # Compare characters from both ends inward
            while left < right:

                # Mismatch means it is not a palindrome
                if s[left] != s[right]:
                    return False

                # Move both pointers inward
                left += 1
                right -= 1

            # Every compared pair matched
            return True

        # Partition the suffix beginning at start
        def backtrack(start):

            # Whole string consumed: current path is one valid partition
            if start == len(s):

                # Store a copy, since path keeps changing
                answer.append(path.copy())
                return

            # Try every possible next piece starting at start
            for end in range(start, len(s)):

                # Only continue if this piece is a palindrome
                if is_palindrome(start, end):

                    # CHOOSE the palindrome substring
                    path.append(s[start:end + 1])

                    # EXPLORE the remaining suffix
                    backtrack(end + 1)

                    # UNDO the choice
                    path.pop()

        # Begin partitioning from index 0
        backtrack(0)

        # Return every valid partition
        return answer
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(N * 2^N)` | Up to `2^(n-1)` partitions to explore, each palindrome check costing up to `O(N)` |
| **Space** | `O(N)` | Recursion depth and `path` size are both bounded by `N`; output storage excluded |

## 5. Solution 2: Backtracking with Precomputed Palindrome Table

### Intuition

The on-the-fly check re-verifies overlapping substrings across different branches. Since there are only `O(n^2)` distinct substrings total, precompute all of them once with DP, then every palindrome check during backtracking becomes an `O(1)` lookup.

### Approach

1. Build `pal[i][j]` for all `0 <= i <= j < n` using `pal[i][j] = s[i] == s[j] and (j - i <= 1 or pal[i+1][j-1])`, filled with `i` decreasing and `j` increasing from `i`.
2. Run the same backtracking as Solution 1, but replace `is_palindrome(start, end)` with `pal[start][end]`.

### Dry Run

```text
s = "aab", n = 3

Build pal bottom-up (i from 2 down to 0):
i=2: pal[2][2] = ('b'=='b') = True
i=1: pal[1][1] = True
     pal[1][2]: s[1]='a', s[2]='b' -> mismatch -> False
i=0: pal[0][0] = True
     pal[0][1]: s[0]='a', s[1]='a' match, len 2 -> True
     pal[0][2]: s[0]='a', s[2]='b' -> mismatch -> False

pal table:
        j=0    j=1    j=2
i=0     T      T      F
i=1     -      T      F
i=2     -      -      T

Backtracking then reuses pal[start][end] directly:
pal[0][0]=T -> "a" ; pal[0][1]=T -> "aa" ; pal[0][2]=F -> skip "aab"
```

### Code

```python
# Define the class solution
class Solution:

    # Return every valid palindrome partition of s
    def partition(self, s: str) -> List[List[str]]:

        # Store string length
        n = len(s)

        # pal[i][j] = whether s[i:j+1] is a palindrome
        pal = [[False] * n for _ in range(n)]

        # Fill the table so that pal[i+1][j-1] is ready before pal[i][j]
        for i in range(n - 1, -1, -1):
            for j in range(i, n):

                # Outer characters must match, and inside must be a palindrome
                if s[i] == s[j] and (j - i <= 1 or pal[i + 1][j - 1]):
                    pal[i][j] = True

        # Store all valid partitions
        answer = []

        # Store the partition currently being built
        path = []

        # Partition the suffix beginning at start
        def backtrack(start):

            # Whole string consumed: save the current partition
            if start == n:
                answer.append(path.copy())
                return

            # Try every possible next piece
            for end in range(start, n):

                # O(1) lookup instead of re-scanning the substring
                if pal[start][end]:

                    # CHOOSE
                    path.append(s[start:end + 1])

                    # EXPLORE
                    backtrack(end + 1)

                    # UNDO
                    path.pop()

        # Begin from index 0
        backtrack(0)

        # Return every valid partition
        return answer
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(N^2 + 2^N)` | `O(N^2)` to build the table, exponential search still enumerates every partition (each `O(1)` lookup instead of `O(N)` scan) |
| **Space** | `O(N^2)` | The `pal` table dominates; recursion depth is only `O(N)` |

## 6. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| `answer.append(path)` without `.copy()` | `path` is the same mutable list object; later pops mutate the already-saved answer | `answer.append(path.copy())` |
| Forgetting `path.pop()` after recursing | Stale substrings from a finished branch leak into sibling branches, corrupting later partitions | Always pop right after `backtrack(end + 1)` returns |
| Recomputing palindrome checks in `O(length)` per call, per branch | Same substrings get re-verified across many overlapping branches, wasting time | Precompute `pal[i][j]` once in `O(n^2)` and look it up in `O(1)` |
| Recursing with `backtrack(start + 1)` instead of `backtrack(end + 1)` | Re-processes characters already committed to the current piece, or skips them incorrectly | Always jump past the whole chosen substring: `end + 1` |
| Using `s[start:end]` instead of `s[start:end+1]` | Python slicing excludes the right endpoint, silently dropping the last character of the piece | Use `s[start:end + 1]` to include index `end` |
| Checking the palindrome condition after already recursing deeper | Wastes time exploring branches that were doomed from the first invalid piece | Check `is_palindrome`/`pal[start][end]` **before** choosing and recursing (prune early) |

## 7. Interview Follow-ups

**Q: How would you return only the minimum number of cuts needed, not every partition?**

A: That is a different problem (LeetCode 132, Palindrome Partitioning II). It drops the backtracking entirely and uses DP: `cuts[i]` = minimum cuts for `s[0:i+1]`, using the same `pal[i][j]` table to test each candidate last piece in `O(1)`. It runs in `O(n^2)` total instead of exponential time, because it only needs a count, not every partition.

**Q: How would you count the number of valid partitions without listing them?**

A: Replace the backtracking with DP: `ways[start]` = number of valid partitions of `s[start:]`, computed as `sum(ways[end+1] for end in range(start, n) if pal[start][end])`, with `ways[n] = 1`. This is `O(n^2)` instead of exponential, since we only need a count and can reuse overlapping subproblems.

**Q: Why can't the whole problem be solved in polynomial time?**

A: Because the problem statement asks for *all* valid partitions, and the number of valid partitions can itself be exponential (e.g. `s` made entirely of one repeated character). Any algorithm that must emit every partition is bound by the size of its own output, so exponential time is unavoidable in the worst case — DP only removes redundant palindrome checks, not the enumeration itself.

**Q: Why is this called backtracking and not just recursion?**

A: The key part specifically making it backtracking is the CHOOSE / EXPLORE / UNDO discipline: `path.append(...)` mutates shared state, `backtrack(end + 1)` explores based on that state, and `path.pop()` restores state before trying the next candidate. Removing that `pop()` would still be recursive, but it would silently corrupt every sibling branch.

**Q: How does the DP table change the time complexity in practice, if the search is still exponential?**

A: It changes the constant factor per branch from `O(length of substring)` down to `O(1)`, and it removes duplicate work across branches that test the same `(i, j)` pair. The overall complexity class is still exponential because the *number of valid partitions to emit* is exponential in the worst case — the DP only optimizes the per-check cost, not the number of checks needed to enumerate every partition.

## 8. Interview Explanation

> Starting from an index `start`, I try every possible end index, which represents choosing the next piece of the partition. If `s[start:end+1]` is a palindrome, I add it to the current partition and recursively partition the remaining suffix starting at `end + 1`. Once that recursive branch finishes exploring, I remove the substring — that's the backtracking step — and try the next candidate end index. When `start` reaches `len(s)`, every character has been consumed by valid palindrome pieces, so I save a copy of the current partition. If asked to optimize, I'd precompute an `n x n` table of which substrings are palindromes in `O(n^2)`, so each check inside the backtracking becomes `O(1)` instead of rescanning the substring every time.

```python
def as_set(partitions):
    # Normalize a list of partitions into a set of tuples for order-independent comparison
    return set(tuple(p) for p in partitions)
```
