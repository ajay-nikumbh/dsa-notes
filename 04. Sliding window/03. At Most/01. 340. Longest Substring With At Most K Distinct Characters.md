## 1. Problem Statement

Given a string `s` and a number `k`, return the length of the **longest substring** that has **at most `k` different characters**.

### Constraints

- `1 <= s.length <= 5 * 10^4`
- `0 <= k <= 50`

### What the constraints tell us (simple theory)

A **constraint** is the biggest input the judge will ever give you. A computer does about **100 million (10^8) simple steps per second**.

| Biggest input `n` | Steps you can afford | Ideas that fit |
|:---:|:---:|:---|
| up to ~5,000 | about `n^2` | Two nested loops |
| up to ~1,000,000 | about `n` | One loop, sliding window |

**For this problem:** `n` can be `5 × 10^4`.

- Trying every start and scanning right is about `n^2 / 2` = `1.25 × 10^9` steps in the worst case (when `k` covers every character, nothing stops early).
- The sliding window: at most `2n` = `10^5` steps.

**How to spot it:** longest + substring (contiguous) + at most → variable sliding window + count map. "At most" also means: if a window is valid, every smaller window inside it is valid, so shrinking from the left always helps.

### What to remember about the window

The window is valid when `number of different characters <= k`. A **count map** answers "how many different characters?" instantly:

```text
freq: character -> how many times it is inside the window
len(freq) = number of different characters
```

### Why a count map, not a set

When `left` moves off a character, another copy may still be inside:


In `"ece"`, `left` leaves an `e` (orange), but another `e` is still inside. A count map just lowers `e` from 2 to 1 and keeps it. Only when a count reaches `0` is the character really gone.

### The template

1. **Expand:** `freq[s[right]] += 1`
2. **Shrink:** while `len(freq) > k`: lower `freq[s[left]]`; **if it is 0, delete the key**; move `left`.
3. **Record:** `best = max(best, right - left + 1)`

**Deleting the zero-count key is required.** `len(freq)` is the number of different characters only if the map holds exactly the characters inside the window. A key stuck at `0` is a character that already left; it makes `len(freq)` too big, the window keeps shrinking for no reason, and the answer comes out too small.


**Why `O(n)`:** `right` moves `n` times and `left` moves at most `n` times, never back.

**Space `O(k)`:** the map holds at most `k + 1` characters at any time.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| `k = 0` | `"abc"`, `k = 0` | `0` | Every character is too many; window is always empty |
| One character | `"a"`, `k = 1` | `1` | Smallest real case |
| `k` bigger than the distinct count | `"abc"`, `k = 5` | `3` | Never shrinks |
| All the same | `"aaaa"`, `k = 1` | `4` | Never shrinks |
| A character leaves and returns | `"abaccc"`, `k = 2` | `4` | `"accc"`: needs counts, not a set |
| `k = 1` | `"aabbbcc"`, `k = 1` | `3` | Longest run of one letter |

## 4. Brute Force: Try Every Start

### Idea

From each start, move right and collect characters in a set. When the set has more than `k` characters, stop. Keep the longest valid length.

### Code

```python
# Brute force: every start, extend until too many different characters
class SolutionBrute:

    # Main method
    def lengthOfLongestSubstringKDistinct(self, s: str, k: int) -> int:

        # Length of the string
        n = len(s)

        # Longest valid length so far
        best = 0

        # Every start index
        for start in range(n):

            # Different characters seen from this start
            seen = set()

            # Extend to the right
            for end in range(start, n):

                # Add this character
                seen.add(s[end])

                # Too many different characters: stop this start
                if len(seen) > k:

                    # Try the next start
                    break

                # Keep the longest
                best = max(best, end - start + 1)

        # Longest valid length
        return best
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Every start may scan far to the right |
| **Space** | `O(k)` | The set has at most `k + 1` characters |

## 5. Optimal Approach: Sliding Window + Count Map

### Idea

Keep a window with at most `k` different characters and a count map of what is inside. Add the new character; while there are more than `k` different characters, remove from the left (deleting a key at 0); then record the length.

### Code

```python
# Optimal: sliding window with a count map
class Solution:

    # Main method (trace is optional and only used by the tests)
    def lengthOfLongestSubstringKDistinct(self, s: str, k: int, trace: list = None) -> int:

        # Character -> how many times it is inside the window
        freq = {}

        # Left edge of the window
        left = 0

        # Longest valid length so far
        best = 0

        # Add one character at a time
        for right in range(len(s)):

            # Count the new character
            freq[s[right]] = freq.get(s[right], 0) + 1

            # Too many different characters: shrink from the left
            while len(freq) > k:

                # The character leaving the window
                out = s[left]

                # One fewer copy inside
                freq[out] -= 1

                # No copies left: the character is gone
                if freq[out] == 0:

                    # Required, or len(freq) stays too big
                    del freq[out]

                # Move the left edge
                left += 1

            # The window is valid: record its length
            best = max(best, right - left + 1)

            # Save (right, left, counts, best) for the tests
            if trace is not None:

                # One entry per step
                trace.append((right, left, dict(sorted(freq.items())), best))

        # Longest valid length
        return best


# Lazy version: shrink at most once, width never shrinks
class SolutionLazy:

    # Main method
    def lengthOfLongestSubstringKDistinct(self, s: str, k: int) -> int:

        # Character -> count inside the window
        freq = {}

        # Left edge of the window
        left = 0

        # Add one character at a time
        for right in range(len(s)):

            # Count the new character
            freq[s[right]] = freq.get(s[right], 0) + 1

            # Too many: shrink by exactly one
            if len(freq) > k:

                # The character leaving the window
                out = s[left]

                # One fewer copy inside
                freq[out] -= 1

                # No copies left
                if freq[out] == 0:

                    # Remove the key
                    del freq[out]

                # Move the left edge once
                left += 1

        # Final width is the best length
        return len(s) - left
```

**About `trace`:** it is only for the tests. LeetCode calls `lengthOfLongestSubstringKDistinct(s, k)` and the code works the same.

**The lazy version** shrinks at most once per step and returns `len(s) - left`. The window may be invalid for a while, but it never grows while invalid, so its final width is the best length (same idea as in [1004](../02.%20Basic/03.%201004.%20Max%20Consecutive%20Ones%20III.md)). It only works for "longest" questions; for counting or exact-`k` problems use the `while` version.

### Complexity

| Approach | Time | Space |
|:---|:---:|:---:|
| Brute force | `O(n^2)` | `O(k)` |
| **Sliding window + count map** | **`O(n)`** (at most `2n` pointer moves) | **`O(k)`** |
| Lazy version | `O(n)` | `O(k)` |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Not deleting a key at 0 | `len(freq)` counts characters that left; answer too small | `if freq[ch] == 0: del freq[ch]` |
| Using a set | Cannot tell if another copy is still inside | Count map |
| Shrinking at `len(freq) >= k` | `k` different characters are allowed | Shrink only at `> k` |
| Recording before the shrink | Records an invalid window | Record after the loop |
| Lazy `if` while still using `max(...)` | Measures invalid windows | `while` + `max`, or `if` + `return n - left` |

## 7. Interview Follow-ups

### Q1. How does this relate to 159 and 904?

**Answer:**
- 159 is this problem with `k = 2`.
- 904 is the same with `k = 2` on an array of numbers, wrapped in a story.

### Q2. How do you count substrings with at most `k` distinct characters?

**Answer:**
- Same window. After shrinking, every substring ending at `right` that starts inside the window is valid.
- Add `right - left + 1` each step.

### Q3. What about **exactly** `k` distinct characters?

**Answer:**
- For counting: `exactly(k) = atMost(k) - atMost(k - 1)`.
- That is the trick used in [992](../04.%20At%20Most%20Trick/03.%20992.%20Subarrays%20with%20K%20Different%20Integers.md).

### Q4. What if the string uses any Unicode characters?

**Answer:**
- Nothing changes: a dictionary works with any character.
- Space stays `O(k)`, since the map never holds more than `k + 1` keys.

### Q5. How do you return the substring itself?

**Answer:**
- When `best` improves, store `best_left = left`.
- Return `s[best_left : best_left + best]`.

## 8. Interview Explanation

> This is a longest contiguous window with an at-most condition, so I use a variable sliding window and a count map of characters inside it; the map's size is the number of different characters. For each new character on the right I increase its count. While the map has more than k keys, I lower the count of s[left], delete it when it reaches zero, and move left. Then I record right minus left plus one. Each pointer moves at most n times, so it is O(n) time, and the map never holds more than k plus one keys, so O(k) space. With k equal to 2 this is LeetCode 159 and Fruit Into Baskets.
