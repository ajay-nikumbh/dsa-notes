## 1. Problem Statement

A farm has one row of fruit trees, from left to right. `fruits[i]` is the **type** of fruit tree `i` gives.

The owner's rules:

- You have **two baskets**. Each basket holds only **one type** of fruit, but any amount of it.
- Start at any tree. Pick **one fruit from every tree** while moving **right**.
- Stop as soon as a tree's fruit does not fit in either basket.

Return the **maximum number of fruits** you can pick.

### Example (from the lecture)

```text
Input:  fruits = [3, 3, 3, 1, 2, 1, 1, 2, 3, 3, 4]
Output: 5   (trees 3 to 7: [1, 2, 1, 1, 2], only types 1 and 2)
```

### Constraints

- `1 <= fruits.length <= 10^5`
- `0 <= fruits[i] < fruits.length`

### What the constraints tell us (simple theory)

A **constraint** is the biggest input the judge will ever give you. A computer does about **100 million (10^8) simple steps per second**.

| Biggest input `n` | Steps you can afford | Ideas that fit |
|:---:|:---:|:---|
| up to ~5,000 | about `n^2` | Two nested loops |
| up to ~1,000,000 | about `n` | One loop, sliding window |

**For this problem:** `n` can be `10^5`.

- Trying every start and scanning right is about `n^2 / 2` = `5 × 10^9` steps in the worst case (only two fruit types, so nothing stops early).
- The sliding window: `right` moves `n` times and `left` at most `n` times, so at most `2 × 10^5` steps.

## 2. Core Theory

### The hard part is the translation

The baskets and the farm are just a story. Turn each rule into plain array words:

| Story rule | What it really means |
|:---|:---|
| one row of trees, only move right | the answer is a **contiguous subarray** |
| two baskets, one type each | the subarray has **at most 2 different values** |
| any amount per basket | how many of each does not matter, only how many **types** |
| maximum number of fruits | maximise the **length** |

So the whole problem is one sentence:

```text
Find the longest subarray with at most 2 different values.
```

Say this sentence first in an interview. It shows you decoded the story, and that is what the interviewer is checking.

**Why a variable window:** longest + contiguous + at most → variable sliding window. And if a window has at most 2 types, every smaller window inside it does too, so shrinking from the left always helps.

### Why a count map, not a set

When `left` moves off a fruit, we must know if **another** fruit of that type is still inside.

`left` moves off a `1` (orange), but another `1` (index 2) is still inside. A set cannot tell; a **count map** can: decrease the count, and remove the type only when its count reaches `0`.

```text
state: fruit type -> how many of it are inside the window
valid when: len(freq) <= 2
```

### The steps, and the bug everybody writes

1. **Expand:** `freq[fruits[right]] += 1`.
2. **Shrink:** while `len(freq) > 2`: decrease `freq[fruits[left]]`; **if it reaches 0, delete the key**; move `left`.
3. **Record:** `best = max(best, right - left + 1)`.

**The classic bug:** forgetting to delete a key whose count is `0`. Then `len(freq)` still counts a type that is no longer in the window, the map looks full forever, `left` keeps running, and the answer is too small.


**Why `while`, not `if`:** one new fruit adds at most one new type, but the fruit leaving on the left may have copies behind it. In our example at `right = 4`, three trees (`3, 3, 3`) had to leave before type `3` was gone.

**Why still `O(n)`:** `right` moves at most `n` times, `left` moves at most `n` times, never back. At most `2n` steps.

**It is the `k = 2` case of a general template.** Replace `2` with `k` and you get "longest subarray with at most `k` distinct values" ([340](../03.%20At%20Most/01.%20340.%20Longest%20Substring%20With%20At%20Most%20K%20Distinct%20Characters.md)).

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| One tree | `[5]` | `1` | Smallest input |
| One type only | `[2,2,2,2]` | `4` | Never shrinks |
| Two types only | `[1,2,1,2]` | `4` | Whole array |
| All different | `[0,1,2,3]` | `2` | Every window of 3 is invalid |
| Best at the start | `[1,1,2,3,4]` | `3` | Found early |
| Best at the end | `[4,3,1,1,2]` | `3` | Found at the last step |
| Type leaves but comes back | `[1,2,1,3,1]` | `3` | Count map, not a set |

## 4. Brute Force: Try Every Starting Tree

### Idea

From each start, move right and collect fruit types in a set. When the set has 3 types, stop. Keep the longest run.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: every start, extend until a third type appears
class SolutionBrute:

    # Main method
    def totalFruit(self, fruits: List[int]) -> int:

        # Number of trees
        n = len(fruits)

        # Most fruits so far
        max_fruits = 0

        # Every start tree
        for start in range(n):

            # Types collected from this start
            types = set()

            # Walk right
            for end in range(start, n):

                # Put this fruit's type in a basket
                types.add(fruits[end])

                # A third type: this start is done
                if len(types) > 2:

                    # Try the next start
                    break

                # Keep the longest run
                max_fruits = max(max_fruits, end - start + 1)

        # Most fruits
        return max_fruits
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Each start may scan far to the right |
| **Space** | `O(1)` | The set never holds more than 3 types |

## 5. Optimal Approach: Sliding Window + Count Map

### Idea

Keep a window `fruits[left .. right]` with at most 2 types, and a map `freq` of how many of each type are inside. Add the new tree on the right; while there are 3 types, remove trees from the left (deleting a type when its count hits 0); then record the length.

| In the story | In the code |
|:---|:---|
| Two baskets | at most 2 keys in `freq` |
| Fruit count per basket | `freq[type]` |
| Throwing out the oldest fruit | `freq[fruits[left]] -= 1`, `left += 1` |
| A basket becomes empty and free | `del freq[type]` when the count is 0 |
| Longest run | `max_fruits` |

### Code

```python
# Optimal: sliding window with a count map
class Solution:

    # Main method (trace is optional and only used by the tests)
    def totalFruit(self, fruits: List[int], trace: list = None) -> int:

        # Fruit type -> how many are inside the window
        freq = {}

        # Left edge of the window
        left = 0

        # Most fruits so far
        max_fruits = 0

        # Add one tree at a time
        for right in range(len(fruits)):

            # Put the new fruit in its basket
            freq[fruits[right]] = freq.get(fruits[right], 0) + 1

            # Three types: shrink from the left
            while len(freq) > 2:

                # The fruit leaving the window
                left_fruit = fruits[left]

                # One fewer of that type
                freq[left_fruit] -= 1

                # Its basket is empty now
                if freq[left_fruit] == 0:

                    # Free the basket (the key bug if you forget this)
                    del freq[left_fruit]

                # Move the left edge
                left += 1

            # The window is valid: record its length
            max_fruits = max(max_fruits, right - left + 1)

            # Save (right, left, baskets, best) for the tests
            if trace is not None:

                # One entry per step
                trace.append((right, left, dict(sorted(freq.items())), max_fruits))

        # Most fruits
        return max_fruits


# Lazy version: shrink at most once, width never shrinks
class SolutionLazy:

    # Main method
    def totalFruit(self, fruits: List[int]) -> int:

        # Fruit type -> how many are inside the window
        freq = {}

        # Left edge of the window
        left = 0

        # Add one tree at a time
        for right in range(len(fruits)):

            # Put the new fruit in its basket
            freq[fruits[right]] = freq.get(fruits[right], 0) + 1

            # Three types: shrink by exactly one
            if len(freq) > 2:

                # The fruit leaving the window
                left_fruit = fruits[left]

                # One fewer of that type
                freq[left_fruit] -= 1

                # Basket empty: free it
                if freq[left_fruit] == 0:

                    # Remove the type
                    del freq[left_fruit]

                # Move the left edge once
                left += 1

        # The width at the end is the best length
        return len(fruits) - left
```

**About `trace`:** it is only for the tests. LeetCode calls `totalFruit(fruits)` and the code works the same.

**The lazy version** (`SolutionLazy`) uses the same "width never shrinks" idea as the `if` version in [1004](03.%201004.%20Max%20Consecutive%20Ones%20III.md): the window may be invalid for a while, but it never grows while invalid, so the final width `n - left` is the answer. It only works for "longest" problems; the `while` version is the general template.

### Complexity

| Approach | Time | Space |
|:---|:---:|:---:|
| Brute force | `O(n^2)` | `O(1)` |
| **Sliding window + count map** | **`O(n)`** (at most `2n` pointer moves) | **`O(1)`** (at most 3 keys) |
| Lazy version | `O(n)` | `O(1)` |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Not deleting a key at count 0 | `len(freq)` counts types that left; answer too small | `if freq[x] == 0: del freq[x]` |
| Using a set instead of a count map | Cannot tell if another fruit of the type is still inside | Store counts, delete only at 0 |
| `if` shrink but still recording `max(...)` | Mixes the two ideas and measures invalid windows | `while` + `max`, or `if` + `return n - left` |
| Shrinking at `len(freq) >= 2` | Two types are allowed | Shrink only at `> 2` |
| Recording before the shrink | Counts an invalid window | Record after the loop |
| Reading `fruits[left]` after `left += 1` | Lowers the wrong count | Save `left_fruit` first |

## 7. Interview Follow-ups

### Q1. What if you had `k` baskets?

**Answer:**
- Replace `2` with `k`: `while len(freq) > k`.
- That is LeetCode 340, the general "at most `k` distinct" template.

### Q2. How do you return the actual trees?

**Answer:**
- When `max_fruits` improves, store `best_left = left`.
- Return `fruits[best_left : best_left + max_fruits]`.

### Q3. How do you count all subarrays with at most 2 types?

**Answer:**
- Same window. After shrinking, every subarray that ends at `right` and starts between `left` and `right` is valid.
- Add `right - left + 1` to a counter each step.

### Q4. What if the fruit types are strings?

**Answer:**
- Nothing changes: a dictionary works with any hashable key.

### Q5. Can you solve it without a map?

**Answer:**
- Yes: keep the last two types, the length of the current run of the last type, and the current window length.
- When a third type comes, the new window is "last run + new fruit".
- Still `O(n)` and `O(1)`, but harder to explain and does not generalise to `k`.

## 8. Interview Explanation

> The story translates to: find the longest subarray with at most two different values. That is a variable sliding window. I keep a count map of fruit types inside the window. For each new tree I add its type. While the map has more than two types, I remove fruits from the left, lowering their count and deleting the type when its count reaches zero, which is the step people forget. Then I record the window length. Each pointer moves at most n times, so it is O(n) time and O(1) space, since the map never holds more than three types. Replacing 2 with k gives the general at-most-k-distinct template.
