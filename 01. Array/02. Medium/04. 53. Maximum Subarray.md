# 04. 53. Maximum Subarray

| Difficulty | Pattern | Source | Time | Space |

## 1. Problem Statement

Given an integer array `nums`, find the subarray with the largest sum, and return *its sum*.

You are given an integer array `nums`.

You need to find the **maximum possible sum** of a **contiguous subarray**.

Important word:

```text
contiguous subarray
```

That means elements must be continuous.

### Examples

**Example 1:**

```text
Input: nums = [-2,1,-3,4,-1,2,1,-5,4]
Output: 6
Explanation: The subarray [4,-1,2,1] has the largest sum 6.
```

Explanation:

```text
The subarray [4, -1, 2, 1] has the maximum sum.

4 + (-1) + 2 + 1 = 6
```

So answer is:

```text
6
```

**Example 2:**

```text
Input: nums = [1]
Output: 1
Explanation: The subarray [1] has the largest sum 1.
```

Only one subarray exists:

```text
[1]
```

Maximum sum is 1.

**Example 3:**

```text
Input: nums = [5,4,-1,7,8]
Output: 23
Explanation: The subarray [5,4,-1,7,8] has the largest sum 23.
```

Explanation:

```text
The whole array has the maximum sum.

5 + 4 + (-1) + 7 + 8 = 23
```

### Constraints

- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

**Follow up:** If you have figured out the `O(n)` solution, try coding another solution using the **divide and conquer** approach, which is more subtle.

## 2. Core Theory

Kadane's algorithm is the canonical example of a **one-dimensional dynamic program collapsed to `O(1)` memory**. The whole technique rests on choosing the right subproblem. The naive subproblem — "what is the best subarray anywhere in `nums[0..i]`?" — does not compose, because knowing the best answer in a prefix tells you nothing about how to extend it. The subproblem that *does* compose is the **ending-at framing**: let `dp[i]` be the maximum sum of a subarray that **ends exactly at index `i`**. Every subarray ending at `i` either consists of `nums[i]` alone, or is some subarray ending at `i-1` with `nums[i]` appended. That gives the one-line recurrence:

```text
dp[i] = max(nums[i], dp[i-1] + nums[i])
```

Because `dp[i]` depends only on `dp[i-1]`, you never need the array — one scalar `current_sum` suffices, and the answer is `max(dp[0..n-1])`, tracked in a second scalar `max_sum`. That is why the algorithm is `O(n)` time and `O(1)` space: the ending-at constraint pins down exactly one predecessor, so each index is decided in constant time instead of being re-summed against all earlier starts.

Read the recurrence as a **decision: extend or restart**. If `dp[i-1] > 0`, carrying it forward strictly improves `dp[i-1] + nums[i]` over `nums[i]`, so extend. If `dp[i-1] <= 0`, the accumulated prefix is dead weight — appending it can only drag any future subarray down — so restart at `nums[i]`. This is the invariant worth saying out loud in an interview: **a negative running sum can never help**, because for any later element `x`, `negative + x < x`. The prefix's only effect on the future is through its sum; once that sum turns non-positive it is strictly worse than the empty prefix, and it is discarded permanently.

The initialization is where most implementations break. Seeding `max_sum = 0` silently encodes "the empty subarray is allowed, and it scores 0." For an all-negative array like `[-3, -2, -5]` that returns `0`, but the problem forbids an empty subarray, so the correct answer is `-2` — the least-bad single element. Seeding with `current_sum = max_sum = nums[0]` and scanning from index `1` keeps the empty subarray out of the search space entirely and handles all-negative input for free.

| Framing | Recurrence | Why it works |
|:---|:---|:---|
| `dp[i]` = best subarray **ending at** `i` | `max(nums[i], dp[i-1] + nums[i])` | Only one predecessor -> `O(n)`, collapses to a scalar |
| `dp[i]` = best subarray **within** `nums[0..i]` | no local recurrence | The winner may not touch `i`; cannot extend locally |

Recognizing the pattern elsewhere: whenever a problem asks for the best **contiguous** run under some accumulating quantity, and a running accumulator can be reset when it becomes unhelpful, Kadane applies. Maximum product subarray (track both max and min because of sign flips), best time to buy and sell stock (Kadane over the daily-difference array), maximum circular subarray (total minus the minimum subarray), and longest run problems all reuse the same "extend or restart, keep a global best" skeleton.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[1]` | `1` | Loop from index `1` must never run; initialization alone is the answer |
| Single negative element | `[-5]` | `-5` | Empty subarray is not allowed; `0` is wrong |
| All negative | `[-3, -2, -5]` | `-2` | The classic trap — `max_sum = 0` initialization returns `0` |
| All positive | `[5, 4, 7, 8]` | `24` | `current_sum` never resets; the whole array wins |
| Mixed with a dip worth crossing | `[5, 4, -1, 7, 8]` | `23` | A negative element is kept because the running sum stays positive |
| Mixed with a dip not worth crossing | `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` | `6` | Restart happens at `4`; answer is `[4,-1,2,1]` |
| All identical | `[3, 3, 3]` | `9` | No restart ever helps when every element is positive |
| All zeros | `[0, 0, 0]` | `0` | Legitimate `0` answer, distinct from the empty-subarray `0` |
| Duplicates around a large negative | `[2, 2, -100, 2, 2]` | `4` | Two equal-scoring runs; either is acceptable for the sum |
| Two elements, negative then positive | `[-2, 1]` | `1` | Restart must win over extending to `-1` |

## 4. What Is a Subarray?

For:

```text
nums = [1, 2, 3]
```

Valid subarrays are:

```text
[1]
[2]
[3]
[1, 2]
[2, 3]
[1, 2, 3]
```

Invalid:

```text
[1, 3]
```

Because 1 and 3 are not continuous.

## 5. Key Observation

We need the best continuous segment.

At every index, we can ask:

```text
Should I extend the previous subarray?

OR

Should I start a new subarray from current element?
```

Example:

```text
nums = [-2, 1]
```

At 1, should we take:

```text
[-2, 1] sum = -1
```

or start fresh:

```text
[1] sum = 1
```

Clearly, starting fresh is better.

This is the core idea behind **Kadane's Algorithm**.

## 6. Brute Force Solution

### Intuition

Generate every possible subarray.

Calculate its sum.

Return the maximum sum.

### Approach

1. Choose every possible starting index.
2. Choose every possible ending index.
3. Calculate sum from start to end.
4. Keep track of maximum sum.

### Dry Run

```text
nums = [-2, 1, -3, 4]
```

All important subarrays:

```text
[-2]                sum = -2
[-2, 1]             sum = -1
[-2, 1, -3]         sum = -4
[-2, 1, -3, 4]      sum = 0

[1]                 sum = 1
[1, -3]             sum = -2
[1, -3, 4]          sum = 2

[-3]                sum = -3
[-3, 4]             sum = 1

[4]                 sum = 4
```

Maximum sum:

```text
4
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxSubArray(self, nums: List[int]) -> int:

        # Store the length of the array
        n = len(nums)

        # Initialize maximum sum with very small value
        max_sum = float("-inf")

        # Try every possible starting index
        for start in range(n):

            # Try every possible ending index
            for end in range(start, n):

                # Store sum of current subarray
                current_sum = 0

                # Calculate sum from start to end
                for index in range(start, end + 1):

                    # Add current element to current_sum
                    current_sum += nums[index]

                # Update max_sum if current subarray sum is greater
                max_sum = max(max_sum, current_sum)

        # Return the largest subarray sum
        return max_sum
```

### Complexity

Brute Force Complexity

```text
Time Complexity: O(n³)
```

Because we choose `start`, `end`, and then calculate sum again.

```text
Space Complexity: O(1)
```

Because we only use variables.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n³)` | Two loops pick `start` and `end`, a third re-sums that range from scratch |
| Space | `O(1)` | Only `max_sum`, `current_sum` and loop counters |

## 7. Better Brute Force: Running Sum

### Intuition

Instead of recalculating sum again and again, maintain a running sum for each starting index.

For fixed `start`, as `end` moves forward:

```text
current_sum += nums[end]
```

### Approach

Fix `start`, reset `current_sum = 0`, then sweep `end` from `start` to `n-1`, adding one element at a time and updating `max_sum` after each addition. The inner re-summation loop of the brute force disappears.

### Dry Run

```text
nums = [-2, 1, -3, 4]
```

For `start = 0`:

```text
end = 0 -> current_sum = -2
end = 1 -> current_sum = -1
end = 2 -> current_sum = -4
end = 3 -> current_sum = 0
```

For `start = 1`:

```text
end = 1 -> current_sum = 1
end = 2 -> current_sum = -2
end = 3 -> current_sum = 2
```

For `start = 3`:

```text
end = 3 -> current_sum = 4
```

Maximum:

```text
4
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxSubArray(self, nums: List[int]) -> int:

        # Store the length of the array
        n = len(nums)

        # Initialize maximum sum with very small value
        max_sum = float("-inf")

        # Try every starting index
        for start in range(n):

            # Running sum for subarray starting at start
            current_sum = 0

            # Expand ending index from start to end
            for end in range(start, n):

                # Add current element into running sum
                current_sum += nums[end]

                # Update max_sum if current running sum is larger
                max_sum = max(max_sum, current_sum)

        # Return maximum subarray sum
        return max_sum
```

### Complexity

```text
Time Complexity: O(n²)
Space Complexity: O(1)
```

This is better, but still not optimal.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n²)` | Each `start` sweeps `end` once; the running sum removes the third loop |
| Space | `O(1)` | Two scalars only |

## 8. Most Optimal Solution: Kadane's Algorithm

### Intuition

**Core Intuition**

At every index, decide:

```text
Should I continue the previous subarray?

OR

Should I start a new subarray from current element?
```

Let:

```text
current_sum = maximum subarray sum ending at current index
max_sum     = maximum subarray sum found overall
```

For every number:

```text
current_sum = max(num, current_sum + num)
```

Meaning:

```text
Either start new from num

OR

Extend previous subarray by adding num
```

Then:

```text
max_sum = max(max_sum, current_sum)
```

**Kadane's Algorithm Intuition in Simple Words**

If your current running sum becomes negative, it will hurt any future subarray.

Example:

```text
current_sum = -5
next number = 10
```

If we extend:

```text
-5 + 10 = 5
```

If we start fresh:

```text
10
```

Starting fresh is better.

So whenever previous sum is bad, drop it.

### Approach

1. Initialize `current_sum = nums[0]` and `max_sum = nums[0]`.
2. Traverse from index `1` to the end.
3. At each index, set `current_sum = max(num, current_sum + num)` — extend or restart.
4. Update `max_sum = max(max_sum, current_sum)`.
5. Return `max_sum`.

### Dry Run

**Kadane Dry Run**

```text
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
```

Initial:

```text
current_sum = nums[0] = -2
max_sum = nums[0] = -2
```

| i | num | Start new `num` | Extend `current_sum + num` | `current_sum` | `max_sum` |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | -2 | -2 | - | -2 | -2 |
| 1 | 1 | 1 | -1 | 1 | 1 |
| 2 | -3 | -3 | -2 | -2 | 1 |
| 3 | 4 | 4 | 2 | 4 | 4 |
| 4 | -1 | -1 | 3 | 3 | 4 |
| 5 | 2 | 2 | 5 | 5 | 5 |
| 6 | 1 | 1 | 6 | 6 | 6 |
| 7 | -5 | -5 | 1 | 1 | 6 |
| 8 | 4 | 4 | 5 | 5 | 6 |

Final answer:

```text
6
```

Subarray:

```text
[4, -1, 2, 1]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxSubArray(self, nums: List[int]) -> int:

        # Initialize current_sum with first element
        current_sum = nums[0]

        # Initialize max_sum with first element
        max_sum = nums[0]

        # Traverse array starting from second element
        for i in range(1, len(nums)):

            # Store current number
            num = nums[i]

            # Decide whether to start new subarray or extend previous one
            current_sum = max(num, current_sum + num)

            # Update global maximum subarray sum
            max_sum = max(max_sum, current_sum)

        # Return the best sum found
        return max_sum
```

### Complexity

**Complexity of Kadane's Algorithm**

```text
Time Complexity: O(n)
```

Because we scan the array once.

```text
Space Complexity: O(1)
```

Because we only use two variables.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | One pass; each index does `O(1)` work |
| Space | `O(1)` | Only `current_sum` and `max_sum` |

## 9. Alternative Kadane Style

### Intuition

This version is also popular.

**Idea**

Keep adding elements to `current_sum`.

If `current_sum` becomes negative, reset it to `0`.

But we must be careful with all-negative arrays.

So initialize `max_sum` as negative infinity.

**Why Initialize With First Element?**

This is important for arrays with all negative numbers.

Example:

```text
nums = [-3, -2, -5]
```

Answer should be:

```text
-2
```

Because the maximum subarray is:

```text
[-2]
```

If we blindly initialize `max_sum = 0`, we may return `0`, which is wrong because empty subarray is not allowed.

So safe initialization is:

```text
current_sum = nums[0]
max_sum = nums[0]
```

### Approach

1. Start with `current_sum = 0` and `max_sum = float("-inf")`.
2. Add each number to `current_sum`.
3. **Update `max_sum` before resetting** — this is what keeps all-negative arrays correct.
4. If `current_sum < 0`, reset it to `0` so the next subarray starts fresh.

### Dry Run

```text
nums = [-3, -2, -5]
```

| num | `current_sum` after add | `max_sum` after update | Reset? | `current_sum` after reset |
|:---:|:---:|:---:|:---:|:---:|
| -3 | -3 | -3 | yes | 0 |
| -2 | -2 | -2 | yes | 0 |
| -5 | -5 | -2 | yes | 0 |

Final answer: `-2`, which matches the single-element subarray `[-2]`.

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxSubArray(self, nums: List[int]) -> int:

        # Running sum of current subarray
        current_sum = 0

        # Best subarray sum found so far
        max_sum = float("-inf")

        # Traverse every number
        for num in nums:

            # Add current number to running sum
            current_sum += num

            # Update answer before resetting
            max_sum = max(max_sum, current_sum)

            # If current_sum is negative, it will hurt future subarrays
            if current_sum < 0:

                # Reset current_sum and start fresh from next index
                current_sum = 0

        # Return maximum subarray sum
        return max_sum
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | Single pass |
| Space | `O(1)` | Two scalars |

## 10. Follow-Up: Return the Actual Subarray Too

### Intuition

Sometimes interviewer asks:

```text
Can you also return the subarray?
```

Then we track start and end indices.

### Approach

Keep a `temp_start` that moves whenever we restart, plus `best_start` and `best_end` that are frozen at the moment `max_sum` improves. The expression `nums[i] > current_sum + nums[i]` is the explicit form of the extend-or-restart decision, which lets us detect the restart and record its index.

### Dry Run

For:

```text
nums = [-2,1,-3,4,-1,2,1,-5,4]
```

Output:

```text
(6, [4, -1, 2, 1])
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxSubArrayWithElements(self, nums: List[int]) -> Tuple[int, List[int]]:

        # Current running sum
        current_sum = nums[0]

        # Best maximum sum found
        max_sum = nums[0]

        # Temporary start index of current subarray
        temp_start = 0

        # Final start index of best subarray
        best_start = 0

        # Final end index of best subarray
        best_end = 0

        # Traverse from second element
        for i in range(1, len(nums)):

            # If starting new from nums[i] is better than extending
            if nums[i] > current_sum + nums[i]:

                # Start new subarray at i
                current_sum = nums[i]

                # Update temporary start
                temp_start = i

            # Otherwise extend previous subarray
            else:

                # Add current number to current_sum
                current_sum += nums[i]

            # If current_sum becomes better than max_sum
            if current_sum > max_sum:

                # Update best sum
                max_sum = current_sum

                # Update best start
                best_start = temp_start

                # Update best end
                best_end = i

        # Return maximum sum and actual subarray
        return max_sum, nums[best_start:best_end + 1]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | Still one pass; index bookkeeping is `O(1)` per step |
| Space | `O(1)` | Extra space is the returned slice only |

## 11. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Initializing `max_sum = 0` | For an all-negative array like `[-3, -2, -5]` it returns `0` instead of the largest single element `-2`; the empty subarray is not allowed | Initialize `current_sum = max_sum = nums[0]`, or use `float("-inf")` for `max_sum` |
| Resetting `current_sum = 0` *before* updating `max_sum` | The all-negative values never get a chance to reach `max_sum`, so the answer is stuck at `-inf` or `0` | Always do `max_sum = max(max_sum, current_sum)` first, then check the reset |
| Starting the loop at index `0` after seeding with `nums[0]` | `nums[0]` is counted twice: `current_sum` becomes `2 * nums[0]` | Loop `for i in range(1, len(nums))` |
| Resetting on `current_sum <= 0` and treating `0` specially | Harmless for the sum, but changes which subarray is reported in the index-tracking variant | Reset only on strictly `< 0`, or accept any equally-scoring answer |
| Confusing subarray with subsequence | `[1, 3]` from `[1, 2, 3]` is a subsequence, not a subarray; picking non-contiguous elements inflates the answer | The elements must be continuous — the recurrence only ever appends `nums[i]` to a run ending at `i-1` |
| Returning `current_sum` instead of `max_sum` | `current_sum` is only the best run *ending at the last index*, which is often not the global best (e.g. `[4, -1, -1]`) | Return the tracked global `max_sum` |

## 12. Interview Follow-ups

**Q: Can you return the actual subarray indices, not just the sum?**

A: Yes — see section 10. Keep `temp_start` which moves whenever the decision is "restart", and freeze `best_start`/`best_end` whenever `current_sum` beats `max_sum`. Still `O(n)` time and `O(1)` extra space.

**Q: What about the divide and conquer `O(n log n)` solution?**

A: Split the array in half. The maximum subarray either lies entirely in the left half, entirely in the right half, or **crosses the midpoint**. The first two are solved recursively; the crossing case is computed in `O(n)` by extending the best suffix sum leftward from the midpoint and the best prefix sum rightward, then adding them. Recurrence `T(n) = 2T(n/2) + O(n)` gives `O(n log n)`. It is strictly worse than Kadane but is what LeetCode's follow-up is asking for, and it is the standard warm-up for segment-tree versions that support updates.

**Q: What about the maximum subarray in a CIRCULAR array (LeetCode 918)?**

A: The answer is either a normal (non-wrapping) Kadane result, or a wrapping one. A wrapping subarray is exactly the complement of a non-wrapping one, so its sum is `total_sum - (minimum subarray sum)`. Run Kadane twice — once for max, once for min — and return `max(kadane_max, total - kadane_min)`. The one trap: if all elements are negative, `total - kadane_min` is `0` (the empty complement), so guard with `if kadane_max < 0: return kadane_max`.

**Q: What if the array is streaming and you cannot store it?**

A: Kadane is already an online algorithm — it keeps only `current_sum` and `max_sum` and consumes each element once, so it works unchanged on a stream. That is a direct consequence of the ending-at-`i` DP framing depending on a single predecessor.

**Q: What if elements are multiplied instead of added (maximum product subarray)?**

A: The extend-or-restart idea survives but the single-scalar state does not, because a large negative product can become the maximum after one more negative element. Track both `max_here` and `min_here` at every index and swap them when `nums[i] < 0`. Still `O(n)` time and `O(1)` space.

**Q: How would you support updates — "change `nums[i]` to `v`, then query the max subarray"?**

A: Build a segment tree where each node stores four values for its range: `total`, `best prefix`, `best suffix`, and `best subarray`. Merging two children is `O(1)` using the same crossing logic as divide and conquer. Point update and query both become `O(log n)`.

## 13. Interview Explanation

You can say:

> I use Kadane's Algorithm. At every index, I decide whether it is better to extend the previous subarray or start a new subarray from the current number. So `current_sum` becomes the maximum subarray sum ending at the current index. Then I update the global `max_sum`. This works because if the previous sum is harmful, we drop it and start fresh. The solution runs in `O(n)` time and uses `O(1)` space.

# Cross-check against an O(n^2) reference on random inputs
import random


# Define the brute-force reference function
def reference(nums: List[int]) -> int:

    # Track the best sum seen so far, starting at negative infinity
    best = float("-inf")

    # Try every possible start index
    for start in range(len(nums)):

        # Running sum for subarrays beginning at start
        running = 0

        # Extend the subarray one element at a time
        for end in range(start, len(nums)):

            # Add the next element to the running sum
            running += nums[end]

            # Update the best sum found so far
            best = max(best, running)

    # Return the best sum across all subarrays
    return best
