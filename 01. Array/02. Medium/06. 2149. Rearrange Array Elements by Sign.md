# 06. 2149. Rearrange Array Elements by Sign

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Medium** | Two Write Indices | [2149. Rearrange Array Elements by Sign](https://leetcode.com/problems/rearrange-array-elements-by-sign/) | `O(n)` | `O(n)` |

## 1. Problem Statement

You are given a **0-indexed** integer array `nums` of **even** length consisting of an **equal** number of positive and negative integers.

You should return the array of nums such that the array follows the given conditions:

1. Every **consecutive pair** of integers have **opposite signs**.
2. For all integers with the same sign, the **order** in which they were present in `nums` is **preserved**.
3. The rearranged array begins with a positive integer.

Return *the modified array after rearranging the elements to satisfy the aforementioned conditions*.

### Examples

```text
Input:  nums = [3,1,-2,-5,2,-4]
Output: [3,-2,1,-5,2,-4]
Explanation:
The positive integers in nums are [3,1,2]. The negative integers are [-2,-5,-4].
The only possible way to rearrange them such that they satisfy all conditions
is [3,-2,1,-5,2,-4].
Other ways such as [1,-2,2,-5,3,-4], [3,1,2,-2,-5,-4], [-2,3,-5,1,-4,2] are
incorrect because they do not satisfy one or more conditions.
```

```text
Input:  nums = [-1,1]
Output: [1,-1]
Explanation:
1 is the only positive integer and -1 the only negative integer in nums.
So nums is rearranged to [1,-1].
```

### Constraints

- `2 <= nums.length <= 2 * 10^5`
- `nums.length` is **even**
- `1 <= |nums[i]| <= 10^5`
- `nums` consists of **equal** number of positive and negative integers.

It is not required to do the modifications in-place.

## 2. Core Theory

This is a **stable partition into interleaved slots**. The insight that collapses the whole problem: because the output must start positive and alternate, every element's destination is fixed by its sign alone, before you look at anything else.

```text
Index:  0   1   2   3   4   5
Sign:   +   -   +   -   +   -
```

Positives own the even indices, negatives own the odd ones. So rather than *rearranging*, you can **compute each element's final address directly** and write it there in one pass.

Keep two write cursors, each advancing by two:

| Cursor | Starts at | Steps by | Claims |
|:---|:---:|:---:|:---|
| `positive_index` | `0` | `+2` | `0, 2, 4, ...` |
| `negative_index` | `1` | `+2` | `1, 3, 5, ...` |

**Why relative order is preserved for free.** Scanning the source left to right means the first positive encountered is written to index `0`, the second to `2`, the third to `4`, and so on. A cursor only ever moves forward, so earlier elements always land at lower indices than later ones of the same sign. Stability is a consequence of the scan direction — it needs no extra work.

**Why the equal-count guarantee matters.** With `n/2` of each sign, the two cursors consume exactly the even and odd slots and finish together. If the counts were unequal, one cursor would run past the array end, which is why the unequal variant (section 9) needs different handling.

**The `O(1)` space trap.** It is tempting to attempt this in place, but a stable in-place interleave is genuinely hard. Moving an element into position forces every element between its old and new home to shift, which degrades to `O(n^2)`. An output array is the practical optimum here, and the problem explicitly permits it.

**Recognizing the pattern:** whenever an element's final index is a pure function of some property it carries (sign, parity, bucket id), skip the comparisons and write directly into the computed slot. The same idea drives counting sort and bucket placement.

## 3. Problem Explanation

You are given an array nums containing an **equal number of positive and negative integers**.

You need to rearrange the array so that:

```text
1. Every positive number is followed by a negative number.
2. The relative order of positive numbers should remain same.
3. The relative order of negative numbers should remain same.
4. The result should start with a positive number.
```

### Example

```text
Input:
nums = [3, 1, -2, -5, 2, -4]

Output:
[3, -2, 1, -5, 2, -4]
```

Positive numbers in original order:

```text
[3, 1, 2]
```

Negative numbers in original order:

```text
[-2, -5, -4]
```

Now arrange alternately starting with positive:

```text
[3, -2, 1, -5, 2, -4]
```

## 4. Key Observation

Since the answer must start with a positive number:

```text
positive numbers go to even indices
negative numbers go to odd indices
```

Example:

```text
Index:  0   1   2   3   4   5
Value:  +   -   +   -   +   -
```

So:

```text
Positive index positions = 0, 2, 4, ...
Negative index positions = 1, 3, 5, ...
```

## 6. Brute Force Solution: Separate Positives and Negatives

### Intuition

We can first collect all positive numbers in one list and all negative numbers in another list.

Then place them alternately:

```text
positive, negative, positive, negative, ...
```

### Approach

1. Create `positives` list.
2. Create `negatives` list.
3. Traverse nums.
4. Store positives in `positives`.
5. Store negatives in `negatives`.
6. Build answer by taking one positive, then one negative.

### Dry Run

```text
nums = [3, 1, -2, -5, 2, -4]
```

After separation:

```text
positives = [3, 1, 2]
negatives = [-2, -5, -4]
```

Now build result:

```text
take positives[0] = 3
take negatives[0] = -2

take positives[1] = 1
take negatives[1] = -5

take positives[2] = 2
take negatives[2] = -4
```

Final:

```text
[3, -2, 1, -5, 2, -4]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def rearrangeArray(self, nums: List[int]) -> List[int]:

        # Store all positive numbers in original order
        positives = []

        # Store all negative numbers in original order
        negatives = []

        # Traverse every number in nums
        for num in nums:

            # If current number is positive
            if num > 0:

                # Add it to positives list
                positives.append(num)

            # If current number is negative
            else:

                # Add it to negatives list
                negatives.append(num)

        # Store final rearranged result
        result = []

        # Since positives and negatives count is equal, loop through either list
        for i in range(len(positives)):

            # Add one positive number first
            result.append(positives[i])

            # Add one negative number after it
            result.append(negatives[i])

        # Return final rearranged array
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array once to separate and once to build result. |
| **Space** | `O(n)` | Because we use extra lists. |

This is accepted, but we can build the answer more directly.

## 7. Better Solution: Direct Placement Using Two Pointers

### Intuition

Since positives must go to even positions and negatives must go to odd positions, we can directly place each number in its final position.

Use:

```text
positive_index = 0
negative_index = 1
```

When we see a positive number:

```text
result[positive_index] = num
positive_index += 2
```

When we see a negative number:

```text
result[negative_index] = num
negative_index += 2
```

This automatically preserves order because we scan from left to right.

### Dry Run

```text
nums = [3, 1, -2, -5, 2, -4]
```

Initial:

```text
result = [0, 0, 0, 0, 0, 0]
positive_index = 0
negative_index = 1
```

| num | Action | result | positive_index | negative_index |
|:---:|:---|:---|:---:|:---:|
| 3 | place at 0 | `[3,0,0,0,0,0]` | 2 | 1 |
| 1 | place at 2 | `[3,0,1,0,0,0]` | 4 | 1 |
| -2 | place at 1 | `[3,-2,1,0,0,0]` | 4 | 3 |
| -5 | place at 3 | `[3,-2,1,-5,0,0]` | 4 | 5 |
| 2 | place at 4 | `[3,-2,1,-5,2,0]` | 6 | 5 |
| -4 | place at 5 | `[3,-2,1,-5,2,-4]` | 6 | 7 |

Final:

```text
[3, -2, 1, -5, 2, -4]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def rearrangeArray(self, nums: List[int]) -> List[int]:

        # Create a result array of same length
        result = [0] * len(nums)

        # Positive numbers should be placed at even indices
        positive_index = 0

        # Negative numbers should be placed at odd indices
        negative_index = 1

        # Traverse numbers from left to right to preserve relative order
        for num in nums:

            # If current number is positive
            if num > 0:

                # Place it at next available even index
                result[positive_index] = num

                # Move to next even index
                positive_index += 2

            # If current number is negative
            else:

                # Place it at next available odd index
                result[negative_index] = num

                # Move to next odd index
                negative_index += 2

        # Return rearranged array
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array once. |
| **Space** | `O(n)` | Because the problem expects a returned rearranged array and we create `result`. |

## 8. Can We Do It In-Place With O(1) Space?

For this LeetCode problem, the expected clean solution uses extra array.

Why?

Because we must preserve relative order of positives and negatives.

If we try to do it fully in-place while preserving order, we may need shifting operations, which can become expensive.

Example:

```text
nums = [-1, -2, -3, 4, 5, 6]
```

Expected:

```text
[4, -1, 5, -2, 6, -3]
```

To place 4 at index 0, we need to shift `-1`, `-2`, `-3` right while preserving their order.

This type of stable in-place rearrangement generally becomes more complex and can take `O(n^2)` time if done by shifting.

So for this problem:

```text
O(n) time + O(n) space
```

is the practical optimal solution.

## 9. Variant: Unequal Number of Positives and Negatives

This is not LeetCode 2149, but it is a common interview variant.

Example:

```text
nums = [1, 2, -3, -1, -2, 3, 4]
```

Positive count and negative count may not be equal.

In that case:

1. First alternate as much as possible.
2. Then append the remaining elements.

But LeetCode 2149 guarantees equal positives and negatives, so we do not need this logic here.

## 10. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Advancing a cursor by `1` instead of `2` | Both cursors collide and overwrite each other's slots | Each cursor owns every other index, so step by `2` |
| Starting `negative_index` at `0` | Output begins with a negative, violating condition 3 | `positive_index = 0`, `negative_index = 1` |
| Sorting the array first | Destroys the relative order the problem demands | Never sort; scan the original order left to right |
| Using `if num >= 0` | Would place zero as positive — harmless here but wrong in the general variant | Constraints exclude zero; use `> 0` and state the assumption |
| Swapping in place to "save space" | A stable interleave by shifting costs `O(n^2)` | Write into a result array; the problem allows it |
| Appending to `result` instead of indexed writes | Appends land in scan order, not alternating order | Assign to `result[index]`, do not append |
| Assuming the input alternates already | Input may be fully grouped like `[-1,-2,3,4]` | The algorithm handles any order; do not special-case |

## 11. Interview Follow-ups

**Q: What if the counts of positives and negatives are not equal?**

A: Alternate while both groups still have elements, then append the entire remainder of the longer group in its original order. Collect the two groups first, since you can no longer precompute a slot from the sign alone — the fixed even/odd mapping breaks once one group runs out.

**Q: Can you do it in `O(1)` extra space?**

A: Not while keeping the order stable and staying linear. The stable in-place version needs rotations or shifts that push it to `O(n^2)`. If stability were dropped you could partition in place in `O(n)` with two pointers, but the output would violate condition 2. There is a cycle-leader in-place algorithm in `O(n log n)` for special sizes, which is rarely expected in an interview.

**Q: What if the array should start with a negative number instead?**

A: Swap the cursor initialization — `negative_index = 0` and `positive_index = 1`. Nothing else changes, which is a good illustration that the mapping from sign to slot is the only thing driving the algorithm.

**Q: How would you handle zeroes?**

A: The constraints rule them out, but you would need a defined policy: treat zero as its own group appended at the end, or assign it to one side. The important interview move is to ask rather than let `num > 0` silently bucket every zero as negative.

**Q: Could you do this without two separate cursors?**

A: Yes — since positives go to even slots, the `k`-th positive lands at `2k` and the `k`-th negative at `2k + 1`. Keep a single counter per sign and compute the index. It is the same algorithm with the arithmetic made explicit.

## 12. Interview Explanation

> Since the result must start with a positive number and signs must alternate, positive numbers must occupy even indices and negative numbers must occupy odd indices. I create a result array and maintain two pointers: `positive_index = 0` and `negative_index = 1`. While scanning the original array from left to right, I place positives at the next even index and negatives at the next odd index. Scanning left to right preserves relative order. This gives `O(n)` time and `O(n)` space.

## 13. Verify

```python
from typing import List


def rearrange_array(nums: List[int]) -> List[int]:
    # Create a result array of same length
    result = [0] * len(nums)

    # Positive numbers should be placed at even indices
    positive_index = 0

    # Negative numbers should be placed at odd indices
    negative_index = 1

    # Traverse numbers from left to right to preserve relative order
    for num in nums:

        # If current number is positive
        if num > 0:

            # Place it at next available even index
            result[positive_index] = num

            # Move to next even index
            positive_index += 2

        # If current number is negative
        else:

            # Place it at next available odd index
            result[negative_index] = num

            # Move to next odd index
            negative_index += 2

    # Return rearranged array
    return result

assert rearrange_array([1, -1]) == [1, -1]

# Duplicate values keep relative order
```
