## 1. Problem Statement

Given an array `nums` with `n` objects colored red, white, or blue, sort them **in-place** so that objects of the same color are adjacent, with the colors in the order red, white, and blue.

We will use the integers `0`, `1`, and `2` to represent the color red, white, and blue, respectively.

You must solve this problem without using the library's sort function.

This is the famous **Dutch National Flag** problem.

You are given an array containing only:

```text
0, 1, and 2
```

You need to sort the array in-place so that:

```text
All 0s come first
All 1s come in the middle
All 2s come at the end
```

### Examples

**Example 1:**

```text
Input: nums = [2,0,2,1,1,0]
Output: [0,0,1,1,2,2]
```

**Example 2:**

```text
Input: nums = [2,0,1]
Output: [0,1,2]
```

**Example (author's):**

```text
Input:
nums = [2, 0, 2, 1, 1, 0]

Output:
[0, 0, 1, 1, 2, 2]
```

### Constraints

- `n == nums.length`
- `1 <= n <= 300`
- `nums[i]` is either `0`, `1`, or `2`.

**Follow up:** Could you come up with a one-pass algorithm using only constant extra space?

## 2. Core Theory

The technique is **three-way partitioning**, better known as the **Dutch National Flag (DNF)** algorithm, invented by Dijkstra. It is the generalisation of Hoare's two-way partition (the one inside quicksort) to three buckets: instead of splitting the array into "less than pivot" and "not less than pivot", you split it into "less", "equal", and "greater" in a single pass with constant extra space.

The whole algorithm is a **loop invariant** maintained by three pointers `low`, `mid`, `high`. At every iteration the array is carved into four stretches:

```text
0 region        1 region          unknown          2 region
[0 ... low-1]  [low ... mid-1]  [mid ... high]  [high+1 ... n-1]
```

Concretely: `[0..low-1]` are all `0`, `[low..mid-1]` are all `1`, `[mid..high]` is the not-yet-examined region, and `[high+1..n-1]` are all `2`. The loop runs while `mid <= high`, i.e. while the unknown region is non-empty; when it empties the invariant *is* the sorted array. Each of the three cases shrinks the unknown region by exactly one, which is why the algorithm is one pass and linear.

The subtlety worth internalising — and the point interviewers probe — is the asymmetry between the two swaps. When `nums[mid] == 0` you swap with `nums[low]`; the value arriving at `mid` came from the `1` region (or from `mid` itself when `low == mid`), so it is known to be a `1` and you may safely advance **both** `low` and `mid`. When `nums[mid] == 2` you swap with `nums[high]`; the value arriving at `mid` came from the *unknown* region and has never been examined — it could be `0`, `1`, or `2`. Advancing `mid` there would let an unexamined element escape into the `1` region. So you only shrink `high` and re-test the same `mid` on the next iteration.

Recognize the pattern whenever the values come from a **small fixed set of categories with a required relative order**, and you must rearrange in place: sorting `0/1/2`, partitioning around a pivot value, moving zeroes/negatives/evens to one end, or the three-way partition that makes quicksort robust against many duplicate keys. If the categories are only two, the same idea collapses to a single `low` pointer; if there are `k` categories, DNF no longer generalises cleanly in one pass and counting sort becomes the right answer instead.

## 3. Edge Cases

The author lists several inputs in Section 4 below; the table below merges those with the remaining traps.

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[0]` | `[0]` | `low = mid = 0`, `high = 0`; the loop must still execute exactly once. |
| Single element `2` | `[2]` | `[2]` | Swaps with itself and `high` drops to `-1`, ending the loop — no out-of-range access. |
| All identical | `[1, 1, 1]` | `[1, 1, 1]` | Every step takes the `mid += 1` branch; `low` and `high` never move. |
| All one colour, `0` only | `[0, 0, 0]` | `[0, 0, 0]` | `low` and `mid` advance in lockstep; self-swaps must be harmless. |
| All one colour, `2` only | `[2, 2, 2]` | `[2, 2, 2]` | `mid` never advances, only `high` retreats — the loop still terminates. |
| Already sorted | `[0, 1, 2]` | `[0, 1, 2]` | The algorithm must not disturb correct input. |
| Reverse sorted | `[2, 1, 0]` | `[0, 1, 2]` | Worst rearrangement; exercises both swap branches. |
| No middle colour | `[2, 2, 0, 0]` | `[0, 0, 2, 2]` | The `1` region is empty, so `low` and `mid` stay equal throughout. |
| Unexamined value after a `high` swap | `[1, 2, 0]` | `[0, 1, 2]` | The canonical trap: advancing `mid` after the `2` swap skips the `0` and yields `[1, 0, 2]`. |
| Longer mixed input | `[2, 0, 2, 1, 1, 0]` | `[0, 0, 1, 1, 2, 2]` | The problem's own example; sanity check on the full loop. |

Note: `nums[i]` is constrained to `0`, `1`, `2`, so there are no negatives and no values outside the three colours; an empty array is also excluded by `1 <= n`.

## 5. Brute Force Solution: Sorting

### Intuition

The simplest way is to use built-in sorting.

Since sorting arranges values in ascending order:

```text
0 < 1 < 2
```

it gives the correct result.

### Approach

1. Call the library sort on `nums`.
2. Because `0 < 1 < 2`, ascending order is exactly the required colour order.

### Dry Run

```text
nums = [2, 0, 2, 1, 1, 0]
```

Sorting ascending gives:

```text
[0, 0, 1, 1, 2, 2]
```

### Code

```python
from typing import List

        # Sort the array in-place using built-in sort
        nums.sort()
```

## 6. Better Solution: Counting 0s, 1s, and 2s

### Intuition

Since the array contains only `0`, `1`, and `2`, we can count how many of each exist.

Then overwrite the array:

```text
first count0 times write 0
then count1 times write 1
then count2 times write 2
```

### Approach

1. Traverse the array once and count how many `0`, `1`, and `2` there are.
2. Start writing from index `0`.
3. Write `count_zero` zeroes, then `count_one` ones, then `count_two` twos.

### Dry Run

```text
nums = [2, 0, 2, 1, 1, 0]
```

Count:

```text
0 appears 2 times
1 appears 2 times
2 appears 2 times
```

Now rewrite:

```text
[0, 0, 1, 1, 2, 2]
```

### Code

```python
class Solution:

    # Define the colors
    def sortColors(self, nums: List[int]) -> None:

        # Count number of zeroes
        count_zero = 0

        # Count number of ones
        count_one = 0

        # Count number of twos
        count_two = 0

        # Traverse every number in the array
        for num in nums:

            # If current number is 0
            if num == 0:
                # Increase zero count
                count_zero += 1

            # If current number is 1
            elif num == 1:

                # Increase one count
                count_one += 1

            # If current number is 2
            else:

                # Increase two count
                count_two += 1

        # Start writing from index 0
        index = 0

        # Write all zeroes first
        for _ in range(count_zero):

            # Place 0 at current index
            nums[index] = 0

            # Move index forward
            index += 1

        # Write all ones next
        for _ in range(count_one):

            # Place 1 at current index
            nums[index] = 1

            # Move index forward
            index += 1

        # Write all twos last
        for _ in range(count_two):

            # Place 2 at current index
            nums[index] = 2

            # Move index forward
            index += 1
```

### Complexity

```text
Time Complexity: O(n)
Space Complexity: O(1)
```

This is good, but it needs two passes:

```text
Pass 1: Count values
Pass 2: Rewrite values
```

The best solution does it in one pass.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | Two linear passes: one to count, one to rewrite. |
| Space | `O(1)` | Only three counters and an index. |

## 7. Most Optimal Solution: Dutch National Flag Algorithm

### Core Intuition

We maintain three regions inside the array:

```text
0 region        unknown region      2 region
[0 ... low-1] [low ... mid ... high] [high+1 ... n-1]
```

We use three pointers:

```text
low
mid
high
```

Meaning:

```text
0 to low-1      -> all 0s
low to mid-1    -> all 1s
mid to high     -> unknown
high+1 to end   -> all 2s
```

Initially:

```text
low = 0
mid = 0
high = n - 1
```

### Rules

While:

```text
mid <= high
```

Check `nums[mid]`.

**Case 1: `nums[mid] == 0`**

A `0` belongs to the left side.

So swap it with `nums[low]`.

Then move both:

```text
low += 1
mid += 1
```

Why move both?

Because after swapping, the element at `low` position is correctly placed as `0`.

Also the element that comes to `mid` is from the known `1` region, so it is safe to move `mid`.

**Case 2: `nums[mid] == 1`**

A `1` belongs in the middle.

So it is already in correct region.

Only move:

```text
mid += 1
```

**Case 3: `nums[mid] == 2`**

A `2` belongs to the right side.

So swap it with `nums[high]`.

Then move:

```text
high -= 1
```

Important:

```text
Do not move mid here.
```

Why?

Because the element swapped from `high` to `mid` is still unknown.

It could be:

```text
0, 1, or 2
```

So we must check it again.

### Approach

1. Set `low = 0`, `mid = 0`, `high = len(nums) - 1`.
2. While `mid <= high`, inspect `nums[mid]` and apply Case 1, 2, or 3 above.
3. Stop when `mid > high`; the array is then sorted.

### Dry Run

```text
nums = [2, 0, 2, 1, 1, 0]
```

Initial:

```text
low = 0
mid = 0
high = 5
```

| Step | nums | nums[mid] | Action | low | mid | high |
|:---:|:---|:---:|:---|:---:|:---:|:---:|
| 1 | `[2,0,2,1,1,0]` | 2 | swap mid and high | 0 | 0 | 4 |
| 2 | `[0,0,2,1,1,2]` | 0 | swap low and mid | 1 | 1 | 4 |
| 3 | `[0,0,2,1,1,2]` | 0 | swap low and mid | 2 | 2 | 4 |
| 4 | `[0,0,2,1,1,2]` | 2 | swap mid and high | 2 | 2 | 3 |
| 5 | `[0,0,1,1,2,2]` | 1 | mid++ | 2 | 3 | 3 |
| 6 | `[0,0,1,1,2,2]` | 1 | mid++ | 2 | 4 | 3 |

Stop because:

```text
mid > high
```

Final:

```text
[0, 0, 1, 1, 2, 2]
```

### Code

```python
class Solution:

    # Define the colors
    def sortColors(self, nums: List[int]) -> None:

        # Pointer for placing next 0
        low = 0

        # Pointer for scanning current element
        mid = 0

        # Pointer for placing next 2
        high = len(nums) - 1

        # Continue while unknown region still exists
        while mid <= high:

            # If current element is 0, it belongs to the left side
            if nums[mid] == 0:

                # Swap current element with low pointer element
                nums[low], nums[mid] = nums[mid], nums[low]

                # Move low forward because 0 is placed correctly
                low += 1

                # Move mid forward because swapped element is already processed
                mid += 1

            # If current element is 1, it is already in middle region
            elif nums[mid] == 1:

                # Move mid forward
                mid += 1

            # If current element is 2, it belongs to the right side
            else:

                # Swap current element with high pointer element
                nums[mid], nums[high] = nums[high], nums[mid]

                # Move high backward because 2 is placed correctly
                # Do not move mid because swapped element from high is unknown
                high -= 1
```

### Complexity

```text
Time Complexity: O(n)
```

Because every element is processed at most once.

```text
Space Complexity: O(1)
```

Because we use only three pointers.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | Because every element is processed at most once. |
| Space | `O(1)` | Because we use only three pointers. |

## 8. Why We Do Not Move `mid` When `nums[mid] == 2`

This is the most important interview point.

Example:

```text
nums = [1, 2, 0]
```

Initial:

```text
low = 0
mid = 0
high = 2
```

`nums[mid] = 1`, move `mid`:

```text
low = 0
mid = 1
high = 2
```

Now:

```text
nums[mid] = 2
```

Swap with `high`:

```text
[1, 0, 2]
```

Now `high` decreases:

```text
high = 1
```

But `mid` is still `1`.

At index `1`, we now have:

```text
0
```

This `0` must still be processed and moved to the left.

If we had moved `mid`, we would skip it and array would remain wrong.

So:

```text
When nums[mid] == 2:
    high -= 1
    mid does not move
```

## 9. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Advancing `mid` after swapping with `high` | The value pulled in from `high` is unexamined. For `[1, 2, 0]` you skip the `0` and finish with `[1, 0, 2]`. | On `nums[mid] == 2` only do `high -= 1`; re-test the same `mid`. |
| Writing the loop as `while mid < high` | The final unknown cell at `mid == high` is never inspected, so a trailing `0` or `2` is left in place — `[2, 0]` finishes as `[0, 2]` by luck but `[1, 0]` finishes as `[1, 0]`. | The unknown region is inclusive on both ends: loop `while mid <= high`. |
| Advancing only `mid` (not `low`) after the `0` swap | `low` stops marking the boundary of the `0` region, so subsequent zeros overwrite zeros already placed and the `1`s are lost. | On `nums[mid] == 0` advance both `low += 1` and `mid += 1`. |
| Initialising `high = len(nums)` instead of `len(nums) - 1` | The first `2` swaps with an index one past the end — `IndexError` in Python, silent corruption elsewhere. | `high = len(nums) - 1`. |
| Returning a new sorted list instead of mutating | The problem requires in-place modification; LeetCode reads back the caller's `nums`, so the answer is discarded. | Assign into `nums[...]`; return `None`. |
| Reaching for `nums.sort()` or a counting sort when asked for one pass | Library sort is explicitly forbidden, and counting needs two passes; neither answers the follow-up. | Use the three-pointer DNF partition. |

## 10. Interview Follow-ups

**Q: What if there were `k` colours instead of 3?**

A: DNF does not extend cleanly — with `k` regions you would need `k - 1` boundary pointers and the bookkeeping stops being one clean pass. Use **counting sort** instead: one pass to build a `k`-sized frequency array, a second pass to write values back in order. That is `O(n + k)` time and `O(k)` extra space, which is constant when `k` is a fixed small alphabet.

**Q: Is the Dutch National Flag partition stable?**

A: No. The swaps move elements across arbitrary distances, so equal elements do not keep their relative order. That is irrelevant for plain integers `0/1/2`, but it matters the moment the items are objects sorted by a colour key — for that you need counting sort with a prefix-sum placement, or a stable merge.

**Q: Where else does this three-way partition appear in real code?**

A: Inside **quicksort**. A two-way partition degrades to `O(n^2)` when the array has many keys equal to the pivot; a three-way partition ("fat pivot") puts all pivot-equal elements in the middle region and recurses only on the strictly-less and strictly-greater sides, making the algorithm linear on inputs with few distinct keys. It also underlies "move all zeroes/negatives to one end" style problems.

**Q: How would you prove the algorithm terminates and is correct?**

A: Termination: every branch either increments `mid` or decrements `high`, so the quantity `high - mid` strictly decreases each iteration and the loop exits when it goes negative. Correctness: the invariant `[0..low-1] = 0`, `[low..mid-1] = 1`, `[high+1..n-1] = 2` holds before the loop (all regions empty) and each case is exactly the restoration of that invariant after shrinking the unknown region by one. On exit the unknown region is empty, so the three regions tile the array in order.

**Q: Could you do it with two passes but no counting array?**

A: Yes — a two-pass "two-pointer twice" variant: first pass moves all the `0`s to the front with a single write pointer, second pass moves all the `2`s to the back the same way, leaving the `1`s in the middle by elimination. It is `O(n)` time and `O(1)` space but touches elements twice, which is why the one-pass DNF is the preferred answer to the follow-up.

## 11. Interview Explanation

You can say:

> I use the Dutch National Flag algorithm with three pointers: `low`, `mid`, and `high`. Everything before `low` is `0`, everything between `low` and `mid - 1` is `1`, everything after `high` is `2`, and `mid` to `high` is unknown. If `nums[mid]` is `0`, I swap it with `low` and move both `low` and `mid`. If it is `1`, I move only `mid`. If it is `2`, I swap it with `high` and move only `high`, because the swapped element is still unknown. This sorts the array in one pass with constant space.

from typing import List


class Solution:
    def sortColors(self, nums: List[int]) -> None:
        low = 0
        mid = 0
        high = len(nums) - 1
        while mid <= high:
            if nums[mid] == 0:
                nums[low], nums[mid] = nums[mid], nums[low]
                low += 1
                mid += 1
            elif nums[mid] == 1:
                mid += 1
            else:
                nums[mid], nums[high] = nums[high], nums[mid]
                high -= 1

    return nums
