# 08. Array Leaders

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Right-to-Left Suffix Maximum | [Array Leaders](https://www.geeksforgeeks.org/problems/leaders-in-an-array-1587115620/1) | `O(n)` | `O(1)` extra |

## 1. Problem Statement

You are given an array **arr** of positive integers. Your task is to find all the leaders in the array. An element is considered a leader if it is greater than or equal to all elements to its right. The rightmost element is always a leader.

### Examples

```text
Input: arr = [16, 17, 4, 3, 5, 2]
Output: [17, 5, 2]
Explanation: Note that there is nothing greater on the right side of 17, 5 and, 2.

Input: arr = [10, 4, 2, 4, 1]
Output: [10, 4, 4, 1]
Explanation: Note that both of the 4s are in output, as to be a leader an equal element is also allowed on the right. side

Input: arr = [5, 10, 20, 40]
Output: [40]
Explanation: When an array is sorted in increasing order, only the rightmost element is leader.

Input: arr = [30, 10, 10, 5]
Output: [30, 10, 10, 5]
Explanation: When an array is sorted in non-increasing order, all elements are leaders.
```

### Constraints

- `1 <= arr.size() <= 10^6`
- `0 <= arr[i] <= 10^6`

### Problem Explanation

Given an array `arr`, find all **leaders** in the array.

An element is called a **leader** if it is greater than or equal to all elements on its right side.

The rightmost element is always a leader because there is no element after it.

### Example

```text
arr = [16, 17, 4, 3, 5, 2]

Output:
[17, 5, 2]
```

Explanation:

```text
16 is not leader because 17 is on its right and 17 > 16

17 is leader because all elements on right are smaller:
4, 3, 5, 2

4 is not leader because 5 is on its right and 5 > 4

3 is not leader because 5 is on its right and 5 > 3

5 is leader because 2 is on its right and 5 > 2

2 is leader because it is the rightmost element
```

So answer:

```text
[17, 5, 2]
```

## 2. Core Theory

The naive reading of "greater than or equal to **all** elements to its right" invites an `O(n^2)` solution: for every index, look at every index after it. But the condition can be restated without the word "all". `arr[i]` is a leader exactly when `arr[i] >= max(arr[i+1..n-1])` — one comparison against a single number, the **suffix maximum**, instead of `n - i` comparisons against individual elements. Collapsing a quantifier over a suffix into a single aggregate is the whole trick.

The direction of traversal is what makes that aggregate free. If you scan left to right you would need the suffix maximum of a region you have not read yet, so you would have to precompute a whole suffix-max array — `O(n)` time but `O(n)` extra space. Scanning **right to left** you build the same aggregate incrementally: before visiting index `i` you have already visited every index to its right, so a single running variable `max_from_right` already holds `max(arr[i+1..n-1])`. Test, then update. One pass, one variable.

The invariant is precise and worth stating in an interview:

```text
Invariant: just before processing index i,
           max_from_right == max(arr[i+1 .. n-1])
           (and -infinity when i == n-1, since that suffix is empty)
```

Initializing `max_from_right` to `-infinity` is what makes the last element fall out of the general rule rather than needing a special case: `arr[n-1] >= -infinity` is always true, so the rightmost element is automatically reported as a leader. The only bookkeeping cost is that leaders are discovered in reverse order, so the result is reversed once at the end — still `O(n)`.

The comparison operator encodes the problem's definition of ties. `>=` means an equal element on the right does not disqualify you, so in `[10, 4, 2, 4, 1]` both `4`s are leaders. Switching to `>` gives the "strictly greater than everything on the right" variant. Everything else about the algorithm is unchanged.

| Aspect | Left-to-right | Right-to-left |
|:---|:---|:---|
| What you need at index `i` | `max(arr[i+1..n-1])` — not yet seen | `max(arr[i+1..n-1])` — already seen |
| Extra storage | `O(n)` suffix-max array, or `O(n^2)` rescans | `O(1)` running variable |
| Total time | `O(n^2)` naive, `O(n)` with precompute | `O(n)` in one pass |
| Output order | natural | reversed, fix with one `reverse()` |

Recognize this pattern whenever a condition at index `i` depends on an aggregate (max, min, sum, count) of everything on one side. Stock-span, "next greater element", trapping rain water's prefix/suffix maxima, and "replace every element with the greatest element on its right" are all the same move: pick the traversal direction that turns the lookahead into a lookbehind.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[5]` | `[5]` | Single element is always leader; the `-infinity` seed handles it with no special case |
| Last element always a leader | `[16, 17, 4, 3, 5, 2]` | `[17, 5, 2]` | `2` qualifies because its right suffix is empty — never forget to include it |
| Strictly increasing | `[1, 2, 3, 4, 5]` | `[5]` | Only last element is leader; smallest possible output |
| Strictly decreasing | `[5, 4, 3, 2, 1]` | `[5, 4, 3, 2, 1]` | Every element is leader because all right-side elements are smaller; largest possible output |
| All identical | `[10, 10, 10]` | `[10, 10, 10]` | Using GFG-style definition, leader is greater than or **equal** to all elements on right, so duplicates can also be leaders |
| Duplicates in the middle | `[10, 4, 2, 4, 1]` | `[10, 4, 4, 1]` | Confirms `>=`, not `>`; both `4`s survive |
| Non-increasing with ties | `[30, 10, 10, 5]` | `[30, 10, 10, 5]` | Ties do not break the chain when the comparison is `>=` |
| Zeros | `[0, 0]` | `[0, 0]` | Constraints allow `arr[i] = 0`; the `-infinity` seed keeps zero from being mishandled |
| Negatives (generalized input) | `[-5, -2, -9]` | `[-2, -9]` | The problem states positive integers, but the algorithm is comparison-only so signs never matter |

## 4. Important Point

Most platforms like GFG expect leaders in the **same order as they appear in the array**, from left to right.

So for:

```text
arr = [16, 17, 4, 3, 5, 2]
```

Leaders are found from right side as:

```text
[2, 5, 17]
```

But final answer should be:

```text
[17, 5, 2]
```

So we reverse before returning.

## 5. Brute Force Solution

### Intuition

For each element, check every element on its right.

If no greater element exists on the right, current element is a leader.

### Approach

1. Pick each element `arr[i]`.
2. Compare it with all elements to its right.
3. If any right-side element is greater than `arr[i]`, then `arr[i]` is not a leader.
4. If no greater element is found, add `arr[i]` to answer.

### Dry Run

```text
arr = [16, 17, 4, 3, 5, 2]
```

Check 16:

```text
17 > 16
So 16 is not leader.
```

Check 17:

```text
No element greater than or equal? Actually no element greater than 17.
So 17 is leader.
```

Check 4:

```text
5 > 4
So 4 is not leader.
```

Check 3:

```text
5 > 3
So 3 is not leader.
```

Check 5:

```text
2 is smaller than 5.
So 5 is leader.
```

Check 2:

```text
No element on right.
So 2 is leader.
```

Answer:

```text
[17, 5, 2]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def leaders(self, arr):

        # Store the size of the array
        n = len(arr)

        # Store all leader elements
        result = []

        # Check each element as a possible leader
        for i in range(n):

            # Assume current element is a leader
            is_leader = True

            # Check all elements to the right of current element
            for j in range(i + 1, n):

                # If any right-side element is greater than current element
                if arr[j] > arr[i]:

                    # Current element cannot be a leader
                    is_leader = False

                    # Stop checking further
                    break

            # If no greater element was found on the right side
            if is_leader:

                # Add current element to result
                result.append(arr[i])

        # Return leaders in original order
        return result
```

### Complexity

```text
Time Complexity: O(n²)
```

Because for every element, we may scan all elements on its right.

```text
Space Complexity: O(1) extra
```

Ignoring the output array.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n^2)` | For each of the `n` indices the inner loop may scan up to `n - i - 1` elements to the right |
| Space | `O(1)` extra | Only `is_leader` and loop counters, ignoring the output array |

## 6. Most Optimal Solution: Traverse from Right

### Intuition

**Core Intuition**

An element is a leader if it is greater than or equal to the maximum element on its right.

So if we traverse from right to left, we can keep track of:

```text
max_from_right
```

At every index:

```text
If arr[i] >= max_from_right:
    arr[i] is a leader
```

Then update:

```text
max_from_right = arr[i]
```

### Approach

1. Initialize `max_from_right = -infinity` and an empty `result`.
2. Traverse the array from index `n - 1` down to `0`.
3. If `arr[i] >= max_from_right`, append `arr[i]` to `result` and set `max_from_right = arr[i]`.
4. After the loop, reverse `result` so leaders appear in original left-to-right order.
5. Return `result`.

### Why Right-to-Left Works

For:

```text
arr = [16, 17, 4, 3, 5, 2]
```

Start from right:

```text
2 is leader
max_from_right = 2
```

Move left:

```text
5 >= 2
So 5 is leader
max_from_right = 5
```

Move left:

```text
3 >= 5? No
So 3 is not leader
```

Move left:

```text
4 >= 5? No
So 4 is not leader
```

Move left:

```text
17 >= 5
So 17 is leader
max_from_right = 17
```

Move left:

```text
16 >= 17? No
So 16 is not leader
```

Leaders found from right side:

```text
[2, 5, 17]
```

Reverse:

```text
[17, 5, 2]
```

### Dry Run

**Optimal Dry Run**

```text
arr = [16, 17, 4, 3, 5, 2]
```

Initial:

```text
max_from_right = -infinity
result = []
```

| i | `arr[i]` | `max_from_right` before | Is leader? | `result` | `max_from_right` after |
|:---:|:---:|:---:|:---:|:---|:---:|
| 5 | 2 | -inf | Yes | `[2]` | 2 |
| 4 | 5 | 2 | Yes | `[2, 5]` | 5 |
| 3 | 3 | 5 | No | `[2, 5]` | 5 |
| 2 | 4 | 5 | No | `[2, 5]` | 5 |
| 1 | 17 | 5 | Yes | `[2, 5, 17]` | 17 |
| 0 | 16 | 17 | No | `[2, 5, 17]` | 17 |

Reverse result:

```text
[17, 5, 2]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def leaders(self, arr):

        # Store the size of the array
        n = len(arr)

        # Store leaders found while scanning from right to left
        result = []

        # Store the maximum element seen so far from the right
        max_from_right = float("-inf")

        # Traverse array from right to left
        for i in range(n - 1, -1, -1):

            # If current element is greater than or equal to all elements on right
            if arr[i] >= max_from_right:

                # Current element is a leader
                result.append(arr[i])

                # Update max_from_right
                max_from_right = arr[i]

        # Leaders are collected from right to left, so reverse them
        result.reverse()

        # Return leaders in original left-to-right order
        return result
```

### Complexity

**Complexity of Optimal Solution**

```text
Time Complexity: O(n)
```

Because we traverse the array once and reverse the result.

```text
Space Complexity: O(1) extra
```

Ignoring the output array.

If output array is counted, space is:

```text
O(n)
```

because in the worst case all elements can be leaders.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | One right-to-left pass plus one reverse of at most `n` elements |
| Space | `O(1)` extra | Only `max_from_right` and the index; the output list is `O(n)` in the worst case when every element is a leader |

## 7. Strict Greater Variant

Some versions define leader as:

```text
greater than all elements on right
```

instead of:

```text
greater than or equal to all elements on right
```

Then change this condition:

```python
if arr[i] >= max_from_right:
```

to:

```python
if arr[i] > max_from_right:
```

For GFG, use:

```python
arr[i] >= max_from_right
```

because equal elements are also considered leaders.

## 8. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Forgetting to reverse `result` | Leaders come out right-to-left as `[2, 5, 17]`, but the expected answer is `[17, 5, 2]` | Call `result.reverse()` before returning, or insert at the front (`O(n^2)` — prefer the reverse) |
| Using `>` instead of `>=` | `[10, 4, 2, 4, 1]` loses the second `4` and `[10, 10, 10]` collapses to `[10]`, because equal elements are also leaders in this definition | Use `arr[i] >= max_from_right`; switch to `>` only for the strict-greater variant |
| Initializing `max_from_right = 0` | Works only because constraints say `arr[i] >= 0`; with `0` in the array or any generalization to negatives, the rightmost element can be wrongly dropped or kept | Initialize to `float("-inf")` so the empty-suffix case is handled uniformly |
| Updating `max_from_right` before the comparison | The element ends up compared against itself, so every index trivially passes and all elements are reported as leaders | Compare first, then update inside the `if` |
| Scanning left to right with a running max of the prefix | That computes "greater than everything on the **left**", a different problem entirely | The condition is about the suffix, so traverse right to left |
| Keeping the `O(n^2)` brute force at `n = 10^6` | Up to `10^12` comparisons; guaranteed TLE under the stated constraints | Replace the inner loop with the running suffix maximum |

## 9. Interview Follow-ups

**Q: What if you had to return the indices of the leaders instead of the values?**

A: Identical loop — append `i` rather than `arr[i]`, then reverse. Nothing about the invariant changes, since `max_from_right` still tracks the suffix maximum by value.

**Q: How would you handle a stream where elements arrive one at a time and you cannot go backwards?**

A: Leaders are defined relative to a suffix, so with a forward-only stream you cannot know a leader until the stream ends. Keep a monotonically non-increasing stack: push each arriving element after popping everything strictly smaller than it. At any moment the stack holds exactly the leaders of what has arrived so far, in left-to-right order, in `O(1)` amortized per element and `O(k)` space for `k` leaders.

**Q: How many leaders can there be, and what does that mean for space?**

A: Between `1` (strictly increasing array — only the last element) and `n` (non-increasing array — every element). So the output alone is `O(n)` worst case; the `O(1)` claim is about *auxiliary* space beyond the result, which is the standard convention.

**Q: How would you answer many queries of the form "is `arr[i]` a leader of the subarray `arr[i..j]`"?**

A: Precompute a sparse table for range maximum in `O(n log n)`, then each query is `arr[i] >= RMQ(i+1, j)` in `O(1)`. The single-pass trick only answers the fixed suffix-to-the-end version.

**Q: Can you do it in one pass without the final reverse?**

A: Yes, if you are allowed `O(n)` output space upfront: allocate a list of size `n`, fill it from the back as you scan right to left, and slice off the used tail. Or compute a suffix-max array left to right and then emit leaders in order — but that trades the `O(1)` auxiliary space for `O(n)`. The reverse is `O(n)` and simpler, so it is the usual choice.

## 10. Interview Explanation

You can say:

> A leader is an element that is not smaller than any element on its right. So I traverse from right to left and keep the maximum element seen so far. If the current element is greater than or equal to this maximum, it means no element on its right is greater, so it is a leader. Since I collect leaders from right to left, I reverse the answer before returning. This takes `O(n)` time.
