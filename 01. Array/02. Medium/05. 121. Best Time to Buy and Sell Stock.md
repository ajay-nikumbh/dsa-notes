# 05. 121. Best Time to Buy and Sell Stock

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Running Minimum / One Pass (Kadane variant) | [121. Best Time to Buy and Sell Stock](https://leetcode.com/problems/best-time-to-buy-and-sell-stock/) | `O(n)` | `O(1)` |

## 1. Problem Statement

You are given an array `prices` where `prices[i]` is the price of a given stock on the `i`th day.

You want to maximize your profit by choosing a **single day** to buy one stock and choosing a **different day in the future** to sell that stock.

Return *the maximum profit you can achieve from this transaction*. If you cannot achieve any profit, return `0`.

You are given an array `prices`.

```text
prices[i] = price of a stock on day i
```

You need to choose:

```text
one day to buy
one later day to sell
```

and return the **maximum profit**.

Important rule:

```text
You must buy before you sell.
```

If no profit is possible, return 0.

### Examples

**Example 1:**

```text
Input: prices = [7,1,5,3,6,4]
Output: 5
Explanation: Buy on day 2 (price = 1) and sell on day 5 (price = 6), profit = 6-1 = 5.
Note that buying on day 2 and selling on day 1 is not allowed because you must buy before you sell.
```

Explanation:

```text
Buy at price 1
Sell at price 6

Profit = 6 - 1 = 5
```

**Example 2:**

```text
Input: prices = [7,6,4,3,1]
Output: 0
Explanation: In this case, no transactions are done and the max profit = 0.
```

Explanation:

```text
Prices are continuously decreasing.

No profitable transaction is possible.
```

So answer is:

```text
0
```

### Constraints

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

## 2. Core Theory

The technique here is the **running-extremum scan**: sweep the array once, maintain the best value seen *strictly before or at* the current position, and evaluate the current element against it. The problem asks for `max(prices[j] - prices[i])` over all pairs `i < j`. Fixing the *later* index `j` — the selling day — splits that double maximum into two nested ones:

```text
answer = max over j of ( prices[j] - min over i < j of prices[i] )
```

The inner term, "cheapest price before day `j`", is a **prefix minimum**. Prefix minima satisfy `min_so_far[j] = min(min_so_far[j-1], prices[j-1])`, so they can be computed incrementally in `O(1)` per step. That is why one pass suffices: as the scan reaches day `j`, everything it needs about the entire past is compressed into a single number. There is no need to remember every previous price, only the smallest one — any price above the minimum is dominated as a buying day and can never be part of an optimal answer.

Fixing `j` rather than `i` is the whole trick, and it is the same move as Kadane's "ending at `i`" framing. The connection is exact, not analogous. Define the **daily-difference array** `d[i] = prices[i] - prices[i-1]`. Any transaction "buy at `i`, sell at `j`" telescopes into `prices[j] - prices[i] = d[i+1] + d[i+2] + ... + d[j]` — a contiguous sum of `d`. So the best transaction is precisely the **maximum subarray sum of `d`**, and "return `0` if no profit" is the same as allowing the empty subarray. Kadane run on `d` with `max_profit` initialized to `0` therefore solves this problem exactly.

```text
prices = [7,  1,  5,  3,  6,  4]
d      =    [-6, +4, -2, +3, -2]

Kadane on d:  best contiguous run is [+4, -2, +3] = 5
Equivalently: buy at 1 (day 1), sell at 6 (day 4) -> 6 - 1 = 5
```

Notice the correspondence in the running state: Kadane's `current_sum` on `d` after day `j` equals `prices[j] - min_price_so_far` exactly whenever the run is positive, and Kadane's reset-to-zero is the same event as `min_price` being updated to the current price. The two formulations are the same algorithm wearing different clothes; the min-price version is usually preferred because it avoids building `d` and reads more naturally as a trading story.

Recognize the pattern whenever you see "best pair with an ordering constraint `i < j`". Trapping rain water (prefix max on the left, suffix max on the right), maximum difference, the largest `j - i` with `a[i] <= a[j]`, and stock problems II through IV all start from the same move: fix one endpoint, compress the other side into a running extremum.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single day | `[5]` | `0` | You cannot buy and sell on the same day; the loop must produce `0` |
| Two days, rising | `[1, 5]` | `4` | The minimal profitable case |
| Two days, falling | `[5, 1]` | `0` | Selling before buying is forbidden |
| Monotonically decreasing | `[7, 6, 4, 3, 1]` | `0` | The classic trap — never return a negative profit |
| Monotonically increasing | `[1, 2, 3, 4, 5]` | `4` | Buy at the global min, sell at the global max |
| All identical | `[3, 3, 3, 3]` | `0` | Profit is `0`, not negative; `min_price` never improves things |
| Duplicates at the extremes | `[2, 1, 1, 5, 5]` | `4` | Ties on both the buy and the sell side must not break the scan |
| Minimum appears last | `[5, 4, 3, 2, 1]` | `0` | The cheapest day has no future day to sell into |
| Maximum appears first | `[9, 1, 2]` | `1` | The global max is useless because it precedes the global min |
| Zero prices allowed | `[0, 0, 10]` | `10` | `prices[i]` can be `0`; do not treat `0` as a sentinel |
| Deep dip after an early rise | `[3, 8, 1, 4]` | `5` | The best pair (`3 -> 8`) comes before the global minimum `1` |

## 4. Key Observation

We need:

```text
maximum profit = selling price - buying price
```

But buying must happen before selling.

So for each day as selling day, we need to know:

```text
minimum price before this day
```

Then profit is:

```text
today's price - minimum price so far
```

## 5. Brute Force Solution

### Intuition

Try every possible pair:

```text
buy day
sell day
```

For every buy day, check every future sell day.

Calculate profit and keep maximum.

### Approach

1. Choose every index `i` as buy day.
2. Choose every index `j > i` as sell day.
3. Calculate `prices[j] - prices[i]`.
4. Update maximum profit.

### Dry Run

```text
prices = [7, 1, 5, 3, 6, 4]
```

If buy at 7:

```text
Sell at 1 -> profit = -6
Sell at 5 -> profit = -2
Sell at 3 -> profit = -4
Sell at 6 -> profit = -1
Sell at 4 -> profit = -3
```

If buy at 1:

```text
Sell at 5 -> profit = 4
Sell at 3 -> profit = 2
Sell at 6 -> profit = 5
Sell at 4 -> profit = 3
```

Maximum profit:

```text
5
```

### Code

```python
# Define the class solution
class Solution:
    # Define the method
    def maxProfit(self, prices: List[int]) -> int:

        # Store the length of the prices array
        n = len(prices)

        # Store the maximum profit found so far
        max_profit = 0

        # Try every day as the buying day
        for buy_day in range(n):

            # Try every later day as the selling day
            for sell_day in range(buy_day + 1, n):

                # Calculate profit if we buy on buy_day and sell on sell_day
                profit = prices[sell_day] - prices[buy_day]

                # Update maximum profit if current profit is better
                max_profit = max(max_profit, profit)

        # Return the best profit found
        return max_profit
```

### Complexity

Brute Force Complexity

```text
Time Complexity: O(n²)
```

Because we check every pair of buy and sell days.

```text
Space Complexity: O(1)
```

Because we only use variables.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n²)` | Every ordered pair `(buy_day, sell_day)` is evaluated |
| Space | `O(1)` | Only `max_profit`, `profit` and loop counters |

## 6. Better Solution: Prefix Minimum Array

### Intuition

For each day, if we sell today, we need the minimum price before today.

So we can precompute:

```text
min_price_before_or_at_i
```

Then for every selling day:

```text
profit = prices[sell_day] - min_price_so_far
```

### Approach

1. Allocate `min_price_so_far` of length `n` and set `min_price_so_far[0] = prices[0]`.
2. Fill it left to right with `min(min_price_so_far[i - 1], prices[i])`.
3. Sweep every day as a selling day and take `prices[sell_day] - min_price_so_far[sell_day]`.
4. Keep the maximum, floored at `0` by the initialization.

### Dry Run

```text
prices = [7, 1, 5, 3, 6, 4]
```

Build minimum price so far:

| Day | Price | Minimum price so far |
|:---:|:---:|:---:|
| 0 | 7 | 7 |
| 1 | 1 | 1 |
| 2 | 5 | 1 |
| 3 | 3 | 1 |
| 4 | 6 | 1 |
| 5 | 4 | 1 |

Now calculate profit:

| Sell Day | Sell Price | Min Before/So Far | Profit |
|:---:|:---:|:---:|:---:|
| 0 | 7 | 7 | 0 |
| 1 | 1 | 1 | 0 |
| 2 | 5 | 1 | 4 |
| 3 | 3 | 1 | 2 |
| 4 | 6 | 1 | 5 |
| 5 | 4 | 1 | 3 |

Answer:

```text
5
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxProfit(self, prices: List[int]) -> int:

        # Store the length of prices array
        n = len(prices)

        # Create an array to store minimum price up to each day
        min_price_so_far = [0] * n

        # Minimum price on day 0 is prices[0]
        min_price_so_far[0] = prices[0]

        # Build prefix minimum array
        for i in range(1, n):

            # Minimum price up to current day
            min_price_so_far[i] = min(min_price_so_far[i - 1], prices[i])

        # Store maximum profit
        max_profit = 0

        # Try every day as selling day
        for sell_day in range(n):

            # Calculate profit if selling today using best previous minimum price
            profit = prices[sell_day] - min_price_so_far[sell_day]

            # Update maximum profit
            max_profit = max(max_profit, profit)

        # Return best profit
        return max_profit
```

### Complexity

Prefix Minimum Complexity

```text
Time Complexity: O(n)
```

Because we traverse the array twice.

```text
Space Complexity: O(n)
```

Because we use an extra prefix minimum array.

This is good, but we can avoid the extra array.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | Two linear passes, `2n` steps total |
| Space | `O(n)` | The `min_price_so_far` array of length `n` |

## 7. Most Optimal Solution: One Pass

### Intuition

**Core Intuition**

While scanning prices from left to right, maintain:

```text
min_price = lowest price seen so far
max_profit = best profit seen so far
```

For every price:

```text
profit_if_sold_today = current_price - min_price
```

Then update:

```text
max_profit = max(max_profit, profit_if_sold_today)
min_price = min(min_price, current_price)
```

**Why This Works**

At every day, we ask:

```text
If I sell today, what is the best day before today to buy?
```

The best day to buy is simply the minimum price seen so far.

So we do not need to remember every previous price.

We only need:

```text
minimum price so far
```

### Approach

1. Initialize `min_price = float("inf")` and `max_profit = 0`.
2. Traverse each price left to right.
3. If the price is lower than `min_price`, it becomes the new best buying price.
4. Otherwise, treat today as a selling day and update `max_profit`.
5. Return `max_profit`.

### Dry Run

**One Pass Dry Run**

```text
prices = [7, 1, 5, 3, 6, 4]
```

Initial:

```text
min_price = infinity
max_profit = 0
```

| Day | Price | `min_price` before/update | Profit if sold today | `max_profit` |
|:---:|:---:|:---:|:---:|:---:|
| 0 | 7 | 7 | 0 | 0 |
| 1 | 1 | 1 | 0 | 0 |
| 2 | 5 | 1 | 4 | 4 |
| 3 | 3 | 1 | 2 | 4 |
| 4 | 6 | 1 | 5 | 5 |
| 5 | 4 | 1 | 3 | 5 |

Final answer:

```text
5
```

**Important Decreasing Price Case**

```text
prices = [7, 6, 4, 3, 1]
```

Dry run:

| Price | `min_price` | profit | `max_profit` |
|:---:|:---:|:---:|:---:|
| 7 | 7 | 0 | 0 |
| 6 | 6 | 0 | 0 |
| 4 | 4 | 0 | 0 |
| 3 | 3 | 0 | 0 |
| 1 | 1 | 0 | 0 |

No positive profit is possible.

Return:

```text
0
```

### Code

Variant A — explicit `if`/`else` branch:

```python
# Define the class solution
class Solution:
    # Define the method
    def maxProfit(self, prices: List[int]) -> int:

        # Store the minimum stock price seen so far
        min_price = float("inf")

        # Store the maximum profit found so far
        max_profit = 0

        # Traverse each stock price from left to right
        for price in prices:

            # If current price is lower than previous minimum, update min_price
            if price < min_price:

                # Current price becomes the best buying price so far
                min_price = price

            # Otherwise, check profit if we sell at current price
            else:

                # Calculate profit by selling today after buying at min_price
                profit = price - min_price

                # Update maximum profit if current profit is better
                max_profit = max(max_profit, profit)

        # Return best possible profit
        return max_profit
```

Variant B — branchless, always compute both:

```python
# Define the class solution
class Solution:
    # Define the method
    def maxProfit(self, prices: List[int]) -> int:

        # Minimum buying price seen so far
        min_price = float("inf")

        # Best profit seen so far
        max_profit = 0

        # Traverse every price
        for price in prices:

            # Update minimum price if current price is smaller
            min_price = min(min_price, price)

            # Calculate profit if sold today
            profit = price - min_price

            # Update maximum profit
            max_profit = max(max_profit, profit)

        # Return final maximum profit
        return max_profit
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | A single left-to-right pass, `O(1)` work per day |
| Space | `O(1)` | Only `min_price`, `profit` and `max_profit` |

## 8. Two Pointer View

### Intuition

This problem can also be understood using two pointers:

```text
left  = buy day
right = sell day
```

Rules:

```text
If prices[right] > prices[left]:
    calculate profit
Else:
    left = right
```

Why?

If current selling price is lower than buying price, then this current day is a better buying day.

### Approach

1. Set `left = 0` (buy day) and `right = 1` (sell day).
2. While `right` is in range, if `prices[right] > prices[left]`, record the profit.
3. Otherwise move `left` to `right`, because a cheaper buying day has appeared.
4. Advance `right` every iteration.

### Dry Run

```text
prices = [7, 1, 5, 3, 6, 4]
```

| `left` | `right` | `prices[left]` | `prices[right]` | Action | `max_profit` |
|:---:|:---:|:---:|:---:|:---|:---:|
| 0 | 1 | 7 | 1 | `1 <= 7`, move `left = 1` | 0 |
| 1 | 2 | 1 | 5 | profit `4` | 4 |
| 1 | 3 | 1 | 3 | profit `2` | 4 |
| 1 | 4 | 1 | 6 | profit `5` | 5 |
| 1 | 5 | 1 | 4 | profit `3` | 5 |

Final answer: `5`.

### Code

```python
# Define the class solution
class Solution:
    # Define the method
    def maxProfit(self, prices: List[int]) -> int:

        # Left pointer represents buying day
        left = 0

        # Right pointer represents selling day
        right = 1

        # Store maximum profit
        max_profit = 0

        # Continue until right reaches the end
        while right < len(prices):

            # If selling price is greater than buying price
            if prices[right] > prices[left]:

                # Calculate current profit
                profit = prices[right] - prices[left]

                # Update maximum profit
                max_profit = max(max_profit, profit)

            # If selling price is lower or equal, choose this as new buying day
            else:
                # Move buying day to current right day
                left = right

            # Move selling day forward
            right += 1

        # Return best profit
        return max_profit
```

### Complexity

Complexity:

```text
Time Complexity: O(n)
Space Complexity: O(1)
```

This is the same logic as maintaining `min_price`.

| Measure | Complexity | Why |
|:---|:---:|:---|
| Time | `O(n)` | `right` advances once per iteration and never moves back |
| Space | `O(1)` | Two indices and one accumulator |

## 9. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Initializing `max_profit = float("-inf")` | On a monotonically decreasing array like `[7,6,4,3,1]` it returns a negative number, but the problem says return `0` when no profit is possible | Initialize `max_profit = 0` — the "do nothing" transaction is always available |
| Updating `min_price` *before* computing profit, then treating them as different days | Actually harmless: `price - price = 0` cannot beat `max_profit >= 0`, so variant B is correct — but reasoning about it wrongly leads people to "fix" it into a bug | Either branch (`if`/`else`) or compute both; both variants are valid because a same-day profit is `0` |
| Tracking the global max price instead of the future max | `[9, 1, 2]` would report `9 - 1 = 8` if you paired the global min with the global max ignoring order | Fix the *selling* day and look only backwards for the minimum, preserving `i < j` |
| Using `min_price = 0` as the sentinel | `prices[i]` can be `0`, and a `0` sentinel makes every price look like a profit — `[3, 5]` would report `5` | Use `float("inf")`, or seed with `prices[0]` |
| Returning on the first profitable day | Greedy early exit misses a bigger profit later; `[1, 2, 100]` would return `1` | Scan the entire array and keep the running maximum |
| Two-pointer version with `right = 0` | `left` and `right` start equal, so the first comparison is a price against itself and `left` never lags behind | Start `right = 1`, and guard `len(prices) == 1` implicitly by the `while` condition |
| Forgetting the single-day input | An unguarded `prices[1]` access raises `IndexError` on `[5]` | The scan-based versions handle `n == 1` naturally and return `0` |

## 10. Interview Follow-ups

**Q: What if you could make unlimited transactions (LeetCode 122)?**

A: Sum every positive daily difference: `sum(max(0, prices[i] - prices[i-1]))`. Because you may buy and sell on consecutive days, any rising run can be decomposed into its individual up-steps with the same total profit, so grabbing every up-step is optimal. Still `O(n)` time and `O(1)` space. In Kadane terms, this is "take every positive element of `d`" rather than "take the best contiguous run of `d`".

**Q: What about at most 2 transactions (LeetCode 123)?**

A: Track four running states in one pass: `buy1` (best balance after one buy), `sell1` (best after one complete transaction), `buy2` (best after buying a second time using `sell1` as capital), and `sell2`. Update in that order per day: `buy1 = max(buy1, -p)`, `sell1 = max(sell1, buy1 + p)`, `buy2 = max(buy2, sell1 - p)`, `sell2 = max(sell2, buy2 + p)`. Return `sell2`. `O(n)` time, `O(1)` space.

**Q: What about at most `k` transactions (LeetCode 188)?**

A: Generalize the above to arrays `buy[1..k]` and `sell[1..k]` updated per day, giving `O(nk)` time and `O(k)` space. When `k >= n // 2` the constraint is no longer binding and it degenerates to the unlimited-transactions greedy, which is the standard optimization to avoid `k` blowing up.

**Q: Can you also return the buy and sell days, not just the profit?**

A: Keep `min_index` alongside `min_price`, and whenever `max_profit` improves, freeze `best_buy = min_index` and `best_sell = current_index`. Same `O(n)` / `O(1)` bounds.

**Q: How is this related to Maximum Subarray?**

A: They are the same problem. Build `d[i] = prices[i] - prices[i-1]`; every transaction's profit telescopes to a contiguous sum of `d`, so the answer is Kadane's maximum subarray sum over `d`, with `max_profit` floored at `0` to permit the empty (no-transaction) subarray. Saying this in an interview shows you see the pattern rather than the story.

**Q: What if the data arrives as a stream and cannot be stored?**

A: The one-pass version is already online — it keeps two scalars and consumes each price once. That is a direct consequence of compressing the entire past into a single prefix minimum.

## 11. Interview Explanation

You can say:

> I scan the prices from left to right and maintain the minimum price seen so far. For each day, I treat it as a selling day and calculate the profit as current price minus the minimum price before it. Then I update the maximum profit. If the current price is lower than the minimum price, it becomes the new best buying price. This gives `O(n)` time and `O(1)` space.

## 12. Verify

```python
from typing import List


def max_profit(prices: List[int]) -> int:
    min_price = float("inf")
    max_profit = 0
    for price in prices:
        if price < min_price:
            min_price = price
        else:
            profit = price - min_price
            max_profit = max(max_profit, profit)
    return max_profit


def max_profit_kadane(prices: List[int]) -> int:
    # Equivalent formulation: Kadane over the daily-difference array
    current = 0
    best = 0
    for i in range(1, len(prices)):
        d = prices[i] - prices[i - 1]
        current = max(0, current + d)
        best = max(best, current)
    return best


def max_profit_two_pointer(prices: List[int]) -> int:
    left = 0
    right = 1
    max_profit = 0
    while right < len(prices):
        if prices[right] > prices[left]:
            max_profit = max(max_profit, prices[right] - prices[left])
        else:
            left = right
        right += 1
    return max_profit


solutions = [max_profit, max_profit_kadane, max_profit_two_pointer]


def check(prices: List[int], expected: int) -> None:
    for fn in solutions:
        assert fn(list(prices)) == expected, (fn.__name__, prices, fn(list(prices)), expected)


# LeetCode examples
check([7, 1, 5, 3, 6, 4], 5)
check([7, 6, 4, 3, 1], 0)

# Edge cases table
check([5], 0)                       # single day
check([1, 5], 4)                    # two days, rising
check([5, 1], 0)                    # two days, falling
check([1, 2, 3, 4, 5], 4)           # monotonically increasing
check([3, 3, 3, 3], 0)              # all identical
check([2, 1, 1, 5, 5], 4)           # duplicates at both extremes
check([5, 4, 3, 2, 1], 0)           # minimum appears last
check([9, 1, 2], 1)                 # maximum appears first
check([0, 0, 10], 10)               # zero prices are legal
check([3, 8, 1, 4], 5)              # best pair precedes the global minimum

# Cross-check against the O(n^2) brute force on random inputs
import random


def brute(prices: List[int]) -> int:
    best = 0
    for i in range(len(prices)):
        for j in range(i + 1, len(prices)):
            best = max(best, prices[j] - prices[i])
    return best


random.seed(121)
for _ in range(500):
    arr = [random.randint(0, 15) for _ in range(random.randint(1, 12))]
```
