# 03. 169. Majority Element

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Boyer-Moore Voting | [169. Majority Element](https://leetcode.com/problems/majority-element/) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given an array `nums` of size `n`, return *the majority element*.

The majority element is the element that appears more than `⌊n / 2⌋` times. You may assume that the majority element always exists in the array.

### Examples

```text
Input:  nums = [3,2,3]
Output: 3
```

```text
Input:  nums = [2,2,1,1,1,2,2]
Output: 2
```

### Constraints

- `n == nums.length`
- `1 <= n <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`
- The input is generated such that a majority element will exist in the array.

**Follow-up:** Could you solve the problem in linear time and in `O(1)` space?

## 2. Core Theory

**Boyer-Moore voting** finds an element occurring more than `n/2` times using two variables and one pass. It is the canonical answer to "find the dominant item in a stream without storing counts".

The technique rests on a counting argument. Imagine repeatedly deleting a *pair* of unequal elements from the array. Each deletion removes at most one copy of the majority element, and always removes one non-majority element. Because the majority element has more copies than everything else **combined**, you run out of non-majority elements first — so whatever survives must be the majority.

```text
nums = [2, 2, 1, 1, 1, 2, 2]

majority 2 appears 4 times
everything else appears 3 times

pair off:  2↔1   2↔1   2↔1     (three cancellations)
left over: 2                    -> the majority
```

The algorithm simulates this without actually deleting anything. It holds a `candidate` and a `count`:

| Situation | Action | Meaning |
|:---|:---|:---|
| `count == 0` | adopt current element as `candidate` | nobody is currently winning |
| element `==` candidate | `count += 1` | a vote for the candidate |
| element `!=` candidate | `count -= 1` | one cancellation pair |

**The critical misunderstanding to avoid:** `count` is *not* the frequency of the candidate. It is a running lead margin — how many uncancelled copies of the candidate remain. It can rise and fall and hit zero mid-array while the true majority is still the eventual answer.

**Why a second pass is sometimes required.** Boyer-Moore always returns *some* element, even when no majority exists — `[1, 2, 3]` returns `3`. The guarantee is one-directional: if a majority exists, the algorithm finds it. If the problem does not promise one, count the candidate's real frequency in a verification pass before trusting it. LeetCode 169 guarantees existence, so the single pass suffices here.

**Recognizing the pattern:** reach for voting when a problem asks for an element exceeding a `n/k` frequency threshold and constrains you to `O(1)` space. The generalization to `n/3` keeps two candidates (at most two elements can exceed `n/3`), and to `n/k` keeps `k-1`.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[1]` | `1` | The lone element is trivially the majority |
| All identical | `[5, 5, 5]` | `5` | `count` never decrements |
| Exact minimum majority | `[1, 2, 1]` | `1` | Appears `2 > 1.5` times, the tightest passing case |
| Majority at the end | `[1, 2, 3, 3, 3]` | `3` | Candidate is replaced twice before settling |
| Candidate reset mid-scan | `[2, 2, 1, 1, 1, 2, 2]` | `2` | `count` hits `0` twice, yet the answer still emerges |
| Negative values | `[-1, -1, -2]` | `-1` | Values are compared, never summed or indexed |
| Two elements | `[2, 2]` | `2` | Even-length array where majority is `n/2 + 1` |

## 4. Key Observation

Majority element appears more than half of the array.

So if one element appears more than `n / 2` times, no other element can also be majority.

There can be only one majority element.

## 5. Brute Force Solution

### Intuition

For every element, count how many times it appears.

If its count is greater than `n / 2`, return it.

### Approach

1. Pick each element.
2. Count its frequency by scanning the whole array.
3. If count is greater than `n / 2`, return that element.

### Dry Run

```text
nums = [2, 2, 1, 1, 1, 2, 2]
```

For 2:

```text
2 appears 4 times
n / 2 = 3.5

4 > 3.5
```

So answer is:

```text
2
```

### Code

```python
# Define the class solution
class Solution:

    # Define the class solution
    def majorityElement(self, nums: List[int]) -> int:

        # Store the size of the array
        n = len(nums)

        # Try every element as possible majority element
        for i in range(n):

            # Count frequency of nums[i]
            count = 0

            # Compare nums[i] with every element
            for j in range(n):

                # If both elements are equal
                if nums[j] == nums[i]:

                    # Increase count
                    count += 1

            # If frequency is greater than n / 2
            if count > n // 2:

                # Return the majority element
                return nums[i]

        # This line will never be reached because majority element exists
        return -1
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Because for every element, we scan the whole array. |
| **Space** | `O(1)` | Because we only use variables. |

## 6. Better Solution: Hash Map / Frequency Count

### Intuition

Instead of counting frequency again and again, store frequency in a dictionary.

Once any element count becomes greater than `n / 2`, return it.

### Approach

1. Create a dictionary.
2. Traverse the array.
3. Increase frequency of current number.
4. If frequency becomes greater than `n / 2`, return current number.

### Dry Run

```text
nums = [2, 2, 1, 1, 1, 2, 2]
```

Frequency building:

| num | frequency map | Majority found? |
|:---:|:---|:---:|
| 2 | `{2: 1}` | No |
| 2 | `{2: 2}` | No |
| 1 | `{2: 2, 1: 1}` | No |
| 1 | `{2: 2, 1: 2}` | No |
| 1 | `{2: 2, 1: 3}` | No |
| 2 | `{2: 3, 1: 3}` | No |
| 2 | `{2: 4, 1: 3}` | Yes |

Return:

```text
2
```

### Code

```python
# Define the class solution
class Solution:

    # Define the class solution
    def majorityElement(self, nums: List[int]) -> int:

        # Store the size of the array
        n = len(nums)

        # Dictionary to store frequency of each element
        frequency = {}

        # Traverse every number in the array
        for num in nums:

            # If number is already present, increment its count
            if num in frequency:

                # Increase frequency
                frequency[num] += 1

            # If number appears for the first time
            else:

                # Initialize frequency as 1
                frequency[num] = 1

            # If current number count is greater than n / 2
            if frequency[num] > n // 2:

                # Return majority element
                return num

        # This line will never be reached because majority element exists
        return -1
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we scan the array once. |
| **Space** | `O(n)` | Because dictionary can store many unique elements. |

## 7. Better Solution: Sorting

### Intuition

If an element appears more than `n / 2` times, then after sorting, it must occupy the middle index.

So the majority element will always be:

```text
nums[n // 2]
```

after sorting.

### Why Middle Element Works

Example:

```text
nums = [2, 2, 1, 1, 1, 2, 2]
```

After sorting:

```text
[1, 1, 1, 2, 2, 2, 2]
```

Middle index:

```text
n = 7
n // 2 = 3
```

Element at index 3:

```text
2
```

So answer is 2.

Because majority element appears more than half of array, it must cross the middle position.

### Code

```python
from typing import List

class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        # Sort the array
        nums.sort()

        # Majority element must be at middle index
        return nums[len(nums) // 2]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Because sorting takes `O(n log n)`. |
| **Space** | `O(1)` or `O(n)` | Depending on sorting implementation. |

## 8. Most Optimal Solution: Boyer-Moore Voting Algorithm

### Core Intuition

Majority element appears more than all other elements combined.

So we can cancel one majority element with one non-majority element.

After all cancellations, the element left as candidate will be the majority.

### Simple Voting Idea

Maintain:

```text
candidate
count
```

When `count == 0`, choose current number as candidate.

Then:

```text
If current number == candidate:
    count += 1
Else:
    count -= 1
```

Meaning:

```text
Same as candidate -> vote for candidate
Different from candidate -> vote against candidate
```

Since majority appears more than half, it survives all cancellations.

## 9. Boyer-Moore Dry Run

```text
nums = [2, 2, 1, 1, 1, 2, 2]
```

Initial:

```text
candidate = None
count = 0
```

| num | Action | candidate | count |
|:---:|:---|:---:|:---:|
| 2 | count is 0, choose 2, vote +1 | 2 | 1 |
| 2 | same as candidate, vote +1 | 2 | 2 |
| 1 | different, vote -1 | 2 | 1 |
| 1 | different, vote -1 | 2 | 0 |
| 1 | count is 0, choose 1, vote +1 | 1 | 1 |
| 2 | different, vote -1 | 1 | 0 |
| 2 | count is 0, choose 2, vote +1 | 2 | 1 |

Final candidate:

```text
2
```

Since majority is guaranteed, return 2.

## 10. Cancellation Intuition

For:

```text
nums = [2, 2, 1, 1, 1, 2, 2]
```

Majority element 2 appears 4 times.

Other elements appear 3 times.

If we cancel each 2 with one non-2:

```text
2 cancels 1
2 cancels 1
2 cancels 1
```

One 2 still remains.

That remaining candidate is the majority.

### Code

```python
# Define the class solution
class Solution:

    # Define the class solution
    def majorityElement(self, nums: List[int]) -> int:

        # Current candidate for majority element
        candidate = None

        # Vote count for current candidate
        count = 0

        # Traverse every number in the array
        for num in nums:

            # If count becomes zero, choose current number as new candidate
            if count == 0:

                # Set current number as candidate
                candidate = num

            # If current number matches candidate
            if num == candidate:

                # Increase vote count
                count += 1

            # If current number differs from candidate
            else:

                # Decrease vote count
                count -= 1

        # Since majority is guaranteed, candidate is the answer
        return candidate
```

## 11. Complexity of Boyer-Moore

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we scan the array once. |
| **Space** | `O(1)` | Because we only use two variables. |

## 12. Important: What If Majority Is Not Guaranteed?

LeetCode 169 says majority always exists.

But in some interviews, they may ask:

```text
What if majority may not exist?
```

Then Boyer-Moore gives only a candidate.

We must verify it in a second pass.

### Code

```python
# Define the class solution
class Solution:

    # Define the class solution
    def majorityElement(self, nums: List[int]) -> int:

        # Current majority candidate
        candidate = None

        # Vote count
        count = 0

        # First pass: find candidate
        for num in nums:

            # If vote count is zero, select new candidate
            if count == 0:

                # Set current number as candidate
                candidate = num

            # If number matches candidate
            if num == candidate:

                # Increase votes
                count += 1

            # Otherwise cancel one vote
            else:

                # Decrease votes
                count -= 1

        # Store actual frequency of candidate
        actual_count = 0

        # Verify candidate frequency
        for num in nums:

            # If current number equals candidate
            if num == candidate:

                # Increase actual count
                actual_count += 1

        # If candidate appears more than n / 2 times
        if actual_count > len(nums) // 2:

            # Return valid majority element
            return candidate

        # Return -1 if no majority element exists
        return -1
```

Complexity:

```text
Time Complexity: O(n)
Space Complexity: O(1)
```

Even with verification, time remains linear.

## 13. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Treating `count` as a frequency | It is a lead margin, not an occurrence count; reporting it gives a wrong number | Only use `count` to decide when to swap candidates |
| Using `elif count == 0` after the equality check | The candidate is never adopted on the first element, so `candidate` stays `None` | Check `count == 0` **first**, then compare to the candidate |
| Trusting the candidate with no guarantee | `[1, 2, 3]` returns `3`, which is not a majority | Add a verification pass when existence is not promised |
| Using `count >= n // 2` | `n // 2` floors, so `[1, 1, 2, 2]` would wrongly accept | The condition is strictly `> n // 2` |
| Resetting `count` to `0` instead of `1` on a new candidate | The new candidate gets no vote for its own occurrence | Adopt the candidate, then fall through to the `+= 1` branch |
| Sorting when the input must stay unchanged | `nums.sort()` mutates the caller's list | Use Boyer-Moore, or sort a copy |

## 14. Interview Follow-ups

**Q: What if the majority element is not guaranteed to exist?**

A: Boyer-Moore still returns a candidate, but it may be meaningless. Add a second pass counting the candidate's real occurrences and return it only if that count exceeds `n // 2`. This stays `O(n)` time and `O(1)` space.

**Q: Find all elements appearing more than `n/3` times.**

A: At most two such elements can exist, so track two candidates with two counters. Decrement both when an element matches neither. Then verify both in a second pass, since the `n/3` variant does not guarantee either is valid. This is LeetCode 229.

**Q: Generalize to more than `n/k` times.**

A: At most `k-1` elements can exceed `n/k`, so keep `k-1` candidates with counts, and cancel `k` distinct elements at a time. Verification is mandatory. Cost becomes `O(nk)` time and `O(k)` space.

**Q: Why does the sorting approach work, and when would you prefer it?**

A: An element occupying more than half the positions must cover index `n//2` after sorting, no matter where its block sits. It is worth mentioning as an easy-to-justify solution, but at `O(n log n)` it is strictly worse than voting, and it mutates the input.

**Q: What if the data arrives as a stream too large to store?**

A: Boyer-Moore is ideal — it needs only two variables and one sequential pass, never revisiting earlier elements. The caveat is verification: if you cannot replay the stream, you cannot confirm the candidate, so you must either trust the majority guarantee or buffer a second pass.

## 15. Interview Explanation

> I use Boyer-Moore Voting Algorithm. I maintain a candidate and a count. When count becomes zero, I choose the current element as candidate. If the current element equals candidate, I increment count; otherwise, I decrement count. This works because the majority element appears more than all other elements combined, so it cannot be completely cancelled out. Since the problem guarantees a majority element, the final candidate is the answer.

from typing import List


def majority_element(nums: List[int]) -> int:
    # Current candidate for majority element
    candidate = None

    # Vote count for current candidate
    count = 0

    # Traverse every number in the array
    for num in nums:

        # If count becomes zero, choose current number as new candidate
        if count == 0:

            # Set current number as candidate
            candidate = num

        # If current number matches candidate
        if num == candidate:

            # Increase vote count
            count += 1

        # If current number differs from candidate
        else:

            # Decrease vote count
            count -= 1

    # Since majority is guaranteed, candidate is the answer
    return candidate


def majority_element_verified(nums: List[int]) -> int:
    """Variant for when a majority is NOT guaranteed."""
    # Get the Boyer-Moore candidate first
    candidate = majority_element(nums)

    # Confirm the candidate actually appears more than n / 2 times
    if nums.count(candidate) > len(nums) // 2:
        return candidate

    # No true majority exists
    return -1
