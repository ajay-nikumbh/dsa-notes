# 11. Longest Subarray with Sum K

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Medium** | Prefix Sum + Hash Map | [Longest Sub-Array with Sum K](https://www.geeksforgeeks.org/problems/longest-sub-array-with-sum-k0809/1) | `O(n)` | `O(n)` |

## 1. Problem Statement

Given an array `arr[]` containing integers and an integer `k`, your task is to find the length of the longest subarray where the sum of its elements is equal to the given value `k`. If there is no subarray with sum equal to `k`, return `0`.

### Examples

```text
Input:  arr[] = [10, 5, 2, 7, 1, -10], k = 15
Output: 6
Explanation: Subarrays with sum = 15 are [5, 2, 7, 1], [10, 5] and [10, 5, 2, 7, 1, -10]. The length of
the longest subarray with a sum of 15 is 6.
```

```text
Input:  arr[] = [-5, 8, -14, 2, 4, 12], k = -5
Output: 5
Explanation: Subarrays with sum = -5 are [-5] and [-5, 8, -14, 2, 4]. The length of the longest
subarray with a sum of -5 is 5.
```

```text
Input:  arr[] = [10, -10, 20, 30], k = 5
Output: 0
Explanation: No subarray with sum = 5 is present in arr[].
```

### Constraints

- `1 <= arr.size() <= 10^5`
- `-10^4 <= arr[i] <= 10^4`
- `-10^9 <= k <= 10^9`

## 2. Problem Explanation

Given an array `nums` and an integer `k`, find the **length of the longest contiguous subarray** whose sum is exactly `k`.

Important word:

```text
Contiguous subarray
```

That means elements must be continuous.

### Example

```text
nums = [10, 5, 2, 7, 1, 9]
k = 15
```

Possible subarrays with sum 15:

```text
[10, 5]         length = 2
[5, 2, 7, 1]    length = 4
```

Longest length is:

```text
4
```

So answer:

```text
4
```

## 3. What is a Subarray?

A subarray is a continuous part of the array.

For:

```text
nums = [1, 2, 3, 4]
```

Valid subarrays:

```text
[1]
[1, 2]
[1, 2, 3]
[2, 3]
[3, 4]
```

Invalid subarray:

```text
[1, 3]
```

Because 1 and 3 are not continuous.

## 4. Important Versions of This Problem

This problem has two major versions.

### Version 1: Array has only positive numbers

Example:

```text
nums = [1, 2, 3, 1, 1, 1, 1]
k = 3
```

For positive numbers, we can use **sliding window / two pointers**.

### Version 2: Array can contain positive, zero, and negative numbers

Example:

```text
nums = [1, -1, 5, -2, 3]
k = 3
```

For negative numbers, sliding window may fail.

The most general and safest approach is:

```text
Prefix Sum + Hash Map
```

This works for:

```text
positive numbers
negative numbers
zeroes
```

## 5. Brute Force Solution

### Intuition

Generate every possible subarray.

Calculate its sum.

If the sum is equal to `k`, update the maximum length.

### Approach

1. Start from every index `i`.
2. End at every index `j`.
3. Calculate sum from `i` to `j`.
4. If sum equals `k`, update answer.

### Dry Run

```text
nums = [10, 5, 2, 7, 1, 9]
k = 15
```

Subarrays:

```text
[10]            sum = 10
[10, 5]         sum = 15  length = 2
[10, 5, 2]      sum = 17
```

Starting from index 1:

```text
[5]             sum = 5
[5, 2]          sum = 7
[5, 2, 7]       sum = 14
[5, 2, 7, 1]    sum = 15  length = 4
```

Answer:

```text
4
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def longestSubarrayWithSumK(self, nums: List[int], k: int) -> int:

        # Store the size of the array
        n = len(nums)

        # Store the maximum length found so far
        max_length = 0

        # Try every possible starting index
        for start in range(n):

            # Try every possible ending index
            for end in range(start, n):

                # Store sum of current subarray
                current_sum = 0

                # Calculate sum from start to end
                for index in range(start, end + 1):

                    # Add current element to current_sum
                    current_sum += nums[index]

                # If current subarray sum equals k
                if current_sum == k:

                    # Calculate current subarray length
                    current_length = end - start + 1

                    # Update max_length if current length is larger
                    max_length = max(max_length, current_length)

        # Return longest valid subarray length
        return max_length
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^3)` | Because we choose `start`, `end`, and then calculate sum again. |
| **Space** | `O(1)` | Because we only use variables. |

## 6. Better Brute Force: Running Sum

### Intuition

Instead of recalculating the sum from scratch for every `end`, we can maintain a running sum.

For fixed `start`, as `end` moves forward:

```text
current_sum += nums[end]
```

### Dry Run

```text
nums = [10, 5, 2, 7, 1, 9]
k = 15
```

Start from index 1:

```text
current_sum = 0
```

Move end:

```text
end = 1 -> current_sum = 5
end = 2 -> current_sum = 7
end = 3 -> current_sum = 14
end = 4 -> current_sum = 15
```

Now subarray is:

```text
[5, 2, 7, 1]
```

Length:

```text
4
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def longestSubarrayWithSumK(self, nums: List[int], k: int) -> int:

        # Store the size of the array
        n = len(nums)

        # Store maximum valid subarray length
        max_length = 0

        # Try every starting index
        for start in range(n):

            # Running sum for subarrays starting at start
            current_sum = 0

            # Expand end index from start to end of array
            for end in range(start, n):

                # Add current element to running sum
                current_sum += nums[end]

                # If running sum becomes equal to k
                if current_sum == k:

                    # Calculate current subarray length
                    current_length = end - start + 1

                    # Update max_length
                    max_length = max(max_length, current_length)

        # Return longest length found
        return max_length
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Because for every `start` we expand `end` across the array. |
| **Space** | `O(1)` | Because we only use variables. |

This is better, but not optimal.

## 7. Optimal for Positive Numbers: Sliding Window

### When can we use this?

Use this approach only when:

```text
All elements are positive
```

or sometimes when all elements are non-negative with care.

For strictly positive numbers, it works perfectly.

### Core Intuition

Use a window:

```text
left ........ right
```

Maintain sum of current window.

Because all numbers are positive:

```text
If sum < k:
    expand right

If sum > k:
    shrink left

If sum == k:
    update answer
```

Why does this work?

Because with positive numbers:

```text
Adding more elements always increases sum.
Removing elements always decreases sum.
```

So two pointers move safely.

### Dry Run

```text
nums = [10, 5, 2, 7, 1, 9]
k = 15
```

Initial:

```text
left = 0
current_sum = 0
max_length = 0
```

| right | nums[right] | current_sum after add | Action | Window | max_length |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 10 | 10 | sum < k | [10] | 0 |
| 1 | 5 | 15 | sum == k | [10, 5] | 2 |
| 2 | 2 | 17 | shrink left | [5, 2] | 2 |
| 3 | 7 | 14 | sum < k | [5, 2, 7] | 2 |
| 4 | 1 | 15 | sum == k | [5, 2, 7, 1] | 4 |
| 5 | 9 | 24 | shrink left | [7, 1, 9] | 4 |

Answer:

```text
4
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def longestSubarrayWithSumK(self, nums: List[int], k: int) -> int:

        # Store the size of the array
        n = len(nums)

        # Left pointer of the current window
        left = 0

        # Running sum of current window
        current_sum = 0

        # Maximum length of subarray with sum k
        max_length = 0

        # Move right pointer from left to right
        for right in range(n):

            # Add current right element into window sum
            current_sum += nums[right]

            # Shrink window while sum is greater than k
            while left <= right and current_sum > k:

                # Remove left element from current sum
                current_sum -= nums[left]

                # Move left pointer forward
                left += 1

            # If current window sum is exactly k
            if current_sum == k:

                # Calculate current window length
                current_length = right - left + 1

                # Update maximum length
                max_length = max(max_length, current_length)

        # Return longest valid length
        return max_length
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because each pointer moves at most `n` times. |
| **Space** | `O(1)` | Because we only use variables. |

## 8. Why Sliding Window Fails With Negative Numbers

Consider:

```text
nums = [1, -1, 5, -2, 3]
k = 3
```

The answer is:

```text
[1, -1, 5, -2] = 3
length = 4
```

But with negative numbers, this logic breaks:

```text
If current_sum > k, shrink left
```

Why?

Because adding a future negative number can reduce the sum.

Example:

```text
current_sum = 5
k = 3
```

In positive arrays, if sum is already greater than `k`, adding more numbers only increases it.

But with negatives:

```text
5 + (-2) = 3
```

So shrinking early can remove useful elements.

Therefore:

```text
Sliding window is not reliable when negatives are present.
```

## 9. Most General Optimal Solution: Prefix Sum + Hash Map

This is the best solution when array can contain:

```text
positive numbers
negative numbers
zeroes
```

### Prefix Sum Intuition

Prefix sum means:

```text
sum from index 0 to current index
```

Example:

```text
nums = [1, -1, 5, -2, 3]
```

Prefix sums:

```text
index 0: 1
index 1: 0
index 2: 5
index 3: 3
index 4: 6
```

Now suppose at index `i`, prefix sum is `current_sum`.

We want some previous prefix sum such that:

```text
current_sum - previous_sum = k
```

Rearrange:

```text
previous_sum = current_sum - k
```

So if we have seen `current_sum - k` before, then the subarray after that previous index up to current index has sum `k`.

### Core Formula

If:

```text
prefix_sum[j] - prefix_sum[i] = k
```

Then subarray from:

```text
i + 1 to j
```

has sum `k`.

So while traversing:

```text
current_sum = prefix sum till current index
needed_sum = current_sum - k
```

If `needed_sum` existed earlier, we found a valid subarray.

### Why Store Earliest Index?

We want the **longest** subarray.

Length is:

```text
current_index - previous_index
```

To maximize length, we need the earliest previous index.

So for each prefix sum, store only its **first occurrence**.

### Prefix Sum Dry Run

```text
nums = [1, -1, 5, -2, 3]
k = 3
```

Expected answer:

```text
[1, -1, 5, -2]
length = 4
```

Initial:

```text
prefix_index = {0: -1}
current_sum = 0
max_length = 0
```

Why `{0: -1}`?

It means:

```text
Before array starts, prefix sum is 0 at index -1.
```

This helps when subarray starts from index 0.

| i | nums[i] | current_sum | needed_sum = current_sum - k | Found? | Length | max_length |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 1 | 1 | -2 | No | - | 0 |
| 1 | -1 | 0 | -3 | No | - | 0 |
| 2 | 5 | 5 | 2 | No | - | 0 |
| 3 | -2 | 3 | 0 | Yes, index -1 | 4 | 4 |
| 4 | 3 | 6 | 3 | Yes, index 3 | 1 | 4 |

Answer:

```text
4
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def longestSubarrayWithSumK(self, nums: List[int], k: int) -> int:

        # Dictionary to store first occurrence index of each prefix sum
        prefix_index = {}

        # Prefix sum 0 exists before the array starts at index -1
        prefix_index[0] = -1

        # Running prefix sum
        current_sum = 0

        # Store maximum length found
        max_length = 0

        # Traverse each index of the array
        for i in range(len(nums)):

            # Add current element to running prefix sum
            current_sum += nums[i]

            # We need a previous prefix sum equal to current_sum - k
            needed_sum = current_sum - k

            # If needed_sum was seen before
            if needed_sum in prefix_index:

                # Calculate length of subarray with sum k
                current_length = i - prefix_index[needed_sum]

                # Update maximum length
                max_length = max(max_length, current_length)

            # Store current_sum only if it is appearing for the first time
            if current_sum not in prefix_index:

                # Store earliest index of this prefix sum
                prefix_index[current_sum] = i

        # Return longest subarray length
        return max_length
```

## 10. Complexity of Prefix Sum Solution

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we scan the array once. |
| **Space** | `O(n)` | Because in the worst case, all prefix sums can be different. |

## 11. Why We Should Not Overwrite Prefix Sum Index

Very important interview point.

Suppose:

```text
nums = [1, -1, 5, -2, 3]
k = 3
```

Prefix sum 0 appears at:

```text
index -1
index 1
```

If we overwrite:

```text
prefix_index[0] = 1
```

Then at index 3, current sum is 3.

Needed sum:

```text
3 - 3 = 0
```

If using earliest index -1:

```text
length = 3 - (-1) = 4
```

If overwritten with index 1:

```text
length = 3 - 1 = 2
```

We lose the longest answer.

So we store the prefix sum only the first time.

## 12. Which Solution Should You Use?

### If array has only positive integers

Use sliding window:

```text
Time: O(n)
Space: O(1)
```

### If array can contain negative numbers and zeroes

Use prefix sum + hash map:

```text
Time: O(n)
Space: O(n)
```

### In interviews

Ask this clarification first:

```text
Can the array contain negative numbers?
```

If yes or not specified, use prefix sum + hash map.

## 13. One-Line Interview Explanation

> If the array contains only positive numbers, I use sliding window because increasing the right pointer only increases the sum and moving the left pointer decreases it. But if negatives are allowed, sliding window fails, so I use prefix sum with a hash map. For every index, if `current_sum - k` appeared earlier, then the subarray between that earlier index and current index has sum `k`. I store the earliest index of every prefix sum to maximize the length.
