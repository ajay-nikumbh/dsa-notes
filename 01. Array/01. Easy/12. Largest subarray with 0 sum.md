# 12. Largest subarray with 0 sum

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Medium** | Prefix Sum + Hash Map | [Largest subarray with 0 sum](https://www.geeksforgeeks.org/problems/largest-subarray-with-0-sum/1) | `O(n)` | `O(n)` |

## 1. Problem Statement

Given an array `arr[]` containing both positive and negative integers, the task is to find the **length** of the **longest subarray** with a sum equals to **0**.

**Note:** A subarray is a contiguous part of an array, formed by selecting one or more consecutive elements while maintaining their original order.

### Examples

```text
Input:  arr[] = [15, -2, 2, -8, 1, 7, 10, 23]
Output: 5
Explanation: The longest subarray with sum equals to 0 is [-2, 2, -8, 1, 7].
```

```text
Input:  arr[] = [2, 10, 4]
Output: 0
Explanation: There is no subarray with a sum of 0.
```

```text
Input:  arr[] = [1, 0, -4, 3, 1, 0]
Output: 5
Explanation: The longest subarray with sum equals to 0 is [0, -4, 3, 1, 0]
```

### Constraints

- `1 <= arr.size() <= 10^6`
- `-10^3 <= arr[i] <= 10^3`

## 2. Problem Explanation

Given an array `nums`, find the **length of the longest contiguous subarray** whose sum is 0.

Important word:

```text
contiguous subarray
```

That means elements must be continuous.

### Example

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
Output = 5
```

Why?

The subarray is:

```text
[-2, 2, -8, 1, 7]
```

Sum:

```text
-2 + 2 - 8 + 1 + 7 = 0
```

Length:

```text
5
```

So answer is 5.

## 3. Key Observation

This problem is very similar to:

```text
Longest Subarray with Sum K
```

Here:

```text
k = 0
```

So we need the longest subarray whose sum is exactly 0.

The best approach is:

```text
Prefix Sum + Hash Map
```

## 4. What is Prefix Sum?

Prefix sum means:

```text
sum from index 0 to current index
```

Example:

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
```

Prefix sums:

| index | nums[index] | prefix sum |
|:---:|:---:|:---:|
| 0 | 15 | 15 |
| 1 | -2 | 13 |
| 2 | 2 | 15 |
| 3 | -8 | 7 |
| 4 | 1 | 8 |
| 5 | 7 | 15 |
| 6 | 10 | 25 |
| 7 | 23 | 48 |

Notice prefix sum 15 appears multiple times:

```text
index 0
index 2
index 5
```

This is the main clue.

## 5. Core Intuition

Suppose prefix sum at index `i` and index `j` is the same.

```text
prefix_sum[i] == prefix_sum[j]
```

That means the sum between `i + 1` and `j` is 0.

Why?

Because:

```text
prefix_sum[j] - prefix_sum[i] = 0
```

So:

```text
sum from i + 1 to j = 0
```

### Example

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
```

Prefix sum 15 appears at:

```text
index 0 and index 5
```

That means subarray from index 1 to 5 has sum 0.

```text
nums[1:6] = [-2, 2, -8, 1, 7]
```

Sum:

```text
-2 + 2 - 8 + 1 + 7 = 0
```

Length:

```text
5 - 0 = 5
```

## 6. Edge Cases

```text
nums = [1, 2, 3]
Output = 0
```

No subarray has sum 0.

```text
nums = [0]
Output = 1
```

Single zero itself is a zero-sum subarray.

```text
nums = [0, 0, 0]
Output = 3
```

Whole array has sum 0.

```text
nums = [1, -1]
Output = 2
```

Whole array has sum 0.

```text
nums = [1, 2, -3, 3]
Output = 3
```

Subarray `[1, 2, -3]` has sum 0.

## 7. Brute Force Solution

### Intuition

Generate every possible subarray.

Calculate its sum.

If the sum is 0, update the maximum length.

### Approach

1. Start from every index `start`.
2. End at every index `end`.
3. Calculate sum from `start` to `end`.
4. If sum is 0, update answer.

### Dry Run

```text
nums = [1, 2, -3, 3]
```

All important subarrays:

```text
[1]             sum = 1
[1, 2]          sum = 3
[1, 2, -3]      sum = 0    length = 3
[1, 2, -3, 3]   sum = 3
[2, -3]         sum = -1
[-3, 3]         sum = 0    length = 2
```

Maximum zero-sum length:

```text
3
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxLen(self, nums: List[int]) -> int:

        # Store the length of the array
        n = len(nums)

        # Store the largest zero-sum subarray length found so far
        max_length = 0

        # Try every possible starting index
        for start in range(n):

            # Try every possible ending index
            for end in range(start, n):

                # Store sum of current subarray
                current_sum = 0

                # Calculate sum from start to end
                for index in range(start, end + 1):

                    # Add current value into current_sum
                    current_sum += nums[index]

                # If current subarray sum is zero
                if current_sum == 0:

                    # Calculate current subarray length
                    current_length = end - start + 1

                    # Update answer if current length is larger
                    max_length = max(max_length, current_length)

        # Return largest zero-sum subarray length
        return max_length
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^3)` | Because we choose `start`, `end`, and then calculate sum again. |
| **Space** | `O(1)` | Because we only use variables. |

## 8. Better Brute Force: Running Sum

### Intuition

Instead of recalculating the sum every time, maintain a running sum for each starting index.

For fixed `start`, as `end` moves forward:

```text
current_sum += nums[end]
```

### Dry Run

```text
nums = [1, 2, -3, 3]
```

For `start = 0`:

```text
end = 0 -> current_sum = 1
end = 1 -> current_sum = 3
end = 2 -> current_sum = 0   length = 3
end = 3 -> current_sum = 3
```

For `start = 2`:

```text
end = 2 -> current_sum = -3
end = 3 -> current_sum = 0   length = 2
```

Answer:

```text
3
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxLen(self, nums: List[int]) -> int:

        # Store the length of the array
        n = len(nums)

        # Store the largest zero-sum subarray length found
        max_length = 0

        # Try every possible starting index
        for start in range(n):

            # Running sum for subarray starting at start
            current_sum = 0

            # Expand ending index from start to end
            for end in range(start, n):

                # Add current ending element into running sum
                current_sum += nums[end]

                # If running sum is zero
                if current_sum == 0:

                    # Calculate current subarray length
                    current_length = end - start + 1

                    # Update maximum length
                    max_length = max(max_length, current_length)

        # Return largest zero-sum subarray length
        return max_length
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Because for every `start` we expand `end` across the array. |
| **Space** | `O(1)` | Because we only use variables. |

This is better, but not optimal.

## 9. Most Optimal Solution: Prefix Sum + Hash Map

### Core Intuition

While scanning the array, calculate prefix sum.

If the same prefix sum appears again, the elements between the previous index and current index have sum 0.

So we store:

```text
prefix_sum -> first index where this prefix sum appeared
```

Why first index?

Because we want the **longest** subarray.

The earlier the previous index, the larger the length.

### Important Case: Prefix Sum Becomes 0

If prefix sum itself becomes 0 at index `i`, then subarray from index 0 to `i` has sum 0.

Example:

```text
nums = [1, 2, -3, 3]
```

At index 2:

```text
current_sum = 1 + 2 - 3 = 0
```

So subarray:

```text
[1, 2, -3]
```

Length:

```text
3
```

To handle this cleanly, we initialize:

```text
prefix_index = {0: -1}
```

Meaning:

```text
Prefix sum 0 exists before the array starts at index -1.
```

Then if current sum is 0 at index `i`, length becomes:

```text
i - (-1) = i + 1
```

Correct.

### Dry Run of Optimal Solution

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
```

Initial:

```text
prefix_index = {0: -1}
current_sum = 0
max_length = 0
```

| i | nums[i] | current_sum | Seen before? | Length | max_length |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 15 | 15 | No | - | 0 |
| 1 | -2 | 13 | No | - | 0 |
| 2 | 2 | 15 | Yes, index 0 | 2 | 2 |
| 3 | -8 | 7 | No | - | 2 |
| 4 | 1 | 8 | No | - | 2 |
| 5 | 7 | 15 | Yes, index 0 | 5 | 5 |
| 6 | 10 | 25 | No | - | 5 |
| 7 | 23 | 48 | No | - | 5 |

Answer:

```text
5
```

The longest zero-sum subarray is:

```text
[-2, 2, -8, 1, 7]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxLen(self, nums: List[int]) -> int:

        # Dictionary stores first index where each prefix sum appeared
        prefix_index = {0: -1}

        # Running prefix sum from start to current index
        current_sum = 0

        # Store maximum length of zero-sum subarray
        max_length = 0

        # Traverse every index in the array
        for i in range(len(nums)):

            # Add current element to running prefix sum
            current_sum += nums[i]

            # If current prefix sum was seen before
            if current_sum in prefix_index:

                # Subarray between previous index + 1 and current index has sum zero
                current_length = i - prefix_index[current_sum]

                # Update max length if this subarray is longer
                max_length = max(max_length, current_length)

            # If current prefix sum is appearing for the first time
            else:

                # Store its first occurrence index
                prefix_index[current_sum] = i

        # Return the largest zero-sum subarray length
        return max_length
```

## 10. Why Repeated Prefix Sum Means Zero Sum

Let:

```text
prefix_sum at index a = S
prefix_sum at index b = S
```

Then:

```text
sum from 0 to a = S
sum from 0 to b = S
```

So the extra elements between `a + 1` and `b` added nothing.

Therefore:

```text
sum from a + 1 to b = 0
```

That is why repeated prefix sum creates a zero-sum subarray.

## 11. Why We Store First Occurrence Only

Suppose prefix sum 15 appears at:

```text
index 0
index 2
index 5
```

At index 5, if we use first occurrence index 0:

```text
length = 5 - 0 = 5
```

If we overwrite with latest occurrence index 2:

```text
length = 5 - 2 = 3
```

We lose the longer answer.

So:

```text
Never overwrite prefix sum index.
Store only first occurrence.
```

## 12. Complexity of Optimal Solution

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we scan the array once. |
| **Space** | `O(n)` | Because in the worst case, all prefix sums can be different. |

3

## 14. Interview Explanation

You can say:

> I will use prefix sum. If the same prefix sum appears at two different indices, then the subarray between those two indices has sum zero. So I store the first index where each prefix sum appears. While scanning, if the current prefix sum was already seen, I calculate the length between the previous index and current index and update the answer. I store only the first occurrence because we need the longest subarray. This gives `O(n)` time and `O(n)` space.
