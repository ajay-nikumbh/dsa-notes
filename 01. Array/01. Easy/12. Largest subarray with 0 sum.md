# 12. Largest subarray with 0 sum

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Medium** | Prefix Sum + Hash Map | [Largest subarray with 0 sum](https://www.geeksforgeeks.org/problems/largest-subarray-with-0-sum/1) | `O(n)` | `O(n)` |

## 1. Problem Statement

Given an array `arr[]` containing both positive and negative integers, the task is to find the **length** of the **longest subarray** with a sum equals to **0**.

**Note:** A subarray is a contiguous part of an array, formed by selecting one or more consecutive elements while maintaining their original order.

### Examples

```text
Input:  arr[] = [15, -2, 2, -8, 1, 7, 10, 23]
Output: 5
Explanation: The longest subarray with sum equals to 0 is [-2, 2, -8, 1, 7].
```

```text
Input:  arr[] = [2, 10, 4]
Output: 0
Explanation: There is no subarray with a sum of 0.
```

```text
Input:  arr[] = [1, 0, -4, 3, 1, 0]
Output: 5
Explanation: The longest subarray with sum equals to 0 is [0, -4, 3, 1, 0]
```

### Constraints

- `1 <= arr.size() <= 10^6`
- `-10^3 <= arr[i] <= 10^3`

## 2. Core Theory

### The technique: prefix sums

A **prefix sum** is the running total from index `0` up to each index:

```text
prefix[i] = nums[0] + nums[1] + ... + nums[i]
```

Worked table for `nums = [1, 2, -3, 3, 1, -1]`:

| i | `nums[i]` | `prefix[i]` |
|:---:|:---:|:---:|
| 0 | 1 | 1 |
| 1 | 2 | 3 |
| 2 | -3 | 0 |
| 3 | 3 | 3 |
| 4 | 1 | 4 |
| 5 | -1 | 3 |

### The key identity

Any contiguous range sum is a difference of two prefix sums:

```text
sum(i..j) = prefix[j] - prefix[i - 1]
```

Set that equal to `0` and you get `prefix[j] == prefix[i - 1]`. So **a zero-sum subarray is exactly a repeated prefix sum**. In the table above, prefix `3` appears at indices `1`, `3` and `5`; the slice from index `2` to index `5` (`[-3, 3, 1, -1]`) sums to `0` and has length `5 - 1 = 4`.

This is the `k = 0` special case of "longest subarray with sum `k`": instead of looking up `current_sum - k`, you look up `current_sum` itself.

### Why the hash map makes it `O(n)`

The naive approach fixes every left endpoint and extends right, which is `O(n^2)`. With a map from prefix sum to the index where it first appeared, each index needs exactly one `O(1)` lookup: *have I seen this exact running total before?* One pass, `O(n)`.

### Why store the FIRST index

Length is `j - (first index with the same prefix sum)`. Maximizing length means minimizing that previous index, so the earliest occurrence always wins. Overwriting the map entry with a later index silently shortens your answer. The sentinel `{0: -1}` encodes "the empty prefix has sum `0` and sits just before index `0`", which is what lets a zero-sum run that starts at index `0` be measured correctly.

### Recognizing the pattern

Contiguous subarray + a sum condition + negative numbers allowed is the signature. Prerequisite: a hash map with `O(1)` average lookup.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Empty array | `nums = []` | `0` | Loop never runs; must return `0`, not crash. |
| Single zero | `nums = [0]` | `1` | Only the `{0: -1}` sentinel produces length `1`. |
| Single non-zero | `nums = [7]` | `0` | No zero-sum subarray exists. |
| No valid answer | `nums = [2, 10, 4]` | `0` | Must return `0`, not `-1`. |
| All identical non-zero | `nums = [3, 3, 3]` | `0` | Prefix sums `3, 6, 9` never repeat. |
| All zeros | `nums = [0, 0, 0]` | `3` | Prefix stays `0`; sentinel index `-1` gives the full length. |
| Simple negative pair | `nums = [1, -1]` | `2` | Prefix `0` at index `1` matches the sentinel. |
| Zero-sum run starts at index 0 | `nums = [1, 2, -3, 3]` | `3` | Without the sentinel this returns `2` instead of `3`. |
| Repeated prefix, first occurrence matters | `nums = [15, -2, 2, -8, 1, 7, 10, 23]` | `5` | Prefix `15` at indices `0, 2, 5`; keeping index `0` gives `5`, overwriting gives `3`. |
| Duplicates plus zeros | `nums = [1, 0, -4, 3, 1, 0]` | `5` | Zeros extend the run; the answer is `[0, -4, 3, 1, 0]`. |
| Sliding window trap | `nums = [-1, 1, -1, 1]` | `4` | Two-pointer shrinking is invalid with negatives; only prefix sum finds the full length. |

## 4. Problem Explanation

Given an array `nums`, find the **length of the longest contiguous subarray** whose sum is 0.

Important word:

```text
contiguous subarray
```

That means elements must be continuous.

### Example

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
Output = 5
```

Why?

The subarray is:

```text
[-2, 2, -8, 1, 7]
```

Sum:

```text
-2 + 2 - 8 + 1 + 7 = 0
```

Length:

```text
5
```

So answer is 5.

## 6. What is Prefix Sum?

Prefix sum means:

```text
sum from index 0 to current index
```

Example:

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
```

Prefix sums:

| index | nums[index] | prefix sum |
|:---:|:---:|:---:|
| 0 | 15 | 15 |
| 1 | -2 | 13 |
| 2 | 2 | 15 |
| 3 | -8 | 7 |
| 4 | 1 | 8 |
| 5 | 7 | 15 |
| 6 | 10 | 25 |
| 7 | 23 | 48 |

Notice prefix sum 15 appears multiple times:

```text
index 0
index 2
index 5
```

This is the main clue.

## 7. Core Intuition

Suppose prefix sum at index `i` and index `j` is the same.

```text
prefix_sum[i] == prefix_sum[j]
```

That means the sum between `i + 1` and `j` is 0.

Why?

Because:

```text
prefix_sum[j] - prefix_sum[i] = 0
```

So:

```text
sum from i + 1 to j = 0
```

### Example

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
```

Prefix sum 15 appears at:

```text
index 0 and index 5
```

That means subarray from index 1 to 5 has sum 0.

```text
nums[1:6] = [-2, 2, -8, 1, 7]
```

Sum:

```text
-2 + 2 - 8 + 1 + 7 = 0
```

Length:

```text
5 - 0 = 5
```

## 8. More Edge Cases in Detail

| Input | Output | Reason |
|:---|:---:|:---|
| `nums = [1, 2, 3]` | `0` | No subarray has sum 0. |
| `nums = [0]` | `1` | Single zero itself is a zero-sum subarray. |
| `nums = [0, 0, 0]` | `3` | Whole array has sum 0. |
| `nums = [1, -1]` | `2` | Whole array has sum 0. |
| `nums = [1, 2, -3, 3]` | `3` | Subarray `[1, 2, -3]` has sum 0. |

## 9. Brute Force Solution

### Intuition

Generate every possible subarray.

Calculate its sum.

If the sum is 0, update the maximum length.

### Approach

1. Start from every index `start`.
2. End at every index `end`.
3. Calculate sum from `start` to `end`.
4. If sum is 0, update answer.

### Dry Run

```text
nums = [1, 2, -3, 3]
```

All important subarrays:

```text
[1]             sum = 1
[1, 2]          sum = 3
[1, 2, -3]      sum = 0    length = 3
[1, 2, -3, 3]   sum = 3
[2, -3]         sum = -1
[-3, 3]         sum = 0    length = 2
```

Maximum zero-sum length:

```text
3
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxLen(self, nums: List[int]) -> int:

        # Store the length of the array
        n = len(nums)

        # Store the largest zero-sum subarray length found so far
        max_length = 0

        # Try every possible starting index
        for start in range(n):

            # Try every possible ending index
            for end in range(start, n):

                # Store sum of current subarray
                current_sum = 0

                # Calculate sum from start to end
                for index in range(start, end + 1):

                    # Add current value into current_sum
                    current_sum += nums[index]

                # If current subarray sum is zero
                if current_sum == 0:

                    # Calculate current subarray length
                    current_length = end - start + 1

                    # Update answer if current length is larger
                    max_length = max(max_length, current_length)

        # Return largest zero-sum subarray length
        return max_length
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^3)` | Because we choose `start`, `end`, and then calculate sum again. |
| **Space** | `O(1)` | Because we only use variables. |

## 10. Better Brute Force: Running Sum

### Intuition

Instead of recalculating the sum every time, maintain a running sum for each starting index.

For fixed `start`, as `end` moves forward:

```text
current_sum += nums[end]
```

### Dry Run

```text
nums = [1, 2, -3, 3]
```

For `start = 0`:

```text
end = 0 -> current_sum = 1
end = 1 -> current_sum = 3
end = 2 -> current_sum = 0   length = 3
end = 3 -> current_sum = 3
```

For `start = 2`:

```text
end = 2 -> current_sum = -3
end = 3 -> current_sum = 0   length = 2
```

Answer:

```text
3
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxLen(self, nums: List[int]) -> int:

        # Store the length of the array
        n = len(nums)

        # Store the largest zero-sum subarray length found
        max_length = 0

        # Try every possible starting index
        for start in range(n):

            # Running sum for subarray starting at start
            current_sum = 0

            # Expand ending index from start to end
            for end in range(start, n):

                # Add current ending element into running sum
                current_sum += nums[end]

                # If running sum is zero
                if current_sum == 0:

                    # Calculate current subarray length
                    current_length = end - start + 1

                    # Update maximum length
                    max_length = max(max_length, current_length)

        # Return largest zero-sum subarray length
        return max_length
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Because for every `start` we expand `end` across the array. |
| **Space** | `O(1)` | Because we only use variables. |

This is better, but not optimal.

## 11. Most Optimal Solution: Prefix Sum + Hash Map

### Core Intuition

While scanning the array, calculate prefix sum.

If the same prefix sum appears again, the elements between the previous index and current index have sum 0.

So we store:

```text
prefix_sum -> first index where this prefix sum appeared
```

Why first index?

Because we want the **longest** subarray.

The earlier the previous index, the larger the length.

### Important Case: Prefix Sum Becomes 0

If prefix sum itself becomes 0 at index `i`, then subarray from index 0 to `i` has sum 0.

Example:

```text
nums = [1, 2, -3, 3]
```

At index 2:

```text
current_sum = 1 + 2 - 3 = 0
```

So subarray:

```text
[1, 2, -3]
```

Length:

```text
3
```

To handle this cleanly, we initialize:

```text
prefix_index = {0: -1}
```

Meaning:

```text
Prefix sum 0 exists before the array starts at index -1.
```

Then if current sum is 0 at index `i`, length becomes:

```text
i - (-1) = i + 1
```

Correct.

### Dry Run of Optimal Solution

```text
nums = [15, -2, 2, -8, 1, 7, 10, 23]
```

Initial:

```text
prefix_index = {0: -1}
current_sum = 0
max_length = 0
```

| i | nums[i] | current_sum | Seen before? | Length | max_length |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 15 | 15 | No | - | 0 |
| 1 | -2 | 13 | No | - | 0 |
| 2 | 2 | 15 | Yes, index 0 | 2 | 2 |
| 3 | -8 | 7 | No | - | 2 |
| 4 | 1 | 8 | No | - | 2 |
| 5 | 7 | 15 | Yes, index 0 | 5 | 5 |
| 6 | 10 | 25 | No | - | 5 |
| 7 | 23 | 48 | No | - | 5 |

Answer:

```text
5
```

The longest zero-sum subarray is:

```text
[-2, 2, -8, 1, 7]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def maxLen(self, nums: List[int]) -> int:

        # Dictionary stores first index where each prefix sum appeared
        prefix_index = {0: -1}

        # Running prefix sum from start to current index
        current_sum = 0

        # Store maximum length of zero-sum subarray
        max_length = 0

        # Traverse every index in the array
        for i in range(len(nums)):

            # Add current element to running prefix sum
            current_sum += nums[i]

            # If current prefix sum was seen before
            if current_sum in prefix_index:

                # Subarray between previous index + 1 and current index has sum zero
                current_length = i - prefix_index[current_sum]

                # Update max length if this subarray is longer
                max_length = max(max_length, current_length)

            # If current prefix sum is appearing for the first time
            else:

                # Store its first occurrence index
                prefix_index[current_sum] = i

        # Return the largest zero-sum subarray length
        return max_length
```

## 12. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Overwriting the map entry on every index instead of keeping the first occurrence | `i - prefix_index[current_sum]` then measures from a later index, shortening the answer. On `[15, -2, 2, -8, 1, 7, 10, 23]` you get `3` instead of `5`. | Only write `prefix_index[current_sum] = i` in the `else` branch, when the sum is new. |
| Forgetting the `{0: -1}` seed | A zero-sum run starting at index `0` is invisible. `[1, 2, -3]` returns `0` instead of `3`. | Initialize `prefix_index = {0: -1}`. |
| Seeding `{0: 0}` instead of `{0: -1}` | Off-by-one; every prefix-anchored answer comes out one short. | The empty prefix sits at index `-1`. |
| Special-casing `if current_sum == 0: max_length = i + 1` *and* also using the sentinel | Harmless duplication, but people often write the special case and then *forget* the sentinel, or write the sentinel and then reset it later. | Pick one mechanism; the sentinel alone is sufficient and cleaner. |
| Returning `-1` when no zero-sum subarray exists | The problem asks for a length; `0` is the correct "none found" value. | Initialize `max_length = 0` and return it unchanged. |
| Trying a sliding window because "the target is just 0" | Negatives make the sum non-monotonic, so shrinking on `current_sum > 0` discards elements a later negative would have balanced. | Prefix sum + hash map is the only correct linear approach here. |

## 13. Why Repeated Prefix Sum Means Zero Sum

Let:

```text
prefix_sum at index a = S
prefix_sum at index b = S
```

Then:

```text
sum from 0 to a = S
sum from 0 to b = S
```

So the extra elements between `a + 1` and `b` added nothing.

Therefore:

```text
sum from a + 1 to b = 0
```

That is why repeated prefix sum creates a zero-sum subarray.

## 14. Why We Store First Occurrence Only

Suppose prefix sum 15 appears at:

```text
index 0
index 2
index 5
```

At index 5, if we use first occurrence index 0:

```text
length = 5 - 0 = 5
```

If we overwrite with latest occurrence index 2:

```text
length = 5 - 2 = 3
```

We lose the longer answer.

So:

```text
Never overwrite prefix sum index.
Store only first occurrence.
```

## 17. Interview Follow-ups

**Q: What if I asked for the COUNT of zero-sum subarrays instead of the longest one?**

A: Swap the map from `prefix sum -> first index` to `prefix sum -> frequency`, seeded with `{0: 1}`. At each index, add `freq[current_sum]` to the answer *before* incrementing it. Every earlier occurrence of the same prefix sum pairs with the current index to form one zero-sum subarray.

**Q: What if all numbers were positive — is there a faster or `O(1)`-space solution?**

A: With strictly positive numbers no zero-sum subarray can exist at all, so the answer is always `0` in `O(1)` time. If zeros are allowed too, the answer is the length of the longest run of consecutive zeros, findable in `O(n)` time and `O(1)` space.

**Q: How would you return the actual subarray rather than its length?**

A: Track `best_start` and `best_end`. Whenever you update `max_length`, set `best_start = prefix_index[current_sum] + 1` and `best_end = i`, then slice `nums[best_start:best_end + 1]` at the end.

**Q: How would you handle a streaming input, or `n = 10^6` as in the constraints?**

A: The algorithm is already one-pass and online — it never looks backwards at the array itself, only at the map. Time stays `O(n)`; the cost is `O(distinct prefix sums)` memory, up to `O(n)`. With `|arr[i]| <= 10^3` and `n = 10^6`, prefix sums live in `[-10^9, 10^9]`, which fits comfortably in a 64-bit integer.

**Q: What changes if the target is some `k` instead of `0`?**

A: Only the lookup key. Instead of checking whether `current_sum` was seen, check whether `current_sum - k` was seen. Everything else — the sentinel, the first-occurrence rule, the complexity — is identical.

## 18. Interview Explanation

You can say:

> I will use prefix sum. If the same prefix sum appears at two different indices, then the subarray between those two indices has sum zero. So I store the first index where each prefix sum appears. While scanning, if the current prefix sum was already seen, I calculate the length between the previous index and current index and update the answer. I store only the first occurrence because we need the longest subarray. This gives `O(n)` time and `O(n)` space.

## 19. Verify

```python
def max_len_zero_sum(nums):
    # Prefix sum 0 exists before the array starts, at index -1
    prefix_index = {0: -1}
    # Running prefix sum from start to current index
    current_sum = 0
    # Store maximum length of zero-sum subarray
    max_length = 0

    # Traverse every index in the array
    for i, value in enumerate(nums):
        # Add current element to running prefix sum
        current_sum += value

        # A repeated prefix sum means the slice between them sums to 0
        if current_sum in prefix_index:
            # Update max length if this subarray is longer
            max_length = max(max_length, i - prefix_index[current_sum])
        else:
            # Store only the first occurrence to maximize length
            prefix_index[current_sum] = i

    # Return the largest zero-sum subarray length
    return max_length


# Given examples: repeated prefix keeping first occurrence, no valid answer, duplicates plus zeros
assert max_len_zero_sum([15, -2, 2, -8, 1, 7, 10, 23]) == 5
assert max_len_zero_sum([2, 10, 4]) == 0
assert max_len_zero_sum([1, 0, -4, 3, 1, 0]) == 5

# Empty array must return 0 without crashing, and a single zero uses the sentinel to give length 1
assert max_len_zero_sum([]) == 0
assert max_len_zero_sum([0]) == 1
# Single non-zero element has no zero-sum subarray
assert max_len_zero_sum([7]) == 0

# All identical non-zero values never repeat a prefix sum
assert max_len_zero_sum([3, 3, 3]) == 0
# All zeros keep the prefix at 0, so the sentinel gives the full length
assert max_len_zero_sum([0, 0, 0]) == 3

# Simple negative pair matches the sentinel prefix sum
assert max_len_zero_sum([1, -1]) == 2
# Sliding window trap: negatives make two-pointer shrinking invalid, only prefix sum works
assert max_len_zero_sum([-1, 1, -1, 1]) == 4

# Zero-sum run starting at index 0 needs the sentinel, otherwise the length is undercounted
assert max_len_zero_sum([1, 2, -3, 3]) == 3

# No zero-sum subarray exists
assert max_len_zero_sum([1, 2, 3]) == 0

print("All tests passed")
```
