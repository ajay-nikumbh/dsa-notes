# 13. Find Second Smallest and Second Largest Element in an Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Linear Scan / One Pass | [Second Largest](https://www.geeksforgeeks.org/problems/second-largest3735/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given an array `nums`, find:

```text
Second smallest element
Second largest element
```

### Example

```text
Input: nums = [10, 5, 20, 8, 15]

Output:
Second smallest = 8
Second largest  = 15
```

Sorted order would be:

```text
[5, 8, 10, 15, 20]
```

So:

```text
Smallest = 5
Second smallest = 8

Largest = 20
Second largest = 15
```

## 2. Core Theory

### The technique: tracking running extremes

This is the **running-extremes** pattern. You keep a tiny fixed-size "leaderboard" of the best `k` values seen so far and update it as each new element arrives. For `k = 2` that is two variables per side: `smallest`/`second_smallest` and `largest`/`second_largest`. One pass, `O(n)` time, `O(1)` space. It generalizes to any small `k` (for large `k` you would use a heap instead).

### The invariant

After processing the first `i` elements, `smallest` and `second_smallest` hold the two smallest **distinct** values among those `i` elements (or sentinels if fewer than two distinct values exist). Every update must restore this invariant before moving on.

### Why update ORDER matters

The single most common bug. When a new value beats `first`, the old `first` is demoted to `second`. You must do the demotion **before** overwriting `first`:

```text
Correct:
    if num < smallest:
        second_smallest = smallest    # demote the old champion first
        smallest = num                # then crown the new one

Wrong:
    if num < smallest:
        smallest = num                # old value is now destroyed
        second_smallest = smallest    # second_smallest == smallest, information lost
```

In the wrong version both variables end up holding the same number, and the true runner-up is gone forever because you only get one pass over the data.

### Why sentinels must be `+inf` / `-inf`

Initialization has to be a value that **every** real input beats, so the first comparison always fires.

| Initialization | Failure |
|:---|:---|
| `second_largest = 0` | On all-negative input like `[-10, -3, -20]`, no element is `> 0`, so `second_largest` stays `0` and you report `0` — a value not even in the array. |
| `smallest = 0` | On all-positive input like `[10, 5, 20]`, nothing is `< 0`, so `smallest` stays `0` and both answers are wrong. |
| `smallest = nums[0]`, `second_smallest = nums[1]` | Works only if you also handle the case `nums[1] < nums[0]` and it silently breaks on `n < 2`. Sentinels avoid all of that. |

`float("inf")` / `float("-inf")` beat every finite value, so the first element always wins. As a bonus the sentinel doubles as the "no such element" flag at the end: if `second_smallest` is still `inf`, there was no distinct runner-up.

### The strictness rule for distinctness

Use `<` and `>`, never `<=` / `>=`, and use the band condition `smallest < num < second_smallest`. A duplicate of `smallest` fails `smallest < num`, so it is ignored and `second_smallest` stays distinct. Flipping to `<=` would let `[5, 5, 5]` report a second smallest of `5`.

### Recognizing this pattern

"Find the k-th largest/smallest without sorting", "find the two largest", "find min and max in one pass" — anything asking for a small number of order statistics in `O(n)`. Prerequisite: understanding that sorting (`O(n log n)`) is overkill when you only need a constant number of extremes.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Empty array | `nums = []` | `(None, None)` | Loop never runs; the `len < 2` guard must catch it. |
| Single element | `nums = [5]` | `(None, None)` | No second of either kind exists. |
| Two distinct elements | `nums = [1, 2]` | `(1, 2)` | Second largest is `1`, second smallest is `2` — they cross over. |
| All identical | `nums = [5, 5, 5]` | `(None, None)` | Strict comparisons must reject duplicates; `<=` would wrongly return `(5, 5)`. |
| All negative | `nums = [-10, -3, -20, -7]` | `(-7, -10)` | `second_largest = 0` initialization fails here; must be `-inf`. |
| All positive | `nums = [10, 5, 20, 8, 15]` | `(15, 8)` | `smallest = 0` initialization fails here; must be `+inf`. |
| Duplicates around the extremes | `nums = [10, 10, 20, 20, 5]` | `(10, 10)` | Distinct version: second largest and second smallest are both `10`. |
| Only two distinct values | `nums = [1, 1, 2, 2]` | `(1, 2)` | Second largest `1`, second smallest `2`. |
| Descending input | `nums = [5, 4, 3, 2, 1]` | `(4, 2)` | Every element triggers the `num < smallest` branch, exercising the demotion order. |
| Ascending input | `nums = [1, 2, 3, 4, 5]` | `(4, 2)` | Every element triggers the `num > largest` branch instead. |
| Mixed with zero | `nums = [0, -1, 1]` | `(0, 0)` | `0` is a legitimate value, so it must not be confused with a sentinel. |

## 4. Important Clarification

There are two common versions of this problem.

### Version 1: Distinct second smallest / second largest

Duplicates are ignored.

```text
nums = [10, 10, 20, 20, 5]

Smallest = 5
Second smallest = 10

Largest = 20
Second largest = 10
```

This is the most common interview version.

### Version 2: Index-based second value after sorting

Duplicates are counted.

```text
nums = [10, 10, 20, 20, 5]

Sorted = [5, 10, 10, 20, 20]

Second smallest = 10
Second largest = 20
```

For interviews and DSA, we usually solve **distinct second smallest and distinct second largest**.

## 5. More Edge Cases in Detail

| Input | Second smallest | Second largest | Reason |
|:---|:---:|:---:|:---|
| `nums = [5]` | none | none | Only one element. |
| `nums = [5, 5, 5]` | none | none | All elements are the same, so no distinct second value. |
| `nums = [1, 2]` | `2` | `1` | Sorted `[1, 2]`; the two answers cross over. |
| `nums = [-10, -3, -20, -7]` | `-10` | `-7` | Sorted `[-20, -10, -7, -3]`. |

## 6. Brute Force Solution

### Intuition

We can compare every element with every other element to find:

```text
smallest
largest
```

Then again scan the array to find:

```text
smallest element greater than smallest
largest element smaller than largest
```

### Brute Force Approach

Step 1:

```text
Find smallest and largest by checking all elements.
```

Step 2:

```text
Find the minimum element greater than smallest.
That becomes second smallest.
```

Step 3:

```text
Find the maximum element smaller than largest.
That becomes second largest.
```

### Dry Run

```text
nums = [10, 5, 20, 8, 15]
```

First pass:

```text
smallest = 5
largest = 20
```

Second pass for second smallest:

```text
Numbers greater than 5: 10, 20, 8, 15
Minimum among them = 8
```

Second pass for second largest:

```text
Numbers smaller than 20: 10, 5, 8, 15
Maximum among them = 15
```

Answer:

```text
Second smallest = 8
Second largest = 15
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def getSecondOrderElements(self, nums: List[int]) -> Tuple[Optional[int], Optional[int]]:

        # Get the length of the array
        n = len(nums)

        # If array has less than 2 elements, second elements do not exist
        if n < 2: return None, None

        # Initialize smallest with the first element
        smallest = nums[0]

        # Initialize largest with the first element
        largest = nums[0]

        # Traverse the array to find smallest and largest
        for num in nums:

            # If current number is smaller than current smallest
            if num < smallest:

                # Update smallest
                smallest = num

            # If current number is greater than current largest
            if num > largest:

                # Update largest
                largest = num

        # Initialize second smallest as None
        second_smallest = None

        # Initialize second largest as None
        second_largest = None

        # Traverse the array again to find second smallest and second largest
        for num in nums:

            # Check if num is a valid candidate for second smallest
            if num > smallest:

                # If second_smallest is not set yet or num is smaller
                if second_smallest is None or num < second_smallest:

                    # Update second smallest
                    second_smallest = num

            # Check if num is a valid candidate for second largest
            if num < largest:

                # If second_largest is not set yet or num is greater
                if second_largest is None or num > second_largest:

                    # Update second largest
                    second_largest = num

        # Return second largest and second smallest
        return second_largest, second_smallest
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Although we are doing multiple passes, each pass is linear. So total is `O(n) + O(n) = O(n)`. |
| **Space** | `O(1)` | We only use a few variables. |

This is already efficient, but we can do it in **one pass**.

## 7. Better Solution Using Sorting

### Intuition

If we sort the array, then:

```text
Second smallest will be near the start.
Second largest will be near the end.
```

But because duplicates may exist, we should skip duplicate values.

### Approach

1. Sort the array.
2. From left side, find the first element greater than smallest.
3. From right side, find the first element smaller than largest.

### Dry Run

```text
nums = [10, 5, 20, 8, 15]
```

After sorting:

```text
[5, 8, 10, 15, 20]
```

Second smallest:

```text
8
```

Second largest:

```text
15
```

### Dry Run With Duplicates

```text
nums = [10, 10, 20, 20, 5]
```

After sorting:

```text
[5, 10, 10, 20, 20]
```

Smallest:

```text
5
```

First element greater than 5:

```text
10
```

Largest:

```text
20
```

First element smaller than 20 from right:

```text
10
```

Answer:

```text
Second smallest = 10
Second largest = 10
```

### Code

```python
# Define the class solution
class Solution:

    def getSecondOrderElements(self, nums: List[int]) -> Tuple[Optional[int], Optional[int]]:

        # If array has less than 2 elements, second values do not exist
        if len(nums) < 2:
            return None, None

        # Sort the array in ascending order
        nums.sort()

        # Store the smallest element
        smallest = nums[0]

        # Store the largest element
        largest = nums[-1]

        # Initialize second smallest as None
        second_smallest = None

        # Initialize second largest as None
        second_largest = None

        # Traverse from left to right to find second smallest
        for num in nums:
            # First number greater than smallest is second smallest
            if num > smallest:

                # Store second smallest
                second_smallest = num

                # Stop because we found the smallest valid greater value
                break

        # Traverse from right to left to find second largest
        for i in range(len(nums) - 1, -1, -1):

            # First number smaller than largest is second largest
            if nums[i] < largest:

                # Store second largest
                second_largest = nums[i]

                # Stop because we found the largest valid smaller value
                break

        # Return second largest and second smallest
        return second_largest, second_smallest
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Because sorting takes `O(n log n)`. |
| **Space** | `O(1) or O(n)` | Depending on the sorting implementation. |

## 8. Most Optimal Solution: One Pass

### Intuition

We can find everything in one traversal by maintaining four variables:

```text
smallest
second_smallest
largest
second_largest
```

While scanning each number:

For smallest side:

```text
If num < smallest:
    second_smallest becomes old smallest
    smallest becomes num
```

For largest side:

```text
If num > largest:
    second_largest becomes old largest
    largest becomes num
```

We also need to handle numbers that are between first and second values.

## 9. One Pass Logic

For every num:

### To update smallest and second smallest

```text
If num < smallest:
    second_smallest = smallest
    smallest = num
```

Meaning:

```text
We found a new smallest.
Old smallest now becomes second smallest.
```

Else if:

```text
num > smallest and num < second_smallest:
    second_smallest = num
```

Meaning:

```text
num is not the smallest,
but it is smaller than current second smallest.
```

### To update largest and second largest

```text
If num > largest:
    second_largest = largest
    largest = num
```

Meaning:

```text
We found a new largest.
Old largest now becomes second largest.
```

Else if:

```text
num < largest and num > second_largest:
    second_largest = num
```

Meaning:

```text
num is not the largest,
but it is greater than current second largest.
```

### Code

```python
# Define the class solution
class Solution:

    def getSecondOrderElements(self, nums: List[int]) -> Tuple[Optional[int], Optional[int]]:

        # If there are fewer than two elements, second values do not exist
        if len(nums) < 2:
            return None, None

        # Store the smallest value seen so far
        smallest = float("inf")

        # Store the second smallest distinct value seen so far
        second_smallest = float("inf")

        # Store the largest value seen so far
        largest = float("-inf")

        # Store the second largest distinct value seen so far
        second_largest = float("-inf")

        # Traverse each number in the array
        for num in nums:

            # If num is smaller than the current smallest
            if num < smallest:

                # Current smallest becomes second smallest
                second_smallest = smallest

                # Num becomes the new smallest
                smallest = num

            # If num is between smallest and second smallest
            elif smallest < num < second_smallest:

                # Num becomes the new second smallest
                second_smallest = num

            # If num is greater than the current largest
            if num > largest:

                # Current largest becomes second largest
                second_largest = largest

                # Num becomes the new largest
                largest = num

            # If num is between second largest and largest
            elif second_largest < num < largest:
                # Num becomes the new second largest
                second_largest = num

        # Convert infinity to None if no second smallest exists
        if second_smallest == float("inf"):
            second_smallest = None

        # Convert negative infinity to None if no second largest exists
        if second_largest == float("-inf"):
            second_largest = None

        # Return second largest first, then second smallest
        return second_largest, second_smallest
```

## 12. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Initializing `second_largest = 0` (or `largest = 0`) | On all-negative input like `[-10, -3, -20, -7]` nothing is `> 0`, so `second_largest` stays `0` and you return a value that is not in the array. | Initialize `largest` and `second_largest` to `float("-inf")`, `smallest` and `second_smallest` to `float("inf")`. |
| Overwriting `first` before demoting it: `smallest = num` then `second_smallest = smallest` | The old `smallest` is destroyed, so `second_smallest == smallest` and the real runner-up is lost. You only get one pass, so it cannot be recovered. | Always demote first: `second_smallest = smallest`, *then* `smallest = num`. |
| Using `<=` / `>=` instead of strict `<` / `>` | A duplicate of the champion slides into the runner-up slot, so `[5, 5, 5]` reports second smallest `5` instead of "none". | Use strict comparisons and the band condition `smallest < num < second_smallest`. |
| Using `if` instead of `elif` for the second-place branch | A new champion falls straight through into the runner-up branch and immediately overwrites the value it just demoted. | Make the runner-up check an `elif` on each side. |
| Initializing with `nums[0]` and `nums[1]` without ordering them | If `nums[1] < nums[0]` the invariant is violated from the start, and the code crashes on arrays of length `0` or `1`. | Use sentinels plus an explicit `len(nums) < 2` guard. |
| Forgetting to convert the leftover sentinel back to `None` (or `-1`) | The caller receives `inf` / `-inf`, which is not a valid array element and will break any arithmetic downstream. | After the loop, check `if second_smallest == float("inf"): second_smallest = None` and likewise for `second_largest`. |

## 13. Interview Follow-ups

**Q: What if I asked for the k-th smallest instead of the second smallest?**

A: For small `k`, a max-heap of size `k` gives `O(n log k)` time and `O(k)` space. For arbitrary `k`, Quickselect gives `O(n)` average time (`O(n^2)` worst case), and median-of-medians gives a guaranteed `O(n)`. The four-variable trick only scales while `k` is a tiny constant.

**Q: Do you want the second smallest *distinct* value, or the element at index 1 after sorting?**

A: This is the clarification to ask up front. For `[10, 10, 20, 20, 5]` the distinct answer is second smallest `10`, second largest `10`; the index-based answer is second smallest `10`, second largest `20`. The distinct version is the usual interview intent, and it is the one the strict `<` / `>` comparisons implement.

**Q: How would you handle a streaming input where you cannot store the array?**

A: Unchanged — the algorithm is already online and `O(1)` space. It only reads each value once and never revisits it, so you can feed it from a socket or a generator exactly as written.

**Q: Can you find both the minimum and the maximum in fewer than `2n` comparisons?**

A: Yes. Process elements in pairs: compare the two against each other first (1 comparison), then the smaller against `min` and the larger against `max` (2 more). That is 3 comparisons per 2 elements, about `1.5n` total instead of `2n`. Same asymptotic `O(n)`, but it is the classic comparison-count optimization interviewers like to hear.

**Q: What if the array can contain floats or `NaN`?**

A: Floats work unchanged. `NaN` breaks everything, because every comparison with `NaN` returns `False`, so `NaN` is silently skipped by both branches. If `NaN` is possible, filter it out first or reject the input explicitly.

## 14. Interview Explanation

You can say:

> I will maintain four variables: smallest, second smallest, largest, and second largest. While traversing the array once, if I find a new smallest, the old smallest becomes second smallest. Similarly, if I find a new largest, the old largest becomes second largest. I ignore duplicates by using strict comparisons. This gives the answer in one pass with `O(n)` time and `O(1)` space.

## 15. Verify

```python
def get_second_order_elements(nums):
    # Fewer than two elements means no second smallest or second largest
    if len(nums) < 2:
        return None, None

    # Sentinels that every real value beats
    smallest = float("inf")
    second_smallest = float("inf")
    largest = float("-inf")
    second_largest = float("-inf")

    for num in nums:
        # New smallest: demote the old one BEFORE overwriting
        if num < smallest:
            second_smallest = smallest
            smallest = num
        # Strictly between smallest and second smallest
        elif smallest < num < second_smallest:
            second_smallest = num

        # New largest: demote the old one BEFORE overwriting
        if num > largest:
            second_largest = largest
            largest = num
        # Strictly between second largest and largest
        elif second_largest < num < largest:
            second_largest = num

    # Untouched sentinels mean no distinct second element exists
    if second_smallest == float("inf"):
        second_smallest = None
    if second_largest == float("-inf"):
        second_largest = None

    # Returns (second_largest, second_smallest)
    return second_largest, second_smallest
```
