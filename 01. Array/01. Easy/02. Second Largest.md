# 02. Second Largest

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Linear Scan / One Pass | [Second Largest](https://www.geeksforgeeks.org/problems/second-largest3735/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given an array of **positive** integers `arr[]`, return the **second largest** element from the array. If the second largest element doesn't exist then return **-1**.

Note: The second largest element should not be equal to the largest element.

### Examples

```text
Input:  arr[] = [12, 35, 1, 10, 34, 1]
Output: 34
Explanation: The largest element of the array is 35 and the second largest element is 34.
```

```text
Input:  arr[] = [10, 5, 10]
Output: 5
Explanation: The largest element of the array is 10 and the second largest element is 5.
```

```text
Input:  arr[] = [10, 10, 10]
Output: -1
Explanation: The largest element of the array is 10 and the second largest element does not exist.
```

### Constraints

- `2 <= arr.size() <= 10^5`
- `1 <= arr[i] <= 10^5`

## 2. Core Theory

This is the **top-k by single pass** pattern with `k = 2`. Instead of one accumulator you carry `k` accumulators holding the best `k` values seen so far, kept in sorted order. Adding element `x` means inserting it into that tiny sorted list and dropping the overflow. For `k = 2` the "insert and shift" is just two `if` branches, which is why it looks like an ad-hoc trick rather than a general algorithm.

The invariant: *after processing index `i`, `largest` and `second_largest` hold the two largest **distinct** values among `nums[0..i]`* (with `-inf` standing for "does not exist yet"). The crucial step is the cascade — when a new maximum arrives, the old maximum is demoted rather than discarded, because the previous champion is exactly the best remaining runner-up.

```text
new num > largest        ->  second = largest ; largest = num   (cascade)
second < num < largest   ->  second = num                       (improve runner-up)
num == largest           ->  ignore (distinctness)
```

Recognize the pattern whenever the answer is the top few elements and `k` is much smaller than `n`. Sorting costs `O(n log n)` to produce `n` ordered values when you only need `k` of them; the running top-k costs `O(n·k)`, or `O(n log k)` with a min-heap once `k` grows. For `k = 2` the constant is tiny, so two scalars beat both.

The prerequisite concept is **distinctness versus positional rank**. "Second largest" can mean the second element of the sorted array (`[10, 10, 5]` -> `10`) or the largest strictly-smaller value (`[10, 10, 5]` -> `5`). This problem wants the second reading, which is why every comparison uses strict `<` and `>` and never `<=`.

| `k` | Technique | Time | Space |
|:---:|:---|:---:|:---:|
| 1 | One accumulator | `O(n)` | `O(1)` |
| 2 | Two accumulators with cascade | `O(n)` | `O(1)` |
| small fixed `k` | Sorted list of size `k` | `O(n·k)` | `O(k)` |
| large `k` | Min-heap of size `k` | `O(n log k)` | `O(k)` |

## 3. Problem Explanation

**Problem: Find Second Largest Element in an Array**

Given an array `nums`, find the **second largest distinct element**.

### Example

```text
Input: nums = [10, 5, 20, 8, 15]
Output: 15
```

Because:

```text
Largest = 20
Second largest = 15
```

We need to find the element that is **smaller than the largest element**, but greater than all remaining elements.

Sorted view:

```text
nums = [10, 5, 20, 8, 15]

Sorted = [5, 8, 10, 15, 20]
```

So:

```text
Largest = 20
Second largest = 15
```

## 4. Important Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[5]` | `None` / `-1` | No second value can exist; the length guard must fire before any scan. |
| Empty array | `[]` | `None` / `-1` | Same guard; `nums[0]` would raise `IndexError`. |
| All identical | `[10, 10, 10]` | `None` / `-1` | Strict comparisons never update `second`, so the sentinel check is what returns "does not exist". |
| Exactly two distinct | `[10, 20]` | `10` | Smallest input where an answer exists; catches an off-by-one loop. |
| Duplicated maximum | `[10, 5, 10]` | `5` | A `>=` cascade would demote `10` into `second` and wrongly return `10`. |
| All negatives | `[-10, -3, -20, -7]` | `-7` | `second = 0` or `second = -1` as a sentinel would beat every real value. |
| Maximum at the end | `[1, 2, 3, 90]` | `3` | The cascade must run on the very last element too. |
| Descending input | `[90, 3, 2, 1]` | `3` | The cascade never fires after index 0; only the `elif` branch can set `second`. |
| Two distinct, many dupes | `[5, 5, 5, 1]` | `1` | Distinctness is about values, not counts. |

```text
nums = [5]
Output = None
```

Only one element exists, so second largest does not exist.

```text
nums = [5, 5, 5]
Output = None
```

All elements are same, so no distinct second largest exists.

Largest is 20, second largest is 10.

Largest is -3, second largest is -7.

## 5. Brute Force Solution

### Intuition

First find the largest element.

Then find the largest element that is **strictly smaller** than the largest.

### Approach

1. Traverse the array and find `largest`.
2. Traverse again and find the biggest number smaller than `largest`.
3. Return that number.

### Dry Run

```text
nums = [10, 5, 20, 8, 15]
```

First pass:

```text
largest = 20
```

Second pass:

```text
Numbers smaller than 20 are: 10, 5, 8, 15
Largest among them = 15
```

Answer:

```text
15
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def getSecondLargest(self, nums):

        # If array has fewer than 2 elements, second largest cannot exist
        if len(nums) < 2: return None

        # Assume first element is the largest
        largest = nums[0]

        # Traverse every number to find the largest element
        for num in nums:

            # If current number is greater than largest
            if num > largest:

                # Update largest
                largest = num

        # Store second largest as None initially
        second_largest = None

        # Traverse again to find the largest number smaller than largest
        for num in nums:

            # Current number must be strictly smaller than largest
            if num < largest:

                # If second_largest is not set yet or current number is bigger
                if second_largest is None or num > second_largest:

                    # Update second largest
                    second_largest = num

        # Return the second largest value
        return second_largest
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we scan the array twice. |
| **Space** | `O(1)` | Because we only use a few variables. |

## 6. Better Solution Using Sorting

### Intuition

If we sort the array, the largest will be at the end.

The second largest distinct element will be the first element from the right side that is smaller than the largest.

### Approach

1. Sort the array.
2. Store the last element as `largest`.
3. Move from right to left.
4. Return the first element smaller than `largest`.

### Dry Run

```text
nums = [10, 5, 20, 8, 15]
```

After sorting:

```text
[5, 8, 10, 15, 20]
```

Largest:

```text
20
```

First element from right smaller than 20:

```text
15
```

Answer:

```text
15
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def getSecondLargest(self, nums):

        # If array has fewer than 2 elements, second largest cannot exist
        if len(nums) < 2: return None

        # Sort the array in ascending order
        nums.sort()

        # Store the largest element
        largest = nums[-1]

        # Traverse from second last index to start
        for i in range(len(nums) - 2, -1, -1):

            # First element smaller than largest is second largest distinct element
            if nums[i] < largest:

                # Return second largest
                return nums[i]

        # If no smaller distinct value exists, return None
        return None
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Because sorting takes `O(n log n)`. |
| **Space** | `O(1)` or `O(n)` | Depending on the sorting implementation. |

## 7. Most Optimal Solution: One Pass

### Intuition

We can solve this in one traversal by maintaining two variables:

```text
largest
second_largest
```

While scanning every number:

```text
If num > largest:
    second_largest = largest
    largest = num
```

Because if we find a new largest, the old largest automatically becomes the second largest.

Also:

```text
If num < largest but num > second_largest:
    second_largest = num
```

Because this number is not the largest, but it is a better candidate for second largest.

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def getSecondLargest(self, nums):

        # If array has fewer than 2 elements, second largest cannot exist
        if len(nums) < 2:
            return None

        # Store the largest value seen so far
        largest = float("-inf")

        # Store the second largest distinct value seen so far
        second_largest = float("-inf")

        # Traverse every number in the array
        for num in nums:

            # If current number is greater than largest
            if num > largest:

                # Old largest becomes second largest
                second_largest = largest

                # Current number becomes new largest
                largest = num

            # If current number is smaller than largest but greater than second largest
            elif second_largest < num < largest:

                # Current number becomes new second largest
                second_largest = num

        # If second_largest was never updated, no distinct second largest exists
        if second_largest == float("-inf"):

            # Return None when second largest does not exist
            return None

        # Return the second largest element
        return second_largest
```

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array only once. |
| **Space** | `O(1)` | Because we only use two variables. |

## 10. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Initializing `second = 0` instead of `float("-inf")` | On an all-negative array like `[-10, -3, -20, -7]`, no element ever exceeds `0`, so the sentinel `0` is returned even though it is not in the array. | Initialize both to `float("-inf")` and check the sentinel before returning. |
| Using `>=` in the cascade | `[10, 5, 10]` demotes the second `10` into `second_largest`, returning `10` instead of `5`. | Use strict `>` for the cascade so equal values are ignored. |
| Writing `elif num > second_largest` without the upper bound | Looks right only because the `if` already handled `num > largest`; but with `>=` anywhere above, a duplicate of the maximum slips through. | Keep the explicit `second_largest < num < largest` so the intent is visible. |
| Setting `second = largest` **after** `largest = num` | Both variables end up equal to the new maximum, losing the old champion forever. | Demote first, promote second — order matters. |
| Two separate passes with `max(nums)` then `max(x for x in nums if x != largest)` | Correct but raises `ValueError` on an empty generator when every element is identical. | Wrap with a `default=None`, or use the one-pass version. |
| Returning `second_largest` without the sentinel check | `[10, 10, 10]` returns `-inf` rather than the required `-1` / `None`. | Test `if second_largest == float("-inf")` before returning. |

## 11. Interview Follow-ups

**Q: What if the interviewer wants the second element of the sorted array instead of the second distinct value?**

A: That is a different problem: `[10, 10, 5]` would answer `10`, not `5`. I switch the cascade to `>=` and drop the distinctness guard, so a duplicate of the maximum is allowed to occupy `second_largest`. I would clarify this before writing any code, because the two readings differ on every input with a repeated maximum.

**Q: Generalize it to the k-th largest distinct element.**

A: For a fixed small `k` I keep a sorted list of the `k` best distinct values and insert-and-trim on each element: `O(n·k)` time, `O(k)` space. For larger `k` I use a min-heap of size `k` combined with a seen-set for distinctness, giving `O(n log k)`. For arbitrary `k` on an in-memory array, deduplicate and run Quickselect for `O(n)` average.

**Q: The array is a stream you can only read once. Does anything change?**

A: No. The one-pass solution already holds only two scalars and never revisits an element, so it works unchanged on a stream of any length. That is the concrete advantage over the sorting solution, which needs the whole array resident.

**Q: What if duplicates should count, and you must return how many elements are strictly below the maximum?**

A: I keep the same cascade but add a counter incremented whenever `num < largest`. The subtlety is that the counter must be **reset** when a new maximum arrives, because every element previously counted is still below the new maximum — actually it grows by the count of old maxima, so I track the frequency of `largest` too and adjust in the cascade branch.

**Q: Can you do it with fewer than `2n` comparisons?**

A: Yes. A tournament (single-elimination) finds the maximum in `n - 1` comparisons, and the second largest must be one of the `ceil(log2 n)` elements the winner directly beat. Taking the max of those costs `ceil(log2 n) - 1` more, for `n + ceil(log2 n) - 2` total, which is provably optimal. It needs `O(n)` space to record the tournament, so the two-scalar scan is still preferable in practice.

## 12. Interview Explanation

You can say:

> I will maintain two variables: `largest` and `second_largest`. Initially both are negative infinity. While traversing the array, if I find a number greater than `largest`, then the old `largest` becomes `second_largest`, and the current number becomes the new `largest`. Otherwise, if the number is smaller than `largest` but greater than `second_largest`, I update `second_largest`. This handles duplicates using strict comparison and gives O(n) time with O(1) space.

def get_second_largest(nums):

    if len(nums) < 2:
