# 09. 283. Move Zeroes

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Two Pointers | [283. Move Zeroes](https://leetcode.com/problems/move-zeroes/) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given an integer array `nums`, move all `0`'s to the end of it while maintaining the relative order of the non-zero elements.

**Note** that you must do this in-place without making a copy of the array.

### Examples

```text
Example 1:

Input: nums = [0,1,0,3,12]
Output: [1,3,12,0,0]
```

```text
Example 2:

Input: nums = [0]
Output: [0]
```

### Constraints

- `1 <= nums.length <= 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`

### Follow up

Could you minimize the total number of operations done?

### Example

```text
Input:
nums = [0, 1, 0, 3, 12]

Output:
[1, 3, 12, 0, 0]
```

The non-zero elements are:

```text
[1, 3, 12]
```

Their order must remain same.

So we move them to the front and fill the remaining positions with zeroes:

```text
[1, 3, 12, 0, 0]
```

## 2. Core Theory

This problem is a **stable in-place partition**, and that phrase is worth unpacking because it names the whole technique. *Partition* means split the elements into two groups by a predicate — here, non-zero versus zero. *In-place* means do it with `O(1)` extra memory. *Stable* means elements within a group keep their original relative order, which is exactly the constraint that rules out the obvious tricks.

The tool for this is the **fast/slow two-pointer** (also called read/write pointers). One pointer scans every element; the other marks the boundary of the finished region. They move at different rates: the reader always advances, while the writer advances only when it actually places something.

| Pointer | Moves | Meaning |
|:---|:---|:---|
| `current` (fast/read) | Every iteration | The element under inspection |
| `last_non_zero_position` (slow/write) | Only on a non-zero | Where the next kept element belongs |

The invariant that proves correctness: **at the top of every iteration, `nums[0 .. last_non_zero_position - 1]` holds exactly the non-zero elements seen so far, in their original order.** When the reader finds another non-zero it appends it at the boundary and pushes the boundary forward, which preserves the invariant by construction. Because the scan runs strictly left to right, non-zero elements are appended in encounter order — that is precisely why stability comes for free and why you must *never* use the "swap with the end" trick that fixes this in one pass but scrambles the order.

There is a second reason the swap variant is safe rather than destructive. Since `last_non_zero_position <= current` always holds, the write pointer never runs ahead of the reader, so you can only overwrite a cell the reader has already consumed. The swap sends the displaced value (necessarily a `0`, or the element itself when the pointers coincide) into the gap, which is exactly where zeros belong.

```text
[0, 1, 0, 3, 12]      write=0, read=1  -> found 1, swap
 ^w ^r
[1, 0, 0, 3, 12]      write=1, read=3  -> found 3, swap
    ^w    ^r
[1, 3, 0, 0, 12]      write=2, read=4  -> found 12, swap
       ^w    ^r
[1, 3, 12, 0, 0]      done: [0, write) is the answer
```

**How to recognize this pattern.** Reach for fast/slow pointers whenever a problem says "remove / move / keep elements matching a predicate, in place, preserving order." It is the same skeleton as Remove Element (LC 27), Remove Duplicates from Sorted Array (LC 26), and Sort Colors (LC 75, which needs three pointers because there are three groups). If the problem drops the stability requirement, a two-ended partition — the Lomuto or Hoare step from quicksort — does it with strictly fewer writes.

## 3. Key Observations

The problem is not asking us to sort the array.

It only asks:

```text
Move zeroes to the end.
Keep non-zero order same.
```

So this is valid:

```text
[0, 1, 0, 3, 12] -> [1, 3, 12, 0, 0]
```

But this is wrong:

```text
[0, 1, 0, 3, 12] -> [12, 3, 1, 0, 0]
```

Because the order of non-zero elements changed.

## 4. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single zero | `[0]` | `[0]` | Smallest legal input; the write pointer never advances and the array must be left alone. |
| Single non-zero | `[1]` | `[1]` | Write and read coincide, producing a self-swap — harmless, but the trigger for the `current != last_non_zero_position` guard. |
| All zeros | `[0,0,0]` | `[0,0,0]` | No element is ever written. A fill-loop version must still write zeros over positions `0..n-1` correctly. |
| No zeros at all (already satisfied) | `[1,2,3]` | `[1,2,3]` | The array is already correct; the naive swap does `n` pointless self-swaps, which is exactly what the follow-up asks you to avoid. |
| Zeros only at the front | `[0,0,1]` | `[1,0,0]` | The single non-zero must travel the full distance to index `0`. |
| Zeros only at the end (already satisfied) | `[1,2,0,0]` | `[1,2,0,0]` | Pointers stay locked together for the whole prefix; no movement should occur. |
| Negative values | `[0,-1,0,-3]` | `[-1,-3,0,0]` | The predicate is `!= 0`, not `> 0`. Negatives are non-zero and must be kept and ordered. |
| Duplicates among non-zeros | `[0,2,0,2,1]` | `[2,2,1,0,0]` | Stability means equal values keep their original relative order; a swap-based fix must not reorder them. |
| Mixed signs and duplicates | `[4,0,-4,0,4]` | `[4,-4,4,0,0]` | Combines both traps; the two `4`s must stay in first-seen order. |
| Interleaved | `[0,1,0,3,12]` | `[1,3,12,0,0]` | The canonical example; the write pointer lags the read pointer by the running zero count. |
| Empty array | `[]` | `[]` | Out of constraints (`1 <= nums.length`) but should not crash — both loops simply never run. |

## 5. Brute Force Solution: Use Extra Array

### Intuition

Create a new array.

First put all non-zero elements into it.

Then add zeroes at the end.

Finally copy the result back into nums.

### Dry Run

```text
nums = [0, 1, 0, 3, 12]
```

Collect non-zero elements:

```text
temp = [1, 3, 12]
```

Number of zeroes:

```text
2
```

Add zeroes:

```text
temp = [1, 3, 12, 0, 0]
```

Copy back:

```text
nums = [1, 3, 12, 0, 0]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def moveZeroes(self, nums: List[int]) -> None:

        # Create an empty temporary array
        temp = []

        # Traverse every number in nums
        for num in nums:

            # If current number is not zero
            if num != 0:

                # Add it to temp while maintaining order
                temp.append(num)

        # Count how many zeroes need to be added
        zero_count = len(nums) - len(temp)

        # Add all zeroes at the end of temp
        for _ in range(zero_count):

            # Append zero to the temporary array
            temp.append(0)

        # Copy temp back into nums because problem asks in-place modification
        for i in range(len(nums)):

            # Update original nums array
            nums[i] = temp[i]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array multiple times, but each traversal is linear. |
| **Space** | `O(n)` | Because we use an extra array `temp`. |

This is not accepted for the follow-up because it asks to do it in-place.

## 6. Better Solution: Shift Non-Zero Elements, Then Fill Zeroes

### Intuition

Instead of making a new array, we can overwrite the same array.

Use a pointer `insert_position`.

This pointer tells us:

```text
Where should the next non-zero element be placed?
```

### Approach

1. Start `insert_position = 0`.
2. Traverse the array.
3. Whenever you find a non-zero number, place it at `nums[insert_position]`.
4. Increase `insert_position`.
5. After all non-zero numbers are placed, fill remaining positions with `0`.

### Dry Run

```text
nums = [0, 1, 0, 3, 12]
```

Initial:

```text
insert_position = 0
```

**i = 0, nums[i] = 0**

Zero found, ignore.

```text
nums = [0, 1, 0, 3, 12]
insert_position = 0
```

**i = 1, nums[i] = 1**

Non-zero found.

Place at `insert_position = 0`.

```text
nums[0] = 1
```

Array becomes:

```text
nums = [1, 1, 0, 3, 12]
insert_position = 1
```

Do not worry about duplicate 1; it will be overwritten later.

**i = 2, nums[i] = 0**

Zero found, ignore.

```text
nums = [1, 1, 0, 3, 12]
insert_position = 1
```

**i = 3, nums[i] = 3**

Place at `insert_position = 1`.

```text
nums[1] = 3
```

Array becomes:

```text
nums = [1, 3, 0, 3, 12]
insert_position = 2
```

**i = 4, nums[i] = 12**

Place at `insert_position = 2`.

```text
nums[2] = 12
```

Array becomes:

```text
nums = [1, 3, 12, 3, 12]
insert_position = 3
```

Now all non-zero values are correctly placed in front:

```text
[1, 3, 12, _, _]
```

Fill remaining positions from index 3 to end with zero:

```text
nums = [1, 3, 12, 0, 0]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def moveZeroes(self, nums: List[int]) -> None:

        # This pointer stores the position where next non-zero element should be written
        insert_position = 0

        # Traverse every element in the array
        for i in range(len(nums)):

            # If current element is non-zero
            if nums[i] != 0:

                # Place current non-zero element at insert_position
                nums[insert_position] = nums[i]

                # Move insert_position forward for next non-zero element
                insert_position += 1

        # Fill all remaining positions with zero
        for i in range(insert_position, len(nums)):

            # Put zero at the remaining positions
            nums[i] = 0
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we scan the array once and then fill the rest with zeroes. |
| **Space** | `O(1)` | Because we modify the same array. |

## 7. Most Optimal Solution: Two Pointers With Swap

### Why do we need another solution?

The previous solution is already:

```text
Time: O(n)
Space: O(1)
```

But the follow-up asks:

```text
Can you minimize the total number of operations?
```

The previous approach may write many unnecessary values.

Example:

```text
nums = [1, 2, 3]
```

Previous approach does:

```text
nums[0] = 1
nums[1] = 2
nums[2] = 3
```

These are unnecessary writes because the array is already correct.

The swap approach reduces unnecessary writes.

### Core Intuition

Use two pointers:

```text
last_non_zero_position
current
```

`last_non_zero_position` means:

```text
The index where the next non-zero element should go.
```

When we find a non-zero number at index `current`, swap it with `nums[last_non_zero_position]`.

Then increase `last_non_zero_position`.

### Why does this work?

All elements before `last_non_zero_position` are already non-zero and in correct order.

When we find the next non-zero element, we bring it to the next correct position.

Since we scan left to right, the relative order is maintained.

### Dry Run

```text
nums = [0, 1, 0, 3, 12]
```

Initial:

```text
last_non_zero_position = 0
```

**current = 0**

```text
nums[current] = 0
```

It is zero, do nothing.

```text
nums = [0, 1, 0, 3, 12]
last_non_zero_position = 0
```

**current = 1**

```text
nums[current] = 1
```

It is non-zero.

Swap:

```text
nums[0] and nums[1]
```

Array:

```text
[1, 0, 0, 3, 12]
```

Move pointer:

```text
last_non_zero_position = 1
```

**current = 2**

```text
nums[current] = 0
```

It is zero, do nothing.

```text
nums = [1, 0, 0, 3, 12]
last_non_zero_position = 1
```

**current = 3**

```text
nums[current] = 3
```

It is non-zero.

Swap:

```text
nums[1] and nums[3]
```

Array:

```text
[1, 3, 0, 0, 12]
```

Move pointer:

```text
last_non_zero_position = 2
```

**current = 4**

```text
nums[current] = 12
```

It is non-zero.

Swap:

```text
nums[2] and nums[4]
```

Array:

```text
[1, 3, 12, 0, 0]
```

Move pointer:

```text
last_non_zero_position = 3
```

Final:

```text
[1, 3, 12, 0, 0]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def moveZeroes(self, nums: List[int]) -> None:

        # This pointer tracks where the next non-zero element should be placed
        last_non_zero_position = 0

        # Traverse the array using current index
        for current in range(len(nums)):

            # If current element is non-zero
            if nums[current] != 0:

                # Swap current non-zero element with the element at last_non_zero_position
                nums[last_non_zero_position], nums[current] = nums[current], nums[last_non_zero_position]

                # Move last_non_zero_position forward
                last_non_zero_position += 1
```

### Complexity of Most Optimal Solution

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array only once. |
| **Space** | `O(1)` | Because we use only one pointer and modify the array in-place. |

## 8. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Swapping the non-zero element with the element at the *end* of the array | It clears zeros in one pass but destroys relative order. `[0,1,0,3,12]` becomes something like `[12,1,3,0,0]`, which fails the stability requirement. | Swap with `last_non_zero_position`, the front boundary, and scan strictly left to right. |
| Advancing `last_non_zero_position` on every iteration instead of only on a non-zero | The write pointer keeps pace with the reader, so nothing is ever compacted and the array is returned unchanged. | Increment the write pointer *inside* the `if nums[current] != 0` branch only. |
| Using the two-pass version but forgetting the zero-fill loop | Stale values are left behind. `[0,1,0,3,12]` ends as `[1,3,12,3,12]` — the trailing garbage is never overwritten. | After placing all non-zeros, loop `for i in range(insert_position, len(nums)): nums[i] = 0`. |
| Deleting zeros while iterating (`nums.remove(0)` or `del nums[i]` in a `for` loop) | Mutating the list under the iterator skips elements, and it also changes the array's length, which the problem forbids. | Never resize. Overwrite in place with two pointers. |
| Rebinding with `nums = [...]` instead of mutating | Assigning a new list to the local name leaves the caller's array untouched, so an in-place grader sees no change. | Write through the existing object: index assignment, or `nums[:] = ...`. |
| Using truthiness (`if nums[current]`) in a language where `0.0`, `False`, or `""` may appear | Any falsy value is treated as a zero and gets moved, which is wrong when the array holds floats or booleans. | Compare explicitly against `0`. |
| Testing `if nums[current] > 0` | Silently drops negative numbers to the back alongside the zeros. `[0,-1,0,-3]` yields `[0,0,0,0]`-style corruption or wrong ordering. | The predicate is `!= 0`. |

## 9. Small Optimization to Avoid Self-Swap

In the previous code, if array is already like:

```text
[1, 2, 3]
```

Then it swaps every element with itself:

```text
swap nums[0] with nums[0]
swap nums[1] with nums[1]
swap nums[2] with nums[2]
```

This is not logically wrong, but it is unnecessary.

We can avoid this by checking:

```text
if current != last_non_zero_position
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def moveZeroes(self, nums: List[int]) -> None:

        # This pointer stores the next position where a non-zero element should go
        last_non_zero_position = 0

        # Traverse every index of the array
        for current in range(len(nums)):

            # If the current element is non-zero
            if nums[current] != 0:

                # Swap only when current is different from last_non_zero_position
                if current != last_non_zero_position:

                    # Move non-zero element to the correct front position
                    nums[last_non_zero_position], nums[current] = nums[current], nums[last_non_zero_position]

                # Move pointer for the next non-zero element
                last_non_zero_position += 1
```

## 11. Snowball Approach

### Snowball Approach Intuition

Think of every zero as a **snowball**.

As we scan the array from left to right:

```text
Whenever we see 0:
    snowball size increases

Whenever we see non-zero:
    push it left by snowball size
    put 0 at its old place
```

Meaning:

```text
snowball_size = number of zeroes seen so far
```

So if we have already seen 2 zeroes, every next non-zero element should move 2 steps left.

### Example

```text
nums = [0, 1, 0, 3, 12]
```

Initial:

```text
snowball_size = 0
```

**i = 0**

```text
nums[i] = 0
```

Zero found:

```text
snowball_size = 1
```

Array:

```text
[0, 1, 0, 3, 12]
```

**i = 1**

```text
nums[i] = 1
snowball_size = 1
```

Move 1 left by 1 position:

```text
nums[1 - 1] = nums[1]
nums[0] = 1
```

Put zero at current index:

```text
nums[1] = 0
```

Array:

```text
[1, 0, 0, 3, 12]
```

**i = 2**

```text
nums[i] = 0
```

Zero found:

```text
snowball_size = 2
```

Array:

```text
[1, 0, 0, 3, 12]
```

**i = 3**

```text
nums[i] = 3
snowball_size = 2
```

Move 3 left by 2 positions:

```text
nums[3 - 2] = nums[3]
nums[1] = 3
```

Put zero at current index:

```text
nums[3] = 0
```

Array:

```text
[1, 3, 0, 0, 12]
```

**i = 4**

```text
nums[i] = 12
snowball_size = 2
```

Move 12 left by 2 positions:

```text
nums[4 - 2] = nums[4]
nums[2] = 12
```

Put zero at current index:

```text
nums[4] = 0
```

Array:

```text
[1, 3, 12, 0, 0]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def moveZeroes(self, nums: List[int]) -> None:

        # This variable counts how many zeroes we have seen so far
        snowball_size = 0

        # Traverse the array from left to right
        for i in range(len(nums)):

            # If current element is zero
            if nums[i] == 0:

                # Increase snowball size because we found one more zero
                snowball_size += 1

            # If current element is non-zero and at least one zero exists before it
            elif snowball_size > 0:

                # Move current non-zero element left by snowball_size positions
                nums[i - snowball_size] = nums[i]

                # Put zero at current position
                nums[i] = 0
```

### Snowball Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array only once. |
| **Space** | `O(1)` | Because we only use one counter variable. |

## 12. Is Snowball Different From Two Pointer?

Conceptually, both are almost same.

**Two Pointer View**

```text
last_non_zero_position = where next non-zero should go
```

**Snowball View**

```text
snowball_size = how many zeroes are before current index
```

Actually:

```text
last_non_zero_position = current_index - snowball_size
```

So the snowball approach is just another way to think about the same optimized logic.

### Snowball vs Swap Approach

**Swap approach**

```python
nums[last_non_zero_position], nums[current] = nums[current], nums[last_non_zero_position]
```

It swaps non-zero with earliest zero.

**Snowball approach**

```python
nums[i - snowball_size] = nums[i]
nums[i] = 0
```

It shifts the non-zero left and writes zero behind.

### Which one should you use in interview?

Use this one if interviewer asks:

```text
Can you minimize operations?
```

## 13. Interview Follow-ups

**Q: Can you minimise the number of writes? The swap version still writes on every non-zero.**

A: Yes, and this is the actual follow-up on the problem. The swap version performs two writes per non-zero element even when the array needs no change at all — `[1,2,3]` costs six writes to accomplish nothing. Guard it with `if current != last_non_zero_position` so a self-swap is skipped entirely; then an array with no zeros costs zero writes. The snowball variant does even better in the general case: it performs exactly one write per non-zero element that actually moves, plus one write to blank its old slot, and touches nothing before the first zero.

**Q: What if you had to move zeros to the *front* instead, still preserving the order of non-zeros?**

A: Mirror the scan. Run the read pointer from `n-1` down to `0` and let the write pointer start at `n-1`, placing each non-zero you encounter at `nums[write]` and decrementing. Because you now traverse right to left and fill from the right, the non-zeros land in reverse-of-reverse — that is, original — order, and the remaining prefix gets filled with zeros. The invariant is the mirror image: `nums[write+1 .. n-1]` holds the non-zeros seen so far in original order.

**Q: Generalise it — move all elements equal to some value `val` to the end, or partition by an arbitrary predicate.**

A: The algorithm is unchanged; only the test changes. Replace `nums[current] != 0` with `not predicate(nums[current])` — or `nums[current] != val` — and the same two-pointer skeleton performs a stable partition for any predicate. This is literally Remove Element (LC 27) with a fill step appended. The cost stays `O(n)` time and `O(1)` space regardless of how expensive the predicate is to evaluate, since each element is tested exactly once.

**Q: What if there were three categories rather than two — say move all negatives to the front, zeros to the middle, positives to the end?**

A: Two pointers no longer suffice; you need the Dutch National Flag algorithm (LC 75, Sort Colors) with three: `low`, `mid`, and `high`. `mid` scans; a value belonging to the first group swaps to `low` and both advance, a value belonging to the last group swaps to `high` and only `high` retreats (because the swapped-in value is unexamined), and a middle value just advances `mid`. It is one pass and `O(1)` space — but note it is *not* stable, so if the problem also demands preserved order within each group you need either extra space or a stable sort by category key.

**Q: The data arrives as a stream you cannot index into. Does this still work?**

A: The compaction half does, the zero-fill half does not. You can emit non-zero elements downstream as you see them while counting the zeros you skipped, all in `O(1)` memory — that is a pure streaming filter. But you cannot emit the trailing zeros until the stream ends, since you do not know how many there are until then. So it becomes a two-phase operation: stream out the non-zeros, then at end-of-stream emit `zero_count` zeros. If the output must be the same buffer you are reading from, streaming is impossible and you need random access.

## 14. Interview Explanation

> I will use a pointer called `last_non_zero_position`, which marks where the next non-zero element should be placed. I scan the array from left to right. Whenever I find a non-zero element, I swap it with the element at `last_non_zero_position` and then move the pointer forward. This keeps the relative order of non-zero elements because I process them left to right. It runs in `O(n)` time and `O(1)` space.

## 15. Verify

```python
# Define the function under test
def move_zeroes(nums):

    # This pointer tracks where the next non-zero element should be placed
    last_non_zero_position = 0

    # Traverse the array using current index
    for current in range(len(nums)):

        # If current element is non-zero
        if nums[current] != 0:

            # Swap only when current is different from last_non_zero_position
            if current != last_non_zero_position:

                # Move non-zero element to the correct front position
                nums[last_non_zero_position], nums[current] = (
                    nums[current],
                    nums[last_non_zero_position],
                )

            # Move last_non_zero_position forward
            last_non_zero_position += 1
```
