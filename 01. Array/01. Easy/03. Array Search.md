## 1. Problem Statement

Given an array, **arr[]** of n integers, and an integer element **x**, find whether element x is present in the array. Return the index of the first occurrence of x in the array, or -1 if it doesn't exist.

### Examples

```text
Input:  arr[] = [1, 2, 3, 4], x = 3
Output: 2
Explanation: For array [1, 2, 3, 4], the element to be searched is 3. Since 3 is present at index 2, the output is 2.
```

```text
Input:  arr[] = [10, 8, 30, 4, 5], x = 5
Output: 4
Explanation: For array [10, 8, 30, 4, 5], the element to be searched is 5 and it is at index 4. So, the output is 4.
```

```text
Input:  arr[] = [10, 8, 30], x = 6
Output: -1
Explanation: The element to be searched is 6 and it is not present, so we return -1.
```

### Constraints

- `1 <= arr.size <= 10^6`
- `0 <= arr[i] <= 10^6`
- `0 <= x <= 10^5`

## 2. Core Theory

**Linear search** is the baseline membership test: walk the array left to right and stop at the first index whose value equals the target. It makes no assumption about the data, which is exactly why it is the correct default — every faster search technique buys its speed by demanding a precondition (sorted order, a hash function, an index structure) that must be paid for somewhere.

The invariant is simply: *when the loop is about to examine index `i`, the target is known to be absent from `nums[0..i-1]`*. Returning `i` at the first match therefore yields the **first** occurrence for free — the ordering of the scan is what makes "first" correct, not any extra bookkeeping. Falling out of the loop means the invariant covered the whole array, so `-1` is justified.

Recognize the pattern when the data is unsorted and you will search it only once or twice. The break-even analysis is the real interview content:

| Approach | Precondition | Build cost | Per-query cost | Extra space |
|:---|:---|:---:|:---:|:---:|
| Linear search | none | `O(1)` | `O(n)` | `O(1)` |
| Binary search | sorted | `O(n log n)` to sort | `O(log n)` | `O(1)` |
| Hash map | none | `O(n)` | `O(1)` average | `O(n)` |

For a single query, linear search wins outright: sorting first costs `O(n log n)`, strictly worse than the `O(n)` scan it is trying to accelerate. Preprocessing only pays off when the build cost is amortized over many queries — roughly once `q > log n` queries for the sorted-plus-binary-search route.

The trap specific to this problem is that **sorting destroys the answer**. The question asks for an index into the original array; sorting permutes the positions, so the index you find no longer means anything unless you also carry the original indices along as pairs.

## 4. Key Observation

The array is **not guaranteed to be sorted**.

So we cannot directly use binary search.

Example:

```text
arr = [10, 8, 30, 4, 5]
```

This is unsorted.

Therefore, the safest approach is:

```text
Check each element one by one from left to right.
```

Since the problem asks for **first occurrence**, we should return immediately when we find x.

## 5. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element, match | `arr = [7]`, `x = 7` | `0` | Smallest success case; catches a loop that starts at index 1. |
| Single element, no match | `arr = [7]`, `x = 3` | `-1` | The `return -1` after the loop must actually be reachable. |
| Empty array | `arr = []`, `x = 5` | `-1` | Loop body never runs; must not touch `arr[0]`. |
| Target at index 0 | `arr = [5, 1, 2]`, `x = 5` | `0` | A truthiness check like `if index:` would treat a valid `0` as "not found". |
| Target at the last index | `arr = [10, 8, 30, 4, 5]`, `x = 5` | `4` | Catches an off-by-one `range(len(arr) - 1)`. |
| Duplicates present | `arr = [4, 2, 7, 2, 9]`, `x = 2` | `1` | Must return the **first** occurrence, so return immediately, do not keep scanning. |
| All identical | `arr = [3, 3, 3]`, `x = 3` | `0` | Every index matches; the first one wins. |
| Target absent | `arr = [10, 8, 30]`, `x = 6` | `-1` | The full-scan-then-fail path. |
| Negatives | `arr = [-5, -2, -9]`, `x = -9` | `2` | Equality comparison is sign-agnostic; only a sentinel like `0` would break. |
| Unsorted input | `arr = [10, 8, 30, 4, 5]`, `x = 30` | `2` | Binary search would answer incorrectly here. |

## 6. Brute Force / Optimal Solution: Linear Search

For this problem, brute force and optimal are the same because the array is unsorted.

### Intuition

Imagine you are searching for a name in a random list.

Since the list is not sorted, you cannot jump directly.

You must check from the beginning:

```text
index 0
index 1
index 2
...
```

The first index where the element matches x is the answer.

### Approach

1. Start from index 0.
2. Compare `arr[i]` with x.
3. If `arr[i] == x`, return i.
4. If the loop finishes and no match is found, return -1.

### Dry Run

```text
arr = [10, 8, 30, 4, 5]
x = 5
```

| i | arr[i] | arr[i] == x? |
|:---:|:---:|:---:|
| 0 | 10 | No |
| 1 | 8 | No |
| 2 | 30 | No |
| 3 | 4 | No |
| 4 | 5 | Yes |

So return:

```text
4
```

## 7. Case with First Occurrence

```text
arr = [4, 2, 7, 2, 9]
x = 2
```

2 appears at index 1 and index 3.

But the problem asks for first occurrence.

So answer is:

```text
1
```

Dry run:

| i | arr[i] | arr[i] == x? |
|:---:|:---:|:---:|
| 0 | 4 | No |
| 1 | 2 | Yes |

We immediately return 1.

We do not continue searching.

### Code

```python
# Define the class solution
class Solution:

    # Define the method search
    def search(self, arr, x):

        # Traverse every index of the array from left to right
        for i in range(len(arr)):

            # If the current element is equal to target x
            if arr[i] == x:

                # Return the index immediately because we need first occurrence
                return i

        # If loop ends, x was not found in the array
        return -1
```

## 8. Complexity

```text
Time Complexity: O(n)
```

Because in the worst case, we may need to check all elements.

Worst case examples:

```text
arr = [1, 2, 3, 4, 5]
x = 5
```

Target is at the last index.

Or:

```text
arr = [1, 2, 3, 4, 5]
x = 10
```

Target does not exist.

So we check all n elements.

```text
Space Complexity: O(1)
```

Because we only use one loop variable `i`.

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because in the worst case, we may need to check all elements. |
| **Space** | `O(1)` | Because we only use one loop variable `i`. |

## 9. Why Binary Search Is Not Used

Binary search requires sorted data.

This array can be:

```text
[10, 8, 30, 4, 5]
```

If we apply binary search here, it may give wrong results because elements are not arranged in increasing or decreasing order.

So linear search is the correct approach.

## 10. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Sorting the array first, then binary searching | Sorting permutes positions, so the index found refers to the sorted array, not the original. `[10, 8, 30]` with `x = 30` would return `2` by luck but `[30, 8, 10]` returns the wrong index. | Do not sort. Scan the original array, or sort `(value, index)` pairs if you truly need repeated queries. |
| `for i in range(len(arr) - 1)` | Never examines the last element, so `[10, 8, 30, 4, 5]` with `x = 5` returns `-1`. | `range(len(arr))` — `range` already stops before the endpoint. |
| Recording the match and continuing the loop | Later duplicates overwrite the stored index, so `[4, 2, 7, 2, 9]` with `x = 2` returns `3` instead of `1`. | `return i` immediately on the first match. |
| `if index:` to test the result | Index `0` is falsy, so a target found at the front is reported as missing. | Test `if index != -1:` explicitly. |
| Returning `True` / `False` instead of the index | The problem asks for a position, not membership. | Return `i`, and `-1` when absent. |
| Using `arr.index(x)` without a guard | Raises `ValueError` when `x` is absent instead of returning `-1`. | Wrap in `try/except`, or write the explicit loop. |

## 11. Interview Follow-ups

**Q: What if you had to answer a million queries on the same array?**

A: Then preprocessing pays for itself. I would build a hash map from value to its **first** index in one `O(n)` pass — inserting only when the key is absent preserves first-occurrence semantics — and answer each query in `O(1)` average. Total cost `O(n + q)` instead of `O(n·q)`.

**Q: What if the array were sorted and you still needed the first occurrence?**

A: Binary search, but the lower-bound variant: when `arr[mid] == x` do not return immediately, instead record `mid` and continue searching the left half (`hi = mid - 1`). Plain binary search lands on an arbitrary member of a duplicate run; lower bound pins the leftmost, in `O(log n)`.

**Q: What if the array does not fit in memory?**

A: Linear search is already streaming-friendly: read a block, scan it, return the global index on a hit, discard the block. Memory stays `O(1)` beyond the block buffer. This is exactly why linear search survives at scale even though it is asymptotically slow.

**Q: Can you speed up the scan itself without changing the asymptotics?**

A: Yes, constant-factor tricks. A sentinel — append `x` at the end so the loop needs no bounds check, then test whether the found index is the sentinel's — removes one comparison per iteration. On real hardware, vectorized comparison (SIMD) or simply scanning contiguous memory dominates, because cache behavior matters more than the operation count at `O(n)`.

**Q: How would you parallelize it?**

A: Split the array into chunks and scan them concurrently, but each worker must report the index it found and the final answer is the **minimum** of those indices, not the first one to finish. Without that reduction the result is non-deterministic across runs.

## 12. Interview Explanation

You can say:

> Since the array is unsorted and we need the first occurrence of x, I will scan the array from left to right. The moment I find `arr[i] == x`, I return i. If no element matches after the full scan, I return -1. This gives O(n) time and O(1) space.

## 13. Verify

```python
# Define the function to search for the first occurrence of x
def search(arr, x):
    # Traverse every index of the array from left to right
    for i in range(len(arr)):
        # If the current element is equal to target x
        if arr[i] == x:
            # Return the index immediately because we need first occurrence
            return i
    # If loop ends, x was not found in the array
    return -1


# Target present, general case
assert search([1, 2, 3, 4], 3) == 2
# Target at the last index
assert search([10, 8, 30, 4, 5], 5) == 4
# Target absent

# Single element, match
assert search([7], 7) == 0
# Single element, no match
assert search([7], 3) == -1
# Empty array
assert search([], 5) == -1
# Target at index 0
assert search([5, 1, 2], 5) == 0
# Duplicates present, must return first occurrence
assert search([4, 2, 7, 2, 9], 2) == 1
# All identical
assert search([3, 3, 3], 3) == 0
# Negatives

# Unsorted input

assert original == [10, 8, 30, 4, 5]  # input must not be mutated or sorted
```
