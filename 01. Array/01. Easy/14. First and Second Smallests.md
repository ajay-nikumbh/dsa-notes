# 14. First and Second Smallests

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Linear Scan / One Pass | [First and Second Smallests](https://www.geeksforgeeks.org/problems/smallest-and-second-smallest-element-in-an-array3226/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given an array, `arr[]` of integers, your task is to return the **smallest** and **second smallest** element in the array. If the smallest and second smallest do not exist, return **-1**.

### Examples

```text
Input:  arr[] = [2, 4, 3, 5, 6]
Output: [2, 3]
Explanation: 2 and 3 are respectively the smallest and second smallest elements in the array.
```

```text
Input:  arr[] = [1, 1, 1]
Output: [-1]
Explanation: Only element is 1 which is smallest, so there is no second smallest element.
```

### Constraints

- `1 <= arr.size <= 10^5`
- `1 <= arr[i] <= 10^5`

## 2. Core Theory

### The technique: tracking running extremes

This is the **running-extremes** pattern: keep a fixed-size leaderboard of the best values seen so far and update it as each element arrives. Here the leaderboard has two slots, `smallest` and `second_smallest`, so the whole scan is `O(n)` time and `O(1)` space. Sorting would also work but costs `O(n log n)` and throws away the original order for no benefit — you only need two order statistics, not all `n`.

### The invariant

After processing the first `i` elements, `smallest` holds the minimum of those elements and `second_smallest` holds the smallest value strictly greater than `smallest` among them (or the sentinel if no such value has appeared). Every branch of the update must leave this invariant true.

### Why update ORDER matters

This is the classic bug. When a new value beats `smallest`, the old `smallest` must be demoted into `second_smallest` **before** `smallest` is overwritten:

```text
Correct:
    if num < smallest:
        second_smallest = smallest    # save the old champion first
        smallest = num                # then install the new one

Wrong:
    if num < smallest:
        smallest = num                # old value is gone
        second_smallest = smallest    # now both hold the same number
```

With a single pass there is no way to recover the lost value. On `arr = [2, 4, 3, 5, 6]` the wrong order returns `[2, 2]` instead of `[2, 3]`.

The `elif` matters just as much. If the second branch were a plain `if`, a brand-new smallest would fall through into it and immediately overwrite the value it had just demoted.

### Why sentinels must be `+inf`, not `0` or `arr[0]`

The starting value has to be something **every** possible input beats, so the very first comparison fires.

| Initialization | Failure |
|:---|:---|
| `smallest = 0` | On all-positive input `[2, 4, 3]`, nothing is `< 0`, so `smallest` stays `0` — a value not in the array. |
| `second_smallest = 0` | On input containing negatives, `0` may be wrongly reported as the runner-up. |
| `smallest = arr[0]`, `second_smallest = arr[1]` | Only correct if you also swap them when `arr[1] < arr[0]`, and it index-errors on arrays shorter than 2. |

`float("inf")` beats nothing and loses to everything finite, so the first element always wins. It also doubles as the "not found" flag: if `second_smallest` is still `inf` after the loop, no distinct second smallest exists and you return `[-1]`.

### The strictness rule for distinctness

The band condition is `smallest < num < second_smallest`, with strict `<` on both sides. A duplicate of `smallest` fails `smallest < num` and is skipped, which is exactly what keeps the answer *distinct*. Using `<=` would make `[1, 1, 1]` report `[1, 1]` instead of `[-1]`.

### Recognizing this pattern

Any request for a constant number of order statistics in one pass — "two smallest", "min and max together", "largest without sorting". Prerequisite: recognizing that sorting is overkill when `k` is a small constant.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Empty array | `arr = []` | `[-1]` | The `len < 2` guard must catch it before the loop. |
| Single element | `arr = [5]` | `[-1]` | No second smallest can exist. |
| All identical | `arr = [1, 1, 1]` | `[-1]` | Strict `<` rejects duplicates; `<=` would wrongly return `[1, 1]`. |
| Two distinct, reversed | `arr = [2, 1]` | `[1, 2]` | Exercises the demotion path: `1` displaces `2`, which must land in `second_smallest`. |
| Two identical | `arr = [7, 7]` | `[-1]` | Length is 2 but there is only one distinct value. |
| All negative | `arr = [-3, -10, -5]` | `[-10, -5]` | "Smaller" means more negative; `smallest = 0` initialization fails here. |
| Duplicated minimum | `arr = [1, 1, 2, 2, 3]` | `[1, 2]` | The second `1` must not become the second smallest. |
| Strictly ascending | `arr = [2, 4, 3, 5, 6]` | `[2, 3]` | First element sets `smallest`; later ones only fill the runner-up slot. |
| Strictly descending | `arr = [6, 5, 4, 3, 2]` | `[2, 3]` | Every element triggers the demotion branch, stressing the update order. |
| Minimum appears last | `arr = [5, 4, 3, 1]` | `[1, 3]` | The final demotion must overwrite the earlier runner-up correctly. |
| Zero present | `arr = [0, 5, 0, 3]` | `[0, 3]` | `0` is a real value and must not be treated as an unset sentinel. |

## 4. GFG Problem: Smallest and Second Smallest Element in an Array

Problem link: The task is to return the **smallest** and **second smallest distinct** element in the array. If the second smallest does not exist, return `[-1]`.

### Example 1

```text
Input:
arr = [2, 4, 3, 5, 6]

Output:
[2, 3]
```

Explanation:

```text
Smallest = 2
Second smallest = 3
```

### Example 2

```text
Input:
arr = [1, 1, 1]

Output:
[-1]
```

Explanation:

```text
Smallest = 1
Second smallest does not exist
```

Because all elements are the same.

## 5. Problem Explanation

We need to find two values:

```text
1. Smallest distinct element
2. Second smallest distinct element
```

Important point:

```text
The second smallest must be different from the smallest.
```

So:

```text
arr = [1, 1, 2, 2, 3]

Smallest = 1
Second smallest = 2
```

Not 1, because we need the **second distinct smallest** value.

## 6. More Edge Cases in Detail

| Input | Output | Reason |
|:---|:---:|:---|
| `arr = [5]` | `[-1]` | Only one element, so second smallest does not exist. |
| `arr = [5, 5, 5]` | `[-1]` | All elements are the same. |
| `arr = [2, 1]` | `[1, 2]` | Smallest is `1`, second smallest is `2`. |
| `arr = [-3, -10, -5]` | `[-10, -5]` | For negative numbers, smaller means more negative. |

## 7. Brute Force Solution

### Intuition

We can first find the smallest element.

Then we can find the smallest number which is greater than the smallest.

### Approach

Step 1:

```text
Find the minimum element.
```

Step 2:

```text
Find the minimum element greater than the smallest.
```

Step 3:

```text
If no such element exists, return [-1].
Otherwise return [smallest, second_smallest].
```

### Dry Run

```text
arr = [2, 4, 3, 5, 6]
```

First pass:

```text
smallest = 2
```

Second pass:

```text
Elements greater than 2 are: 4, 3, 5, 6
Minimum among them = 3
```

Answer:

```text
[2, 3]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def minAnd2ndMin(self, arr: List[int]) -> List[int]:

        # If the array has less than two elements, second smallest cannot exist
        if len(arr) < 2: return [-1]

        # Initialize smallest with the first element
        smallest = arr[0]

        # Traverse every element to find the smallest value
        for num in arr:

            # If current number is smaller than current smallest
            if num < smallest:

                # Update smallest
                smallest = num

        # Initialize second smallest as positive infinity
        second_smallest = float("inf")

        # Traverse again to find the smallest number greater than smallest
        for num in arr:

            # Check only values strictly greater than smallest
            if num > smallest:

                # If current number is smaller than current second smallest
                if num < second_smallest:

                    # Update second smallest
                    second_smallest = num

        # If second smallest was never updated, it does not exist
        if second_smallest == float("inf"): return [-1]

        # Return smallest and second smallest
        return [smallest, second_smallest]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array twice. |
| **Space** | `O(1)` | Because we use only two variables. |

This is already efficient, but we can do it in **one pass**.

## 8. Sorting Solution

### Intuition

After sorting, the smallest element will be at the beginning.

The second smallest distinct element will be the first value from the left that is greater than the smallest.

### Approach

1. Sort the array.
2. Store `arr[0]` as smallest.
3. Traverse from index 1.
4. Return the first element greater than smallest.
5. If no such element exists, return `[-1]`.

### Dry Run

```text
arr = [2, 4, 3, 5, 6]
```

After sorting:

```text
[2, 3, 4, 5, 6]
```

Smallest:

```text
2
```

First element greater than 2:

```text
3
```

Answer:

```text
[2, 3]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def minAnd2ndMin(self, arr: List[int]) -> List[int]:

        # If the array has less than two elements, second smallest cannot exist
        if len(arr) < 2: return [-1]

        # Sort the array in ascending order
        arr.sort()

        # Store the smallest element
        smallest = arr[0]

        # Traverse from the second element
        for i in range(1, len(arr)):

            # First value greater than smallest is second smallest
            if arr[i] > smallest:

                # Return smallest and second smallest
                return [smallest, arr[i]]

        # If all elements are same, second smallest does not exist
        return [-1]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Because sorting takes `O(n log n)`. |
| **Space** | `O(1) or O(n)` | Depending on sorting implementation. |

## 9. Most Optimal Solution: One Pass

### Intuition

We can maintain two variables:

```text
smallest
second_smallest
```

While traversing the array:

```text
If current number is smaller than smallest:
    old smallest becomes second smallest
    current number becomes smallest
```

And:

```text
If current number is greater than smallest but smaller than second smallest:
    current number becomes second smallest
```

### Important Duplicate Handling

Suppose:

```text
arr = [1, 1, 2]
```

When current number is 1, we should not update second smallest to 1.

So we use strict condition:

```text
smallest < num < second_smallest
```

This ensures second smallest is distinct.

### Code

```python
# Define the class solution
class Solution:

    def minAnd2ndMin(self, arr):

        # If array has less than two elements, second smallest cannot exist
        if len(arr) < 2:
            return [-1]

        # Store the smallest distinct value seen so far
        smallest = float("inf")

        # Store the second smallest distinct value seen so far
        second_smallest = float("inf")

        # Traverse every number in the array
        for num in arr:

            # If current number is smaller than the smallest
            if num < smallest:

                # Old smallest becomes second smallest
                second_smallest = smallest

                # Current number becomes the new smallest
                smallest = num

            # If current number is greater than smallest but smaller than second smallest
            elif smallest < num < second_smallest:

                # Current number becomes the new second smallest
                second_smallest = num

        # If second smallest is still infinity, no distinct second smallest exists
        if second_smallest == float("inf"):
            return [-1]

        # Return smallest and second smallest
        return [smallest, second_smallest]
```

|:---|:---:|:---|
| **Time** | `O(n)` | Because we scan the array once. |
| **Space** | `O(1)` | Because we only use two variables. |

## 12. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Overwriting `smallest` before demoting it: `smallest = num` then `second_smallest = smallest` | The old minimum is destroyed, so both variables end up equal. `[2, 4, 3, 5, 6]` returns `[2, 2]` instead of `[2, 3]`. | Demote first: `second_smallest = smallest`, *then* `smallest = num`. |
| Initializing `second_smallest = 0` | Meaningless on arrays that contain negatives, and on all-positive arrays it never gets replaced by a correct value via the band check. | Initialize both to `float("inf")`. |
| Initializing `smallest = arr[0]` and `second_smallest = arr[1]` without ordering them | If `arr[1] < arr[0]` the invariant is broken from the first step, and short arrays raise `IndexError`. | Use `float("inf")` sentinels plus an explicit `len(arr) < 2` guard. |
| Using `elif num < second_smallest` without the lower bound | A duplicate of `smallest` passes the test, so `[1, 1, 2]` returns `[1, 1]` instead of `[1, 2]`. | Use the full band `elif smallest < num < second_smallest`. |
| Using a second `if` instead of `elif` | A new smallest falls through into the runner-up branch and overwrites the value it just demoted. | Make the runner-up check an `elif`. |
| Returning `[-1]` only when `len(arr) < 2`, forgetting the all-duplicates case | `[1, 1, 1]` has length 3 but no distinct second smallest, so it returns `[1, inf]`. | Also check `if second_smallest == float("inf"): return [-1]` after the loop. |
| Checking `if second_smallest == float("inf")` before the loop instead of after | The sentinel check has to reflect what the scan actually found. | Do the conversion after the traversal completes. |

## 13. Interview Follow-ups

**Q: What if I asked for the k-th smallest instead of the second smallest?**

A: For a small constant `k` you can extend the same idea to `k` variables, but it gets ugly fast. Better: a max-heap of size `k` gives `O(n log k)` time and `O(k)` space, and Quickselect gives `O(n)` average time in place (`O(n^2)` worst case). Median-of-medians makes the `O(n)` worst-case guaranteed.

**Q: What if you also needed the second largest in the same pass?**

A: Add two more variables, `largest` and `second_largest`, initialized to `float("-inf")`, and mirror the update logic on the other side. Still one pass, still `O(1)` space — just two independent leaderboards updated per element.

**Q: How would you handle a streaming input you cannot store?**

A: No change is needed. The algorithm is already online: it reads each value exactly once, never looks back, and holds only two numbers. You can drive it straight from a generator or a socket.

**Q: What if the problem wanted the second smallest by index after sorting, counting duplicates?**

A: Then `[1, 1, 1]` would answer `1` rather than `-1`. Drop the distinctness requirement by relaxing the band to `elif num < second_smallest` (no lower bound), so a duplicate of the minimum can occupy the runner-up slot. Always clarify which version is wanted before coding.

**Q: The constraints say `1 <= arr[i] <= 10^5` — could you use that to avoid sentinels?**

A: You could initialize both variables to `10^5 + 1`, since no input exceeds that. It works, but it hard-codes a constraint that changes if the problem is reused, and it breaks silently if negatives are ever allowed. `float("inf")` is constraint-independent and communicates intent better.

## 14. Interview Explanation

You can say:

> I will keep two variables: `smallest` and `second_smallest`. Initially both are infinity. While traversing the array, if I find a number smaller than `smallest`, then the old smallest becomes `second_smallest`, and the current number becomes the new smallest. Otherwise, if the number is greater than `smallest` but smaller than `second_smallest`, I update `second_smallest`. This handles duplicates because I only update second smallest when the number is strictly greater than smallest. If second smallest never changes, I return `[-1]`.

## 15. Verify

```python
def min_and_2nd_min(arr):
    # Fewer than two elements means no second smallest
    if len(arr) < 2:
        return [-1]

    # Sentinels that every real value beats
    smallest = float("inf")
    second_smallest = float("inf")

    for num in arr:
        # New smallest: demote the old one BEFORE overwriting
        if num < smallest:
            second_smallest = smallest
            smallest = num
        # Strictly between smallest and second smallest keeps the answer distinct
        elif smallest < num < second_smallest:
            second_smallest = num

    # Untouched sentinel means there is no distinct second smallest
    if second_smallest == float("inf"):
        return [-1]

    return [smallest, second_smallest]


# Given examples
assert min_and_2nd_min([2, 4, 3, 5, 6]) == [2, 3]
assert min_and_2nd_min([1, 1, 1]) == [-1]

# Empty and single element
assert min_and_2nd_min([]) == [-1]
assert min_and_2nd_min([5]) == [-1]

# Two elements
assert min_and_2nd_min([2, 1]) == [1, 2]
assert min_and_2nd_min([7, 7]) == [-1]

# Negatives
assert min_and_2nd_min([-3, -10, -5]) == [-10, -5]

# Duplicated minimum must not become the second smallest
assert min_and_2nd_min([1, 1, 2, 2, 3]) == [1, 2]

# Descending input stresses the demotion order
assert min_and_2nd_min([6, 5, 4, 3, 2]) == [2, 3]

# Minimum appears last
assert min_and_2nd_min([5, 4, 3, 1]) == [1, 3]
```
