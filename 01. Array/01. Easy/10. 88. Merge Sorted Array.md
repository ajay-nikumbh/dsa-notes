# 10. 88. Merge Sorted Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Two Pointers (Merge From Back) | [88. Merge Sorted Array](https://leetcode.com/problems/merge-sorted-array/) | `O(m + n)` | `O(1)` |

## 1. Problem Statement

You are given two integer arrays `nums1` and `nums2`, sorted in **non-decreasing order**, and two integers `m` and `n`, representing the number of elements in `nums1` and `nums2` respectively.

**Merge** `nums1` and `nums2` into a single array sorted in **non-decreasing order**.

The final sorted array should not be returned by the function, but instead be *stored inside the array* `nums1`. To accommodate this, `nums1` has a length of `m + n`, where the first `m` elements denote the elements that should be merged, and the last `n` elements are set to `0` and should be ignored. `nums2` has a length of `n`.

### Examples

```text
Example 1:

Input: nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3
Output: [1,2,2,3,5,6]
Explanation: The arrays we are merging are [1,2,3] and [2,5,6].
The result of the merge is [1,2,2,3,5,6] with the underlined elements coming from nums1.
```

```text
Example 2:

Input: nums1 = [1], m = 1, nums2 = [], n = 0
Output: [1]
Explanation: The arrays we are merging are [1] and [].
The result of the merge is [1].
```

```text
Example 3:

Input: nums1 = [0], m = 0, nums2 = [1], n = 1
Output: [1]
Explanation: The arrays we are merging are [] and [1].
The result of the merge is [1].
Note that because m = 0, there are no elements in nums1. The 0 is only there to ensure the
merge result can fit in nums1.
```

### Constraints

- `nums1.length == m + n`
- `nums2.length == n`
- `0 <= m, n <= 200`
- `1 <= m + n <= 200`
- `-10^9 <= nums1[i], nums2[j] <= 10^9`

### Follow up

Can you come up with an algorithm that runs in `O(m + n)` time?

## 2. Problem Explanation

You are given two sorted arrays:

```text
nums1
nums2
```

Both are sorted in **non-decreasing order**.

But `nums1` has extra space at the end.

```text
nums1.length = m + n
```

Where:

```text
First m elements of nums1 are real elements.
Last n elements of nums1 are extra zero placeholders.
```

You need to merge `nums2` into `nums1` so that `nums1` becomes one sorted array.

Important:

```text
Do not return a new array.
Modify nums1 in-place.
```

### Example

```text
nums1 = [1, 2, 3, 0, 0, 0]
m = 3

nums2 = [2, 5, 6]
n = 3
```

Real part of `nums1`:

```text
[1, 2, 3]
```

Extra space:

```text
[0, 0, 0]
```

After merge:

```text
nums1 = [1, 2, 2, 3, 5, 6]
```

## 3. Core Intuition

This is the same idea as the **merge step of merge sort**.

When two arrays are already sorted, we can merge them using two pointers.

Example:

```text
nums1 real part = [1, 2, 3]
nums2           = [2, 5, 6]
```

Compare smallest elements:

```text
1 and 2 -> pick 1
2 and 2 -> pick 2
3 and 2 -> pick 2
3 and 5 -> pick 3
then remaining 5, 6
```

Result:

```text
[1, 2, 2, 3, 5, 6]
```

## 4. Important Catch

The result must be stored inside `nums1`.

If we merge from the front directly, we may overwrite useful values in `nums1`.

Example:

```text
nums1 = [1, 2, 3, 0, 0, 0]
nums2 = [2, 5, 6]
```

If we write from index 0, we may destroy 1, 2, 3 before using them.

So the best trick is:

```text
Merge from the back.
```

Because the back side of `nums1` has empty space.

## 5. Brute Force Solution: Copy + Sort

### Intuition

Put all elements of `nums2` into the empty space of `nums1`.

Then sort `nums1`.

### Approach

1. Copy every element of `nums2` into `nums1` after index `m - 1`.
2. Sort `nums1`.

### Dry Run

```text
nums1 = [1, 2, 3, 0, 0, 0], m = 3
nums2 = [2, 5, 6], n = 3
```

Copy `nums2` into extra space:

```text
nums1 = [1, 2, 3, 2, 5, 6]
```

Sort:

```text
nums1 = [1, 2, 2, 3, 5, 6]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:

        # Start writing nums2 elements from index m in nums1
        index = m

        # Traverse every element of nums2
        for num in nums2:

            # Copy current nums2 element into nums1
            nums1[index] = num

            # Move index forward
            index += 1

        # Sort nums1 in-place
        nums1.sort()
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O((m + n) log(m + n))` | Because sorting the final array takes `O((m+n)log(m+n))`. |
| **Space** | `O(1)` or `O(m+n)` | Depending on sorting implementation. |

This is easy, but it does not use the fact that both arrays are already sorted.

## 6. Better Solution: Extra Array Merge

### Intuition

Use two pointers from the front.

One pointer reads `nums1`.

One pointer reads `nums2`.

Whichever value is smaller gets added to a temporary result array.

### Approach

Use:

```text
i = 0 for nums1
j = 0 for nums2
```

Compare:

```text
nums1[i] and nums2[j]
```

Add the smaller one into `merged`.

After one array finishes, add remaining elements from the other array.

Finally copy `merged` back to `nums1`.

### Dry Run

```text
nums1 real = [1, 2, 3]
nums2      = [2, 5, 6]
```

Initial:

```text
i = 0
j = 0
merged = []
```

| nums1[i] | nums2[j] | Pick | merged |
|:---:|:---:|:---:|:---:|
| 1 | 2 | 1 | [1] |
| 2 | 2 | 2 from nums1 | [1, 2] |
| 3 | 2 | 2 from nums2 | [1, 2, 2] |
| 3 | 5 | 3 | [1, 2, 2, 3] |

Now `nums1` real part is finished.

Add remaining `nums2`:

```text
[5, 6]
```

Final:

```text
merged = [1, 2, 2, 3, 5, 6]
```

Copy to `nums1`.

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:

        # Pointer for valid elements of nums1
        i = 0

        # Pointer for nums2
        j = 0

        # Temporary array to store merged result
        merged = []

        # Merge while both arrays have elements left
        while i < m and j < n:

            # If nums1 current element is smaller or equal
            if nums1[i] <= nums2[j]:

                # Add nums1 element to merged array
                merged.append(nums1[i])

                # Move nums1 pointer forward
                i += 1

            # Otherwise nums2 current element is smaller
            else:

                # Add nums2 element to merged array
                merged.append(nums2[j])

                # Move nums2 pointer forward
                j += 1

        # Add remaining valid nums1 elements
        while i < m:

            # Append current nums1 element
            merged.append(nums1[i])

            # Move nums1 pointer
            i += 1

        # Add remaining nums2 elements
        while j < n:

            # Append current nums2 element
            merged.append(nums2[j])

            # Move nums2 pointer
            j += 1

        # Copy merged result back into nums1
        for index in range(m + n):

            # Update nums1 in-place
            nums1[index] = merged[index]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(m + n)` | Because each element is processed once. |
| **Space** | `O(m + n)` | Because we use a temporary `merged` array. |

## 7. Most Optimal Solution: Merge From Back

### Core Intuition

`nums1` already has empty space at the end.

So instead of filling from the front, we fill from the back.

Why?

Because the largest elements should go to the end.

Example:

```text
nums1 = [1, 2, 3, 0, 0, 0]
nums2 = [2, 5, 6]
```

The biggest element among both arrays is 6.

It should go to the last position.

The next biggest is 5.

It should go to the second last position.

So we compare from the back and place the larger value at the end.

### Pointers Used

```text
i = m - 1
```

Points to last real element of `nums1`.

```text
j = n - 1
```

Points to last element of `nums2`.

```text
k = m + n - 1
```

Points to last position of `nums1`, where final value should be placed.

### Main Logic

Compare:

```text
nums1[i] and nums2[j]
```

The larger value goes to:

```text
nums1[k]
```

Then move the corresponding pointer backward.

## 9. Why We Only Need to Copy Remaining nums2

At the end, there are two possibilities.

### Case 1: nums2 still has elements

Example:

```text
nums1 = [4, 5, 6, 0, 0, 0]
nums2 = [1, 2, 3]
```

After placing bigger elements, some `nums2` elements may remain.

Those must be copied to the front.

### Case 2: nums1 still has elements

Example:

```text
nums1 = [1, 2, 3, 0, 0, 0]
nums2 = [4, 5, 6]
```

If `nums1` elements remain, they are already in their correct place.

No need to copy them.

That is why final loop only needs:

```text
while j >= 0:
    nums1[k] = nums2[j]
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:

        # Pointer for the last valid element in nums1
        i = m - 1

        # Pointer for the last element in nums2
        j = n - 1

        # Pointer for the last position in nums1
        k = m + n - 1

        # Merge from the back while both arrays have elements left
        while i >= 0 and j >= 0:

            # If nums1 has the larger current element
            if nums1[i] > nums2[j]:

                # Put nums1's current element at the final position
                nums1[k] = nums1[i]

                # Move nums1 pointer backward
                i -= 1

            # If nums2 has the larger or equal current element
            else:

                # Put nums2's current element at the final position
                nums1[k] = nums2[j]

                # Move nums2 pointer backward
                j -= 1

            # Move final write pointer backward
            k -= 1

        # Copy remaining nums2 elements, if any
        while j >= 0:

            # Put remaining nums2 element into nums1
            nums1[k] = nums2[j]

            # Move nums2 pointer backward
            j -= 1

            # Move final write pointer backward
            k -= 1
```

## 10. Complexity of Most Optimal Solution

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(m + n)` | Because each element is processed at most once. |
| **Space** | `O(1)` | Because no extra array is used. |

## 11. Edge Cases

### Case 1: nums2 is empty

```text
nums1 = [1]
m = 1

nums2 = []
n = 0
```

Output:

```text
[1]
```

Our code:

```text
j = -1
```

The loops do not run.

Correct.

### Case 2: nums1 has no valid elements

```text
nums1 = [0]
m = 0

nums2 = [1]
n = 1
```

Output:

```text
[1]
```

Our code:

```text
i = -1
j = 0
k = 0
```

Main loop does not run because `i < 0`.

Remaining `nums2` loop copies 1 into `nums1`.

Correct.

### Case 3: nums1 values are all smaller

```text
nums1 = [1, 2, 3, 0, 0, 0]
nums2 = [4, 5, 6]
```

Output:

```text
[1, 2, 3, 4, 5, 6]
```

The code places 6, 5, 4 at the end.

Remaining `nums1` values are already in correct place.

### Case 4: nums2 values are all smaller

```text
nums1 = [4, 5, 6, 0, 0, 0]
nums2 = [1, 2, 3]
```

Output:

```text
[1, 2, 3, 4, 5, 6]
```

The code moves 6, 5, 4 to the back and then copies 3, 2, 1 to the front.

## 12. Interview Explanation

> Since both arrays are sorted and `nums1` has extra space at the end, I merge from the back. I keep three pointers: one at the last valid element of `nums1`, one at the last element of `nums2`, and one at the last index of `nums1`. I compare the two largest available elements and place the larger one at the back. This avoids overwriting useful values in `nums1`. If any elements remain in `nums2`, I copy them. Remaining `nums1` elements are already in correct position. This gives `O(m+n)` time and `O(1)` extra space.
