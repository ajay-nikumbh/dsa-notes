# 01. Largest in Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Basic** | Linear Scan | [Largest Element in Array](https://www.geeksforgeeks.org/problems/largest-element-in-array4009/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given an array `arr[]`. The task is to find the largest element and return it.

### Examples

```text
Input:  arr[] = [1, 8, 7, 56, 90]
Output: 90
Explanation: The largest element of the given array is 90.
```

```text
Input:  arr[] = [5, 5, 5, 5]
Output: 5
Explanation: The largest element of the given array is 5.
```

```text
Input:  arr[] = [10]
Output: 10
Explanation: There is only one element which is the largest.
```

### Constraints

- `1 <= arr.size() <= 10^6`
- `0 <= arr[i] <= 10^6`

## 2. Core Theory

This problem is the simplest instance of a **running aggregate (fold) over a linear scan**. You keep one accumulator that holds the answer for the prefix of the array seen so far, and update it as you walk forward. `max`, `min`, `sum`, `count`, and "longest run so far" are all the same shape.

The invariant is the whole proof: *after processing index `i`, `largest` equals the maximum of `nums[0..i]`*. It holds at the start (`largest = nums[0]`, a one-element prefix), and each step preserves it because `max(nums[0..i+1]) = max(max(nums[0..i]), nums[i+1])`. When the loop ends the prefix is the entire array, so `largest` is the answer.

Recognize the pattern when the answer is a single value that can be decided by looking at each element **once**, with no need to revisit earlier elements. If the update rule only needs the current element and the accumulator, one pass and `O(1)` space is enough — sorting is over-engineering.

| Fold | Accumulator init | Update rule |
|:---|:---:|:---|
| Maximum | `nums[0]` or `-inf` | `acc = x if x > acc else acc` |
| Minimum | `nums[0]` or `+inf` | `acc = x if x < acc else acc` |
| Sum | `0` | `acc += x` |
| Count of matches | `0` | `acc += 1 if cond(x)` |

The one prerequisite trap is **initialization**. Seeding with `0` silently assumes every value is non-negative. Seed with `nums[0]` (safe for any non-empty array) or with `float("-inf")` (the identity element for `max`), never with a hard-coded constant.

## 3. Problem Explanation

We are given an array of numbers.

We need to check all elements and find the maximum value.

```text
nums = [10, 5, 20, 8, 15]
```

Largest element means:

```text
20
```

Because:

```text
20 > 10
20 > 5
20 > 8
20 > 15
```

## 4. Important Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[5]` | `5` | Loop from index 1 never runs; the seed value must already be the answer. |
| All identical | `[4, 4, 4, 4]` | `4` | Strict `>` never fires, so `largest` must stay at its seed, not reset. |
| All negatives | `[-10, -3, -20, -7]` | `-3` | Initializing `largest = 0` would wrongly return `0`. |
| Duplicated maximum | `[7, 2, 7]` | `7` | Answer is a value, not an index, so ties are harmless. |
| Maximum at the end | `[1, 2, 3, 90]` | `90` | Catches an off-by-one loop that stops at `n - 1`. |
| Maximum at the front | `[90, 1, 2, 3]` | `90` | Catches a loop that wrongly starts at index 1 with a bad seed. |
| Empty array | `[]` | error / `None` | `nums[0]` raises `IndexError`; constraints forbid it, but say so aloud. |

```text
nums = [5]
Output = 5
```

Only one element, so that element is the largest.

```text
nums = [-10, -3, -20, -7]
Output = -3
```

For negative numbers, the largest means closest to zero.

```text
nums = [4, 4, 4, 4]
Output = 4
```

All elements are same, so largest is 4.

## 5. Brute Force Solution

### Intuition

For every element, check whether there is any other element greater than it.

If no greater element exists, then that element is the largest.

### Approach

For each element `nums[i]`:

1. Assume it is the largest.
2. Compare it with every other element.
3. If any element is greater, then it is not the largest.
4. If after checking all elements no greater element is found, return it.

### Dry Run

```text
nums = [10, 5, 20, 8]
```

Check 10:

```text
20 > 10
So 10 is not largest.
```

Check 5:

```text
10 > 5
So 5 is not largest.
```

Check 20:

```text
No element greater than 20.
So 20 is largest.
```

Answer:

```text
20
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def largest(self, nums):

        # Get the size of the array
        n = len(nums)

        # Traverse every element one by one
        for i in range(n):

            # Assume current element is the largest
            is_largest = True

            # Compare current element with every other element
            for j in range(n):

                # If any element is greater than current element
                if nums[j] > nums[i]:

                    # Then current element cannot be the largest
                    is_largest = False

                    # No need to check further for this element
                    break

            # If no greater element was found
            if is_largest:

                # Return current element as the largest
                return nums[i]

        # This line is only for safety
        return -1
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Because for every element, we may compare with every other element. |
| **Space** | `O(1)` | Because we are not using any extra data structure. |

## 6. Better Solution Using Sorting

### Intuition

If we sort the array in increasing order, the largest element will always be at the last index.

### Approach

1. Sort the array.
2. Return the last element.

### Dry Run

```text
nums = [10, 5, 20, 8, 15]
```

After sorting:

```text
[5, 8, 10, 15, 20]
```

Last element:

```text
20
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def largest(self, nums):

        # Sort the array in ascending order
        nums.sort()

        # Return the last element because it is the largest
        return nums[-1]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Because sorting takes `O(n log n)` time. |
| **Space** | `O(1)` or `O(n)` | In Python, sorting uses internal memory, so practically it can take extra space depending on implementation details. |

## 7. Most Optimal Solution: Single Traversal

### Intuition

We do not need to compare every element with every other element.

We can simply keep track of the largest element seen so far.

Start with the first element as the largest.

Then traverse the array:

```text
If current element > largest_so_far,
update largest_so_far.
```

### Approach

1. Store first element as `largest`.
2. Traverse from index 1 to end.
3. If current element is greater than `largest`, update `largest`.
4. Return `largest`.

### Working Example

```text
nums = [10, 5, 20, 8, 15]
```

Initial:

```text
largest = 10
```

Now traverse:

```text
Current = 5
5 > 10? No
largest = 10
```

```text
Current = 20
20 > 10? Yes
largest = 20
```

```text
Current = 8
8 > 20? No
largest = 20
```

```text
Current = 15
15 > 20? No
largest = 20
```

Final answer:

```text
20
```

### Code

```python
# Define the class solution
class Solution:

    # Define the method
    def largest(self, nums):

        # Initialize largest with the first element of the array
        largest = nums[0]

        # Traverse the array starting from the second element
        for i in range(1, len(nums)):

            # If the current element is greater than the largest found so far
            if nums[i] > largest:

                # Update largest with the current element
                largest = nums[i]

        # Return the largest element after checking all elements
        return largest
```

## 8. Complexity of Most Optimal Solution

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array only once. |
| **Space** | `O(1)` | Because we use only one variable `largest`. |

## 9. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| `largest = 0` instead of `nums[0]` | Every element of an all-negative array fails `x > 0`, so `0` is returned even though it is not in the array. | Seed with `nums[0]`, or with `float("-inf")`. |
| `for i in range(1, len(nums) - 1)` | Skips the last element, so `[1, 2, 3, 90]` returns `3`. | `range(1, len(nums))` — `range` already excludes the stop value. |
| Returning the index `i` instead of `nums[i]` | The problem asks for the value; `[1, 8, 7, 56, 90]` would return `4`. | Track and return the value, or return `nums[best_index]`. |
| Using `>=` and reassigning inside an `else` branch | Harmless for max, but people often pair it with a "count of maxima" that then double-counts ties. | Use strict `>` so equal values never trigger an update. |
| Calling `nums.sort()` on the caller's list | Mutates the input in place; a later caller sees a reordered array. | Use `sorted(nums)`, or the one-pass scan which touches nothing. |
| Not guarding `nums[0]` on an empty array | `IndexError` at runtime. | Check `if not nums: return None` when constraints allow size `0`. |

## 10. Interview Follow-ups

**Q: What if the array does not fit in memory and arrives as a stream?**

A: Nothing changes. The scan is already a fold with `O(1)` state, so I consume the stream element by element, keep one `largest` variable, and never store the data. This is why streaming maximum is trivial while streaming median is hard.

**Q: What if I asked for the k-th largest instead of the largest?**

A: For small `k` I keep a min-heap of size `k`: push each element, pop when the heap exceeds `k`, and the heap root is the answer — `O(n log k)` time, `O(k)` space. For arbitrary `k` on an in-memory array, Quickselect gives `O(n)` average time.

**Q: Can you find the largest and the smallest in fewer than `2n` comparisons?**

A: Yes. Process elements in pairs: compare the two against each other first (1 comparison), then only the smaller against `min` and the larger against `max` (2 more). That is 3 comparisons per 2 elements, so about `1.5n` instead of `2n`.

**Q: Can this be parallelized?**

A: Yes, because `max` is associative and commutative. Split the array into chunks, take each chunk's max independently, then reduce the chunk maxima. Any fold with those two properties parallelizes the same way.

**Q: What if you needed the index of the largest element, and there are ties?**

A: Track `best_index` alongside the value. Strict `>` keeps the **first** occurrence; switching to `>=` keeps the **last**. I would confirm with the interviewer which tie-break they want.

## 11. Interview Explanation

> I will keep one variable called `largest`, initialized with the first element of the array. Then I will scan the array from left to right. Whenever I find an element greater than `largest`, I update it. At the end of the scan, `largest` will contain the maximum element. This takes linear time and constant space.

# Define the function to find the largest element
def largest(nums):
    # Guard against an empty array
    if not nums:
        return None
    # Initialize best with the first element of the array
    best = nums[0]
    # Traverse the array starting from the second element
    for i in range(1, len(nums)):
        # If the current element is greater than the best found so far
        if nums[i] > best:
            # Update best with the current element
            best = nums[i]
    # Return the largest element after checking all elements
    return best
