# 07. 485. Max Consecutive Ones

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Single Pass Counting | [485. Max Consecutive Ones](https://leetcode.com/problems/max-consecutive-ones/) | `O(n)` | `O(1)` |

## 1. Problem Statement

Given a binary array `nums`, return *the maximum number of consecutive* `1`*'s in the array*.

### Examples

```text
Example 1:
Input: nums = [1,1,0,1,1,1]
Output: 3
Explanation: The first two digits or the last three digits are consecutive 1s. The maximum number of consecutive 1s is 3.

Example 2:
Input: nums = [1,0,1,1,0,1]
Output: 2
```

### Constraints

- `1 <= nums.length <= 10^5`
- `nums[i]` is either `0` or `1`.

## 2. Core Theory

This is the simplest member of a large family: **running-state scan with a reset condition**. You sweep the array once, carrying a small amount of state that describes the run you are currently inside, and you carry a second variable holding the best run seen so far. An element either *extends* the current run or *terminates* it. That is the whole technique.

The reason one pass suffices is an invariant worth saying out loud: after processing index `i`, `current_count` equals the length of the maximal run of `1`s that **ends exactly at** `i` (zero if `nums[i] == 0`), and `max_count` equals the length of the longest run **anywhere in** `nums[0..i]`. Every run in the array ends at *some* index, so if you evaluate the candidate at every index, no run can escape being considered. This is why you never need to restart from earlier positions — the brute force's outer loop is pure redundancy.

| Element | Meaning for the run | State update |
|:---:|:---|:---|
| `1` | Extends the current run by one | `current_count += 1` |
| `0` | Terminates the run; a new one may start after | `current_count = 0` |

There are two equally valid places to fold `current_count` into `max_count`, and they differ in a way that trips people up:

```text
Update-on-every-1        Update-on-reset
-----------------        ---------------
see 1 -> count += 1      see 1 -> count += 1
         max = max(...)  see 0 -> max = max(...)
see 0 -> count = 0                count = 0
                         AFTER LOOP -> max = max(...)   <- mandatory
```

The second form needs a final update after the loop, because a run that reaches the last index is never terminated by a `0` and would otherwise go uncounted. The first form has no such trailing case, which makes it the safer default under interview pressure.

**How to recognize this pattern.** Whenever a problem asks for the longest/largest/count of a *contiguous* segment satisfying a local, memoryless predicate, a single pass with a reset works. The moment the predicate stops being memoryless — "longest run of `1`s if you may flip at most `k` zeros" (LeetCode 1004), or "longest subarray with at most two distinct values" — the reset becomes a *shrink*, and this pattern generalizes into the **sliding window**. Recognizing that Max Consecutive Ones is the `k = 0` special case of a sliding window is exactly the connection interviewers probe for.

## 4. Key Observation

A 1 increases the current streak.

A 0 breaks the current streak.

So while scanning the array:

```text
If nums[i] == 1:
    increase current count

If nums[i] == 0:
    reset current count to 0
```

We also need to keep track of the maximum streak found so far.

## 5. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element, a one | `[1]` | `1` | Smallest legal input; the run must be counted even though no `0` ever terminates it. |
| Single element, a zero | `[0]` | `0` | Answer is `0`, not `1` — `max_count` must start at `0`, never at `1`. |
| All ones | `[1,1,1,1]` | `4` | The run spans the whole array and never hits a reset; catches a missing post-loop update. |
| All zeros | `[0,0,0]` | `0` | No run exists at all; guards against returning a stale or uninitialised `current_count`. |
| Longest run at the start | `[1,1,0,1]` | `2` | A later, shorter run must not overwrite `max_count` — the update must be a `max`, not an assignment. |
| Longest run at the end | `[0,1,1,1]` | `3` | The classic bug: the trailing run is never closed by a `0`, so update-on-reset code loses it. |
| Two equal-length runs | `[1,1,0,1,1]` | `2` | Ties must not double-count or concatenate across the `0`. |
| Leading and trailing zeros | `[0,0,1,1,0,0]` | `2` | Resets before and after the run; verifies the counter truly clears. |
| Alternating | `[1,0,1,0,1]` | `1` | Every run has length `1`; a counter that fails to reset would wrongly report `3`. |

Note that negatives and duplicates are not concerns here: the constraints guarantee `nums[i]` is strictly `0` or `1`, so the only value classes are "extends" and "resets". The array is also guaranteed non-empty (`1 <= nums.length`), but returning `0` for `[]` falls out naturally from initialising both counters to `0`.

## 6. Brute Force Solution

### Intuition

Start from every index.

If that index has 1, count how many consecutive 1s start from there.

Take the maximum count.

### Approach

1. For every index `i`, start counting from `i`.
2. Move forward while elements are 1.
3. Stop when you find 0 or reach the end.
4. Update maximum length.

### Dry Run

```text
nums = [1, 1, 0, 1, 1, 1]
```

Start at index 0:

```text
1, 1 -> count = 2
```

Start at index 1:

```text
1 -> count = 1
```

Start at index 2:

```text
0 -> count = 0
```

Start at index 3:

```text
1, 1, 1 -> count = 3
```

Maximum:

```text
3
```

### Code

```python
# Define the class
class Solution:

    # Define the method
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:

        # Store the length of the array
        n = len(nums)

        # Store the maximum consecutive ones found so far
        max_count = 0

        # Try starting a consecutive sequence from every index
        for i in range(n):

            # Store current streak length starting from index i
            current_count = 0

            # Start checking from index i
            j = i

            # Continue while j is inside array and nums[j] is 1
            while j < n and nums[j] == 1:

                # Increase current streak count
                current_count += 1

                # Move to the next index
                j += 1

            # Update maximum streak if current streak is larger
            max_count = max(max_count, current_count)

        # Return the maximum consecutive ones found
        return max_count
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Because for every index, we may scan forward again. Example worst case: `nums = [1, 1, 1, 1, 1]` — from each index, we keep scanning many elements. |
| **Space** | `O(1)` | Because we only use variables. |

## 7. Better / Most Optimal Solution: Single Pass Counting

### Intuition

We do not need to start from every index.

We can scan once and maintain:

```text
current_count = current streak of consecutive 1s
max_count     = best streak found so far
```

When we see 1:

```text
current_count += 1
```

When we see 0:

```text
current_count = 0
```

At every step, update:

```text
max_count = max(max_count, current_count)
```

### Dry Run

```text
nums = [1, 1, 0, 1, 1, 1]
```

Initial:

```text
current_count = 0
max_count = 0
```

| i | nums[i] | Action | current_count | max_count |
|:---:|:---:|:---:|:---:|:---:|
| 0 | 1 | Increase streak | 1 | 1 |
| 1 | 1 | Increase streak | 2 | 2 |
| 2 | 0 | Reset streak | 0 | 2 |
| 3 | 1 | Increase streak | 1 | 2 |
| 4 | 1 | Increase streak | 2 | 2 |
| 5 | 1 | Increase streak | 3 | 3 |

Final answer:

```text
3
```

### Code

```python
# Define the class
class Solution:

    # Define the method
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:

        # Store the current consecutive ones count
        current_count = 0

        # Store the maximum consecutive ones count found so far
        max_count = 0

        # Traverse every number in the array
        for num in nums:

            # If current number is 1
            if num == 1:

                # Increase the current consecutive ones streak
                current_count += 1

                # Update maximum count if current streak is greater
                max_count = max(max_count, current_count)

            # If current number is 0
            else:

                # Reset current streak because consecutive ones are broken
                current_count = 0

        # Return the longest streak of consecutive ones
        return max_count
```

## 8. Common Mistakes

| Mistake | Why it breaks | Fix |
|:---|:---|:---|
| Updating `max_count` only inside the `else` branch, with no update after the loop | A run that reaches the final index is never terminated by a `0`, so it is never compared. `[0,1,1,1]` returns `0` instead of `3`. | Either update `max_count` on every `1`, or add `max_count = max(max_count, current_count)` after the loop. |
| Forgetting to reset `current_count` on a `0` | The counter simply becomes a total count of `1`s in the array. `[1,0,1,0,1]` returns `3` instead of `1`. | Set `current_count = 0` in the zero branch. |
| Writing `max_count = current_count` instead of `max_count = max(max_count, current_count)` | A later, shorter run overwrites a longer earlier one. `[1,1,0,1]` returns `1` instead of `2`. | Always take the maximum of the two. |
| Initialising `max_count = 1` "because there is at least one element" | The array may be all zeros, where the correct answer is `0`. `[0]` returns `1`. | Initialise both counters to `0`. |
| Resetting `max_count` along with `current_count` | Destroys the best-so-far record every time a `0` appears, leaving only the final run's length. | Only `current_count` is ever reset; `max_count` is monotonically non-decreasing. |
| Using `if nums[i]` / truthiness in a language where the array may hold other values | Fine for a strict binary array, but silently misclassifies any non-zero value as a `1` if the constraint is relaxed. | Compare explicitly: `if num == 1`. |

## 9. Complexity of Optimal Solution

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array only once. |
| **Space** | `O(1)` | Because we only use two variables. |

## 10. Slight Variation: Update Max Only When Zero Comes

This version is also valid.

### Intuition

Instead of updating `max_count` at every 1, we update it only when a 0 breaks the streak.

But then we must also update after the loop, because the longest streak may be at the end.

### Example Where Final Update Is Needed

```text
nums = [0, 1, 1, 1]
```

If we update max only when zero comes, then after the last 1, no zero comes.

So we must do:

```text
max_count = max(max_count, current_count)
```

after the loop.

### Code

```python
# Define the class
class Solution:

    # Define the method
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:

        # Store current streak of ones
        current_count = 0

        # Store best streak found so far
        max_count = 0

        # Traverse every element
        for num in nums:

            # If current number is 1
            if num == 1:

                # Increase current streak
                current_count += 1

            # If current number is 0
            else:

                # Update max before resetting current streak
                max_count = max(max_count, current_count)

                # Reset current streak
                current_count = 0

        # Update max one final time for streak ending at last index
        max_count = max(max_count, current_count)

        # Return maximum consecutive ones
        return max_count
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Because we traverse the array only once. |
| **Space** | `O(1)` | Because we only use two variables. |

## 11. Interview Follow-ups

**Q: What if you are allowed to flip at most `k` zeros to ones — now what is the longest run?**

A: This is LeetCode 1004, and it is the natural generalisation. The reset becomes a shrink: maintain a window `[left, right]` and a count of zeros inside it. Expand `right` one step at a time; whenever the zero count exceeds `k`, advance `left` until it drops back to `k`, decrementing the count as you pass over a zero. The answer is the largest `right - left + 1` seen. Still `O(n)` time and `O(1)` space, since each pointer only moves forward. The `k = 0` case degenerates exactly back to this problem.

**Q: The array arrives as a stream you can only read once and it does not fit in memory. Does your solution survive?**

A: Unchanged — that is the main strength of this approach. It is already a single forward pass holding exactly two integers, so it never needs random access or a second look at any element. You can feed it from a socket or a file iterator element by element. The only subtlety is that `max_count` is a valid answer *at every point*, so a streaming consumer can query the running maximum at any time rather than waiting for end-of-stream.

**Q: Instead of the length, return the start and end indices of the longest run.**

A: Carry two more variables. Track `run_start`, set to `i` whenever a run begins (that is, on a `1` when `current_count` was `0`). When `current_count` beats `max_count`, also record `best_start = run_start` and `best_end = i`. Ties are resolved in favour of the earlier run if you update strictly on `>`, or the later run if you update on `>=` — state which convention you are using, because interviewers do ask.

**Q: What if the array were huge and you had many cores — is this parallelisable?**

A: Yes, with a small amount of care, because the underlying operation is associative. Split the array into chunks and have each chunk compute a triple: the length of the run touching its left edge (prefix), the run touching its right edge (suffix), and the best run strictly inside. Merging two adjacent chunks takes the max of their interior bests and of `left.suffix + right.prefix`, which is exactly the run that straddles the boundary. That makes this a parallel-prefix / segment-tree-style reduction in `O(n / p + log p)`.

**Q: What if the array held arbitrary integers and you wanted the longest run of equal values, whatever they are?**

A: Replace the predicate `num == 1` with `num == previous`. Keep `current_count = 1` at the start of each new value and increment while consecutive elements match, resetting to `1` (not `0`) when the value changes. The reset-to-`1` is the trap: the differing element itself starts a new run of length one rather than no run at all.

## 12. Interview Explanation

You can say:

> I will scan the array once and maintain a running count of consecutive ones. Whenever I see a 1, I increment the count and update the answer. Whenever I see a 0, I reset the running count to zero because the consecutive sequence breaks. The maximum value seen during the scan is the answer. This gives `O(n)` time and `O(1)` space.

def brute(nums):
