# 04. 2381. Shifting Letters II

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Medium** | Difference Array (Range Update) | [2381. Shifting Letters II](https://leetcode.com/problems/shifting-letters-ii/) | `O(n + k)` | `O(n)` |

## 1. Problem Statement

You get a string `s` of lowercase letters and a list `shifts`.

Each `shifts[i] = [start, end, direction]`:

- `direction = 1`: shift every letter from `start` to `end` **forward** by one (`'a' -> 'b'`, `'z' -> 'a'`).
- `direction = 0`: shift every letter from `start` to `end` **backward** by one (`'b' -> 'a'`, `'a' -> 'z'`).

Return the final string after all shifts.

### Example

```text
s = "abc"
shifts = [[0, 1, 0], [1, 2, 1], [0, 2, 1]]

Start:              a  b  c
[0, 1, 0] back:     z  a  c
[1, 2, 1] forward:  z  b  d
[0, 2, 1] forward:  a  c  e

Output: "ace"
```

We use this same example in every section below.

### Constraints

- `1 <= s.length, shifts.length <= 5 * 10^4`
- `shifts[i].length == 3`
- `0 <= start <= end < s.length`
- `0 <= direction <= 1`
- `s` has only lowercase English letters

## 2. Core Theory

### What the problem really asks

Each shift is "add `+1` or `-1` to a range of letters". At the end, each letter moves by the **total** of all shifts that cover it.

That total is a range update, so we use a difference array. (Pattern from scratch: [01. 370. Range Addition](./01.%20370.%20Range%20Addition.md).)

### Two small twists

1. **Turn direction into a number.** `1 -> +1`, `0 -> -1`. In code: `delta = 1 if direction == 1 else -1`.
2. **Wrap around the alphabet.** After we know the total shift for a letter, use `% 26`.

```text
letter index:  a=0  b=1  c=2 ... z=25

new = (old + total) % 26

'c' with total +2:  (2 + 2) % 26 = 4  -> 'e'
'a' with total -1:  (0 - 1) % 26 = 25 -> 'z'   (Python % is never negative)
```

### Why the order of shifts does not matter

- Every shift is just `+1` or `-1`.
- Adding numbers in any order gives the same total.
- So we can sum all shifts first and convert to a letter once, at the end.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Wrap forward | `"z", [[0,0,1]]` | `"a"` | `25 + 1 = 26 -> 0` |
| Wrap backward | `"a", [[0,0,0]]` | `"z"` | `0 - 1 = -1 -> 25` with Python `%` |
| Shifts cancel | `"ab", [[0,1,1],[0,1,0]]` | `"ab"` | Total `0` for every letter |
| Big total | `"a"`, 27 forward shifts on `[0,0]` | `"b"` | `27 % 26 = 1` |
| Range to the end | `"abc", [[0,2,1]]` | `"bcd"` | Stop mark goes in the extra cell |

## 4. Brute Force: Shift Every Letter Every Time

### Idea

Keep letters as numbers `0..25`. For each shift, walk the range and add `+1` or `-1` with `% 26`.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: apply each shift to every letter in its range
class SolutionBrute:

    # Main method
    def shiftingLetters(self, s: str, shifts: List[List[int]]) -> str:

        # Letters as numbers 0..25
        vals = [ord(c) - ord('a') for c in s]

        # Apply each shift
        for start, end, direction in shifts:

            # +1 for forward, -1 for backward
            delta = 1 if direction == 1 else -1

            # Walk the range
            for i in range(start, end + 1):

                # Move this letter, wrapping around
                vals[i] = (vals[i] + delta) % 26

        # Turn numbers back into letters
        return "".join(chr(v + ord('a')) for v in vals)
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n * k)` | Each of `k` shifts can cover `n` letters |
| **Space** | `O(n)` | The `vals` list |

## 5. Optimal Approach: Difference Array

### Idea

1. `diff` of size `n + 1`.
2. For each shift: `delta = +1 or -1`. `diff[start] += delta`, `diff[end + 1] -= delta`.
3. Walk left to right with a running sum. For letter `i`, new letter = `(old + running) % 26`.

### Visual Walkthrough (Story Version)

Before the arrays, let us see the idea as a story.

**The story:** three kids stand in a row holding letter cards `a`, `b`, `c`. Each card can turn like a wheel with 26 letters on it. A teacher gives commands like "kids 0 to 1, turn **back** one click" or "kids 1 to 2, turn **forward** one click". Instead of shouting to each kid every time, the teacher puts **tokens** on the floor: a `+1` or `-1` token where a command starts, and the opposite token right after where it ends. Then the teacher walks the row once, picks up the tokens one by one, and tells each kid their total number of clicks.

**The rules:**

- Command `[start, end, dir]`: put `delta` at `start`, put `-delta` at `end + 1`. (`delta = +1` forward, `-1` back.)
- On the walk, the teacher's hand total = previous total + the token on this spot.
- Each kid turns their wheel by the hand total. Past `z` goes back to `a`, before `a` goes to `z`.

**How to read the pictures:** `[ ]` = tokens on the floor at each spot (spot 3 is just past the row). `^` = where a token was just put, or where the teacher stands.

**Start: no tokens**

```text
spot:    0    1    2    3
kids:    a    b    c
tokens: [0]  [0]  [0]  [0]
```

**Command 1: `[0, 1, 0]`** — kids 0 to 1, turn back.

- `delta = -1`. Put `-1` at spot 0, put `+1` at spot 2.

```text
spot:    0    1    2    3
tokens: [-1] [0]  [+1] [0]
         ^         ^
```

**Command 2: `[1, 2, 1]`** — kids 1 to 2, turn forward.

- `delta = +1`. Put `+1` at spot 1, put `-1` at spot 3.

```text
spot:    0    1    2    3
tokens: [-1] [+1] [+1] [-1]
              ^         ^
```

**Command 3: `[0, 2, 1]`** — kids 0 to 2, turn forward.

- `delta = +1`. Spot 0: `-1 + 1 = 0`. Spot 3: `-1 - 1 = -2`.

```text
spot:    0    1    2    3
tokens: [0]  [+1] [+1] [-2]
         ^              ^
```

**The teacher's walk**

```text
Kid 0: hand = 0 + 0 = 0     a turns 0 clicks -> a
tokens: [0]  [+1] [+1]
         ^
result:  a

Kid 1: hand = 0 + 1 = 1     b turns 1 click  -> c
tokens: [0]  [+1] [+1]
              ^
result:  a    c

Kid 2: hand = 1 + 1 = 2     c turns 2 clicks -> e
tokens: [0]  [+1] [+1]
                   ^
result:  a    c    e
```

Spot 3 is past the row and never walked. Answer: `"ace"`.

**All steps at a glance**

| Step | What happens | Tokens (`diff`) | Hand total | Result so far |
|:---:|:---|:---|:---:|:---|
| Cmd 1 | `-1` at 0, `+1` at 2 | `[-1, 0, 1, 0]` | – | – |
| Cmd 2 | `+1` at 1, `-1` at 3 | `[-1, 1, 1, -1]` | – | – |
| Cmd 3 | `+1` at 0, `-1` at 3 | `[0, 1, 1, -2]` | – | – |
| Kid 0 | `a + 0` | – | 0 | `a` |
| Kid 1 | `b + 1` | – | 1 | `ac` |
| Kid 2 | `c + 2` | – | 2 | `ace` |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Kid's letter wheel | `s[i]` as a number `0..25` |
| Forward / back command | `delta = +1` / `-1` |
| Token at the start | `diff[start] += delta` |
| Opposite token after the end | `diff[end + 1] -= delta` |
| Teacher's hand total | `running += diff[i]` |
| Wheel wraps around | `% 26` |

Now the same steps again, this time with the exact arrays.

### Step-by-Step Example

```text
s = "abc", n = 3
shifts = [[0, 1, 0], [1, 2, 1], [0, 2, 1]]
diff = [0, 0, 0, 0]   (size 4)
```

**Phase 1: mark the shifts**

| Shift | `delta` | `diff[start] += delta` | `diff[end + 1] -= delta` | `diff` after |
|:---:|:---:|:---|:---|:---|
| `[0, 1, 0]` | -1 | `diff[0] = 0 - 1 = -1` | `diff[2] = 0 + 1 = 1` | `[-1, 0, 1, 0]` |
| `[1, 2, 1]` | +1 | `diff[1] = 0 + 1 = 1` | `diff[3] = 0 - 1 = -1` | `[-1, 1, 1, -1]` |
| `[0, 2, 1]` | +1 | `diff[0] = -1 + 1 = 0` | `diff[3] = -1 - 1 = -2` | `[0, 1, 1, -2]` |

**Phase 2: running sum and letters**

| `i` | `s[i]` | old value | `diff[i]` | `running` | `(old + running) % 26` | new letter |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | `a` | 0 | 0 | 0 | 0 | `a` |
| 1 | `b` | 1 | 1 | 1 | 2 | `c` |
| 2 | `c` | 2 | 1 | 2 | 4 | `e` |

**Answer: `"ace"`.**

### Code

```python
# Optimal: difference array of shifts, then one pass with mod 26
class Solution:

    # Main method
    def shiftingLetters(self, s: str, shifts: List[List[int]]) -> str:

        # Length of the string
        n = len(s)

        # One extra cell for end + 1
        diff = [0] * (n + 1)

        # Mark every shift in O(1)
        for start, end, direction in shifts:

            # +1 for forward, -1 for backward
            delta = 1 if direction == 1 else -1

            # Shift starts here
            diff[start] += delta

            # Shift stops after end
            diff[end + 1] -= delta

        # Build the new letters here
        result = []

        # Total shift active at the current letter
        running = 0

        # Walk the letters in order
        for i in range(n):

            # Add this spot's mark
            running += diff[i]

            # Old letter as a number 0..25
            old = ord(s[i]) - ord('a')

            # Move by the total and wrap (Python % is never negative)
            new = (old + running) % 26

            # Turn it back into a letter
            result.append(chr(new + ord('a')))

        # Join the letters
        return "".join(result)


# Check the example from this note, step by step

# Shift [0, 2, 1]: delta +1, start mark

# Shift [0, 2, 1]: stop mark

# Running sum starts at 0

    assert chr((ord("abc"[i]) - 97 + run) % 26 + 97) == letter
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n + k)` | `O(1)` per shift, one pass over the string |
| **Space** | `O(n)` | `diff` and the result list |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Treating `direction = 0` as `0` | Backward shifts do nothing | Map `0 -> -1` |
| Using `% 26` on the running sum only and forgetting the letter | Wrong letters | `(old + running) % 26` |
| Negative mod in Java / C++ | `-1 % 26 = -1` there, so the letter breaks | Use `((x % 26) + 26) % 26` in those languages. Python is fine |
| `diff` of size `n` | `diff[end + 1]` crashes when `end = n - 1` | Size `n + 1` |
| Building the string with `+=` in a loop | Can be `O(n^2)` | Collect letters in a list, then `"".join` |

## 7. Interview Follow-ups

### Q1. How is this different from 848. Shifting Letters (the first version)?

**Answer:**
- In 848, shift `i` moves the first `i + 1` letters. Every range starts at `0`.
- So a suffix sum from the right is enough. No difference array needed.
- Here ranges can start anywhere, so we need start and stop marks.

### Q2. Can the running sum get too big?

**Answer:**
- At most `5 * 10^4` in either direction. Python handles it.
- In other languages it still fits in `int`. You can also take `% 26` as you go.

### Q3. What if a shift could move by `x` letters instead of 1?

**Answer:**
- Put `+x` and `-x` as the marks. Nothing else changes.

### Q4. What if we need the string after every shift, not only at the end?

**Answer:**
- A plain difference array would need a full pass each time.
- Use a Fenwick tree on the difference array: each shift is two point updates, each letter is a prefix query, both `O(log n)`.

### Q5. Why can we combine all shifts before applying the alphabet wrap?

**Answer:**
- Shifting is adding, and adding then taking `% 26` gives the same result as taking `% 26` after every add.
- So one `% 26` at the end per letter is enough.

## 8. Interview Explanation

> Every shift adds plus 1 or minus 1 to a range of letters, so the final letter only depends on the total shift covering it. I use a difference array of size n plus 1: for each shift I turn the direction into plus or minus 1, add it at start, and subtract it at end plus 1. Then I walk the string once with a running sum, and each letter becomes (old plus running) mod 26. Python's mod is never negative, so backward wraps work. That is O(n plus k) time and O(n) space instead of O(n times k).
