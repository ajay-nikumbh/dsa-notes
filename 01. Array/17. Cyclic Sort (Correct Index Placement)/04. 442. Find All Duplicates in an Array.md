# 04. 442. Find All Duplicates in an Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Medium** | Cyclic Sort (Correct Index Placement) | [442. Find All Duplicates in an Array](https://leetcode.com/problems/find-all-duplicates-in-an-array/) | `O(n)` | `O(1)` extra |

## 1. Problem Statement

You get an array `nums` of length `n`. Every value is in the range `1` to `n`.

Each value appears **once or twice**.

Return all values that appear twice, in any order.

You must use `O(n)` time and only constant extra space (the output does not count).

### Example

```text
nums = [5, 1, 4, 1, 4]
n = 5

1 appears twice
4 appears twice
5 appears once

Output: [1, 4]
```

We use this same example in every section below.

### Constraints

- `n == nums.length`
- `1 <= n <= 10^5`
- `1 <= nums[i] <= n`
- Each element appears once or twice

## 2. Core Theory

### What the problem really asks

"Which values have a second copy?"

### Why Cyclic Sort fits

Values `1..n`, so value `v` lives at **index `v - 1`**. (Pattern from scratch: [01. 268. Missing Number (Cyclic Sort)](./01.%20268.%20Missing%20Number%20%28Cyclic%20Sort%29.md).)

- Swap each value home, skipping when the home already holds `v`.
- After that, the first copy of every value is at home.
- The second copy of a duplicate cannot go home. It ends up in a spot whose owner never came.
- So **every index `i` with `nums[i] != i + 1` holds a duplicate value**.

```text
After placing:

index:   0   1   2   3   4
want:   [1] [2] [3] [4] [5]
got:    [1] [1] [4] [4] [5]
             ^   ^
       second copies: 1 and 4
```

### Why we never report the same value twice

- A value appears at most twice.
- One copy is at home. Only one copy can be "wrong".
- So each wrong spot gives a **different** duplicate. No dedup step is needed.

### Same sort, different reading

| Problem | After the sort we read... |
|:---|:---|
| [448. Disappeared](./03.%20448.%20Find%20All%20Numbers%20Disappeared%20in%20an%20Array.md) | the **index** `i + 1` of each wrong spot |
| **442. Duplicates** | the **value** `nums[i]` of each wrong spot |
| [645. Set Mismatch](./02.%20645.%20Set%20Mismatch.md) | both, for the single wrong spot |

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| No duplicates | `[1]` | `[]` | Nothing wrong after the sort |
| Smallest duplicate | `[1, 1]` | `[1]` | Second copy sits at index `1` |
| Every value doubled | `[2, 1, 2, 1]` | `[1, 2]` | Half the spots are wrong |
| Duplicate is `n` | `[3, 3, 1]` | `[3]` | Home is the last index |
| Already a permutation | `[3, 1, 2]` | `[]` | All spots right after the sort |

## 4. Brute Force: Count Every Value

### Idea

For each `x` in `1..n`, count it. If the count is `2`, add it.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: count each candidate with a full scan
class SolutionBrute:

    # Main method
    def findDuplicates(self, nums: List[int]) -> List[int]:

        # Collect duplicates here
        result = []

        # Try every value 1..n
        for x in range(1, len(nums) + 1):

            # Full scan to count x
            if nums.count(x) == 2:

                # x appears twice
                result.append(x)

        # Return all duplicates
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | `n` values, each counted with a full scan |
| **Space** | `O(1)` extra | Only the output |

## 5. Better Approach: Seen Set

### Idea

Walk once. If a value is already in the set, it is a duplicate. Otherwise add it.

### Code

```python
# Better: remember what we have seen
class SolutionBetter:

    # Main method
    def findDuplicates(self, nums: List[int]) -> List[int]:

        # Values seen so far
        seen = set()

        # Collect duplicates here
        result = []

        # Walk every value
        for v in nums:

            # Second time we meet v
            if v in seen:

                # v is a duplicate
                result.append(v)

            # First time we meet v
            else:

                # Remember it
                seen.add(v)

        # Return all duplicates
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass |
| **Space** | `O(n)` | The set |

## 6. Optimal Approach: Cyclic Sort

### Idea

1. Swap each value `v` to index `v - 1`, unless that index already holds `v`.
2. Scan. Every index with `nums[i] != i + 1` holds a duplicate: add `nums[i]`.

### Visual Walkthrough (Story Version)

Before the arrays, let us see the idea as a story.

**The story:** a hotel has 5 rooms, numbered `1` to `5`. Guests arrive with room cards. Some cards were printed twice, so two guests share a card number. The manager walks along the hall and moves each guest into the room on their card. Twins (same card) cannot both fit. The second twin waits in an empty room.

**The rules:**

- The manager stands at one room.
- If the guest there belongs to another room, and that room does not already have a guest with the same card, swap the two guests.
- After a swap, the manager stays, because a new guest arrived.
- If the right room already has the same card, this guest is a twin. Leave them and walk on.
- At the end, every guest in the wrong room is a twin.

**How to read the pictures:** room number on top, guest's card in `[ ]`. `^` = manager. `*` = guest in own room.

Now the same steps again, this time with the exact arrays.

### Step-by-Step Example

```text
nums = [5, 1, 4, 1, 4], n = 5
```

**Phase 1: place values**

| Step | `i` | `v = nums[i]` | `nums[v - 1]` | `== v`? | Action | `nums` after |
|:---:|:---:|:---:|:---:|:---:|:---|:---|
| 1 | 0 | 5 | `nums[4] = 4` | No | swap index 0 and 4 | `[4, 1, 4, 1, 5]` |
| 2 | 0 | 4 | `nums[3] = 1` | No | swap index 0 and 3 | `[1, 1, 4, 4, 5]` |
| 3 | 0 | 1 | `nums[0] = 1` | Yes | `i = 1` | `[1, 1, 4, 4, 5]` |
| 4 | 1 | 1 | `nums[0] = 1` | Yes | `i = 2` | `[1, 1, 4, 4, 5]` |
| 5 | 2 | 4 | `nums[3] = 4` | Yes | `i = 3` | `[1, 1, 4, 4, 5]` |
| 6 | 3 | 4 | `nums[3] = 4` | Yes | `i = 4` | `[1, 1, 4, 4, 5]` |
| 7 | 4 | 5 | `nums[4] = 5` | Yes | `i = 5` | `[1, 1, 4, 4, 5]` |

`i = 5` is not `< 5`. Loop stops. 2 swaps.

**Phase 2: scan**

| `i` | `nums[i]` | `i + 1` | Match? | `result` |
|:---:|:---:|:---:|:---:|:---|
| 0 | 1 | 1 | Yes | `[]` |
| 1 | 1 | 2 | **No** | `[1]` |
| 2 | 4 | 3 | **No** | `[1, 4]` |
| 3 | 4 | 4 | Yes | `[1, 4]` |
| 4 | 5 | 5 | Yes | `[1, 4]` |

**Answer: `[1, 4]`.**

### Code

```python
# Optimal: cyclic sort, then read the values at wrong spots
class Solution:

    # Main method
    def findDuplicates(self, nums: List[int]) -> List[int]:

        # Number of elements
        n = len(nums)

        # Start at the first index
        i = 0

        # Place every value at index v - 1
        while i < n:

            # Value at the current spot
            v = nums[i]

            # Home does not hold v yet
            if nums[v - 1] != v:

                # Swap v home; stay at i
                nums[i], nums[v - 1] = nums[v - 1], nums[i]

            # Home already holds v
            else:

                # Move on
                i += 1

        # Collect duplicates here
        result = []

        # Check every spot
        for i in range(n):

            # A value sits in someone else's spot
            if nums[i] != i + 1:

                # It is the second copy of a duplicate
                result.append(nums[i])

        # Return all duplicates
        return result


# Check the example from this note, step by step
a = [5, 1, 4, 1, 4]

# Step 1: i = 0, value 5 goes to index 4
a[0], a[4] = a[4], a[0]
assert a == [4, 1, 4, 1, 5]

# Step 2: i = 0, value 4 goes to index 3
a[0], a[3] = a[3], a[0]
assert a == [1, 1, 4, 4, 5]

# Step 3 to 7: every home already holds its value, no more swaps
assert all(a[a[i] - 1] == a[i] for i in range(5))

# Scan: values at wrong spots
assert [a[i] for i in range(5) if a[i] != i + 1] == [1, 4]

# Full solution on the example
assert Solution().findDuplicates([5, 1, 4, 1, 4]) == [1, 4]

# LeetCode examples (any order is fine, so compare sorted)

assert Solution().findDuplicates([1, 1, 2]) == [1]

# Edge cases
assert Solution().findDuplicates([1, 1]) == [1]
assert sorted(Solution().findDuplicates([2, 1, 2, 1])) == [1, 2]
assert Solution().findDuplicates([3, 3, 1]) == [3]
assert Solution().findDuplicates([3, 1, 2]) == []

# All three approaches agree on random inputs
for _ in range(300):

    # Random size
    n = random.randint(1, 12)

    # Start from a random permutation of 1..n
    arr = random.sample(range(1, n + 1), n)

    # Turn some cells into copies of others (each value at most twice)
    for _ in range(random.randint(0, n // 2)):

        # Pick two positions
        a_pos, b_pos = random.randrange(n), random.randrange(n)

        # Copy only if that keeps every value at most twice
        if arr.count(arr[a_pos]) == 1 and arr.count(arr[b_pos]) == 1:

            # Make b a copy of a
            arr[b_pos] = arr[a_pos]

    # Brute force answer

```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | At most `n` swaps plus `n` moves of `i`, then one scan |
| **Space** | `O(1)` extra | In place. The output list is not counted |

## 7. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Swap check `nums[i] != i + 1` | Twins swap with each other forever | Check the home: `nums[v - 1] != v` |
| Returning `i + 1` instead of `nums[i]` | You get the missing numbers (problem 448) | Duplicates are the **values** at wrong spots |
| Adding a dedup step | Extra work, not needed | Each value appears at most twice, so each wrong spot is a new value |
| Using a set | Breaks the `O(1)` space rule | Cyclic sort or sign marking |
| Inline swap with `nums[nums[i] - 1]` | Python writes `nums[i]` first | Save `v` first |

## 8. Interview Follow-ups

### Q1. Is there a one-pass trick?

**Answer:**
- Yes, sign marking. For each `v`, look at `nums[abs(v) - 1]`.
- If it is already negative, `abs(v)` was seen before: it is a duplicate.
- Otherwise make it negative.
- One pass, `O(1)` extra space.

### Q2. What if a value could appear three or more times?

**Answer:**
- The cyclic sort still works, but one value could sit in several wrong spots.
- Then you need to dedup, for example by marking the home spot after reporting it once.

### Q3. What if values were `0..n-1` instead of `1..n`?

**Answer:**
- Home becomes index `v` instead of `v - 1`.
- Everything else is the same.

### Q4. Why is the output order fine?

**Answer:**
- LeetCode accepts any order.
- Our scan goes by index, so the order is by the missing slot, not by value. Sort it if the interviewer wants sorted output.

### Q5. Can you restore the input afterwards?

**Answer:**
- After cyclic sort, the original order is lost unless you saved a copy.
- With sign marking, you can flip all values back to positive at the end.

## 9. Interview Explanation

> Values are 1 to n, so value v belongs at index v minus 1. I cyclic sort: if the home of the current value does not already hold it, I swap it home and stay; otherwise I move on. After that, the first copy of every value is home, and each second copy is stuck in a spot whose owner never came. So I scan once and collect nums[i] wherever nums[i] is not i plus 1. Since a value appears at most twice, each wrong spot gives a new duplicate, no dedup needed. It is O(n) time because every swap places a value for good, and O(1) extra space.
