# 03. 1074. Number of Submatrices That Sum to Target

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Hard** | 2D Prefix Sum | [1074. Number of Submatrices That Sum to Target](https://leetcode.com/problems/number-of-submatrices-that-sum-to-target/) | `O(m² · n)` | `O(n)` |

## 1. Problem Statement

You get a grid `matrix` and a number `target`.

Return how many **non-empty submatrices** have a sum equal to `target`.

A submatrix is any rectangle of cells `x1 <= x <= x2`, `y1 <= y <= y2`. Two submatrices are different if any of their corners differ, even if they hold the same numbers.

### Example

```text
matrix = [[ 1, -1],
          [-1,  1]]
target = 0

All 9 submatrices of a 2 x 2 grid:
  single cells: 1, -1, -1, 1                -> none are 0
  row 0 (both cols): 1 + -1 = 0             -> yes
  row 1 (both cols): -1 + 1 = 0             -> yes
  col 0 (both rows): 1 + -1 = 0             -> yes
  col 1 (both rows): -1 + 1 = 0             -> yes
  whole grid: 1 - 1 - 1 + 1 = 0             -> yes

Output: 5
```

We use this same example in every section below.

### Constraints

- `1 <= matrix.length <= 100`
- `1 <= matrix[0].length <= 100`
- `-1000 <= matrix[i][j] <= 1000`
- `-10^8 <= target <= 10^8`

## 2. Core Theory

This note uses two earlier ideas:

- The 2D prefix grid from [01. 304. Range Sum Query 2D - Immutable](./01.%20304.%20Range%20Sum%20Query%202D%20-%20Immutable.md).
- "Count subarrays with sum `k`" from [03. 560. Subarray Sum Equals K](../08.%20Prefix%20Sum%20%2B%20HashMap/03.%20560.%20Subarray%20Sum%20Equals%20K.md).

### What the problem really asks

Count rectangles whose sum is `target`. A rectangle has 4 sides: top, bottom, left, right. Trying all four sides is `O(m² · n²)` rectangles. We want to cut one factor of `n`.

### The key trick: fix top and bottom, squash into 1D

If we **fix the top row and the bottom row**, every rectangle between them is just a choice of left and right column.

Add up each column between top and bottom. Now we have a 1D array `col`. A rectangle between those rows = a subarray of `col`.

```text
matrix:            top = 0, bottom = 1
  [ 1][-1]         squash each column:
  [-1][ 1]           col[0] = 1 + -1 = 0
                     col[1] = -1 + 1 = 0
                   col = [0, 0]

Rectangle rows 0..1, cols 0..0  <->  subarray col[0..0]
Rectangle rows 0..1, cols 0..1  <->  subarray col[0..1]
Rectangle rows 0..1, cols 1..1  <->  subarray col[1..1]
```

So for each (top, bottom) pair, the question becomes **"how many subarrays of `col` sum to `target`?"** That is problem 560, solved in `O(n)` with a running sum and a hash map:

```text
running sum s. For each new value: s += value
subarrays ending here with sum target = how many earlier prefix sums equal s - target
```

### Growing `col` cheaply

For a fixed `top`, move `bottom` down one row at a time. Each step just adds the new row into `col`. No need to rebuild it. (This `col` is a column-wise prefix sum, which is the 2D prefix idea in a lighter form.)

```mermaid
flowchart LR
    A["Pick top row"]:::a --> B["Move bottom down<br/>add row into col"]:::b
    B --> C["Run 560 on col<br/>running sum + hash map"]:::c
    C --> D["Add matches to count"]:::d
    D --> B

    classDef a fill:#1f2937,stroke:#6b7280,color:#e5e7eb
    classDef b fill:#1e3a5f,stroke:#3b82f6,color:#dbeafe
    classDef c fill:#78350f,stroke:#f59e0b,color:#fef3c7
    classDef d fill:#065f46,stroke:#10b981,color:#ecfdf5
```

Row pairs: `m · (m + 1) / 2`. Each costs `O(n)`. Total `O(m² · n)`.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| 1 x 1 grid, miss | `[[904]], target = 0` | `0` | Single cell not equal to target |
| 1 x 1 grid, hit | `[[5]], target = 5` | `1` | Smallest rectangle counts |
| Target 0 with zeros | `[[0,0],[0,0]], target = 0` | `9` | Every rectangle counts. The `{0: 1}` seed in the hash map is needed |
| Negatives | `[[1,-1],[-1,1]], target = 0` | `5` | Sliding window fails with negatives, the hash map does not |
| Single row | `[[1,2,3]], target = 3` | `2` | Becomes plain 560: `[1,2]` and `[3]` |
| Target never reached | `[[1,2],[3,4]], target = 100` | `0` | Count stays 0 |

## 4. Brute Force: Try Every Rectangle with a 2D Prefix Grid

### Idea

Build the 2D prefix grid `P` (from 304). Try every top, bottom, left, right. Each rectangle sum is `O(1)` with the four-corner rule.

### Code

```python
# Import List for type hints
from typing import List

# Import defaultdict for the hash map in the optimal solution
from collections import defaultdict


# Brute force: every rectangle, each summed in O(1)
class SolutionBrute:

    # Main method
    def numSubmatrixSumTarget(self, matrix: List[List[int]], target: int) -> int:

        # Number of rows
        m = len(matrix)

        # Number of columns
        n = len(matrix[0])

        # Prefix grid with a zero border
        P = [[0] * (n + 1) for _ in range(m + 1)]

        # Build the prefix grid
        for r in range(m):

            # Go through every column
            for c in range(n):

                # Cell + above + left - top-left
                P[r + 1][c + 1] = matrix[r][c] + P[r][c + 1] + P[r + 1][c] - P[r][c]

        # Number of rectangles found
        count = 0

        # Pick the top row
        for r1 in range(m):

            # Pick the bottom row
            for r2 in range(r1, m):

                # Pick the left column
                for c1 in range(n):

                    # Pick the right column
                    for c2 in range(c1, n):

                        # Four-corner rule for this rectangle
                        s = P[r2 + 1][c2 + 1] - P[r1][c2 + 1] - P[r2 + 1][c1] + P[r1][c1]

                        # Count it if it matches
                        if s == target:

                            # One more match
                            count += 1

        # Return the total
        return count
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(m² · n²)` | `100^4 = 10^8` rectangles in the worst case. Too slow in Python |
| **Space** | `O(m · n)` | The prefix grid |

## 5. Optimal Approach: Fix Two Rows + 560 on Column Sums

### Idea

1. For each `top` row, start `col = [0] * n`.
2. For each `bottom` from `top` down to `m - 1`:
   - Add row `bottom` into `col`.
   - Count subarrays of `col` with sum `target` using a running sum `s` and a hash map `seen` that starts as `{0: 1}`.
3. Add every count to the answer.

### Visual Walkthrough (Story Version)

**The story:** a toy shop has a 2 x 2 shelf of boxes. Each box has a number of coins: some boxes give coins (`+1`), some take coins away (`-1`). The shop owner asks: "How many rectangles of boxes have **exactly 0 coins** in total?"

The helper has a trick. She picks a **band of shelves** (a top shelf and a bottom shelf). She pours each column of the band into **one bucket**. Now there is a single line of buckets. Then she walks along the buckets with a **running total**, and keeps a **notebook** of every running total she has seen. If the current total minus the target is already in the notebook, those earlier spots start a rectangle with the right sum.

### Step-by-Step Example

```text
matrix = [[1, -1], [-1, 1]], target = 0, m = 2, n = 2
count = 0
```

**`top = 0`: `col = [0, 0]`**

**`bottom = 0`**

- Add row 0: `col[0] = 0 + 1 = 1`, `col[1] = 0 + -1 = -1`. `col = [1, -1]`.
- `seen = {0: 1}`, `s = 0`.
- `c = 0`: `s = 0 + 1 = 1`. `seen[1 - 0] = seen[1] = 0`. `count = 0`. Then `seen[1] = 1`. `seen = {0: 1, 1: 1}`.
- `c = 1`: `s = 1 + -1 = 0`. `seen[0] = 1`. `count = 0 + 1 = 1`. Then `seen[0] = 2`. `seen = {0: 2, 1: 1}`.

**`bottom = 1`**

- Add row 1: `col[0] = 1 + -1 = 0`, `col[1] = -1 + 1 = 0`. `col = [0, 0]`.
- `seen = {0: 1}`, `s = 0`.
- `c = 0`: `s = 0 + 0 = 0`. `seen[0] = 1`. `count = 1 + 1 = 2`. Then `seen[0] = 2`.
- `c = 1`: `s = 0 + 0 = 0`. `seen[0] = 2`. `count = 2 + 2 = 4`. Then `seen[0] = 3`.

**`top = 1`: `col = [0, 0]`**

**`bottom = 1`**

- Add row 1: `col[0] = 0 + -1 = -1`, `col[1] = 0 + 1 = 1`. `col = [-1, 1]`.
- `seen = {0: 1}`, `s = 0`.
- `c = 0`: `s = 0 + -1 = -1`. `seen[-1] = 0`. `count = 4`. Then `seen[-1] = 1`. `seen = {0: 1, -1: 1}`.
- `c = 1`: `s = -1 + 1 = 0`. `seen[0] = 1`. `count = 4 + 1 = 5`. Then `seen[0] = 2`. `seen = {0: 2, -1: 1}`.

**Done.** `count = 5`.

### Code

```python
# Optimal: fix two rows, then count subarrays of column sums (560)
class Solution:

    # Main method
    def numSubmatrixSumTarget(self, matrix: List[List[int]], target: int) -> int:

        # Number of rows
        m = len(matrix)

        # Number of columns
        n = len(matrix[0])

        # Total number of matching rectangles
        count = 0

        # Record (top, bottom, col, count) after each band, for the tests
        self.trace = []

        # Pick the top row
        for top in range(m):

            # Column sums between top and bottom, start empty
            col = [0] * n

            # Move the bottom row down one at a time
            for bottom in range(top, m):

                # Add the new bottom row into every column sum
                for c in range(n):

                    # Pour this cell into its column bucket
                    col[c] += matrix[bottom][c]

                # Notebook of prefix sums seen so far; the empty prefix has sum 0
                seen = defaultdict(int)

                # Count the empty prefix once
                seen[0] = 1

                # Running sum along the columns
                s = 0

                # Walk the columns left to right
                for c in range(n):

                    # Grow the running sum
                    s += col[c]

                    # Earlier prefixes with sum s - target start a matching rectangle
                    count += seen[s - target]

                    # Write the current running sum in the notebook
                    seen[s] += 1

                # Save the state after this band
                self.trace.append((top, bottom, col[:], count))

        # Return the total
        return count


# The example from this note
matrix = [[1, -1], [-1, 1]]

# Run the solution
sol = Solution()

# Get the answer
ans = sol.numSubmatrixSumTarget(matrix, 0)

# Band (0, 0): col = [1, -1], count = 1
assert sol.trace[0] == (0, 0, [1, -1], 1)

# Band (0, 1): col = [0, 0], count = 4
assert sol.trace[1] == (0, 1, [0, 0], 4)

# Band (1, 1): col = [-1, 1], count = 5
assert sol.trace[2] == (1, 1, [-1, 1], 5)

# Final answer
assert ans == 5

# LeetCode example 1
assert Solution().numSubmatrixSumTarget([[0, 1, 0], [1, 1, 1], [0, 1, 0]], 0) == 4

# LeetCode example 3
assert Solution().numSubmatrixSumTarget([[904]], 0) == 0

# Edge case: single cell equals target
assert Solution().numSubmatrixSumTarget([[5]], 5) == 1

# Edge case: all zeros, every rectangle counts
assert Solution().numSubmatrixSumTarget([[0, 0], [0, 0]], 0) == 9

# Edge case: single row
assert Solution().numSubmatrixSumTarget([[1, 2, 3]], 3) == 2

# Edge case: target never reached
assert Solution().numSubmatrixSumTarget([[1, 2], [3, 4]], 100) == 0

# Brute force agrees on the example
assert SolutionBrute().numSubmatrixSumTarget(matrix, 0) == 5

# Import random for comparison tests
import random

# Compare brute and optimal on random grids
for _ in range(300):

    # Random size
    m, n = random.randint(1, 5), random.randint(1, 5)

    # Random small values so matches are common
    g = [[random.randint(-2, 2) for _ in range(n)] for _ in range(m)]

    # Random target
    t = random.randint(-3, 3)

    # Both must agree
    assert SolutionBrute().numSubmatrixSumTarget(g, t) == Solution().numSubmatrixSumTarget(g, t)

# All checks passed
print("All tests passed")
```

|:---|:---:|:---|

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Forgetting `seen[0] = 1` | Misses rectangles that start at column 0 | Seed the map with the empty prefix |
| Not resetting `seen` for each band | Prefix sums from a different band mix in, wrong counts | New hash map for every `(top, bottom)` |
| Resetting `col` for each `bottom` | Loses the rows above, or costs `O(m)` extra per band | Reset `col` only when `top` changes; add one row per `bottom` |
| Adding to `seen` before checking | A prefix matches itself when `target = 0`, counts empty rectangles | Check `seen[s - target]` first, then `seen[s] += 1` |
| Using a sliding window | Breaks with negative numbers | Use the prefix sum + hash map method |

## 7. Interview Follow-ups

### Q1. What if there are many more rows than columns?

**Answer:**
- The cost is `O(min² · max)` if we fix pairs along the **smaller** side.
- If `m > n`, fix two columns instead and squash rows (or transpose the grid first).

### Q2. Why not use a sliding window on `col`?

**Answer:**
- A sliding window only works when all numbers are positive, so the sum grows as the window grows.
- Here values can be negative, so the sum can go up and down. The hash map handles any sign.

### Q3. How would you return the rectangles, not just the count?

**Answer:**
- Store a list of column indexes for each prefix sum instead of a count.
- Each match gives `(top, left + 1, bottom, right)`. Output can be very large, up to `O(m² · n²)`.

### Q4. What if the question was "largest sum rectangle no larger than k" (LeetCode 363)?

**Answer:**
- Same row-pair squash.
- Inside, keep the prefix sums in a sorted list and binary search for the smallest prefix `>= s - k`.
- Time becomes `O(m² · n log n)`.

### Q5. What if we only wanted the maximum sum rectangle?

**Answer:**
- Same row-pair squash, then run **Kadane's algorithm** on `col`.
- Time `O(m² · n)`.

## 8. Interview Explanation

> Trying all four sides of every rectangle is O(m² · n²). Instead, I fix the top row and the bottom row. For that band I keep an array col where col[c] is the sum of column c between those rows; moving the bottom row down just adds one row into col. Any rectangle in the band is now a subarray of col, so I count subarrays with sum target using the Subarray Sum Equals K trick: a running sum and a hash map of earlier prefix sums, seeded with {0: 1}. There are O(m²) bands and each costs O(n), so the total is O(m² · n) time and O(n) extra space.
