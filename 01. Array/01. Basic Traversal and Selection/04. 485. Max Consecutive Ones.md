# 04. 485. Max Consecutive Ones

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Single Pass Counting | [485. Max Consecutive Ones](https://leetcode.com/problems/max-consecutive-ones/) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get a binary array `nums` (only `0`s and `1`s).

Return the maximum number of `1`s that appear **next to each other** in a row.

### Example

```text
Input:  nums = [1, 1, 0, 1, 1, 1]
Output: 3

Why: there are two runs of 1s.
     [1, 1] at the start has length 2.
     [1, 1, 1] at the end has length 3.
     The longest is 3.
```

We use this same example in every section below.

### Constraints

- `1 <= nums.length <= 10^5`
- `nums[i]` is either `0` or `1`.

## 2. Core Theory

### What the problem really asks

Split the array at every `0`. Each piece is a run of `1`s. Return the length of the longest piece.

```text
nums:  [1][1][0][1][1][1]
        \__/     \_____/
       run = 2   run = 3     ->  answer 3
```

### Why one pass is enough

Keep two numbers:

- `count`: length of the run that **ends at the current index**.
- `best`: the longest run seen so far.

Each element does one of two things:

| Element | Meaning | Update |
|:---:|:---|:---|
| `1` | The run gets longer | `count += 1`, then `best = max(best, count)` |
| `0` | The run breaks | `count = 0` |

Every run ends at some index. We check `best` at every index. So no run can be missed.

### The same shape shows up often

- "Longest run of equal values" -> reset `count` to `1` when the value changes.
- "Longest run with at most `k` zeros" (LeetCode 1004) -> the reset becomes a sliding window.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| All zeros | `[0, 0, 0]` | `0` | `best` must start at `0` and never change |
| All ones | `[1, 1, 1, 1]` | `4` | No `0` ever comes. `best` must be updated on `1`s, not only on `0`s |
| Single `1` | `[1]` | `1` | Smallest non-zero answer |
| Single `0` | `[0]` | `0` | Smallest zero answer |
| Longest run at the end | `[1, 1, 0, 1, 1, 1]` | `3` | The last run has no `0` after it |
| Longest run at the start | `[1, 1, 1, 0, 1]` | `3` | `best` must keep the old value after a reset |
| Alternating | `[1, 0, 1, 0, 1]` | `1` | Many resets |

## 4. Brute Force: Start a Count at Every Index

### Idea

For each index `i`, count how many `1`s come in a row starting at `i`. Keep the biggest count.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: count a run from every start
class SolutionBrute:

    # Main method
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:

        # Number of elements
        n = len(nums)

        # Longest run found
        best = 0

        # Try every start index
        for i in range(n):

            # Length of the run starting at i
            count = 0

            # Walk right from i
            for j in range(i, n):

                # A zero ends this run
                if nums[j] == 0:

                    # Stop walking
                    break

                # One more 1 in the run
                count += 1

            # Keep the bigger run
            best = max(best, count)

        # Return the longest run
        return best
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | All ones: every start walks to the end |
| **Space** | `O(1)` | Two counters |

The same `1`s get counted again and again from different starts. That is the waste.

## 5. Optimal Approach: One Pass with a Running Count

### Idea

1. `count = 0`, `best = 0`.
2. For each `num`:
   - If `num == 1`: `count += 1`, then `best = max(best, count)`.
   - Else: `count = 0`.
3. Return `best`.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: one pass with a running count
class Solution:

    # Main method
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:

        # Length of the current run of 1s
        count = 0

        # Longest run seen so far
        best = 0

        # Look at every number once
        for num in nums:

            # A 1 makes the run longer
            if num == 1:

                # Add one to the current run
                count += 1

                # Save it if it is a new record
                best = max(best, count)

            # A 0 breaks the run
            else:

                # Start over
                count = 0

        # Return the longest run
        return best


# Helper that records (count, best) after every step, to check the trace
def trace_ones(nums):

    # Current run
    count = 0

    # Best run
    best = 0

    # States after each step
    states = []

    # Same loop as the solution
    for num in nums:

        # Run gets longer
        if num == 1:

            # Add one
            count += 1

            # Update the record
            best = max(best, count)

        # Run breaks
        else:

            # Reset
            count = 0

        # Save the state
        states.append((count, best))

    # Return every state
    return states
```

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Updating `best` only when a `0` comes | The last run is never saved. `[1, 1, 1]` returns `0` | Update on every `1`, or do one final `max(best, count)` after the loop |
| Forgetting to reset `count` on `0` | Runs merge across zeros. Our example returns `5` | Set `count = 0` on a `0` |
| Resetting `best` instead of `count` | The record is lost | Only `count` resets |
| Starting `best` at `1` | `[0, 0]` returns `1` | Start at `0` |
| Returning `count` | Gives the last run, not the longest | Return `best` |

## 7. Interview Follow-ups

### Q1. What if you may flip at most `k` zeros to ones?

**Answer:**
- This is LeetCode 1004. Use a sliding window `[left, right]`.
- Count zeros inside the window.
- If zeros go above `k`, move `left` right until they drop back to `k`.
- The answer is the biggest window size. Still `O(n)`.

### Q2. The data comes as a stream. Does this still work?

**Answer:**
- Yes. We keep only two numbers and never look back.
- `best` is correct at every moment, so you can ask for it any time.

### Q3. Return the start and end index of the longest run.

**Answer:**
- Track `run_start`: set it to `i` when a new run begins.
- When `count` beats `best`, save `best_start = run_start` and `best_end = i`.
- With `>` you keep the earliest longest run.

### Q4. What if the array has any numbers and you want the longest run of equal values?

**Answer:**
- Compare each number with the one before it.
- Same value: `count += 1`. Different value: `count = 1` (not `0`).
- The new value starts its own run of length one.

### Q5. Can this run in parallel?

**Answer:**
- Yes. Each chunk reports three numbers: run touching its left edge, run touching its right edge, best run inside.
- When joining two chunks, also try `left.right_edge + right.left_edge`.

## 8. Interview Explanation

> I scan the array once with two counters. `count` is the length of the run of 1s ending at the current index, and `best` is the longest run so far. On a 1, I add one to `count` and update `best`. On a 0, the run breaks, so I reset `count` to zero. I update `best` on every 1, so a run at the very end is not missed. This is O(n) time and O(1) space.
