# 13. 1920. Build Array from Permutation

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [1920. Build Array from Permutation](https://leetcode.com/problems/build-array-from-permutation/) | `O(n)` | `O(1)` extra |

## 1. Problem Statement

You get a **zero-based permutation** `nums`. That means it holds every number from `0` to `n - 1` exactly once.

Build an array `ans` of the same length where `ans[i] = nums[nums[i]]` for every `i`. Return `ans`.

### Example

```text
nums = [0, 2, 1, 5, 3, 4]

index:   0  1  2  3  4  5
nums:    0  2  1  5  3  4

ans[0] = nums[nums[0]] = nums[0] = 0
ans[1] = nums[nums[1]] = nums[2] = 1
ans[2] = nums[nums[2]] = nums[1] = 2
ans[3] = nums[nums[3]] = nums[5] = 4
ans[4] = nums[nums[4]] = nums[3] = 5
ans[5] = nums[nums[5]] = nums[4] = 3

Output: [0, 1, 2, 4, 5, 3]
```

We use this same example in every section below.

### Constraints

- `1 <= nums.length <= 1000`
- `0 <= nums[i] < nums.length`
- All values in `nums` are distinct

## 2. Core Theory

### What the problem really asks

Every cell holds an index. Follow that index **one jump** and read what is there.

```text
i = 3:   nums[3] = 5  --->  nums[5] = 4   so ans[3] = 4
```

### The easy way

Make a new array and fill it with `nums[nums[i]]`. That is `O(n)` time and `O(n)` extra space.

### The follow-up: no extra array

LeetCode asks: can you do it with `O(1)` extra space?

The problem: if we overwrite `nums[i]` early, a later index that jumps to `i` reads the **wrong** value.

The trick: **store two numbers in one cell**.

- Every value is less than `n`.
- So a cell can hold `old + n * new`.
- `cell % n` gives back the old value.
- `cell // n` gives back the new value.

```text
n = 6, old = 2, new = 1
cell = 2 + 6 * 1 = 8
8 % 6  = 2   (old value, still safe to read)
8 // 6 = 1   (new value, read at the end)
```

So we do two passes:

1. Pass 1: put the new value in the "top part" of every cell. Read old values with `% n`.
2. Pass 2: divide every cell by `n` to keep only the new value.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| One element | `[0]` | `[0]` | `nums[0] = 0`, jump goes to itself |
| Already sorted | `[0, 1, 2]` | `[0, 1, 2]` | Every jump lands on itself |
| Two swapped | `[1, 0]` | `[0, 1]` | Each jump lands on the other cell |
| Cell read after it was changed | `[5, 0, 1, 2, 3, 4]` | `[4, 5, 0, 1, 2, 3]` | Later cells read early cells that were already encoded. `% n` must be used |
| Biggest input | `n = 1000` | Works | Largest cell is `999 + 1000 * 999`, fine for Python ints |

## 4. Brute Force: New Array

### Idea

Make `ans` of size `n`. For each `i`, set `ans[i] = nums[nums[i]]`.

### Code

```python
# Import List for type hints
from typing import List


# Build the answer in a brand new array
class SolutionBrute:

    # Main method
    def buildArray(self, nums: List[int]) -> List[int]:

        # Number of elements
        n = len(nums)

        # Make an empty answer array
        ans = [0] * n

        # Go through every index
        for i in range(n):

            # Jump once and copy the value
            ans[i] = nums[nums[i]]

        # Return the new array
        return ans
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One loop over the array |
| **Space** | `O(n)` | The new `ans` array |

## 5. Optimal Approach: Two Values in One Cell

### Idea

1. Pass 1: for each `i`, do `nums[i] += n * (nums[nums[i]] % n)`.
2. Pass 2: for each `i`, do `nums[i] //= n`.
3. Return `nums`.

Why `nums[nums[i]] % n`? The cell at `nums[i]` may already be changed. `% n` always gives its **old** value.

Why can we use `nums[i]` as the index without `% n`? When we are at `i`, cell `i` has not been changed yet.

### Code

```python
# Import List for type hints
from typing import List


# Solution for 1920. Build Array from Permutation
class Solution:

    # Main method
    def buildArray(self, nums: List[int]) -> List[int]:

        # Number of elements
        n = len(nums)

        # Pass 1: go through every index
        for i in range(n):

            # Read the old value at the jump target and store it in the top part
            nums[i] += n * (nums[nums[i]] % n)

        # Pass 2: go through every index again
        for i in range(n):

            # Keep only the top part, which is the new value
            nums[i] //= n

        # Return the same array, now changed
        return nums
```

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Writing `nums[i] = nums[nums[i]]` in place | Later cells read values that were already replaced | Use a new array, or the two-values-in-one-cell trick |
| Forgetting `% n` on `nums[nums[i]]` | The jump target may be encoded already, so you read a huge number | Always read `nums[nums[i]] % n` |
| Encoding as `new + n * old` | Pass 2 then gives back the old value | Old value stays in the low part, new value goes in the top part |
| Doing `nums[i] % n` in pass 2 | Gives the old array back | Use `nums[i] // n` |

## 7. Interview Follow-ups

### Q1. Why does `old + n * new` work?

**Answer:**
- `old` is less than `n`, so it never spills into the top part.
- `% n` removes the top part and gives `old`.
- `// n` removes the low part and gives `new`.

### Q2. Can the trick overflow?

**Answer:**
- The biggest cell is about `n * n`. For `n = 1000` that is one million.
- Python ints never overflow.
- In Java or C++, `n * n` must fit in an `int`. For `n = 1000` it does.

### Q3. Why do we not need `% n` on the index `nums[i]`?

**Answer:**
- At step `i`, we only changed cells `0` to `i - 1`.
- Cell `i` is still its original value, so it is a valid index.

### Q4. Is the in-place version better in practice?

**Answer:**
- It saves memory, but it is harder to read and it changes the input.
- In real code, the new array is usually preferred.
- In an interview, show the simple one first, then the trick if asked.

### Q5. What if `nums` was not a permutation?

**Answer:**
- If every value is still in `0..n-1`, the same code works.
- The trick only needs every value to be less than `n`.

## 8. Interview Explanation

> Each answer cell is just one jump: ans[i] = nums[nums[i]]. The simple way is a new array in O(n) time and O(n) space. For O(1) extra space, I store two numbers in one cell. Since every value is less than n, I keep the old value in the low part and add n times the new value on top. In pass 1 I read the jump target with % n, so I always see its old value even if it was already changed. In pass 2 I divide every cell by n to keep only the new value. That is O(n) time and O(1) extra space.
