# 10. 1512. Number of Good Pairs

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [1512. Number of Good Pairs](https://leetcode.com/problems/number-of-good-pairs/) | `O(n)` | `O(n)` |

## 1. Problem Statement

You get an array `nums`.

A pair `(i, j)` is **good** if `nums[i] == nums[j]` and `i < j`.

Return the number of good pairs.

### Example

```text
Input:  nums = [1, 2, 3, 1, 1, 3]
Output: 4

Why: the good pairs are
(0, 3)  -> 1 and 1
(0, 4)  -> 1 and 1
(3, 4)  -> 1 and 1
(2, 5)  -> 3 and 3
```

We use this same example in every section below.

### Constraints

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

## 2. Core Theory

### What the problem really asks

Count how many ways we can pick two **different positions** holding the **same value**, with the left one first.

### The key fact

When a value shows up and we have **already seen it `k` times**, it makes `k` new pairs: one with each earlier copy.

```text
nums:   [1][2][3][1][1][3]
seen 1 before:  0     1  2         -> new pairs from 1s: 0 + 1 + 2 = 3
seen 3 before:     0        1      -> new pairs from 3s: 0 + 1     = 1
                                      total = 4
```

So we walk once and keep a count of how many times we have seen each value.

### The math view

If a value appears `f` times, it makes `f · (f - 1) / 2` pairs.

```text
value 1 appears 3 times -> 3 · 2 / 2 = 3
value 3 appears 2 times -> 2 · 1 / 2 = 1
value 2 appears 1 time  -> 0
total = 4
```

The running count `0 + 1 + 2 + ... + (f - 1)` gives the same number. That is why both ways agree.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| All same | `[1, 1, 1, 1]` | `6` | `4 · 3 / 2 = 6`. LeetCode example 2 |
| All different | `[1, 2, 3]` | `0` | No value repeats. LeetCode example 3 |
| Single element | `[5]` | `0` | A pair needs two positions |
| Two equal | `[7, 7]` | `1` | Smallest good pair |
| Copies far apart | `[4, 1, 2, 4]` | `1` | Positions do not need to be next to each other |

## 4. Brute Force: Check Every Pair

### Idea

Try every `i < j`. Count the ones where `nums[i] == nums[j]`.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: check every pair of positions
class SolutionBrute:

    # Main method
    def numIdenticalPairs(self, nums: List[int]) -> int:

        # Number of elements
        n = len(nums)

        # Good pairs found
        pairs = 0

        # Left position
        for i in range(n):

            # Right position, always after i
            for j in range(i + 1, n):

                # Same value at both positions
                if nums[i] == nums[j]:

                    # Count this pair
                    pairs += 1

        # Return the total
        return pairs
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | About `n^2 / 2` pairs |
| **Space** | `O(1)` | One counter |

## 5. Optimal Approach: Count As You Go

### Idea

1. `seen = {}` (value -> times seen so far), `pairs = 0`.
2. For each `num`:
   - `pairs += seen.get(num, 0)` (pair with every earlier copy).
   - `seen[num] = seen.get(num, 0) + 1`.
3. Return `pairs`.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: count earlier copies while walking once
class Solution:

    # Main method
    def numIdenticalPairs(self, nums: List[int]) -> int:

        # How many times each value has been seen so far
        seen = {}

        # Good pairs found
        pairs = 0

        # Look at every number once
        for num in nums:

            # Pair this number with every earlier copy
            pairs += seen.get(num, 0)

            # Record one more copy of this value
            seen[num] = seen.get(num, 0) + 1

        # Return the total
        return pairs


# Helper that records (seen, pairs) after every step, to check the trace
def trace_good_pairs(nums):

    # Copies seen so far
    seen = {}

    # Pairs so far
    pairs = 0

    # States after each step
    states = []

    # Same loop as the solution
    for num in nums:

        # Add pairs with earlier copies
        pairs += seen.get(num, 0)

        # Count this copy
        seen[num] = seen.get(num, 0) + 1

        # Save a copy of the state
        states.append((dict(seen), pairs))

    # Return every state
    return states
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One dictionary lookup and update per element |
| **Space** | `O(n)` | The dictionary holds up to `n` distinct values |

With `1 <= nums[i] <= 100`, a fixed list of size 101 also works, which is `O(1)` space.

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Updating `seen` before adding to `pairs` | Each number pairs with itself. Example gives `10` | Add `seen[num]` to `pairs` first, then increase it |
| Counting `f · f` or `f · (f + 1) / 2` | Counts a value with itself or counts `(j, i)` too | Use `f · (f - 1) / 2` |
| Inner loop `for j in range(n)` | Counts `(i, i)` and both `(i, j)` and `(j, i)` | Use `range(i + 1, n)` |
| `seen[num] += 1` on a new key | `KeyError` | Use `seen.get(num, 0) + 1` or `defaultdict(int)` |

## 7. Interview Follow-ups

### Q1. Can you use the formula instead?

**Answer:**
- Yes. Count each value's frequency `f` with `Counter`.
- Answer = sum of `f · (f - 1) // 2` over all values.
- Same `O(n)` time.

### Q2. What if values can be huge, like up to `10^9`?

**Answer:**
- Keep the dictionary. A fixed-size list would be too big.
- Time is still `O(n)` on average.

### Q3. What if you must not use extra memory?

**Answer:**
- Sort the array, then count runs of equal values.
- Each run of length `f` gives `f · (f - 1) / 2`.
- Time `O(n log n)`, space `O(1)` extra (if sorting in place is allowed).

### Q4. What if a good pair needs `nums[i] == nums[j]` and `i · j` divisible by `k`?

**Answer:**
- That is LeetCode 2176. The extra rule depends on positions, not just values.
- With `n <= 100`, the double loop is the clean answer.

### Q5. What if a pair is good when `nums[i] + nums[j] == target`?

**Answer:**
- Same idea: for each `num`, add `seen[target - num]` to the answer, then record `num`.
- That is the counting version of Two Sum.

## 8. Interview Explanation

> A value that I have already seen k times makes k new good pairs when it shows up again, one with each earlier copy. So I walk the array once with a dictionary of counts. For each number, I first add its current count to the answer, then increase its count. Adding before increasing makes sure a number never pairs with itself, and only i < j pairs are counted. This is O(n) time and O(n) space.
