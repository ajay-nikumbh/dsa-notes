# 01. Largest in Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Basic** | Linear Scan | [Largest Element in Array](https://www.geeksforgeeks.org/problems/largest-element-in-array4009/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an array `arr[]`.

Find the largest element and return it.

### Example

```text
Input:  arr = [10, 5, 20, 8, 15]
Output: 20

Why: 20 is bigger than 10, 5, 8 and 15.
```

We use this same example in every section below.

### Constraints

- `1 <= arr.size() <= 10^6`
- `0 <= arr[i] <= 10^6`

## 2. Core Theory

### What the problem really asks

We must look at every number once and remember the biggest one we have seen.

We do not need to sort. We do not need to compare every pair.

### Why one variable is enough

Keep one variable called `largest`.

- At the start, `largest` is the first number.
- For every next number: if it is bigger than `largest`, it becomes the new `largest`.
- After the last number, `largest` holds the biggest number of the whole array.

The rule that makes this work:

> After we look at index `i`, `largest` is the biggest number among `arr[0..i]`.

```text
arr:      [10][ 5][20][ 8][15]
largest:   10  10  20  20  20
                    ^
                 new champion
```

### The same shape solves many problems

| Question | Start value | Update rule |
|:---|:---:|:---|
| Largest | `arr[0]` | if `x > largest`: `largest = x` |
| Smallest | `arr[0]` | if `x < smallest`: `smallest = x` |
| Sum | `0` | `total += x` |
| Count of matches | `0` | if the test is true: `count += 1` |

### The one trap: the start value

- Do not start with `largest = 0`.
- If all numbers were negative, `0` would win, but `0` is not in the array.
- Start with `arr[0]` (or `float("-inf")`).

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[5]` | `5` | The loop from index 1 never runs. The start value must already be the answer |
| All same | `[4, 4, 4, 4]` | `4` | `>` never fires. `largest` stays at the start value |
| All negative | `[-10, -3, -20, -7]` | `-3` | Starting with `0` would wrongly return `0` |
| Largest repeated | `[7, 2, 7]` | `7` | We return a value, not an index, so ties do not matter |
| Largest at the end | `[1, 2, 3, 90]` | `90` | Catches a loop that stops one step too early |
| Largest at the front | `[90, 1, 2, 3]` | `90` | The start value is the answer and must never be lost |

## 4. Brute Force: Check Every Element Against All Others

### Idea

For each number, check if any other number is bigger.

If no number is bigger, that number is the largest.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: compare every element with every other element
class SolutionBrute:

    # Main method
    def largest(self, arr: List[int]) -> int:

        # Number of elements
        n = len(arr)

        # Try every element as the answer
        for i in range(n):

            # Assume this element is the largest
            is_largest = True

            # Compare it with every element
            for j in range(n):

                # Someone is bigger, so arr[i] is not the largest
                if arr[j] > arr[i]:

                    # Mark it as not the largest
                    is_largest = False

                    # No need to check more
                    break

            # Nobody was bigger
            if is_largest:

                # This element is the answer
                return arr[i]

        # Only reached when the array is empty
        return -1
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | For each element we may compare with all others |
| **Space** | `O(1)` | Only a few variables |

## 5. Better Approach: Sort

### Idea

Sort a copy of the array. The largest number is now at the end.

### Code

```python
# Sort a copy and take the last element
class SolutionBetter:

    # Main method
    def largest(self, arr: List[int]) -> int:

        # Sort a copy so the input is not changed
        sorted_arr = sorted(arr)

        # The last element is the largest
        return sorted_arr[-1]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Sorting |
| **Space** | `O(n)` | `sorted` makes a copy |

Sorting puts all `n` numbers in order. We only need one number, so this is wasted work.

## 6. Optimal Approach: One Pass

### Idea

1. Set `largest = arr[0]`.
2. Walk from index `1` to the end.
3. If `arr[i] > largest`, set `largest = arr[i]`.
4. Return `largest`.

### Visual Walkthrough (Story Version)

**The story:** five kids stand in a line. Each kid holds a card with a number. A teacher holds a **crown**. The crown must end up with the kid who has the biggest number.

**The rules:**

- The first kid gets the crown at the start.
- The teacher walks down the line, one kid at a time.
- If the new kid's number is **bigger** than the crown holder's number, the crown moves to the new kid.
- If not, the crown stays where it is.

**How to read the pictures:** `[ ]` = a kid's card. `^` = where the teacher stands. `(K)` = the kid with the crown.

**Start: the first kid gets the crown**

```

**Step 2: teacher visits the kid with 20**

- Is 20 bigger than 10? Yes.
- The crown moves to 20.

crown = 20
```

**Step 3: teacher visits the kid with 8**

- The crown stays with 20.

                  ^

**End:** the line is done. The kid with the crown holds **20**. That is the answer.

### Step-by-Step Example

```text

```

**Start**

```text

```

**Step 1: `i = 1`, `arr[1] = 5`**

1. Compare `5 > 10`? No.
2. `largest` stays `10`.

```text

```

**Step 2: `i = 2`, `arr[2] = 20`**

1. Compare `20 > 10`? Yes.
2. Set `largest = 20`.

```text
i = 2, largest = 20
```

**Step 3: `i = 3`, `arr[3] = 8`**

1. Compare `8 > 20`? No.
2. `largest` stays `20`.

```text
i = 3, largest = 20
```

**Step 4: `i = 4`, `arr[4] = 15`**

1. Compare `15 > 20`? No.
2. `largest` stays `20`.

```text
i = 4, largest = 20
```

**Loop ends.** Return `largest = 20`.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: one pass with one variable
class Solution:

    # Main method
    def largest(self, arr: List[int]) -> int:

        # The first element starts as the largest
        largest = arr[0]

        # Walk from the second element to the end
        for i in range(1, len(arr)):

            # Found a bigger element
            if arr[i] > largest:

                # It becomes the new largest
                largest = arr[i]

        # Return the biggest value seen
        return largest


# Helper that records largest after every step, to check the trace
def trace_largest(arr):

    # Start with the first element
    largest = arr[0]

    # Store the value after the start
    states = [largest]

    # Walk the rest of the array
    for i in range(1, len(arr)):

        # Update when a bigger element appears
        if arr[i] > largest:

            # New largest
            largest = arr[i]

        # Store the value after this step
        states.append(largest)

    # Return every state
    return states


# Example from this note
arr = [10, 5, 20, 8, 15]

# Start, Step 1, Step 2, Step 3, Step 4
assert trace_largest(arr) == [10, 10, 20, 20, 20]

# Final answer on the example
assert Solution().largest(arr) == 20

# GfG example 1
assert Solution().largest([1, 8, 7, 56, 90]) == 90

# GfG example 2
assert Solution().largest([5, 5, 5, 5]) == 5

# GfG example 3
assert Solution().largest([10]) == 10

# Edge case: all negative
assert Solution().largest([-10, -3, -20, -7]) == -3

# Edge case: largest repeated
assert Solution().largest([7, 2, 7]) == 7

# Edge case: largest at the end
assert Solution().largest([1, 2, 3, 90]) == 90

# Edge case: largest at the front
assert Solution().largest([90, 1, 2, 3]) == 90

# The input must not be changed
original = [3, 1, 2]

# Run every solution on the same input
assert Solution().largest(original) == SolutionBetter().largest(original) == 3

# Input is still the same
assert original == [3, 1, 2]

# Brute force and better give the same answers as optimal
for case in [arr, [1, 8, 7, 56, 90], [5], [4, 4, 4], [-10, -3, -20, -7], [90, 1, 2, 3]]:

    # Compare all three
    assert SolutionBrute().largest(case) == SolutionBetter().largest(case) == Solution().largest(case)

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | We look at each element once |
| **Space** | `O(1)` | Only the variable `largest` |

## 7. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| `largest = 0` at the start | For `[-10, -3]` it returns `0`, which is not in the array | Start with `arr[0]` or `float("-inf")` |
| `range(1, len(arr) - 1)` | Skips the last element. `[1, 2, 3, 90]` returns `3` | Use `range(1, len(arr))` |
| Returning `i` instead of `arr[i]` | Returns a position, not the value | Keep and return the value |
| Calling `arr.sort()` | Changes the caller's array | Use the one-pass scan, or `sorted(arr)` |
| No check for an empty array | `arr[0]` raises `IndexError` | Constraints say `n >= 1`. Say it out loud, or add `if not arr: return None` |

## 8. Interview Follow-ups

### Q1. What if the numbers come as a stream that does not fit in memory?

**Answer:**
- Nothing changes.
- We keep only one variable, `largest`.
- Read a number, update `largest`, forget the number.

### Q2. What if you want the k-th largest instead?

**Answer:**
- Keep a min-heap of size `k`.
- Push each number. If the heap has more than `k` items, pop the smallest.
- The heap top is the answer. Time `O(n log k)`, space `O(k)`.

### Q3. Can you find both the largest and the smallest with fewer than `2n` comparisons?

**Answer:**
- Yes. Take the numbers two at a time.
- Compare the pair first (1 comparison).
- Compare the smaller one with `smallest` and the bigger one with `largest` (2 comparisons).
- That is 3 comparisons per 2 numbers, about `1.5n` in total.

### Q4. Can this run in parallel?

**Answer:**
- Yes. Split the array into chunks.
- Find the largest of each chunk at the same time.
- Then take the largest of those answers.
- This works because `max` does not care about order.

### Q5. What if you need the index of the largest, and there are ties?

**Answer:**
- Keep `best_index` next to the value.
- With `>`, you keep the **first** index of the largest.
- With `>=`, you keep the **last** one.
- Ask the interviewer which one they want.

## 9. Interview Explanation

> I keep one variable, `largest`, and start it with the first element. Then I walk the array from left to right. Whenever I see an element bigger than `largest`, I update it. After the loop, `largest` is the biggest value in the whole array. I start with `arr[0]` instead of `0` so negative numbers also work. This is O(n) time and O(1) space.
