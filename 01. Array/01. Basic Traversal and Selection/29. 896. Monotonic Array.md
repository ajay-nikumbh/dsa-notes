# 29. 896. Monotonic Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Traversal: Direction Flags | [896. Monotonic Array](https://leetcode.com/problems/monotonic-array/) | `O(n)` | `O(1)` |

## 1. Problem Statement

An array is **monotonic** if it is either:

- **monotone increasing**: `nums[i] <= nums[j]` for all `i <= j`, or
- **monotone decreasing**: `nums[i] >= nums[j]` for all `i <= j`.

You get an integer array `nums`. Return `True` if it is monotonic, else `False`.

### Example

```text
nums = [1, 3, 2]

1 -> 3   goes up
3 -> 2   goes down

It goes up AND down, so it is not monotonic.
Output: False
```

We use this same example in every section below.

### Constraints

- `1 <= nums.length <= 10^5`
- `-10^5 <= nums[i] <= 10^5`

## 2. Core Theory

### What the problem really asks

Look at every pair of neighbors. Each pair does one of three things:

```text
a < b   -> step UP
a > b   -> step DOWN
a == b  -> FLAT (allowed in both directions)
```

The array is monotonic if it **never** has both an up step and a down step.

### Why two flags fit

We do not need to know the direction in advance. We just remember two yes/no facts:

- `went_up`: did we ever see an up step?
- `went_down`: did we ever see a down step?

At the end:

```text
monotonic  <=>  not (went_up and went_down)
```

```text
[1][3][2]
  \/ \/
  up  down

went_up = True, went_down = True  ->  False
```

Flat steps change nothing. That is why `[1, 2, 2, 3]` and `[6, 5, 4, 4]` are both monotonic.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[5]` | `True` | No pairs at all |
| All equal | `[2, 2, 2]` | `True` | Only flat steps. Both directions fit |
| Increasing with flats | `[1, 2, 2, 3]` | `True` | Equal neighbors must not break it |
| Decreasing with flats | `[6, 5, 4, 4]` | `True` | Same idea going down |
| Up then down | `[1, 3, 2]` | `False` | Both flags turn on |
| Flat then change late | `[1, 1, 1, 0, 2]` | `False` | The break can come at the very end |

## 4. Brute Force: Compare With Sorted Copies

### Idea

An array is monotone increasing if it equals its sorted copy. It is monotone decreasing if it equals its reverse-sorted copy. Check both.

### Code

```python
# Import List for type hints
from typing import List


# Compare with sorted copies
class SolutionBrute:

    # Main method
    def isMonotonic(self, nums: List[int]) -> bool:

        # Same as sorted small-to-big means increasing
        if nums == sorted(nums):
            return True

        # Same as sorted big-to-small means decreasing
        return nums == sorted(nums, reverse=True)
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Sorting |
| **Space** | `O(n)` | The sorted copies |

## 5. Optimal Approach: One Pass With Two Flags

### Idea

1. `went_up = False`, `went_down = False`.
2. For each `i` from `1` to `n - 1`, compare `nums[i - 1]` and `nums[i]`.
3. Turn on `went_up` if it went up. Turn on `went_down` if it went down.
4. Return `not (went_up and went_down)`.

### Visual Walkthrough (Story Version)

**The story:** a hiker walks along a path with stones of different heights. The hiker carries two stickers: an **UP** sticker and a **DOWN** sticker. Each time the path goes up, the hiker puts on the UP sticker. Each time it goes down, the DOWN sticker. A flat step needs no sticker. The path is a "one-way path" only if the hiker ends with **at most one kind** of sticker.

**How to read the pictures:** boxes are stone heights. `^` marks the stone the hiker steps onto.

**Start: hiker stands on the first stone**

```text
path: [1][3][2]
       ^
stickers: none
```

**Step 1: step from 1 to 3**

```text
path: [1][3][2]
          ^
1 -> 3 goes UP. Put on the UP sticker.
stickers: UP
```

**Step 2: step from 3 to 2**

```text
path: [1][3][2]
             ^
3 -> 2 goes DOWN. Put on the DOWN sticker.
stickers: UP, DOWN
```

**End:** the hiker has both stickers. The path went up and down. Not a one-way path. Answer: `False`.

**All steps at a glance**

| Step | From | To | Direction | UP sticker | DOWN sticker |
|:---:|:---:|:---:|:---:|:---:|:---:|
| start | – | 1 | – | No | No |
| 1 | 1 | 3 | Up | Yes | No |
| 2 | 3 | 2 | Down | Yes | Yes |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Stone height | `nums[i]` |
| One step on the path | Compare `nums[i - 1]` and `nums[i]` |
| UP sticker | `went_up = True` |
| DOWN sticker | `went_down = True` |
| Flat step, no sticker | Equal neighbors change nothing |
| At most one kind of sticker | `not (went_up and went_down)` |

### Step-by-Step Example

```text
nums = [1, 3, 2]
```

**Start:** `went_up = False, went_down = False`

**Step 1: `i = 1`, compare `nums[0] = 1` and `nums[1] = 3`**

1. Is `3 > 1`? Yes. `went_up = True`.
2. Is `3 < 1`? No. `went_down` stays `False`.

```text
went_up = True, went_down = False
```

**Step 2: `i = 2`, compare `nums[1] = 3` and `nums[2] = 2`**

1. Is `2 > 3`? No. `went_up` stays `True`.
2. Is `2 < 3`? Yes. `went_down = True`.

```text
went_up = True, went_down = True
```

**End:** `went_up and went_down` is `True`. Return `not True = False`.

### Code

```python
# Import List for type hints
from typing import List


# Solution for 896. Monotonic Array
class Solution:

    # Return (went_up, went_down) for the whole array
    def _flags(self, nums: List[int]):

        # No up step seen yet
        went_up = False

        # No down step seen yet
        went_down = False

        # Look at every pair of neighbors
        for i in range(1, len(nums)):

            # This step goes up
            if nums[i] > nums[i - 1]:

                # Remember we went up
                went_up = True

            # This step goes down
            elif nums[i] < nums[i - 1]:

                # Remember we went down
                went_down = True

        # Return both flags
        return went_up, went_down

    # Main method
    def isMonotonic(self, nums: List[int]) -> bool:

        # Get both flags
        went_up, went_down = self._flags(nums)

        # Monotonic means we did not go both ways
        return not (went_up and went_down)


# The example from this note
nums = [1, 3, 2]

# Flags before any step (only the first stone)
assert Solution()._flags(nums[:1]) == (False, False)

# Flags after step 1
assert Solution()._flags(nums[:2]) == (True, False)

# Flags after step 2
assert Solution()._flags(nums[:3]) == (True, True)

# Full example
assert Solution().isMonotonic(nums) is False

# LeetCode example 1: increasing with flats
assert Solution().isMonotonic([1, 2, 2, 3]) is True

# LeetCode example 2: decreasing with flats
assert Solution().isMonotonic([6, 5, 4, 4]) is True

# Edge case: single element
assert Solution().isMonotonic([5]) is True

# Edge case: all equal
assert Solution().isMonotonic([2, 2, 2]) is True

# Edge case: change at the very end
assert Solution().isMonotonic([1, 1, 1, 0, 2]) is False

# Brute force gives the same answers
for arr in [nums, [1, 2, 2, 3], [6, 5, 4, 4], [5], [2, 2, 2], [1, 1, 1, 0, 2], [3, 2, 1, 1, 0]]:

    # Both methods must agree
    assert SolutionBrute().isMonotonic(arr) == Solution().isMonotonic(arr)

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass over neighbor pairs |
| **Space** | `O(1)` | Two flags |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Using `>=` or `<=` to set the flags | Flat steps set both flags, so `[2, 2]` returns `False` | Use strict `>` and `<` |
| Guessing the direction from the first two items | `[2, 2, 1]` starts flat, so the guess is wrong | Use two flags, decide at the end |
| Only checking increasing | `[6, 5, 4, 4]` returns `False` | Check both directions |
| Loop starting at `i = 0` with `nums[i - 1]` | `nums[-1]` is the last element in Python, a fake pair | Start at `i = 1` |

## 7. Interview Follow-ups

### Q1. Can we stop early?

**Answer:**
- Yes. As soon as both flags are `True`, return `False`.
- Worst case is still `O(n)`, but bad arrays finish sooner.

### Q2. What if it must be strictly increasing or strictly decreasing?

**Answer:**
- Treat a flat step as a failure.
- Return `False` the moment `nums[i] == nums[i - 1]`.

### Q3. How do you check this in one line in Python?

**Answer:**
- `all(a <= b for a, b in zip(nums, nums[1:])) or all(a >= b for a, b in zip(nums, nums[1:]))`.
- Still `O(n)`, but it makes up to two passes and a slice copy.

### Q4. How is this related to Valid Mountain Array?

**Answer:**
- A mountain must go strictly up, then strictly down.
- Monotonic must go only one way.
- Both are solved by walking neighbor pairs and tracking direction.

## 8. Interview Explanation

> I walk through every pair of neighbors and keep two flags: did the array ever go up, and did it ever go down. Equal neighbors change nothing, so flat parts are allowed in both directions. The array is monotonic only if it did not go both ways, so I return not (went_up and went_down). This is one pass, O(n) time and O(1) space, and I do not need to guess the direction from the first elements.
