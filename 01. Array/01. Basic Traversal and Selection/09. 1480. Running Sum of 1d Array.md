# 09. 1480. Running Sum of 1d Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [1480. Running Sum of 1d Array](https://leetcode.com/problems/running-sum-of-1d-array/) | `O(n)` | `O(1)` extra |

## 1. Problem Statement

You get an array `nums`.

The running sum at index `i` is `nums[0] + nums[1] + ... + nums[i]`.

Return the array of running sums.

### Example

```text
Input:  nums = [1, 2, 3, 4]
Output: [1, 3, 6, 10]

Why:
index 0: 1                 = 1
index 1: 1 + 2             = 3
index 2: 1 + 2 + 3         = 6
index 3: 1 + 2 + 3 + 4     = 10
```

We use this same example in every section below.

### Constraints

- `1 <= nums.length <= 1000`
- `-10^6 <= nums[i] <= 10^6`

## 2. Core Theory

### What the problem really asks

Build a **prefix sum** array. Each slot holds the total of everything up to and including that index.

### The key fact

Each answer is the **previous answer plus the current number**.

```text
result[i] = result[i - 1] + nums[i]
```

So we never need to add the same numbers twice.

```text
nums:    [ 1][ 2][ 3][ 4]
           |   |   |   |
total:     1 ->3 ->6 ->10
              +2  +3  +4
```

### Why this matters later

Prefix sums are a building block for many problems:

- Sum of any range `[l, r]` = `prefix[r] - prefix[l - 1]`, in `O(1)`.
- Subarray sum equals `k` (LeetCode 560).
- Pivot index (LeetCode 724).
- Find the Highest Altitude (note 12 in this folder).

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[5]` | `[5]` | The first running sum is the element itself |
| All ones | `[1, 1, 1, 1, 1]` | `[1, 2, 3, 4, 5]` | LeetCode example 2 |
| Negatives | `[3, -1, -2]` | `[3, 2, 0]` | Totals can go down |
| Zeros | `[0, 0, 0]` | `[0, 0, 0]` | Total never changes |
| Mixed | `[3, 1, 2, 10, 1]` | `[3, 4, 6, 16, 17]` | LeetCode example 3 |

## 4. Brute Force: Re-add from the Start Every Time

### Idea

For each index `i`, add `nums[0]` through `nums[i]` from scratch.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: recompute every prefix from the start
class SolutionBrute:

    # Main method
    def runningSum(self, nums: List[int]) -> List[int]:

        # Answer list
        result = []

        # For every end index
        for i in range(len(nums)):

            # Total for this prefix
            total = 0

            # Add every element from 0 to i
            for j in range(i + 1):

                # Add one element
                total += nums[j]

            # Save the prefix total
            result.append(total)

        # Return all running sums
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | `1 + 2 + ... + n` additions |
| **Space** | `O(1)` extra | Not counting the answer |

We add `nums[0]` again for every index. That is the waste.

## 5. Optimal Approach: Carry the Total Forward

### Idea

1. `total = 0`, `result = []`.
2. For each `num`: `total += num`, then append `total`.
3. Return `result`.

### Visual Walkthrough (Story Version)

**The story:** a kid walks past four piggy banks. Each bank has some coins. The kid carries a **bag** and pours each bank's coins into it. After each bank, the kid writes the bag's total on a **sticky note** and sticks it on that bank.

**The rules:**

- The bag starts empty.
- At each bank: pour the coins in, then write the new bag total on a note.
- The notes, in order, are the answer.

**How to read the pictures:** `[ ]` = coins in each bank. `^` = the bank the kid is at. `bag` = total so far. `notes` = answer so far.

**Start: the bag is empty**

```text

```

**Step 1: bank with 1 coin**

- Pour 1 coin in. Bag: 0 + 1 = 1.
- Write note "1".

```text

 ^

```

**Step 2: bank with 2 coins**

- Pour 2 coins in. Bag: 1 + 2 = 3.
- Write note "3".

```text
    ^

```

**Step 3: bank with 3 coins**

- Pour 3 coins in. Bag: 3 + 3 = 6.
- Write note "6".

```text
       ^
```

### Step-by-Step Example

```text
nums = [1, 2, 3, 4]
```

**Start**

```text
total = 0, result = []
```

**Step 1: `i = 0`, `num = 1`**

1. `total = 0 + 1 = 1`.
2. `result = [1]`.

**Step 2: `i = 1`, `num = 2`**

1. `total = 1 + 2 = 3`.
2. `result = [1, 3]`.

**Step 3: `i = 2`, `num = 3`**

1. `total = 3 + 3 = 6`.
2. `result = [1, 3, 6]`.

**Step 4: `i = 3`, `num = 4`**

1. `total = 6 + 4 = 10`.
2. `result = [1, 3, 6, 10]`.

**Loop ends.** Return `[1, 3, 6, 10]`.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: carry the running total forward
class Solution:

    # Main method
    def runningSum(self, nums: List[int]) -> List[int]:

        # Total so far
        total = 0

        # Answer list
        result = []

        # Look at every number once
        for num in nums:

            # Add the current number to the total
            total += num

            # Save the running sum for this index
            result.append(total)

        # Return all running sums
        return result


# Helper that records (total, result) after every step, to check the trace
def trace_running_sum(nums):

    # Total so far
    total = 0

    # Answer so far
    result = []

    # States after each step
    states = []

    # Same loop as the solution
    for num in nums:

        # Add the number
        total += num

        # Save the running sum
        result.append(total)

        # Save a copy of the state
        states.append((total, list(result)))

    # Return every state
    return states


# Example from this note
nums = [1, 2, 3, 4]

# Step 1 to Step 4
assert trace_running_sum(nums) == [(1, [1]), (3, [1, 3]), (6, [1, 3, 6]), (10, [1, 3, 6, 10])]

# Final answer on the example (LeetCode example 1)
assert Solution().runningSum(nums) == [1, 3, 6, 10]

# LeetCode example 2
assert Solution().runningSum([1, 1, 1, 1, 1]) == [1, 2, 3, 4, 5]

# LeetCode example 3
assert Solution().runningSum([3, 1, 2, 10, 1]) == [3, 4, 6, 16, 17]

# Edge case: single element
assert Solution().runningSum([5]) == [5]

# Edge case: negatives
assert Solution().runningSum([3, -1, -2]) == [3, 2, 0]

# Edge case: zeros
assert Solution().runningSum([0, 0, 0]) == [0, 0, 0]

# The input list must not be changed
assert nums == [1, 2, 3, 4]

# Brute force gives the same answers
for case in [nums, [1, 1, 1, 1, 1], [3, 1, 2, 10, 1], [5], [3, -1, -2], [0, 0, 0]]:

    # Compare brute force and optimal
    assert SolutionBrute().runningSum(case) == Solution().runningSum(case)

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One addition per element |
| **Space** | `O(1)` extra | Only `total`. The answer list is output |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Appending before adding | Result is shifted: `[0, 1, 3, 6]` | Add first, then append |
| Starting `total = nums[0]` and looping all elements | `nums[0]` is added twice: `[2, 4, 7, 11]` | Start at `0`, or loop from index 1 |
| In-place loop starting at `i = 0` with `nums[i] += nums[i - 1]` | `nums[-1]` is the last element. Index 0 gets a wrong value | Start the in-place loop at `i = 1` |
| Changing the input by accident | The caller's list changes | Build a new list, or say you are doing it in place |

## 7. Interview Follow-ups

### Q1. Can you do it in place?

**Answer:**
- Yes. For `i` from `1` to `n - 1`: `nums[i] += nums[i - 1]`.
- Then return `nums`. No extra list at all.
- Mention that it changes the input.

### Q2. How do you get the sum of any range `[l, r]` fast?

**Answer:**
- Build the prefix sums once.
- Then `sum(l, r) = prefix[r] - (prefix[l - 1] if l > 0 else 0)`.
- Each range query is `O(1)`.

### Q3. Is there a built-in for this in Python?

**Answer:**
- Yes: `list(itertools.accumulate(nums))`.
- Good to know, but write the loop in an interview first.

### Q4. What if values are very large?

**Answer:**
- Python integers do not overflow.
- In Java or C++, use a 64-bit type (`long`). Here `1000 · 10^6 = 10^9` fits even in 32 bits, but barely.

### Q5. What about a 2D running sum?

**Answer:**
- `P[i][j] = grid[i][j] + P[i-1][j] + P[i][j-1] - P[i-1][j-1]`.
- Then any rectangle sum is `O(1)` (LeetCode 304).

## 8. Interview Explanation

> Each running sum is the previous running sum plus the current number. So I keep one variable, `total`, starting at 0. For each number, I add it to `total` and append `total` to the answer. This avoids re-adding the same numbers again and again. It is O(n) time and O(1) extra space besides the output, and I can also do it in place by setting `nums[i] += nums[i - 1]` from index 1.
