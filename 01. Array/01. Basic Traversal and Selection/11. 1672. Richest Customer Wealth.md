# 11. 1672. Richest Customer Wealth

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [1672. Richest Customer Wealth](https://leetcode.com/problems/richest-customer-wealth/) | `O(m · n)` | `O(1)` |

## 1. Problem Statement

You get an `m x n` grid `accounts`.

`accounts[i][j]` is the money customer `i` has in bank `j`.

A customer's **wealth** is the total money in all their banks.

Return the wealth of the richest customer.

### Example

```text
Input:  accounts = [[1, 5],
                    [7, 3],
                    [3, 5]]
Output: 10

Why:
customer 0: 1 + 5 = 6
customer 1: 7 + 3 = 10
customer 2: 3 + 5 = 8
The richest has 10.
```

We use this same example in every section below.

### Constraints

- `m == accounts.length`
- `n == accounts[i].length`
- `1 <= m, n <= 50`
- `1 <= accounts[i][j] <= 100`

## 2. Core Theory

### What the problem really asks

Two simple jobs, one inside the other:

1. **Sum** each row (one customer).
2. Take the **max** of those sums.

```text
           bank 0  bank 1     row sum
customer 0 [  1  ][  5  ]  ->   6
customer 1 [  7  ][  3  ]  ->  10   <- biggest
customer 2 [  3  ][  5  ]  ->   8
```

### Why no list of sums is needed

- We only need the biggest row sum.
- So after each row, compare its sum with `richest` and keep the bigger one.
- This is "Largest in Array" (note 01), where each element is a row sum.

### Every cell is visited once

- `m` rows times `n` columns = `m · n` cells.
- We cannot skip any cell, because any cell could change a row's total.
- So `O(m · n)` is the best possible.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| One customer | `[[2, 8, 7]]` | `17` | The only row is the answer |
| One bank each | `[[3], [9], [4]]` | `9` | Each row sum is just one value |
| Tie | `[[1, 2, 3], [3, 2, 1]]` | `6` | Ties are fine, we return a value |
| Richest is last | `[[1, 5], [7, 3], [3, 5], [9, 9]]` | `18` | The last row must be compared too |
| LeetCode example 2 | `[[1, 5], [7, 3], [3, 5]]` | `10` | Our main example |
| LeetCode example 3 | `[[2, 8, 7], [7, 1, 3], [1, 9, 5]]` | `17` | Richest is the first row |

## 4. Brute Force: Store Every Row Sum, Then Take the Max

### Idea

Build a list with each customer's wealth. Then find the largest value in that list.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: keep all row sums in a list
class SolutionBrute:

    # Main method
    def maximumWealth(self, accounts: List[List[int]]) -> int:

        # Wealth of every customer
        wealth = []

        # Go through every customer
        for customer in accounts:

            # Total for this customer
            total = 0

            # Go through every bank of this customer
            for money in customer:

                # Add the money in this bank
                total += money

            # Save this customer's wealth
            wealth.append(total)

        # The richest is the biggest saved total
        return max(wealth)
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(m · n)` | Every cell once, plus `O(m)` for `max` |
| **Space** | `O(m)` | The `wealth` list |

The time is already the best. The only waste is the list we do not need.

## 5. Optimal Approach: Running Max of Row Sums

### Idea

1. `richest = 0`.
2. For each row: add up its cells into `total`.
3. If `total > richest`, set `richest = total`.
4. Return `richest`.

Starting at `0` is safe here because every value is at least `1`.

### Visual Walkthrough (Story Version)

**The story:** three kids each have some piggy banks. A teacher visits each kid, **counts all the coins in that kid's banks**, and keeps a **gold star** for the kid with the most coins so far.

**The rules:**

- The teacher counts one kid's banks fully before moving on.
- After counting, if this kid has more coins than the gold star number, the star moves to this kid.

**How to read the pictures:** each row is one kid's banks. `>` = the kid being counted. `count` = coins counted so far for this kid. `star` = most coins so far.

**Start: no kid counted yet**

```text
  [1][5]
  [7][3]
  [3][5]

star = 0
```

**Step 1: count kid 0**

- Bank 0 has 1 coin. Count: 0 + 1 = 1.
- Bank 1 has 5 coins. Count: 1 + 5 = 6.
- Is 6 more than star 0? Yes. Star = 6.

```text
> [1][5]   count = 6  *
  [7][3]
  [3][5]

star = 6
```

**Step 2: count kid 1**

- Bank 0 has 7 coins. Count: 0 + 7 = 7.
- Bank 1 has 3 coins. Count: 7 + 3 = 10.
- Is 10 more than star 6? Yes. Star = 10.

```text
  [1][5]   count = 6
> [7][3]   count = 10 *
  [3][5]

star = 10
```

**Step 3: count kid 2**

- Bank 0 has 3 coins. Count: 0 + 3 = 3.
- Bank 1 has 5 coins. Count: 3 + 5 = 8.
- Is 8 more than star 10? No. Star stays 10.

```text
  [1][5]   count = 6
  [7][3]   count = 10 *
> [3][5]   count = 8

star = 10
```

**End:** the gold star number is **10**. That is the answer.

**All steps at a glance**

| Step | Kid | Coins added | Kid's total | More than star? | Star after |
|:---:|:---:|:---|:---:|:---:|:---:|
| start | – | – | – | – | 0 |
| 1 | 0 | 1, 5 | 6 | Yes | 6 |
| 2 | 1 | 7, 3 | 10 | Yes | 10 |
| 3 | 2 | 3, 5 | 8 | No | 10 |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Kid | `customer` (one row) |
| Piggy bank | `money` (one cell) |
| Counting one kid's coins | `total += money` |
| Gold star number | `richest` |
| Star moves | `if total > richest: richest = total` |

### Step-by-Step Example

```text
accounts = [[1, 5], [7, 3], [3, 5]]
```

**Start**

```text
richest = 0
```

**Step 1: customer 0 = `[1, 5]`**

1. `total = 0`.
2. `money = 1`: `total = 0 + 1 = 1`.
3. `money = 5`: `total = 1 + 5 = 6`.
4. `6 > 0`? Yes. `richest = 6`.

```text
total = 6, richest = 6
```

**Step 2: customer 1 = `[7, 3]`**

1. `total = 0`.
2. `money = 7`: `total = 0 + 7 = 7`.
3. `money = 3`: `total = 7 + 3 = 10`.
4. `10 > 6`? Yes. `richest = 10`.

```text
total = 10, richest = 10
```

**Step 3: customer 2 = `[3, 5]`**

1. `total = 0`.
2. `money = 3`: `total = 0 + 3 = 3`.
3. `money = 5`: `total = 3 + 5 = 8`.
4. `8 > 10`? No. `richest` stays `10`.

```text
total = 8, richest = 10
```

**Loop ends.** Return `richest = 10`.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: running max of row sums
class Solution:

    # Main method
    def maximumWealth(self, accounts: List[List[int]]) -> int:

        # Biggest wealth seen so far (all values are at least 1)
        richest = 0

        # Go through every customer
        for customer in accounts:

            # Total for this customer
            total = 0

            # Go through every bank of this customer
            for money in customer:

                # Add the money in this bank
                total += money

            # This customer is the richest so far
            if total > richest:

                # Update the richest wealth
                richest = total

        # Return the richest wealth
        return richest


# Helper that records (total, richest) after every customer, to check the trace
def trace_wealth(accounts):

    # Biggest wealth so far
    richest = 0

    # States after each customer
    states = []

    # Same loop as the solution
    for customer in accounts:

        # Total for this customer
        total = 0

        # Add every bank
        for money in customer:

            # Add one bank
            total += money

        # Update the richest
        if total > richest:

            # New richest
            richest = total

        # Save the state
        states.append((total, richest))

    # Return every state
    return states


# Example from this note
accounts = [[1, 5], [7, 3], [3, 5]]

# Step 1 to Step 3
assert trace_wealth(accounts) == [(6, 6), (10, 10), (8, 10)]

# Final answer on the example (LeetCode example 2)
assert Solution().maximumWealth(accounts) == 10

# LeetCode example 1
assert Solution().maximumWealth([[1, 2, 3], [3, 2, 1]]) == 6

# LeetCode example 3
assert Solution().maximumWealth([[2, 8, 7], [7, 1, 3], [1, 9, 5]]) == 17

# Edge case: one customer
assert Solution().maximumWealth([[2, 8, 7]]) == 17

# Edge case: one bank each
assert Solution().maximumWealth([[3], [9], [4]]) == 9

# Edge case: richest is last
assert Solution().maximumWealth([[1, 5], [7, 3], [3, 5], [9, 9]]) == 18

# Brute force gives the same answers
for case in [accounts, [[1, 2, 3], [3, 2, 1]], [[2, 8, 7], [7, 1, 3], [1, 9, 5]], [[2, 8, 7]], [[3], [9], [4]]]:

    # Compare brute force and optimal
    assert SolutionBrute().maximumWealth(case) == Solution().maximumWealth(case)

# All checks passed
print("All tests passed")
```

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(m · n)` | Every cell is added once |
| **Space** | `O(1)` | Only `total` and `richest` |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Not resetting `total` for each row | Totals pile up. Example gives `6, 16, 24` -> `24` | Set `total = 0` inside the outer loop |
| Comparing inside the inner loop | Works, but does extra compares and is easy to get wrong | Compare once after the row is summed |
| Summing columns instead of rows | Adds bank totals, not customer totals | Outer loop over rows (customers) |
| Starting `richest = 0` when values can be negative | All-negative rows return `0` | Use `float("-inf")` if negatives are allowed |

## 7. Interview Follow-ups

### Q1. Can you write it in one line?

**Answer:**
- `return max(sum(row) for row in accounts)`.
- Same `O(m · n)` time, `O(1)` extra space with a generator.

### Q2. What if you need **which** customer is richest?

**Answer:**
- Keep `best_index` next to `richest`.
- Update it when `total > richest`.
- With `>`, ties keep the first customer.

### Q3. What if accounts can be negative (debts)?

**Answer:**
- Start `richest` at `float("-inf")` (or the first row's sum).
- The rest stays the same.

### Q4. What if the grid is huge and stored on disk?

**Answer:**
- Read one row at a time.
- Sum it, compare, then drop it.
- Memory stays `O(n)` for one row.

### Q5. What if we want the richest bank instead of the richest customer?

**Answer:**
- Sum each **column** instead of each row.
- Keep one running total per column, then take the max.

## 8. Interview Explanation

> Each customer's wealth is the sum of their row. I loop over the rows, add up each row into `total`, and after each row I keep the bigger of `total` and `richest`. I do not need to store all the sums, only the best one so far. Every cell is visited once, so it is O(m · n) time, and it uses O(1) extra space.
