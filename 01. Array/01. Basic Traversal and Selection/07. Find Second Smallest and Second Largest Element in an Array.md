# 07. Find Second Smallest and Second Largest Element in an Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Linear Scan / One Pass | [Second Largest](https://www.geeksforgeeks.org/problems/second-largest3735/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an array `nums`.

Find two values:

- the **second largest** distinct value
- the **second smallest** distinct value

Return them as `(second_largest, second_smallest)`.

If one of them does not exist, return `None` in its place.

### Example

```text
Input:  nums = [10, 5, 20, 8, 15]
Output: (15, 8)

Why: sorted, the array is [5, 8, 10, 15, 20].
     Smallest = 5,  second smallest = 8.
     Largest  = 20, second largest  = 15.
```

We use this same example in every section below.

### Constraints

- `0 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- "Second" means a **different value**, not a copy. `[10, 10, 5]` has second largest `5`.

## 2. Core Theory

### What the problem really asks

This is two problems at once:

- Second Largest (note 02): keep `largest` and `second_largest`.
- Second Smallest (note 06): keep `smallest` and `second_smallest`.

We can do both in **the same loop** with four variables.

### The two rules, side by side

```text
Smallest side                               Largest side
num < smallest:                             num > largest:
    second_smallest = smallest                  second_largest = largest
    smallest = num                              largest = num
elif smallest < num < second_smallest:      elif second_largest < num < largest:
    second_smallest = num                       second_largest = num
```

The two sides are **independent**. Use two separate `if` blocks, not one `if/elif` chain. A number like the first element can update both sides.

### Two meanings of "second"

| Meaning | `[10, 10, 20, 20, 5]` second smallest | second largest |
|:---|:---:|:---:|
| Distinct values (this note) | `10` | `10` |
| Position after sorting | `10` | `20` |

Always ask which one the interviewer wants. This note uses distinct values.

### Start values

- `smallest`, `second_smallest` start at `float("inf")`.
- `largest`, `second_largest` start at `float("-inf")`.
- Any start like `0` breaks for all-negative or all-positive arrays.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Empty | `[]` | `(None, None)` | Loop never runs |
| Single element | `[5]` | `(None, None)` | No second value of either kind |
| Two values | `[1, 2]` | `(1, 2)` | The answers cross: second largest is the small one |
| All same | `[5, 5, 5]` | `(None, None)` | Strict comparisons reject copies |
| All negative | `[-10, -3, -20, -7]` | `(-7, -10)` | `-inf` start is required |
| Copies near both ends | `[10, 10, 20, 20, 5]` | `(10, 10)` | Distinct version |
| Falling order | `[5, 4, 3, 2, 1]` | `(4, 2)` | The smallest side moves every step |
| Zero as a value | `[0, -1, 1]` | `(0, 0)` | `0` is real data, not a "missing" mark |

## 4. Brute Force: Sort and Remove Copies

### Idea

Sort the distinct values. Then the second smallest is index `1` and the second largest is index `-2`.

### Code

```python
# Import types for hints
from typing import List, Optional, Tuple


# Brute force: sort the distinct values
class SolutionBrute:

    # Main method
    def getSecondOrderElements(self, nums: List[int]) -> Tuple[Optional[int], Optional[int]]:

        # Remove copies and sort
        values = sorted(set(nums))

        # Fewer than two distinct values means no answer
        if len(values) < 2:

            # Neither value exists
            return None, None

        # Second largest is second from the end, second smallest is index 1
        return values[-2], values[1]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Sorting |
| **Space** | `O(n)` | The set and the sorted list |

## 5. Better Approach: Two Passes

### Idea

1. Pass 1: find `smallest` and `largest`.
2. Pass 2: find the smallest value `> smallest` and the biggest value `< largest`.

### Code

```python
# Better: two simple passes
class SolutionBetter:

    # Main method
    def getSecondOrderElements(self, nums: List[int]) -> Tuple[Optional[int], Optional[int]]:

        # Not enough values
        if len(nums) < 2:

            # Neither value exists
            return None, None

        # Pass 1: smallest value
        smallest = min(nums)

        # Pass 1: largest value
        largest = max(nums)

        # Best second smallest so far
        second_smallest = float("inf")

        # Best second largest so far
        second_largest = float("-inf")

        # Pass 2: look at every number again
        for num in nums:

            # Bigger than smallest, smaller than current second smallest
            if smallest < num < second_smallest:

                # Update second smallest
                second_smallest = num

            # Smaller than largest, bigger than current second largest
            if second_largest < num < largest:

                # Update second largest
                second_largest = num

        # Turn "never found" into None
        if second_smallest == float("inf"):

            # No second smallest
            second_smallest = None

        # Turn "never found" into None
        if second_largest == float("-inf"):

            # No second largest
            second_largest = None

        # Return both
        return second_largest, second_smallest
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Three short scans (`min`, `max`, loop) |
| **Space** | `O(1)` | Four variables |

The optimal version does everything in **one** scan.

## 6. Optimal Approach: One Pass, Four Variables

### Idea

1. If `len(nums) < 2`, return `(None, None)`.
2. Set `smallest = second_smallest = inf` and `largest = second_largest = -inf`.
3. For each `num`, run the smallest-side rule, then the largest-side rule.
4. Turn any value still at `inf` / `-inf` into `None`.
5. Return `(second_largest, second_smallest)`.

### Visual Walkthrough (Story Version)

**The story:** a fruit stall gives two prizes. The **heavy table** keeps the heaviest fruit (`H1`) and the next heaviest (`H2`). The **light table** keeps the lightest fruit (`L1`) and the next lightest (`L2`). Fruits arrive one by one with their weight.

**The rules:**

- Every fruit visits **both** tables.
- Light table: if the fruit is lighter than `L1`, `L1` slides down to `L2` and the fruit takes `L1`. Else, if it is between `L1` and `L2`, it takes `L2`.
- Heavy table: if the fruit is heavier than `H1`, `H1` slides down to `H2` and the fruit takes `H1`. Else, if it is between `H2` and `H1`, it takes `H2`.
- Equal weights never take a spot.

**How to read the pictures:** `[ ]` = fruits in arrival order. `^` = the fruit arriving now. `-` = empty spot.

**Start: all four spots are empty**

```text
[10][ 5][20][ 8][15]

Light table: L1 = -   L2 = -
Heavy table: H1 = -   H2 = -
```

**Step 1: fruit 10 arrives**

- Light: 10 is lighter than empty `L1`. `L1` (empty) slides to `L2`. 10 takes `L1`.
- Heavy: 10 is heavier than empty `H1`. `H1` (empty) slides to `H2`. 10 takes `H1`.

```text
[10][ 5][20][ 8][15]
  ^
Light table: L1 = 10   L2 = -
Heavy table: H1 = 10   H2 = -
```

**Step 2: fruit 5 arrives**

- Light: 5 is lighter than 10. 10 slides to `L2`. 5 takes `L1`.
- Heavy: 5 is not heavier than 10. Is 5 between empty `H2` and 10? Yes. 5 takes `H2`.

```text
[10][ 5][20][ 8][15]
      ^
Light table: L1 = 5    L2 = 10
Heavy table: H1 = 10   H2 = 5
```

**Step 3: fruit 20 arrives**

- Light: 20 is not lighter than 5. Is 20 between 5 and 10? No. Nothing.
- Heavy: 20 is heavier than 10. 10 slides to `H2`. 20 takes `H1`.

```text
[10][ 5][20][ 8][15]
          ^
Light table: L1 = 5    L2 = 10
Heavy table: H1 = 20   H2 = 10
```

**Step 4: fruit 8 arrives**

- Light: 8 is not lighter than 5. Is 8 between 5 and 10? Yes. 8 takes `L2`.
- Heavy: 8 is not heavier than 20. Is 8 between 10 and 20? No. Nothing.

```text
[10][ 5][20][ 8][15]
              ^
Light table: L1 = 5    L2 = 8
Heavy table: H1 = 20   H2 = 10
```

**Step 5: fruit 15 arrives**

- Light: 15 is not lighter than 5. Is 15 between 5 and 8? No. Nothing.
- Heavy: 15 is not heavier than 20. Is 15 between 10 and 20? Yes. 15 takes `H2`.

```text
[10][ 5][20][ 8][15]
                  ^
Light table: L1 = 5    L2 = 8
Heavy table: H1 = 20   H2 = 15
```

**End:** `H2 = 15` and `L2 = 8`. Answer **(15, 8)**.

**All steps at a glance**

| Step | Fruit | L1 | L2 | H1 | H2 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| start | – | - | - | - | - |
| 1 | 10 | 10 | - | 10 | - |
| 2 | 5 | 5 | 10 | 10 | 5 |
| 3 | 20 | 5 | 10 | 20 | 10 |
| 4 | 8 | 5 | 8 | 20 | 10 |
| 5 | 15 | 5 | 8 | 20 | 15 |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Fruit | `num` |
| `L1`, `L2` | `smallest`, `second_smallest` |
| `H1`, `H2` | `largest`, `second_largest` |
| Empty spot | `inf` on the light side, `-inf` on the heavy side |
| Every fruit visits both tables | Two separate `if` blocks in one loop |
| Slides down | `second_x = x` before `x = num` |
| Spot still empty at the end | Return `None` for it |

Now the same steps again, with the exact variables.

### Step-by-Step Example

```text
nums = [10, 5, 20, 8, 15]
```

**Start**

```text
smallest = inf, second_smallest = inf
largest = -inf, second_largest = -inf
```

**Step 1: `num = 10`**

1. Smallest side: `10 < inf`? Yes. `second_smallest = inf`, `smallest = 10`.
2. Largest side: `10 > -inf`? Yes. `second_largest = -inf`, `largest = 10`.

```text
smallest = 10, second_smallest = inf
largest = 10, second_largest = -inf
```

**Step 2: `num = 5`**

1. Smallest side: `5 < 10`? Yes. `second_smallest = 10`, `smallest = 5`.
2. Largest side: `5 > 10`? No. `-inf < 5 < 10`? Yes. `second_largest = 5`.

```text
smallest = 5, second_smallest = 10
largest = 10, second_largest = 5
```

**Step 3: `num = 20`**

1. Smallest side: `20 < 5`? No. `5 < 20 < 10`? No. No change.
2. Largest side: `20 > 10`? Yes. `second_largest = 10`, `largest = 20`.

```text
smallest = 5, second_smallest = 10
largest = 20, second_largest = 10
```

**Step 4: `num = 8`**

1. Smallest side: `8 < 5`? No. `5 < 8 < 10`? Yes. `second_smallest = 8`.
2. Largest side: `8 > 20`? No. `10 < 8 < 20`? No. No change.

```text
smallest = 5, second_smallest = 8
largest = 20, second_largest = 10
```

**Step 5: `num = 15`**

1. Smallest side: `15 < 5`? No. `5 < 15 < 8`? No. No change.
2. Largest side: `15 > 20`? No. `10 < 15 < 20`? Yes. `second_largest = 15`.

```text
smallest = 5, second_smallest = 8
largest = 20, second_largest = 15
```

**Loop ends.** Neither answer is infinity. Return `(15, 8)`.

### Code

```python
# Import types for hints
from typing import List, Optional, Tuple


# Optimal: one pass with four variables
class Solution:

    # Main method
    def getSecondOrderElements(self, nums: List[int]) -> Tuple[Optional[int], Optional[int]]:

        # Fewer than two values: no second of either kind
        if len(nums) < 2:

            # Neither value exists
            return None, None

        # Smallest value seen so far
        smallest = float("inf")

        # Second smallest distinct value seen so far
        second_smallest = float("inf")

        # Largest value seen so far
        largest = float("-inf")

        # Second largest distinct value seen so far
        second_largest = float("-inf")

        # Look at every number once
        for num in nums:

            # Smallest side: new minimum
            if num < smallest:

                # Old minimum moves up to second
                second_smallest = smallest

                # New minimum
                smallest = num

            # Smallest side: better runner-up
            elif smallest < num < second_smallest:

                # Update second smallest
                second_smallest = num

            # Largest side: new maximum
            if num > largest:

                # Old maximum moves down to second
                second_largest = largest

                # New maximum
                largest = num

            # Largest side: better runner-up
            elif second_largest < num < largest:

                # Update second largest
                second_largest = num

        # Second smallest never found
        if second_smallest == float("inf"):

            # Report it as missing
            second_smallest = None

        # Second largest never found
        if second_largest == float("-inf"):

            # Report it as missing
            second_largest = None

        # Second largest first, then second smallest
        return second_largest, second_smallest


# Helper that records all four variables after every step, to check the trace
def trace_second_order(nums):

    # Light side start values
    smallest = second_smallest = float("inf")

    # Heavy side start values
    largest = second_largest = float("-inf")

    # States after each step
    states = []

    # Same loop as the solution
    for num in nums:

        # New minimum
        if num < smallest:

            # Old minimum moves up
            second_smallest = smallest

            # New minimum
            smallest = num

        # Better second smallest
        elif smallest < num < second_smallest:

            # Update it
            second_smallest = num

        # New maximum
        if num > largest:

            # Old maximum moves down
            second_largest = largest

            # New maximum
            largest = num

        # Better second largest
        elif second_largest < num < largest:

            # Update it
            second_largest = num

        # Save the state as (smallest, second_smallest, largest, second_largest)
        states.append((smallest, second_smallest, largest, second_largest))

    # Return every state
    return states


# Infinity values used in the trace checks
INF = float("inf")

# Negative infinity
NEG = float("-inf")

# Example from this note
nums = [10, 5, 20, 8, 15]

# Step 1 to Step 5
assert trace_second_order(nums) == [
    (10, INF, 10, NEG),
    (5, 10, 10, 5),
    (5, 10, 20, 10),
    (5, 8, 20, 10),
    (5, 8, 20, 15),
]

# Final answer on the example
assert Solution().getSecondOrderElements(nums) == (15, 8)

# Edge case: empty
assert Solution().getSecondOrderElements([]) == (None, None)

# Edge case: single element
assert Solution().getSecondOrderElements([5]) == (None, None)

# Edge case: two values cross over
assert Solution().getSecondOrderElements([1, 2]) == (1, 2)

# Edge case: all same
assert Solution().getSecondOrderElements([5, 5, 5]) == (None, None)

# Edge case: all negative
assert Solution().getSecondOrderElements([-10, -3, -20, -7]) == (-7, -10)

# Edge case: copies near both ends
assert Solution().getSecondOrderElements([10, 10, 20, 20, 5]) == (10, 10)

# Edge case: falling order
assert Solution().getSecondOrderElements([5, 4, 3, 2, 1]) == (4, 2)

# Edge case: zero is a real value
assert Solution().getSecondOrderElements([0, -1, 1]) == (0, 0)

# Brute force and better agree with optimal
for case in [nums, [], [5], [1, 2], [5, 5, 5], [-10, -3, -20, -7], [10, 10, 20, 20, 5], [5, 4, 3, 2, 1], [1, 1, 2, 2], [0, -1, 1]]:

    # Compare all three
    assert SolutionBrute().getSecondOrderElements(case) == SolutionBetter().getSecondOrderElements(case) == Solution().getSecondOrderElements(case)

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One scan, a constant number of checks per element |
| **Space** | `O(1)` | Four variables |

## 7. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| One `if/elif` chain for both sides | When the smallest side updates, the largest side is skipped. Step 1 would leave `largest = -inf` | Use two separate `if` blocks |
| Overwriting before moving down | `largest = num` then `second_largest = largest` makes both equal | Move the old value first |
| Using `<=` or `>=` | Copies become "second". `[5, 5, 5]` returns `(5, 5)` | Use strict comparisons |
| Starting at `0` | All-negative or all-positive arrays give wrong answers | Start at `inf` and `-inf` |
| Returning the order backwards | Returns `(8, 15)` | The expected order is `(second_largest, second_smallest)` |

## 8. Interview Follow-ups

### Q1. Why not just sort?

**Answer:**
- Sorting is `O(n log n)` and orders all `n` values.
- We only need four values, so one `O(n)` pass is enough.

### Q2. What if copies should count ("position after sorting")?

**Answer:**
- Use `<=` for the new-minimum check and `>=` for the new-maximum check.
- Then `[10, 10, 20, 20, 5]` gives second smallest `10` and second largest `20`.

### Q3. How many comparisons does the one-pass version make?

**Answer:**
- Up to 4 per element: about `4n` in the worst case.
- That is still `O(n)`. The pair trick from note 01 can cut the min/max part.

### Q4. How do you extend this to the k-th largest and k-th smallest?

**Answer:**
- Keep a min-heap of size `k` for the largest side and a max-heap of size `k` for the smallest side.
- Use a set to skip copies.
- Time `O(n log k)`.

### Q5. Does this work on a stream?

**Answer:**
- Yes. Four variables, one look at each number.

## 9. Interview Explanation

> I solve second largest and second smallest in the same loop with four variables. The smallest side keeps `smallest` and `second_smallest`, starting at infinity. The largest side keeps `largest` and `second_largest`, starting at negative infinity. For each number I run both sides with two separate if blocks. When a new extreme appears, the old one moves to the second spot first. Strict comparisons skip copies. Anything still at infinity at the end becomes None. This is O(n) time and O(1) space.
