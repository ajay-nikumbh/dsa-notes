# 32. 1431. Kids With the Greatest Number of Candies

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Traversal: Find Max, Then Compare | [1431. Kids With the Greatest Number of Candies](https://leetcode.com/problems/kids-with-the-greatest-number-of-candies/) | `O(n)` | `O(1)` extra |

## 1. Problem Statement

There are `n` kids. Kid `i` has `candies[i]` candies. You also have `extraCandies`.

For each kid, imagine giving **all** the `extraCandies` to that kid only. Would that kid then have the **greatest** number of candies among all kids? (Ties count as greatest.)

Return a list of `n` booleans: `result[i]` is `True` if kid `i` would have the greatest number.

### Example

```text
candies = [2, 3, 5, 1, 3]
extraCandies = 3

Current max = 5

Kid 0: 2 + 3 = 5  >= 5  -> True
Kid 1: 3 + 3 = 6  >= 5  -> True
Kid 2: 5 + 3 = 8  >= 5  -> True
Kid 3: 1 + 3 = 4  <  5  -> False
Kid 4: 3 + 3 = 6  >= 5  -> True

Output: [True, True, True, False, True]
```

We use this same example in every section below.

### Constraints

- `n == candies.length`
- `2 <= n <= 100`
- `1 <= candies[i] <= 100`
- `1 <= extraCandies <= 50`

## 2. Core Theory

### What the problem really asks

When kid `i` gets the extra candies, only kid `i` changes. Everyone else stays the same.

So kid `i` becomes the greatest if they reach the **biggest pile among the others**. That is never more than the overall max. And if kid `i` already holds the max, they win anyway.

So the rule simplifies to:

```text
result[i] = candies[i] + extraCandies >= max(candies)
```

### Why two short passes fit

- Pass 1: find `max(candies)` once.
- Pass 2: compare each kid against that one number.

```text
candies:  [2][3][5][1][3]      max = 5
+ extra:   5  6  8  4  6
>= 5 ?     T  T  T  F  T
```

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Ties count | `[2, 3]`, extra `1` | `[True, True]` | `2 + 1 = 3 >= 3`. Use `>=` |
| Only the top kid wins | `[4, 2, 1, 1, 2]`, extra `1` | `[T, F, F, F, F]` | Only kid 0 reaches `4`. A small extra may help nobody else |
| Two kids share the max | `[12, 1, 12]`, extra `10` | `[T, F, T]` | Both max kids win; `1 + 10 = 11 < 12` |
| Max kid always wins | `[5, 1]`, extra `1` | `[True, False]` | Kid with max is `True` for any extra |
| Two kids, big extra | `[1, 100]`, extra `50` | `[False, True]` | `51 < 100` |

## 4. Brute Force: Compare Each Kid With Every Other Kid

### Idea

For each kid `i`, add the extra candies and check against every other kid one by one.

### Code

```python
# Import List for type hints
from typing import List


# Compare each kid with all other kids
class SolutionBrute:

    # Main method
    def kidsWithCandies(self, candies: List[int], extraCandies: int) -> List[bool]:

        # Number of kids
        n = len(candies)

        # Answer list
        result = []

        # Try each kid
        for i in range(n):

            # Kid i's candies after getting the extra
            mine = candies[i] + extraCandies

            # Assume kid i is the greatest
            greatest = True

            # Compare with every other kid
            for j in range(n):

                # Someone else has more
                if j != i and candies[j] > mine:

                    # Kid i is not the greatest
                    greatest = False

                    # Stop comparing
                    break

            # Save the answer for kid i
            result.append(greatest)

        # Return all answers
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Each kid is compared with every other kid |
| **Space** | `O(1)` extra | Only the output list |

## 5. Optimal Approach: Find the Max Once

### Idea

1. Find `max_candies = max(candies)`.
2. For each kid, `result[i] = candies[i] + extraCandies >= max_candies`.

### Code

```python
# Import List for type hints
from typing import List


# Solution for 1431. Kids With the Greatest Number of Candies
class Solution:

    # Main method
    def kidsWithCandies(self, candies: List[int], extraCandies: int) -> List[bool]:

        # Pass 1: biggest pile right now
        max_candies = max(candies)

        # Answer list
        result = []

        # Pass 2: check each kid
        for c in candies:

            # True if this kid reaches the biggest pile with the extra
            result.append(c + extraCandies >= max_candies)

        # Return all answers
        return result


# The example from this note

# Full answer from the method

# Check every pass 2 step

    # The answer for this kid must match the trace
    assert answer[:step + 1] == expected_result[:step + 1]

# Full example

# LeetCode example 2

# LeetCode example 3
```

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Using `>` instead of `>=` | Ties count as greatest, so `[2, 3]` with extra `1` gives kid 0 `False` | Use `>=` |
| Calling `max(candies)` inside the loop | `O(n^2)` time | Compute the max once before the loop |
| Adding the extra to everyone, then taking the max | The max goes up and nobody but the top kid wins | Only kid `i` gets the extra; compare with the original max |
| Splitting the extra candies | The problem gives all of it to one kid | Add the full `extraCandies` |

## 7. Interview Follow-ups

### Q1. Why is comparing with the overall max correct, even for the max kid?

**Answer:**
- The max kid already has `max_candies`.
- `max_candies + extra >= max_candies` is always true.
- For others, the overall max is the pile to beat, so the rule holds.

### Q2. Can you write it in one line?

**Answer:**
- `m = max(candies); return [c + extraCandies >= m for c in candies]`.
- Same `O(n)`.

### Q3. What if the extra candies could be split among several kids?

**Answer:**
- Then the question changes: how many kids can reach the max at once?
- Sort kids by how many candies they are short, and give greedily to the closest ones.

### Q4. What if candies change often and the question is asked many times?

**Answer:**
- Keep the max in a structure that updates fast, like a max-heap with lazy deletion or a sorted container.
- Each question then needs only the current max.

## 8. Interview Explanation

> Giving the extra candies to one kid changes only that kid, so the kid wins if their new total reaches the current biggest pile. I find the max once, then for each kid I check whether candies[i] plus extraCandies is at least that max, counting ties as wins. That is two short passes, O(n) time, and O(1) extra space besides the output list.
