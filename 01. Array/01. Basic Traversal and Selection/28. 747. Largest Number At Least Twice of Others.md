# 28. 747. Largest Number At Least Twice of Others

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Traversal: Largest and Second Largest | [747. Largest Number At Least Twice of Others](https://leetcode.com/problems/largest-number-at-least-twice-of-others/) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an integer array `nums`. The largest number in `nums` is **unique**.

Check if the largest number is **at least twice** as big as every other number.

- If yes, return the **index** of the largest number.
- If no, return `-1`.

### Example

```text
nums = [3, 6, 1, 0]
index:  0  1  2  3

Largest = 6 at index 1.
6 >= 2 * 3 = 6   yes
6 >= 2 * 1 = 2   yes
6 >= 2 * 0 = 0   yes

Output: 1
```

We use this same example in every section below.

### Constraints

- `2 <= nums.length <= 50`
- `0 <= nums[i] <= 100`
- The largest element in `nums` is unique

## 2. Core Theory

### What the problem really asks

"Largest is at least twice **every** other number" sounds like many checks.

But if the largest beats twice the **second largest**, it beats twice everything smaller too.

```text
largest >= 2 * second
second  >= every other number
So: largest >= 2 * every other number
```

So we only need two values: the largest (with its index) and the second largest.

### Why one pass is enough

This is the classic "largest and second largest" scan:

```text
x > largest              -> old largest becomes second, x becomes largest
largest > x > second     -> x becomes second
otherwise                -> nothing changes
```

At the end, one check: `largest >= 2 * second`.

```text
[3][6][1][0]
     ^
  largest = 6, second = 3
  6 >= 2 * 3  ->  answer = index 1
```

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Exactly twice | `[3, 6, 1, 0]` | `1` | `6 >= 6`. Use `>=`, not `>` |
| Not twice | `[1, 2, 3, 4]` | `-1` | `4 < 2 * 3` |
| Two elements, other is 0 | `[0, 1]` | `1` | `1 >= 0`. Zero is always fine |
| Largest at index 0 | `[10, 2, 5]` | `0` | Index tracking must work from the start |
| Largest at the end | `[1, 0, 5]` | `2` | The last element can be the answer |
| Second largest is 0 | `[0, 0, 3]` | `2` | `3 >= 0` |

## 4. Brute Force: Check Every Candidate Against Everyone

### Idea

For every index `i`, check if `nums[i] >= 2 * nums[j]` for every other `j`. Return the first `i` that passes.

### Code

```python
# Import List for type hints
from typing import List


# Try every index as the answer
class SolutionBrute:

    # Main method
    def dominantIndex(self, nums: List[int]) -> int:

        # Number of elements
        n = len(nums)

        # Try every index as the candidate
        for i in range(n):

            # Assume this candidate works
            ok = True

            # Compare with every other index
            for j in range(n):

                # A different element that is too big breaks the rule
                if j != i and nums[i] < 2 * nums[j]:

                    # This candidate fails
                    ok = False

                    # No need to check more
                    break

            # The candidate passed every check
            if ok:
                return i

        # No index works
        return -1
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Two nested loops |
| **Space** | `O(1)` | Only a few variables |

## 5. Better Approach: Two Passes

### Idea

1. First pass: find the index of the largest number.
2. Second pass: check `largest >= 2 * x` for every other `x`.

### Code

```python
# Find the largest first, then check everyone
class SolutionBetter:

    # Main method
    def dominantIndex(self, nums: List[int]) -> int:

        # Index of the largest so far
        best = 0

        # First pass: find the largest
        for i in range(1, len(nums)):

            # Found a bigger number
            if nums[i] > nums[best]:

                # Remember its index
                best = i

        # Second pass: check every other number
        for i in range(len(nums)):

            # Another number is more than half of the largest
            if i != best and nums[best] < 2 * nums[i]:
                return -1

        # Every check passed
        return best
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Two passes |
| **Space** | `O(1)` | Only an index |

## 6. Optimal Approach: Largest and Second Largest in One Pass

### Idea

1. Track `largest`, `second` and `idx` (index of `largest`). Start with `-1` (all inputs are `>= 0`).
2. If `x > largest`: `second = largest`, `largest = x`, `idx = i`.
3. Else if `x > second`: `second = x`.
4. At the end, return `idx` if `largest >= 2 * second`, else `-1`.

### Visual Walkthrough (Story Version)

**The story:** four trees grow in a row. A giant wants to sit on the tallest tree, but only if that tree is **at least twice as tall** as every other tree. A bird flies along the row. It remembers just two things: the tallest tree so far (and where it is), and the runner-up.

**How to read the pictures:** each box is a tree height. `^` is where the bird is. `T` = tallest so far, `R` = runner-up so far.

**Start**

```text
trees: [3][6][1][0]
bird remembers: tallest = none, runner-up = none
```

**Step 1: bird at tree 0, height 3**

```text
trees: [3][6][1][0]
        ^
        T
3 is taller than "none". Tree 0 is the tallest. Runner-up is still none.
tallest = 3 (at 0), runner-up = none
```

**Step 2: bird at tree 1, height 6**

```text
trees: [3][6][1][0]
        R  ^
           T
6 is taller than 3. Old tallest (3) becomes runner-up. Tree 1 is the tallest.
tallest = 6 (at 1), runner-up = 3
```

**Step 3: bird at tree 2, height 1**

```text
trees: [3][6][1][0]
        R  T  ^
1 is not taller than 6. 1 is not taller than 3. Nothing changes.
tallest = 6 (at 1), runner-up = 3
```

**Step 4: bird at tree 3, height 0**

```text
trees: [3][6][1][0]
        R  T     ^
0 is not taller than 6. 0 is not taller than 3. Nothing changes.
tallest = 6 (at 1), runner-up = 3
```

**End: can the giant sit?**

```text
tallest 6  vs  2 x runner-up = 2 x 3 = 6
6 >= 6  ->  yes! The giant sits on tree 1.
```

**All steps at a glance**

| Step | Tree | Height | What happens | Tallest | Runner-up | Index |
|:---:|:---:|:---:|:---|:---:|:---:|:---:|
| start | – | – | Nothing seen | -1 | -1 | -1 |
| 1 | 0 | 3 | New tallest | 3 | -1 | 0 |
| 2 | 1 | 6 | New tallest, 3 drops to runner-up | 6 | 3 | 1 |
| 3 | 2 | 1 | No change | 6 | 3 | 1 |
| 4 | 3 | 0 | No change | 6 | 3 | 1 |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Tree height | `nums[i]` |
| Tallest so far | `largest` |
| Where the tallest is | `idx` |
| Runner-up | `second` |
| Twice as tall as runner-up | `largest >= 2 * second` |
| Giant sits on tree 1 | Return `idx` |

### Step-by-Step Example

```text
nums = [3, 6, 1, 0]
```

**Start:** `largest = -1, second = -1, idx = -1`

**Step 1: `i = 0`, `x = 3`**

1. Is `3 > largest (-1)`? Yes.
2. `second = -1`, `largest = 3`, `idx = 0`.

**Step 2: `i = 1`, `x = 6`**

1. Is `6 > largest (3)`? Yes.
2. `second = 3`, `largest = 6`, `idx = 1`.

**Step 3: `i = 2`, `x = 1`**

1. Is `1 > largest (6)`? No.
2. Is `1 > second (3)`? No.
3. Nothing changes: `largest = 6, second = 3, idx = 1`.

**Step 4: `i = 3`, `x = 0`**

1. Is `0 > largest (6)`? No.
2. Is `0 > second (3)`? No.
3. Nothing changes: `largest = 6, second = 3, idx = 1`.

**Final check**

1. `2 * second = 2 * 3 = 6`.
2. Is `6 >= 6`? Yes.
3. Return `idx = 1`.

### Code

```python
# Import List for type hints
from typing import List


# Solution for 747. Largest Number At Least Twice of Others
class Solution:

    # Return (largest, second largest, index of largest)
    def _track(self, nums: List[int]):

        # Values are >= 0, so -1 means "nothing yet"
        largest = second = idx = -1

        # Look at every number with its index
        for i, x in enumerate(nums):

            # New largest found
            if x > largest:

                # Old largest becomes the second
                second = largest

                # Save the new largest
                largest = x

                # Save where it is
                idx = i

            # Not the largest, but beats the second
            elif x > second:

                # Save the new second
                second = x

        # Return what we tracked
        return largest, second, idx

    # Main method
    def dominantIndex(self, nums: List[int]) -> int:

        # Get the largest, the second and the index
        largest, second, idx = self._track(nums)

        # Largest is at least twice the second, so twice everyone
        if largest >= 2 * second:
            return idx

        # Otherwise no index works
        return -1


# The example from this note
nums = [3, 6, 1, 0]

# State (largest, second, idx) after each traced step
expected = [(3, -1, 0), (6, 3, 1), (6, 3, 1), (6, 3, 1)]

# Check every traced step on the prefix
for step in range(4):

    # State after step + 1 numbers must match the trace
    assert Solution()._track(nums[:step + 1]) == expected[step]

# Full example
assert Solution().dominantIndex(nums) == 1

# LeetCode example 2: not twice
assert Solution().dominantIndex([1, 2, 3, 4]) == -1

# Edge case: two elements, other is 0
assert Solution().dominantIndex([0, 1]) == 1

# Edge case: largest at index 0
assert Solution().dominantIndex([10, 2, 5]) == 0

# Edge case: largest at the end
assert Solution().dominantIndex([1, 0, 5]) == 2

# Edge case: second largest is 0
assert Solution().dominantIndex([0, 0, 3]) == 2

# Brute force and better approach give the same answers
for arr in [nums, [1, 2, 3, 4], [0, 1], [10, 2, 5], [1, 0, 5], [0, 0, 3], [2, 9, 4]]:

    # Brute force must agree
    assert SolutionBrute().dominantIndex(arr) == Solution().dominantIndex(arr)

    # Better approach must agree
    assert SolutionBetter().dominantIndex(arr) == Solution().dominantIndex(arr)

# All checks passed
print("All tests passed")
```

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass, then one check |
| **Space** | `O(1)` | Three variables |

## 7. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Using `>` in the final check | `[3, 6, 1, 0]` returns `-1`, but `6 >= 6` is allowed | Use `largest >= 2 * second` |
| Forgetting to move old largest to second | `second` misses a real value, e.g. `[3, 6]` ends with `second = -1` | Set `second = largest` before updating `largest` |
| Comparing the largest with itself in the check | `x >= 2 * x` fails for any `x > 0` | Skip the largest's own index |
| Returning the value instead of the index | Wrong output type | Track `idx` and return it |
| Using `x / 2` with integer division | `5 // 2 = 2` rounds down and changes the answer | Multiply instead: `largest >= 2 * second` |

## 8. Interview Follow-ups

### Q1. Why is comparing with the second largest enough?

**Answer:**
- Every other number is `<= second`.
- So `2 * other <= 2 * second <= largest`.
- One check covers everyone.

### Q2. What if the largest was not unique?

**Answer:**
- Two copies of the largest `m` would need `m >= 2 * m`, which only holds when `m = 0`.
- With the "skip equals" rule from Third Maximum you could define it on distinct values, but you must ask the interviewer.

### Q3. What if numbers can be negative?

**Answer:**
- `2 * negative` is even smaller, so the rule behaves differently.
- Start trackers at `float('-inf')` instead of `-1`.
- Clarify whether "twice" should use absolute values.

### Q4. Generalize to "at least k times every other number".

**Answer:**
- Same scan.
- Final check becomes `largest >= k * second`.

## 9. Interview Explanation

> If the largest number is at least twice the second largest, it is at least twice every other number, because every other number is at most the second largest. So in one pass I track the largest value, its index, and the second largest. When a new largest comes, the old largest moves down to second. At the end I return the index if largest is at least two times second, otherwise -1. This is O(n) time and O(1) space.
