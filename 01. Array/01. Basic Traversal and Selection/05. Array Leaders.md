# 05. Array Leaders

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Right-to-Left Suffix Maximum | [Array Leaders](https://www.geeksforgeeks.org/problems/leaders-in-an-array-1587115620/1) | `O(n)` | `O(1)` extra |

## 1. Problem Statement

You get an array `arr` of positive integers.

An element is a **leader** if it is **greater than or equal to** every element on its right.

The rightmost element is always a leader.

Return all leaders in their original left-to-right order.

### Example

```text
Input:  arr = [16, 17, 4, 3, 5, 2]
Output: [17, 5, 2]

Why:
16 -> not a leader, 17 is on its right
17 -> leader, everything on its right (4, 3, 5, 2) is smaller
 4 -> not a leader, 5 is on its right
 3 -> not a leader, 5 is on its right
 5 -> leader, only 2 is on its right
 2 -> leader, nothing is on its right
```

We use this same example in every section below.

### Constraints

- `1 <= arr.size() <= 10^6`
- `0 <= arr[i] <= 10^6`

## 2. Core Theory

### What the problem really asks

`arr[i]` is a leader when:

```text
arr[i] >= max(arr[i+1], arr[i+2], ..., arr[n-1])
```

So for every index we need **the biggest value to its right**.

### Why walk from the right

- From the left, the "right side" is still unknown. We would need to look ahead every time.
- From the right, we have already seen everything on the right side.
- So we keep one variable: `max_right`, the biggest value seen so far from the right.

```text
arr:        [16][17][ 4][ 3][ 5][ 2]
walk:        <-  <-  <-  <-  <-  start
max_right:   17  17   5   5   5   2   (after looking at each index)
leader?      no yes  no  no yes yes
```

### The rule

- If `arr[i] >= max_right`, then `arr[i]` is a leader. Set `max_right = arr[i]`.
- Otherwise, skip it.
- We collect leaders from right to left, so reverse the list at the end.

### Why `>=` and not `>`

- The problem says "greater than or equal".
- `[10, 4, 2, 4, 1]` -> both `4`s are leaders.
- With `>`, the first `4` would be missed.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[5]` | `[5]` | The last element is always a leader |
| Copies | `[10, 4, 2, 4, 1]` | `[10, 4, 4, 1]` | Needs `>=`, not `>` |
| Rising order | `[5, 10, 20, 40]` | `[40]` | Only the last one |
| Falling order | `[30, 10, 10, 5]` | `[30, 10, 10, 5]` | Everyone is a leader |
| All same | `[10, 10, 10]` | `[10, 10, 10]` | Equal counts as a leader |
| Zeros | `[0, 0]` | `[0, 0]` | Start `max_right` at `-inf`, not `0` with `>` |

## 4. Brute Force: Check the Right Side of Every Element

### Idea

For each index `i`, look at every element after it. If none is bigger, `arr[i]` is a leader.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: check every element against its whole right side
class SolutionBrute:

    # Main method
    def leaders(self, arr: List[int]) -> List[int]:

        # Number of elements
        n = len(arr)

        # Leaders found
        result = []

        # Try every element
        for i in range(n):

            # Assume it is a leader
            is_leader = True

            # Look at every element on its right
            for j in range(i + 1, n):

                # Something on the right is bigger
                if arr[j] > arr[i]:

                    # Not a leader
                    is_leader = False

                    # No need to check more
                    break

            # Nothing on the right was bigger
            if is_leader:

                # Add it to the answer
                result.append(arr[i])

        # Leaders are already in left-to-right order
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Each element may scan its whole right side |
| **Space** | `O(1)` extra | Not counting the answer list |

The right side of index `i` and index `i + 1` overlap almost fully. We keep re-reading the same numbers.

## 5. Optimal Approach: Walk from the Right with a Running Max

### Idea

1. `max_right = -inf`, `result = []`.
2. For `i` from `n - 1` down to `0`:
   - If `arr[i] >= max_right`: add `arr[i]` to `result`, set `max_right = arr[i]`.
3. Reverse `result` and return it.

### Visual Walkthrough (Story Version)

**The story:** six kids stand in a line, all facing **right**. Each kid has a height number. A kid is a **leader** if no one in front of them (to the right) is taller. A helper walks from the **back of the line** (the right end) toward the front, holding a sign with the **tallest height seen so far**.

**The rules:**

- The sign starts blank (nobody seen yet).
- At each kid: if the kid is at least as tall as the sign, the kid is a leader. Write the kid's height on the sign.
- If the kid is shorter than the sign, someone taller is ahead. Not a leader.

**How to read the pictures:** `[ ]` = kids by height. `^` = where the helper stands. `L` = leader. `sign` = tallest seen from the right.

**Start: the helper stands at the right end**

```text
[16][17][ 4][ 3][ 5][ 2]

sign = -   leaders = []
```

**Step 1: kid 2 (index 5)**

- Is 2 >= blank sign? Yes. Nobody is in front.
- Kid 2 is a leader. Sign = 2.

```text
[16][17][ 4][ 3][ 5][ 2]
                     ^ L
sign = 2   leaders = [2]
```

**Step 2: kid 5 (index 4)**

- Is 5 >= 2? Yes.
- Kid 5 is a leader. Sign = 5.

```text
[16][17][ 4][ 3][ 5][ 2]
                 ^ L  L
sign = 5   leaders = [2, 5]
```

**Step 3: kid 3 (index 3)**

- Is 3 >= 5? No. Kid 5 is taller and in front.
- Not a leader. Sign stays 5.

```text
[16][17][ 4][ 3][ 5][ 2]
             ^   L   L
sign = 5   leaders = [2, 5]
```

**Step 4: kid 4 (index 2)**

- Is 4 >= 5? No.
- Not a leader. Sign stays 5.

```text
[16][17][ 4][ 3][ 5][ 2]
         ^       L   L
sign = 5   leaders = [2, 5]
```

**Step 5: kid 17 (index 1)**

- Is 17 >= 5? Yes.
- Kid 17 is a leader. Sign = 17.

```text
[16][17][ 4][ 3][ 5][ 2]
     ^ L         L   L
sign = 17   leaders = [2, 5, 17]
```

**Step 6: kid 16 (index 0)**

- Is 16 >= 17? No. Kid 17 is taller and in front.
- Not a leader. Sign stays 17.

```text
[16][17][ 4][ 3][ 5][ 2]
 ^    L          L   L
sign = 17   leaders = [2, 5, 17]
```

**End:** we collected leaders back to front. Flip the list: **[17, 5, 2]**.

**All steps at a glance**

| Step | Index | Kid | Kid >= sign? | Leader? | Sign after | Leaders so far |
|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| start | – | – | – | – | - | `[]` |
| 1 | 5 | 2 | Yes | Yes | 2 | `[2]` |
| 2 | 4 | 5 | Yes | Yes | 5 | `[2, 5]` |
| 3 | 3 | 3 | No | No | 5 | `[2, 5]` |
| 4 | 2 | 4 | No | No | 5 | `[2, 5]` |
| 5 | 1 | 17 | Yes | Yes | 17 | `[2, 5, 17]` |
| 6 | 0 | 16 | No | No | 17 | `[2, 5, 17]` |
| flip | – | – | – | – | – | `[17, 5, 2]` |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Kid's height | `arr[i]` |
| Helper walks from the back | `for i in range(n - 1, -1, -1)` |
| Sign with the tallest seen | `max_right` |
| Blank sign | `float("-inf")` |
| Kid at least as tall as the sign | `arr[i] >= max_right` |
| Write a new height on the sign | `max_right = arr[i]` |
| Flip the list at the end | `result.reverse()` |

Now the same steps again, with the exact variables.

### Step-by-Step Example

```text
arr = [16, 17, 4, 3, 5, 2]
n = 6
```

**Start**

```text
max_right = -inf, result = []
```

**Step 1: `i = 5`, `arr[5] = 2`**

1. `2 >= -inf`? Yes.
2. `result = [2]`.
3. `max_right = 2`.

**Step 2: `i = 4`, `arr[4] = 5`**

1. `5 >= 2`? Yes.
2. `result = [2, 5]`.
3. `max_right = 5`.

**Step 3: `i = 3`, `arr[3] = 3`**

1. `3 >= 5`? No.
2. Nothing changes. `result = [2, 5]`, `max_right = 5`.

**Step 4: `i = 2`, `arr[2] = 4`**

1. `4 >= 5`? No.
2. Nothing changes. `result = [2, 5]`, `max_right = 5`.

**Step 5: `i = 1`, `arr[1] = 17`**

1. `17 >= 5`? Yes.
2. `result = [2, 5, 17]`.
3. `max_right = 17`.

**Step 6: `i = 0`, `arr[0] = 16`**

1. `16 >= 17`? No.
2. Nothing changes. `result = [2, 5, 17]`, `max_right = 17`.

**After the loop**

```text
result.reverse()  ->  [17, 5, 2]
```

Return `[17, 5, 2]`.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: walk from the right and keep the biggest value seen
class Solution:

    # Main method
    def leaders(self, arr: List[int]) -> List[int]:

        # Number of elements
        n = len(arr)

        # Leaders found, from right to left
        result = []

        # Biggest value seen so far from the right
        max_right = float("-inf")

        # Walk from the last index to the first
        for i in range(n - 1, -1, -1):

            # Nothing on the right is bigger
            if arr[i] >= max_right:

                # It is a leader
                result.append(arr[i])

                # It is now the biggest value seen from the right
                max_right = arr[i]

        # Put leaders back in left-to-right order
        result.reverse()

        # Return the leaders
        return result


# Helper that records (max_right, result) after every step, to check the trace
def trace_leaders(arr):

    # Leaders found so far
    result = []

    # Biggest value from the right
    max_right = float("-inf")

    # States after each step
    states = []

    # Same loop as the solution
    for i in range(len(arr) - 1, -1, -1):

        # Leader check
        if arr[i] >= max_right:

            # Add the leader
            result.append(arr[i])

            # Update the running max
            max_right = arr[i]

        # Save a copy of the state
        states.append((max_right, list(result)))

    # Return every state
    return states


# Example from this note
arr = [16, 17, 4, 3, 5, 2]

# Step 1 to Step 6
assert trace_leaders(arr) == [
    (2, [2]),
    (5, [2, 5]),
    (5, [2, 5]),
    (5, [2, 5]),
    (17, [2, 5, 17]),
    (17, [2, 5, 17]),
]

# Final answer on the example
assert Solution().leaders(arr) == [17, 5, 2]

# GfG example 2: copies are leaders too
assert Solution().leaders([10, 4, 2, 4, 1]) == [10, 4, 4, 1]

# GfG example 3: rising order
assert Solution().leaders([5, 10, 20, 40]) == [40]

# GfG example 4: falling order
assert Solution().leaders([30, 10, 10, 5]) == [30, 10, 10, 5]

# Edge case: single element
assert Solution().leaders([5]) == [5]

# Edge case: all same
assert Solution().leaders([10, 10, 10]) == [10, 10, 10]

# Edge case: zeros
assert Solution().leaders([0, 0]) == [0, 0]

# Brute force gives the same answers
for case in [arr, [10, 4, 2, 4, 1], [5, 10, 20, 40], [30, 10, 10, 5], [5], [10, 10, 10], [0, 0]]:

    # Compare brute force and optimal
    assert SolutionBrute().leaders(case) == Solution().leaders(case)

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One scan from the right, plus one reverse |
| **Space** | `O(1)` extra | Only `max_right`. The answer list is output |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Using `>` instead of `>=` | `[10, 4, 2, 4, 1]` misses the first `4` | Use `>=` because "equal" counts |
| Forgetting to reverse | Returns `[2, 5, 17]` | Reverse at the end, or insert at the front |
| `result.insert(0, x)` in the loop | Each insert is `O(n)`. Total becomes `O(n^2)` | Append, then reverse once |
| Walking from the left with a running max | The left max tells nothing about the right side | Walk from the right |
| Starting `max_right = 0` with `>` | `[0, 0]` returns `[]` | Start at `-inf` |

## 7. Interview Follow-ups

### Q1. What if a leader must be **strictly** greater than everything on its right?

**Answer:**
- Change `>=` to `>`.
- The last element is still a leader because `x > -inf`.
- `[10, 4, 2, 4, 1]` becomes `[10, 4, 1]`.

### Q2. What if you must return leader indexes instead of values?

**Answer:**
- Append `i` instead of `arr[i]`.
- Same loop, same reverse.

### Q3. How is this related to LeetCode 1299 (Replace Elements with Greatest Element on Right Side)?

**Answer:**
- Same right-to-left walk with a running max.
- In 1299 you write `max_right` into each slot before updating it.
- Here you only use it to decide "leader or not".

### Q4. Can you do it with a stack from the left?

**Answer:**
- Yes. Walk left to right with a stack.
- Pop every top smaller than the current value, then push it.
- The stack at the end holds the leaders in order. Still `O(n)`, but uses `O(n)` space.

### Q5. What if the data is a stream and you must show leaders at all times?

**Answer:**
- Use the stack version. Each new number pops smaller ones.
- The stack is always the current list of leaders.

## 8. Interview Explanation

> A leader is an element that is greater than or equal to everything on its right. So I walk from the right end and keep `max_right`, the biggest value seen so far. If the current element is at least `max_right`, it is a leader, and it becomes the new `max_right`. I collect leaders from right to left, so I reverse the list at the end. This is O(n) time and O(1) extra space.
