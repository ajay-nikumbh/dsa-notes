# 14. 1929. Concatenation of Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [1929. Concatenation of Array](https://leetcode.com/problems/concatenation-of-array/) | `O(n)` | `O(n)` |

## 1. Problem Statement

You get an integer array `nums` of length `n`.

Build an array `ans` of length `2n` where:

- `ans[i] = nums[i]`
- `ans[i + n] = nums[i]`

for every `0 <= i < n`. In short, `ans` is `nums` written twice, one after the other. Return `ans`.

### Example

```text
nums = [1, 2, 1]
n = 3

ans = [1, 2, 1, 1, 2, 1]
       \_____/  \_____/
        copy 1   copy 2

Output: [1, 2, 1, 1, 2, 1]
```

We use this same example in every section below.

### Constraints

- `n == nums.length`
- `1 <= n <= 1000`
- `1 <= nums[i] <= 1000`

## 2. Core Theory

### What the problem really asks

Write the array twice in a row.

### The key observation

Every value `nums[i]` goes to **two** places in `ans`:

```text
nums:   [a][b][c]
         |  |  |
         v  v  v
ans:    [a][b][c][a][b][c]
         0  1  2  3  4  5
         i     i+n
```

- First copy at index `i`.
- Second copy at index `i + n`.

So one loop over `nums` can fill both places at once.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| One element | `[7]` | `[7, 7]` | Smallest input. `i + n = 1` |
| All same | `[5, 5]` | `[5, 5, 5, 5]` | Order still matters, values just repeat |
| Do not change input | `[1, 2]` | `[1, 2, 1, 2]` and `nums` stays `[1, 2]` | We build a new array |

## 4. Brute Force: Append Twice

### Idea

Start with an empty list. Walk `nums` once and append each value. Walk `nums` a second time and append each value again.

### Code

```python
# Import List for type hints
from typing import List


# Build the answer by appending in two passes
class SolutionBrute:

    # Main method
    def getConcatenation(self, nums: List[int]) -> List[int]:

        # Start with an empty answer
        ans = []

        # First pass over nums
        for x in nums:

            # Add the value to the end
            ans.append(x)

        # Second pass over nums
        for x in nums:

            # Add the value to the end again
            ans.append(x)

        # Return the full answer
        return ans
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Two passes of `n` steps |
| **Space** | `O(n)` | The answer has `2n` cells |

## 5. Optimal Approach: One Pass, Two Writes

### Idea

1. Make `ans` with `2n` empty cells.
2. For each `i`, write `nums[i]` into `ans[i]` and `ans[i + n]`.
3. Return `ans`.

It is the same `O(n)`, but it uses one loop and a fixed-size array (no list growing).

### Visual Walkthrough (Story Version)

**The story:** you have 3 stickers: `1`, `2`, `1`. You also have a sticker book with 6 empty spots. The rule: **every sticker gets a twin.** If a sticker goes in spot `i`, its twin goes exactly 3 spots later, in spot `i + 3`.

**How to read the pictures:** `[ ]` is an empty spot. `^` marks where we just placed stickers.

**Start: empty book**

```text
spot:   0  1  2  3  4  5
book:  [ ][ ][ ][ ][ ][ ]
```

**Step 1: sticker `1` from position 0**

- Put it in spot `0`.
- Put its twin in spot `0 + 3 = 3`.

```text
spot:   0  1  2  3  4  5
book:  [1][ ][ ][1][ ][ ]
        ^        ^
```

**Step 2: sticker `2` from position 1**

- Put it in spot `1`.
- Put its twin in spot `1 + 3 = 4`.

```text
spot:   0  1  2  3  4  5
book:  [1][2][ ][1][2][ ]
           ^        ^
```

**Step 3: sticker `1` from position 2**

- Put it in spot `2`.
- Put its twin in spot `2 + 3 = 5`.

```text
spot:   0  1  2  3  4  5
book:  [1][2][1][1][2][1]
              ^        ^
```

The book is full: `[1, 2, 1, 1, 2, 1]`.

**All steps at a glance**

| Step | Sticker | First spot | Twin spot | Book after |
|:---:|:---:|:---:|:---:|:---|
| 1 | 1 | 0 | 3 | `[1, _, _, 1, _, _]` |
| 2 | 2 | 1 | 4 | `[1, 2, _, 1, 2, _]` |
| 3 | 1 | 2 | 5 | `[1, 2, 1, 1, 2, 1]` |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Sticker | `nums[i]` |
| Sticker book | `ans`, size `2n` |
| First spot | `ans[i]` |
| Twin spot, 3 later | `ans[i + n]` |

### Step-by-Step Example

```text
nums = [1, 2, 1], n = 3
ans  = [0, 0, 0, 0, 0, 0]
```

**Step 1: `i = 0`**

1. `nums[0] = 1`.
2. `ans[0] = 1`.
3. `ans[0 + 3] = ans[3] = 1`.

```text
ans = [1, 0, 0, 1, 0, 0]
```

**Step 2: `i = 1`**

1. `nums[1] = 2`.
2. `ans[1] = 2`.
3. `ans[1 + 3] = ans[4] = 2`.

```text
ans = [1, 2, 0, 1, 2, 0]
```

**Step 3: `i = 2`**

1. `nums[2] = 1`.
2. `ans[2] = 1`.
3. `ans[2 + 3] = ans[5] = 1`.

```text
ans = [1, 2, 1, 1, 2, 1]
```

The loop ends. **Answer: `[1, 2, 1, 1, 2, 1]`.**

### Code

```python
# Import List for type hints
from typing import List


# Solution for 1929. Concatenation of Array
class Solution:

    # Main method
    def getConcatenation(self, nums: List[int]) -> List[int]:

        # Length of the input
        n = len(nums)

        # Make the answer with 2n cells
        ans = [0] * (2 * n)

        # Go through every index of nums
        for i in range(n):

            # First copy
            ans[i] = nums[i]

            # Second copy, n places later
            ans[i + n] = nums[i]

        # Return the answer
        return ans


# Trace the example by hand
nums = [1, 2, 1]

# Size of the example
n = 3

# Empty answer
ans = [0] * 6

# Step 1: i = 0, first copy
ans[0] = nums[0]

# Step 1: i = 0, second copy
ans[3] = nums[0]

# Check after step 1
assert ans == [1, 0, 0, 1, 0, 0]

# Step 2: i = 1, first copy
ans[1] = nums[1]

# Step 2: i = 1, second copy
ans[4] = nums[1]

# Check after step 2
assert ans == [1, 2, 0, 1, 2, 0]

# Step 3: i = 2, first copy
ans[2] = nums[2]

# Step 3: i = 2, second copy
ans[5] = nums[2]

# Check after step 3
assert ans == [1, 2, 1, 1, 2, 1]

# Full solution on the example
assert Solution().getConcatenation([1, 2, 1]) == [1, 2, 1, 1, 2, 1]

# LeetCode example 2
assert Solution().getConcatenation([1, 3, 2, 1]) == [1, 3, 2, 1, 1, 3, 2, 1]

# One element
assert Solution().getConcatenation([7]) == [7, 7]

# All same
assert Solution().getConcatenation([5, 5]) == [5, 5, 5, 5]

# Input list for the no-change check
original = [1, 2]

# Run the solution
Solution().getConcatenation(original)

# The input must stay the same
assert original == [1, 2]

# Brute force gives the same answers
assert SolutionBrute().getConcatenation([1, 2, 1]) == Solution().getConcatenation([1, 2, 1])

# Brute force on LeetCode example 2
assert SolutionBrute().getConcatenation([1, 3, 2, 1]) == [1, 3, 2, 1, 1, 3, 2, 1]

# Python shortcut gives the same answer
assert Solution().getConcatenation([1, 2, 1]) == [1, 2, 1] + [1, 2, 1]

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One loop, two writes per step |
| **Space** | `O(n)` | The answer has `2n` cells (needed for the output) |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Making `ans` of size `n` | `ans[i + n]` is out of range | Size must be `2 * n` |
| Writing the twin at `i + 1` or `2 * i` | Values land in the wrong spots | Twin spot is always `i + n` |
| Doing `nums.extend(nums)` and returning `nums` | Changes the input array | Build a new list if the input must stay the same |
| `ans = [nums] * 2` | Gives a list of two lists, not one flat list | Use `nums + nums` or `nums * 2` |

## 7. Interview Follow-ups

### Q1. Is there a one-line Python answer?

**Answer:**
- Yes: `return nums + nums` or `return nums * 2`.
- Both make a new flat list of size `2n` in `O(n)`.
- In an interview, show the loop first so the index idea is clear.

### Q2. What if we had to repeat the array `k` times?

**Answer:**
- Make `ans` of size `k * n`.
- Put `nums[i]` at `i`, `i + n`, `i + 2n`, ... up to `i + (k-1)n`.
- Or in Python, `nums * k`.

### Q3. Can we do it with `O(1)` extra space?

**Answer:**
- The output itself is `2n`, so we cannot avoid that.
- "Extra" space beyond the output is already `O(1)`.

### Q4. Where does this idea show up again?

**Answer:**
- In circular array problems, like "Next Greater Element II".
- People pretend the array is written twice, and use index `i % n` to read it.
- That way you get the wrap-around without building a real copy.

## 8. Interview Explanation

> The answer is the array written twice. Every value nums[i] goes to two places: ans[i] and ans[i + n]. So I make an answer array of size 2n and fill both spots in a single loop. That is O(n) time, and the O(n) space is just the output. In Python the same thing is nums + nums, and the same "write it twice" idea is what we use for circular array problems with i % n.
