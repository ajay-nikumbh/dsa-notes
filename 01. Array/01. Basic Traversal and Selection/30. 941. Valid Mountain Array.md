# 30. 941. Valid Mountain Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Traversal: Climb Up, Then Down | [941. Valid Mountain Array](https://leetcode.com/problems/valid-mountain-array/) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an integer array `arr`. Return `True` if it is a **valid mountain array**.

`arr` is a mountain array if and only if:

- `arr.length >= 3`
- There is some index `i` with `0 < i < arr.length - 1` such that:
  - `arr[0] < arr[1] < ... < arr[i - 1] < arr[i]` (strictly up)
  - `arr[i] > arr[i + 1] > ... > arr[arr.length - 1]` (strictly down)

### Example

```text
arr = [0, 3, 2, 1]
index: 0  1  2  3

        3
       / \
      /   2
     /     \
    0       1

Up:   0 < 3
Peak: index 1 (value 3), not the first or last index
Down: 3 > 2 > 1

Output: True
```

We use this same example in every section below.

### Constraints

- `1 <= arr.length <= 10^4`
- `0 <= arr[i] <= 10^4`

## 2. Core Theory

### What the problem really asks

A mountain has three parts, in this order:

```text
strictly up  ->  one peak  ->  strictly down
```

Three rules hide in that picture:

1. There must be **some** up part. The peak cannot be index `0`.
2. There must be **some** down part. The peak cannot be the last index.
3. No flat steps anywhere. `2, 2` is neither up nor down.

### Why one walk fits

Put one walker at index `0`.

1. **Climb:** move right while the next value is bigger.
2. Where the walker stops is the peak. Check it is not at either end.
3. **Descend:** move right while the next value is smaller.
4. If the walker reached the last index, every step was valid.

```text
[0][3][2][1]
 ^-->^              climb stops at index 1 (3 < 2 is false)
     ^-->^-->^      descend reaches index 3 = last index  -> True
```

If there is a flat step or a second climb, the walker gets stuck before the end.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Too short | `[2, 1]` | `False` | Needs at least 3 numbers |
| Flat at the top | `[3, 5, 5]` | `False` | `5, 5` is not strictly down |
| Only going down | `[3, 2, 1]` | `False` | Peak is index 0, no climb |
| Only going up | `[1, 2, 3]` | `False` | Peak is the last index, no descent |
| Two peaks | `[1, 3, 2, 4, 1]` | `False` | Descend stops at index 2, not the end |
| Smallest mountain | `[1, 2, 1]` | `True` | Exactly one up and one down step |
| Single element | `[5]` | `False` | Too short |

## 4. Brute Force: Try Every Peak

### Idea

For every possible peak `p` from `1` to `n - 2`, check that everything before `p` goes strictly up and everything after `p` goes strictly down. If any `p` works, return `True`.

### Code

```python
# Import List for type hints
from typing import List


# Try every index as the peak
class SolutionBrute:

    # Main method
    def validMountainArray(self, arr: List[int]) -> bool:

        # Number of elements
        n = len(arr)

        # Try every inner index as the peak
        for p in range(1, n - 1):

            # Every step before the peak must go up
            up_ok = all(arr[i] < arr[i + 1] for i in range(p))

            # Every step after the peak must go down
            down_ok = all(arr[i] > arr[i + 1] for i in range(p, n - 1))

            # This peak works
            if up_ok and down_ok:
                return True

        # No peak works
        return False
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | Up to `n` peaks, `O(n)` check each |
| **Space** | `O(1)` | Generators use no extra list |

## 5. Optimal Approach: Climb Up, Then Walk Down

### Idea

1. `i = 0`. While `arr[i] < arr[i + 1]`, move `i` right. Now `i` is the peak.
2. If `i == 0` or `i == n - 1`, return `False`.
3. While `arr[i] > arr[i + 1]`, move `i` right.
4. Return `i == n - 1`.

### Visual Walkthrough (Story Version)

**The story:** a little climber stands at the start of a mountain trail made of stones. The rule for a real mountain: climb up step by step (every stone higher), reach one top, then walk down step by step (every stone lower) until the very last stone. No flat stones allowed.

**How to read the pictures:** boxes are stone heights. `^` is where the climber stands.

**All steps at a glance**

| Step | Climber at | Next stone | What happens |
|:---:|:---:|:---:|:---|
| 1 | 0 (h=0) | 3 | Higher, climb to stone 1 |
| 2 | 1 (h=3) | 2 | Not higher, stop. Top = stone 1 |
| 3 | 1 | – | Top is not first or last. Fair |
| 4 | 1 (h=3) | 2 | Lower, walk down to stone 2 |
| 5 | 2 (h=2) | 1 | Lower, walk down to stone 3 |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Stone | `arr[i]` |
| Climber's spot | Index `i` |
| Next stone is higher, climb | `while arr[i] < arr[i + 1]: i += 1` |
| The top | Peak index after the first loop |
| Fair top | `i != 0 and i != n - 1` |
| Next stone is lower, walk down | `while arr[i] > arr[i + 1]: i += 1` |
| On the last stone | `i == n - 1` |

### Step-by-Step Example

```text
arr = [0, 3, 2, 1], n = 4
```

**Start:** `i = 0`

**Climb loop**

1. Check `i + 1 < 4` (1 < 4, yes) and `arr[0] < arr[1]` (`0 < 3`, yes). Move: `i = 1`.
2. Check `i + 1 < 4` (2 < 4, yes) and `arr[1] < arr[2]` (`3 < 2`, no). Stop.

Peak is `i = 1`.

**Peak check**

1. Is `i == 0`? No.
2. Is `i == n - 1 = 3`? No.
3. Keep going.

**Descend loop**

1. Check `i + 1 < 4` (2 < 4, yes) and `arr[1] > arr[2]` (`3 > 2`, yes). Move: `i = 2`.
2. Check `i + 1 < 4` (3 < 4, yes) and `arr[2] > arr[3]` (`2 > 1`, yes). Move: `i = 3`.
3. Check `i + 1 < 4` (4 < 4, no). Stop.

**Final check:** is `i == n - 1`? `3 == 3`. Yes. Return `True`.

### Code

```python
# Import List for type hints
from typing import List


# Solution for 941. Valid Mountain Array
class Solution:

    # Walk right while each next value is bigger; return where we stop
    def _climb(self, arr: List[int]) -> int:

        # Start at the first index
        i = 0

        # Move up while the next value is bigger
        while i + 1 < len(arr) and arr[i] < arr[i + 1]:

            # Step to the next index
            i += 1

        # This is the peak
        return i

    # Walk right from i while each next value is smaller; return where we stop
    def _descend(self, arr: List[int], i: int) -> int:

        # Move down while the next value is smaller
        while i + 1 < len(arr) and arr[i] > arr[i + 1]:

            # Step to the next index
            i += 1

        # This is where the descent stops
        return i

    # Main method
    def validMountainArray(self, arr: List[int]) -> bool:

        # Number of elements
        n = len(arr)

        # Climb to the peak
        i = self._climb(arr)

        # Peak at an end means no climb or no descent
        if i == 0 or i == n - 1:
            return False

        # Walk down from the peak
        i = self._descend(arr, i)

        # Valid only if we reached the last index
        return i == n - 1


# The example from this note
arr = [0, 3, 2, 1]

# Climb step 1: from index 0 we can move to index 1
assert Solution()._climb(arr[:2]) == 1

# Climb step 2: at index 1, 3 < 2 is false, so the peak is index 1
assert Solution()._climb(arr) == 1

# Descend step 1: from index 1 we move to index 2
assert Solution()._descend(arr[:3], 1) == 2

# Descend step 2: from index 2 we move to index 3, the last index
assert Solution()._descend(arr, 1) == 3

# Full example
assert Solution().validMountainArray(arr) is True

# LeetCode example 1: too short
assert Solution().validMountainArray([2, 1]) is False

# LeetCode example 2: flat at the top
assert Solution().validMountainArray([3, 5, 5]) is False

# Edge case: only going down
assert Solution().validMountainArray([3, 2, 1]) is False

# Edge case: only going up
assert Solution().validMountainArray([1, 2, 3]) is False

# Edge case: two peaks
assert Solution().validMountainArray([1, 3, 2, 4, 1]) is False

# Edge case: smallest mountain
assert Solution().validMountainArray([1, 2, 1]) is True

# Edge case: single element
assert Solution().validMountainArray([5]) is False

# Brute force gives the same answers
for a in [arr, [2, 1], [3, 5, 5], [3, 2, 1], [1, 2, 3], [1, 3, 2, 4, 1], [1, 2, 1], [5], [0, 1, 2, 3, 2, 1, 0]]:

    # Both methods must agree
    assert SolutionBrute().validMountainArray(a) == Solution().validMountainArray(a)

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | The index only moves right, at most `n - 1` times in total |
| **Space** | `O(1)` | One index |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Not checking the peak position | `[3, 2, 1]` or `[1, 2, 3]` returns `True` | Return `False` if peak is `0` or `n - 1` |
| Using `<=` or `>=` | Flat steps like `[3, 5, 5]` pass | Use strict `<` and `>` |
| Forgetting the bounds check `i + 1 < n` | `IndexError` at the end of the array | Check bounds before reading `arr[i + 1]` |
| Not checking `i == n - 1` at the end | `[1, 3, 2, 4, 1]` passes after the first descent | The walk must reach the last index |
| Peak = index of `max(arr)` | Works, but extra pass and fails to catch flats on its own | Let the climb loop find the peak |

## 7. Interview Follow-ups

### Q1. Can you solve it with two pointers?

**Answer:**
- Yes. One walker climbs from the left, another climbs from the right.
- Both stop at their own peak.
- Valid if they meet at the same index, and that index is not `0` or `n - 1`.

### Q2. How would you return the peak index instead?

**Answer:**
- Return `i` after the climb, if the full check passes.
- If you know it is a mountain, use binary search for `O(log n)` (LeetCode 852).

### Q3. What if flat parts were allowed at the top?

**Answer:**
- Add a middle loop: `while arr[i] == arr[i + 1]: i += 1`.
- Then descend as before.

### Q4. How do you find the longest mountain inside an array?

**Answer:**
- That is LeetCode 845.
- From each possible base, climb and descend, and record the length.
- Jump `i` to where the descent ended so the total is still `O(n)`.

## 8. Interview Explanation

> I put one index at the start and climb right while the next value is strictly bigger. Where it stops is the peak, and the peak must not be the first or last index, or there is no up part or no down part. Then I walk right while the next value is strictly smaller. If this walk reaches the last index, the array went strictly up then strictly down, so it is a valid mountain. The index only moves forward, so it is O(n) time and O(1) space.
