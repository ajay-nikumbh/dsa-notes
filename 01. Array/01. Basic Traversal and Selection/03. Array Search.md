# 03. Array Search

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Basic** | Linear Search | [Array Search](https://www.geeksforgeeks.org/problems/search-an-element-in-an-array-1587115621/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an array `arr[]` of `n` integers and a number `x`.

Return the index of the **first** place where `x` appears.

If `x` is not in the array, return `-1`.

### Example

```text
Input:  arr = [10, 8, 30, 4, 5], x = 5
Output: 4

Why: 5 sits at index 4. No earlier index holds 5.
```

We use this same example in every section below.

### Constraints

- `1 <= arr.size <= 10^6`
- `0 <= arr[i] <= 10^6`
- `0 <= x <= 10^5`

## 2. Core Theory

### What the problem really asks

"Where is `x` first?" We must check the array from the left. The first match is the answer.

### Why linear search fits

- The array is **not sorted**. So binary search cannot be used.
- We do not know where `x` might be. Any index could hold it.
- So we check index `0`, then `1`, then `2`, and so on.

```text
arr:  [10][ 8][30][ 4][ 5]
        0   1   2   3   4
        ^ -> -> -> -> ^
       start         found x = 5
```

### Why "first" comes for free

- We walk from left to right.
- The first time `arr[i] == x`, we return `i` right away.
- Every index before `i` was already checked and did not match.
- So `i` must be the first match.

### Why not sort first?

| Approach | Needs | Cost for one search |
|:---|:---|:---:|
| Linear search | Nothing | `O(n)` |
| Sort + binary search | Sorted data | `O(n log n)` to sort |
| Hash map | Extra memory | `O(n)` to build |

- Sorting costs more than just scanning once.
- Worse: sorting **moves the numbers**, so the index we find no longer matches the original array.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element, match | `[7]`, `x = 7` | `0` | Catches a loop that starts at index 1 |
| Single element, no match | `[7]`, `x = 3` | `-1` | The `return -1` after the loop must be reached |
| `x` at index 0 | `[5, 1, 2]`, `x = 5` | `0` | `if index:` would treat `0` as "not found" |
| `x` at the last index | `[10, 8, 30, 4, 5]`, `x = 5` | `4` | Catches `range(len(arr) - 1)` |
| Copies of `x` | `[4, 2, 7, 2, 9]`, `x = 2` | `1` | Must return the **first** copy |
| All same | `[3, 3, 3]`, `x = 3` | `0` | Every index matches. The first wins |
| `x` missing | `[10, 8, 30]`, `x = 6` | `-1` | Full scan, no match |

## 4. Brute Force: Scan Everything, Remember the First Match

### Idea

Walk the whole array. The first time we see `x`, write down its index. Keep walking anyway. At the end, return what we wrote down.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: always scan the full array
class SolutionBrute:

    # Main method
    def search(self, arr: List[int], x: int) -> int:

        # No match found yet
        first = -1

        # Check every index
        for i in range(len(arr)):

            # Match, and it is the first one we have seen
            if arr[i] == x and first == -1:

                # Remember this index
                first = i

        # Return the first match, or -1
        return first
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` always | Scans all `n` elements even after a match |
| **Space** | `O(1)` | One variable |

The answer is right, but the walk keeps going after the answer is known.

## 5. Optimal Approach: Linear Search with Early Return

### Idea

1. Walk from index `0`.
2. If `arr[i] == x`, return `i` right now.
3. If the loop ends with no match, return `-1`.

**Step 4: `i = 3`**

### Code

```python
# Import List for type hints
from typing import List


# Optimal: linear search that stops at the first match
class Solution:

    # Main method
    def search(self, arr: List[int], x: int) -> int:

        # Check every index from left to right
        for i in range(len(arr)):

            # Found x
            if arr[i] == x:

                # First match, so return right away
                return i

        # x is not in the array
        return -1


# Helper that records every index checked, to check the trace
def trace_search(arr, x):

    # Indexes we looked at
    checked = []

    # Same loop as the solution
    for i in range(len(arr)):

        # Record this index
        checked.append(i)

        # Stop at the first match
        if arr[i] == x:

            # Return the answer and the checked list
            return i, checked

    # No match
    return -1, checked


# Example from this note
arr = [10, 8, 30, 4, 5]

# Steps 1 to 5 checked indexes 0, 1, 2, 3, 4 and found 5 at index 4
assert trace_search(arr, 5) == (4, [0, 1, 2, 3, 4])

# Final answer on the example
assert Solution().search(arr, 5) == 4

# GfG example 1
assert Solution().search([1, 2, 3, 4], 3) == 2

# GfG example 3
assert Solution().search([10, 8, 30], 6) == -1

# Edge case: single element, match
assert Solution().search([7], 7) == 0

# Edge case: single element, no match
assert Solution().search([7], 3) == -1

# Edge case: x at index 0
assert Solution().search([5, 1, 2], 5) == 0

# Edge case: copies of x, first one wins
assert Solution().search([4, 2, 7, 2, 9], 2) == 1

# Edge case: all same
assert Solution().search([3, 3, 3], 3) == 0

# Early return checks fewer indexes than a full scan
assert trace_search([4, 2, 7, 2, 9], 2) == (1, [0, 1])

# Brute force gives the same answers
for case, target in [(arr, 5), ([1, 2, 3, 4], 3), ([10, 8, 30], 6), ([4, 2, 7, 2, 9], 2), ([3, 3, 3], 3)]:

    # Compare brute force and optimal
    assert SolutionBrute().search(case, target) == Solution().search(case, target)

# The input must not be changed
assert arr == [10, 8, 30, 4, 5]

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` worst case | `x` at the end or missing means we check all `n` boxes |
| **Space** | `O(1)` | Only the loop index |

Best case is `O(1)`, when `x` is at index 0.

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Sorting, then binary search | Sorting moves the numbers. The index no longer fits the original array | Do not sort. Scan the original array |
| `range(len(arr) - 1)` | Never checks the last element. Our example returns `-1` | Use `range(len(arr))` |
| Saving the match and not stopping | A later copy overwrites it. `[4, 2, 7, 2, 9]`, `x = 2` returns `3` | `return i` at the first match |
| `if index:` to test the result | Index `0` counts as false | Test `if index != -1:` |
| `arr.index(x)` with no guard | Raises `ValueError` when `x` is missing | Use the loop, or `try/except` |

## 7. Interview Follow-ups

### Q1. What if we get a million searches on the same array?

**Answer:**
- Build a dictionary once: value -> first index. Only add a key the first time you see it.
- Then each search is `O(1)` on average.
- Total `O(n + q)` instead of `O(n · q)`.

### Q2. What if the array is sorted and we still need the first copy?

**Answer:**
- Use binary search, lower-bound style.
- When `arr[mid] == x`, save `mid` and keep searching the **left** half.
- This finds the leftmost copy in `O(log n)`.

### Q3. What if the array does not fit in memory?

**Answer:**
- Read one chunk at a time and scan it.
- Keep a running offset so you can return the global index.
- Memory stays small.

### Q4. Can we make the scan itself faster?

**Answer:**
- Big-O stays `O(n)`.
- A sentinel trick (put `x` at the end) removes the bounds check each step.
- In real code, scanning memory in order is already fast because of the CPU cache.

### Q5. How would you run this in parallel?

**Answer:**
- Split the array into chunks. Each worker finds its first match.
- The answer is the **smallest** index any worker found.
- Do not just take the first worker to finish.

## 8. Interview Explanation

> The array is not sorted, so I use linear search. I walk from index 0 to the end. The moment `arr[i]` equals `x`, I return `i`. Because I walk from left to right, that is automatically the first match. If the loop ends with no match, I return -1. This is O(n) time in the worst case and O(1) space.
