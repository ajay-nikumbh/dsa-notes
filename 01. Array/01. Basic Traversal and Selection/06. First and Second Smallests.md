# 06. First and Second Smallests

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Linear Scan / One Pass | [First and Second Smallests](https://www.geeksforgeeks.org/problems/smallest-and-second-smallest-element-in-an-array3226/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an array `arr[]` of integers.

Return the **smallest** and the **second smallest** element as `[smallest, second_smallest]`.

The second smallest must be **different** from the smallest.

If they do not both exist, return `[-1]`.

### Example

```text
Input:  arr = [2, 4, 3, 5, 6]
Output: [2, 3]

Why: sorted, the array is [2, 3, 4, 5, 6].
     The smallest is 2. The next different value is 3.
```

We use this same example in every section below.

### Constraints

- `1 <= arr.size <= 10^5`
- `1 <= arr[i] <= 10^5`

## 2. Core Theory

### What the problem really asks

- `smallest` = the minimum value.
- `second` = the smallest value that is **strictly bigger** than `smallest`.
- `[1, 1, 1]` has no second value -> `[-1]`.

### Why two variables are enough

Keep `smallest` and `second`. For every number `num` there are three cases:

```text
num < smallest            ->  second = smallest, smallest = num   (old minimum moves up)
smallest < num < second   ->  second = num                        (better runner-up)
anything else             ->  do nothing                          (too big, or equal to smallest)
```

This is the mirror image of "Second Largest" (note 02). All signs are flipped.

### Why the order of the two lines matters

```text
Right:  second = smallest   then   smallest = num
Wrong:  smallest = num      then   second = smallest   -> both are now num
```

The old minimum must move to `second` **before** it is overwritten.

### Start values

- Start both at `float("inf")`, a value bigger than everything.
- Do not start at `0`: every real value is `>= 1`, so `0` would never be beaten.
- If `second` is still `inf` at the end, return `[-1]`.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| All same | `[1, 1, 1]` | `[-1]` | `second` never changes |
| Single element | `[5]` | `[-1]` | No second value |
| Two values | `[2, 1]` | `[1, 2]` | Smallest case with an answer |
| Two equal values | `[7, 7]` | `[-1]` | Equal is not "second" |
| Smallest repeated | `[1, 1, 2, 2, 3]` | `[1, 2]` | Strict `<` stops `1` from becoming `second` |
| Falling order | `[6, 5, 4, 3, 2]` | `[2, 3]` | The "move up" branch runs every step |
| Smallest at the end | `[5, 4, 3, 1]` | `[1, 3]` | The move-up must work on the last element |

## 4. Brute Force: Sort

### Idea

Sort a copy. The first value is the smallest. Walk right and return the first value bigger than it.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: sort a copy and walk from the left
class SolutionBrute:

    # Main method
    def minAnd2ndMin(self, arr: List[int]) -> List[int]:

        # Sort a copy so the input does not change
        nums = sorted(arr)

        # The smallest is the first element
        smallest = nums[0]

        # Walk from the second element
        for i in range(1, len(nums)):

            # First value bigger than the smallest is the second smallest
            if nums[i] > smallest:

                # Return both
                return [smallest, nums[i]]

        # Every value equals the smallest
        return [-1]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Sorting |
| **Space** | `O(n)` | The sorted copy |

## 5. Better Approach: Two Passes

### Idea

1. Pass 1: find `smallest`.
2. Pass 2: find the smallest value that is `> smallest`.

### Code

```python
# Better: two simple passes
class SolutionBetter:

    # Main method
    def minAnd2ndMin(self, arr: List[int]) -> List[int]:

        # Start the smallest with the first element
        smallest = arr[0]

        # Pass 1: look at every number
        for num in arr:

            # Found a smaller number
            if num < smallest:

                # Update the smallest
                smallest = num

        # No second smallest found yet
        second = float("inf")

        # Pass 2: look at every number again
        for num in arr:

            # Bigger than smallest and smaller than current second
            if smallest < num < second:

                # Update the second smallest
                second = num

        # Second was never found
        if second == float("inf"):

            # GfG wants [-1]
            return [-1]

        # Return both
        return [smallest, second]
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Two scans |
| **Space** | `O(1)` | Two variables |

The optimal version does both jobs in **one** scan.

## 6. Optimal Approach: One Pass

### Idea

1. `smallest = second = inf`.
2. For each `num`:
   - If `num < smallest`: `second = smallest`, then `smallest = num`.
   - Else if `smallest < num < second`: `second = num`.
3. If `second` is still `inf`, return `[-1]`. Else return `[smallest, second]`.

### Visual Walkthrough (Story Version)

**The story:** kids line up to get on a tiny bus with only **two seats**. The bus wants the **two shortest** kids, with different heights. Seat 1 is for the shortest. Seat 2 is for the next shortest.

**The rules:**

- At the start, both seats are empty (`-`).
- If a new kid is shorter than the kid in seat 1, the seat 1 kid **moves to seat 2**, and the new kid takes seat 1.
- If the new kid is not shorter than seat 1, but is shorter than seat 2 (and not the same height as seat 1), the new kid takes seat 2.
- Otherwise the kid stays off the bus.

**How to read the pictures:** `[ ]` = kids in arrival order. `^` = the kid arriving now. `S1` = seat 1. `S2` = seat 2.

**Start: both seats are empty**

```text

```

**Step 1: kid 2 arrives**

- Seat 1 (empty) moves to seat 2. Kid 2 takes seat 1.

 ^
S1 = 2   S2 = -
```

**Step 2: kid 4 arrives**

- Is 4 shorter than seat 1 (2)? No.
- Is 4 shorter than seat 2 (empty) and not 2? Yes.
- Kid 4 takes seat 2.

    ^
S1 = 2   S2 = 4
```

**Step 3: kid 3 arrives**

- Is 3 shorter than 2? No.
- Is 3 shorter than 4 and not 2? Yes.
- Kid 3 takes seat 2. Kid 4 gets off.

**End:** the bus has **[2, 3]**. That is the answer.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: one pass with two variables
class Solution:

    # Main method
    def minAnd2ndMin(self, arr: List[int]) -> List[int]:

        # Smallest value seen so far
        smallest = float("inf")

        # Second smallest distinct value seen so far
        second = float("inf")

        # Look at every number once
        for num in arr:

            # New minimum found
            if num < smallest:

                # Old minimum moves up to second
                second = smallest

                # New number becomes the smallest
                smallest = num

            # Not the smallest, but better than the current second
            elif smallest < num < second:

                # Update the second smallest
                second = num

        # Second was never set, so it does not exist
        if second == float("inf"):

            # GfG wants [-1] in this case
            return [-1]

        # Return both values
        return [smallest, second]


# Helper that records (smallest, second) after every step, to check the trace
def trace_two_smallest(arr):

    # Start value for smallest
    smallest = float("inf")

    # Start value for second
    second = float("inf")

    # States after each step
    states = []

    # Same loop as the solution
    for num in arr:

        # New minimum
        if num < smallest:

            # Old minimum moves up
            second = smallest

            # New minimum
            smallest = num

        # Better runner-up
        elif smallest < num < second:

            # Update second
            second = num

        # Save the state
        states.append((smallest, second))

    # Return every state
    return states


# Positive infinity, used in the trace checks
INF = float("inf")

# Example from this note
arr = [2, 4, 3, 5, 6]

# Step 1 to Step 5
assert trace_two_smallest(arr) == [(2, INF), (2, 4), (2, 3), (2, 3), (2, 3)]

# Final answer on the example (GfG example 1)
assert Solution().minAnd2ndMin(arr) == [2, 3]

# GfG example 2
assert Solution().minAnd2ndMin([1, 1, 1]) == [-1]

# Edge case: single element
assert Solution().minAnd2ndMin([5]) == [-1]

# Edge case: two values
assert Solution().minAnd2ndMin([2, 1]) == [1, 2]

# Edge case: two equal values
assert Solution().minAnd2ndMin([7, 7]) == [-1]

# Edge case: smallest repeated
assert Solution().minAnd2ndMin([1, 1, 2, 2, 3]) == [1, 2]

# Edge case: falling order
assert Solution().minAnd2ndMin([6, 5, 4, 3, 2]) == [2, 3]

# Edge case: smallest at the end
assert Solution().minAnd2ndMin([5, 4, 3, 1]) == [1, 3]

# Brute force and better agree with optimal
for case in [arr, [1, 1, 1], [5], [2, 1], [7, 7], [1, 1, 2, 2, 3], [6, 5, 4, 3, 2], [5, 4, 3, 1]]:

    # Compare all three
    assert SolutionBrute().minAnd2ndMin(case) == SolutionBetter().minAnd2ndMin(case) == Solution().minAnd2ndMin(case)

# All checks passed
print("All tests passed")
```

## 7. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| `smallest = num` before `second = smallest` | Both become the same value. The old minimum is lost | Move the old one up first |
| Using `<=` for the new minimum | `[1, 1, 2]`: the second `1` pushes `1` into `second`. Returns `[1, 1]` | Use strict `<` |
| Starting at `0` | No positive value is `< 0`. Nothing ever updates | Start at `float("inf")` |
| Starting both at `arr[0]` | `[1, 2]`: `second` starts at `1` and `2` is never `< 1` | Start at `inf` |
| No `inf` check at the end | `[1, 1, 1]` returns `[1, inf]` | Return `[-1]` when `second` is still `inf` |

## 8. Interview Follow-ups

### Q1. How is this different from Second Largest?

**Answer:**
- Same idea, every sign flipped.
- `>` becomes `<`. `-inf` becomes `inf`.

### Q2. What if copies are allowed, so `[1, 1, 2]` should give `[1, 1]`?

**Answer:**
- Use `<=` for the new-minimum check.
- Then a copy of the smallest moves the old one into `second`.
- Ask which meaning the interviewer wants.

### Q3. How do you get the k smallest distinct values?

**Answer:**
- Keep a max-heap of size `k`, plus a set to skip copies.
- If the heap grows past `k`, pop the biggest.
- Time `O(n log k)`.

### Q4. What if the data comes as a stream?

**Answer:**
- The one-pass version works as is.
- It keeps two numbers and never looks back.

### Q5. Can you find the smallest and largest with fewer than `2n` comparisons?

**Answer:**
- Yes. Take numbers in pairs and compare the pair first.
- Send the smaller one to the min check and the bigger one to the max check.
- About `1.5n` comparisons.

## 9. Interview Explanation

> I keep two variables, `smallest` and `second`, both starting at infinity. For each number, if it is smaller than `smallest`, the old smallest moves up to `second` first, then the number becomes `smallest`. Otherwise, if it is strictly between `smallest` and `second`, it becomes the new `second`. Strict comparisons keep the two values different. If `second` is still infinity at the end, I return [-1]. This is one pass, O(n) time and O(1) space.
