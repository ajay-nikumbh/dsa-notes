# 12. 1732. Find the Highest Altitude

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [1732. Find the Highest Altitude](https://leetcode.com/problems/find-the-highest-altitude/) | `O(n)` | `O(1)` |

## 1. Problem Statement

A biker goes on a road trip with `n + 1` points.

The biker starts at point `0` with altitude `0`.

You get an array `gain` of length `n`. `gain[i]` is the change in altitude from point `i` to point `i + 1`.

Return the **highest altitude** of any point.

### Example

```text
Input:  gain = [-5, 1, 5, 0, -7]
Output: 1

Why: the altitudes at each point are
point:     0   1   2   3   4   5
altitude:  0  -5  -4   1   1  -6

The highest is 1.
```

We use this same example in every section below.

### Constraints

- `n == gain.length`
- `1 <= n <= 100`
- `-100 <= gain[i] <= 100`

## 2. Core Theory

### What the problem really asks

The altitude at each point is a **running sum** of the gains, starting from `0`.

```text
altitude[0] = 0
altitude[i + 1] = altitude[i] + gain[i]
```

Then we want the **max** of all those altitudes.

So this is two easy ideas glued together:

- Running sum (note 09).
- Running max (note 01).

### The trap: do not forget the start

The starting point has altitude `0`. It counts as a point.

```text
gain = [-4, -3, -2]
altitudes = 0, -4, -7, -9
highest = 0        <- the start point
```

If we only looked at the sums after each gain, we would wrongly return `-4`.

That is why `best` must start at `0`, not at `float("-inf")` or `gain[0]`.

### Picture of the example

```text
altitude
   1 |                 *   *
   0 * . . . . . . . . . . . . . .
  -1 |
  -4 |         *
  -5 |     *
  -6 |                         *
     +---+---+---+---+---+---+
     p0  p1  p2  p3  p4  p5
```

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Always going down | `[-4, -3, -2, -1, 4, 3, 2]` | `0` | LeetCode example 2. The start point wins |
| Always going up | `[1, 2, 3]` | `6` | The last point is highest |
| Single gain, down | `[-1]` | `0` | Start point wins |
| Single gain, up | `[5]` | `5` | Smallest case where a later point wins |
| Flat | `[0, 0, 0]` | `0` | Altitude never changes |
| Peak in the middle | `[3, 4, -10]` | `7` | `best` must keep the peak after the drop |

## 4. Brute Force: Build Every Altitude, Then Take the Max

### Idea

Make a list of all `n + 1` altitudes. Return the biggest.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: store every altitude in a list
class SolutionBrute:

    # Main method
    def largestAltitude(self, gain: List[int]) -> int:

        # The start point has altitude 0
        altitudes = [0]

        # Build the altitude of every next point
        for g in gain:

            # Next altitude = last altitude + this gain
            altitudes.append(altitudes[-1] + g)

        # The highest point
        return max(altitudes)
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass to build, one pass for `max` |
| **Space** | `O(n)` | The list of `n + 1` altitudes |

Time is already linear. The list is the only waste: we only need the current altitude and the best one.

## 5. Optimal Approach: Running Sum with a Running Max

### Idea

1. `altitude = 0`, `best = 0` (the start point counts).
2. For each `g` in `gain`:
   - `altitude += g`.
   - `best = max(best, altitude)`.
3. Return `best`.

### Visual Walkthrough (Story Version)

**The story:** a kid rides a bike over hills. The kid starts at **sea level (0)**. A sign at each part of the road says how much to go up or down. The kid carries a **flag** and plants it at the highest spot reached so far.

**The rules:**

- At the start, the kid is at height 0. The flag is at 0.
- At each sign, the kid's height changes by the sign's number.
- If the new height is higher than the flag, move the flag up to it.

**How to read the pictures:** `[ ]` = road signs. `^` = the sign being used now. `height` = current altitude. `flag` = highest so far.

**Start: the kid is at sea level**

```text
[-5][ 1][ 5][ 0][-7]

height = 0   flag = 0
```

**Step 1: sign says -5**

- Height: 0 + (-5) = -5. Going down.
- Is -5 higher than flag 0? No. Flag stays 0.

```text
[-5][ 1][ 5][ 0][-7]
  ^
height = -5   flag = 0
```

**Step 2: sign says 1**

- Height: -5 + 1 = -4.
- Is -4 higher than flag 0? No. Flag stays 0.

```text
[-5][ 1][ 5][ 0][-7]
      ^
height = -4   flag = 0
```

**Step 3: sign says 5**

- Height: -4 + 5 = 1. Going up a big hill.
- Is 1 higher than flag 0? Yes. Flag moves to 1.

```text
[-5][ 1][ 5][ 0][-7]
          ^
height = 1    flag = 1
```

**Step 4: sign says 0**

- Height: 1 + 0 = 1. Flat road.
- Is 1 higher than flag 1? No, it is equal. Flag stays 1.

```text
[-5][ 1][ 5][ 0][-7]
              ^
height = 1    flag = 1
```

**Step 5: sign says -7**

- Height: 1 + (-7) = -6. Big drop.
- Is -6 higher than flag 1? No. Flag stays 1.

```text
[-5][ 1][ 5][ 0][-7]
                  ^
height = -6   flag = 1
```

**End:** the flag is at **1**. That is the answer.

**All steps at a glance**

| Step | Sign | Height before | Height after | Higher than flag? | Flag after |
|:---:|:---:|:---:|:---:|:---:|:---:|
| start | – | – | 0 | – | 0 |
| 1 | -5 | 0 | -5 | No | 0 |
| 2 | 1 | -5 | -4 | No | 0 |
| 3 | 5 | -4 | 1 | Yes | 1 |
| 4 | 0 | 1 | 1 | No | 1 |
| 5 | -7 | 1 | -6 | No | 1 |

**What the story teaches**

| In the story | In the code |
|:---|:---|
| Road sign | `g` in `gain` |
| Kid's height | `altitude` |
| Start at sea level | `altitude = 0` |
| Flag | `best` |
| Flag starts at sea level | `best = 0` |
| Ride past a sign | `altitude += g` |
| Move the flag up | `best = max(best, altitude)` |

Now the same steps again, with the exact variables.

### Step-by-Step Example

```text
gain = [-5, 1, 5, 0, -7]
```

**Start**

```text
altitude = 0, best = 0
```

**Step 1: `i = 0`, `g = -5`**

1. `altitude = 0 + (-5) = -5`.
2. `best = max(0, -5) = 0`.

**Step 2: `i = 1`, `g = 1`**

1. `altitude = -5 + 1 = -4`.
2. `best = max(0, -4) = 0`.

**Step 3: `i = 2`, `g = 5`**

1. `altitude = -4 + 5 = 1`.
2. `best = max(0, 1) = 1`.

**Step 4: `i = 3`, `g = 0`**

1. `altitude = 1 + 0 = 1`.
2. `best = max(1, 1) = 1`.

**Step 5: `i = 4`, `g = -7`**

1. `altitude = 1 + (-7) = -6`.
2. `best = max(1, -6) = 1`.

**Loop ends.** Return `best = 1`.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: running sum with a running max
class Solution:

    # Main method
    def largestAltitude(self, gain: List[int]) -> int:

        # The biker starts at altitude 0
        altitude = 0

        # The start point counts, so the best starts at 0
        best = 0

        # Ride past every gain
        for g in gain:

            # Move to the next point
            altitude += g

            # Keep the highest altitude seen
            best = max(best, altitude)

        # Return the highest altitude
        return best


# Helper that records (altitude, best) after every step, to check the trace
def trace_altitude(gain):

    # Start altitude
    altitude = 0

    # Start best
    best = 0

    # States after each step
    states = []

    # Same loop as the solution
    for g in gain:

        # Next altitude
        altitude += g

        # Update the best
        best = max(best, altitude)

        # Save the state
        states.append((altitude, best))

    # Return every state
    return states


# Example from this note
gain = [-5, 1, 5, 0, -7]

# Step 1 to Step 5
assert trace_altitude(gain) == [(-5, 0), (-4, 0), (1, 1), (1, 1), (-6, 1)]

# Final answer on the example (LeetCode example 1)
assert Solution().largestAltitude(gain) == 1

# LeetCode example 2: the start point is highest
assert Solution().largestAltitude([-4, -3, -2, -1, 4, 3, 2]) == 0

# Edge case: always going up
assert Solution().largestAltitude([1, 2, 3]) == 6

# Edge case: single gain, down
assert Solution().largestAltitude([-1]) == 0

# Edge case: single gain, up
assert Solution().largestAltitude([5]) == 5

# Edge case: flat
assert Solution().largestAltitude([0, 0, 0]) == 0

# Edge case: peak in the middle
assert Solution().largestAltitude([3, 4, -10]) == 7

# Brute force gives the same answers
for case in [gain, [-4, -3, -2, -1, 4, 3, 2], [1, 2, 3], [-1], [5], [0, 0, 0], [3, 4, -10]]:

    # Compare brute force and optimal
    assert SolutionBrute().largestAltitude(case) == Solution().largestAltitude(case)

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass over `gain` |
| **Space** | `O(1)` | Two variables |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| `best = float("-inf")` | All-downhill trips return a negative number. Example 2 gives `-1` | Start `best = 0`: the start point counts |
| `best = gain[0]` | Same problem, and it is the wrong value for point 1 | Start at `0` |
| `return max(gain)` | Returns the biggest single step, not the highest point. Example gives `5` | Track the running sum |
| Updating `best` before adding `g` | Misses the last point. `[5]` returns `0` | Add first, then compare |

## 7. Interview Follow-ups

### Q1. How is this related to Running Sum (LeetCode 1480)?

**Answer:**
- The altitudes are the running sums of `gain`, with a `0` in front.
- Then we take their max.

### Q2. Can you write it in one line?

**Answer:**
- `return max(0, max(itertools.accumulate(gain)))`.
- Or `max(itertools.accumulate(gain, initial=0))` in Python 3.8+.

### Q3. What if we want the lowest point too?

**Answer:**
- Keep `low = 0` next to `best`.
- Update `low = min(low, altitude)` in the same loop.

### Q4. What if we want the biggest climb from any point to any later point?

**Answer:**
- That is "best time to buy and sell stock" on the altitudes.
- Keep the lowest altitude so far, and the best `altitude - lowest`.
- Still one pass, `O(1)` space.

### Q5. What if we want the point index of the highest altitude?

**Answer:**
- Keep `best_point = 0`.
- When `altitude > best`, set `best_point = i + 1` (point after gain `i`).

## 8. Interview Explanation

> The altitude at each point is a running sum of the gains, starting from 0. So I keep `altitude` and add each gain to it, and I keep `best`, the highest altitude so far. The key detail is that the start point has altitude 0 and counts, so `best` starts at 0, not at negative infinity. That makes all-downhill trips return 0. This is one pass, O(n) time and O(1) space.
