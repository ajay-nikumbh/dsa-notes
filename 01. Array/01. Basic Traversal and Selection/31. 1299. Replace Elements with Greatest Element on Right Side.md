# 31. 1299. Replace Elements with Greatest Element on Right Side

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Traversal: Right-to-Left Running Max | [1299. Replace Elements with Greatest Element on Right Side](https://leetcode.com/problems/replace-elements-with-greatest-element-on-right-side/) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an array `arr`.

Replace every element with the **greatest element among the elements to its right**. Replace the last element with `-1`.

Return the array.

### Example

```text
arr = [17, 18, 5, 4, 6, 1]

index 0 (17): right side [18, 5, 4, 6, 1] -> max 18
index 1 (18): right side [5, 4, 6, 1]     -> max 6
index 2 (5):  right side [4, 6, 1]        -> max 6
index 3 (4):  right side [6, 1]           -> max 6
index 4 (6):  right side [1]              -> max 1
index 5 (1):  right side []               -> -1

Output: [18, 6, 6, 6, 1, -1]
```

We use this same example in every section below.

### Constraints

- `1 <= arr.length <= 10^4`
- `1 <= arr[i] <= 10^5`

## 2. Core Theory

### What the problem really asks

Each position wants the max of **everything to its right**.

Going left to right, every position would need a fresh scan of its right side. That is slow.

### Why scanning from the right fits

Walk from the **right end** to the left. Carry one number: `max_right`, the biggest value seen so far on the right.

- When we stand at index `i`, `max_right` is exactly "the max of everything to the right of `i`". That is the answer for `i`.
- Then we fold `arr[i]` into `max_right` for the next index to the left.

```text
arr:        [17][18][ 5][ 4][ 6][ 1]
                                  <- start here, max_right = -1

answer:     [18][ 6][ 6][ 6][ 1][-1]
max_right after each:
             18  18   6   6   6   1
```

The only trick: **save `arr[i]` before overwriting it**, because we still need it to update `max_right`.

This is the same "suffix max" idea used in Array Leaders and in Best Time to Buy and Sell Stock.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Single element | `[400]` | `[-1]` | Only the last-element rule applies |
| Two elements | `[1, 2]` | `[2, -1]` | Smallest real case |
| Strictly decreasing | `[5, 4, 3]` | `[4, 3, -1]` | Each answer is its right neighbor |
| Strictly increasing | `[1, 2, 3]` | `[3, 3, -1]` | Last big value carries all the way left |
| All equal | `[7, 7, 7]` | `[7, 7, -1]` | Equal values are still "greatest" |

## 4. Brute Force: Scan the Right Side for Each Index

### Idea

For each index `i`, look at every `j > i` and take the max. Put `-1` for the last index.

### Code

```python
# Import List for type hints
from typing import List


# Scan the right side for every index
class SolutionBrute:

    # Main method
    def replaceElements(self, arr: List[int]) -> List[int]:

        # Number of elements
        n = len(arr)

        # Build a new answer list
        result = []

        # Go through every index
        for i in range(n):

            # Default for the last index
            best = -1

            # Look at everything to the right
            for j in range(i + 1, n):

                # Keep the biggest value
                best = max(best, arr[j])

            # Save the answer for index i
            result.append(best)

        # Return the new list
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n^2)` | For each index, scan its right side |
| **Space** | `O(n)` | The new result list |

## 5. Optimal Approach: Running Max From the Right

### Idea

1. `max_right = -1`.
2. For `i` from `n - 1` down to `0`:
   - save `current = arr[i]`
   - write `arr[i] = max_right`
   - update `max_right = max(max_right, current)`
3. Return `arr`.

### Code

```python
# Import List for type hints
from typing import List


# Solution for 1299. Replace Elements with Greatest Element on Right Side
class Solution:

    # Main method
    def replaceElements(self, arr: List[int]) -> List[int]:

        # Nothing is to the right of the last element yet
        max_right = -1

        # Walk from the last index to the first
        for i in range(len(arr) - 1, -1, -1):

            # Save the value before we overwrite it
            current = arr[i]

            # The answer for i is the max of everything to its right
            arr[i] = max_right

            # Fold this value into the running max
            max_right = max(max_right, current)

        # Return the changed array
        return arr


# The example from this note
original = [17, 18, 5, 4, 6, 1]

# Array state after each traced step (step 1 handles index 5, step 6 handles index 0)
states = [
    [17, 18, 5, 4, 6, -1],
    [17, 18, 5, 4, 1, -1],
    [17, 18, 5, 6, 1, -1],
    [17, 18, 6, 6, 1, -1],
    [17, 6, 6, 6, 1, -1],
    [18, 6, 6, 6, 1, -1],
]

# Check every traced step: after handling index i, the suffix from i is final
for step in range(6):

    # Index handled in this step
    i = 5 - step

    # Running the method on the suffix gives the same suffix as the trace
    assert Solution().replaceElements(original[i:]) == states[step][i:]

    # The part to the left of i is still untouched
    assert states[step][:i] == original[:i]

# Full example
assert Solution().replaceElements(list(original)) == [18, 6, 6, 6, 1, -1]

# LeetCode example 2: single element
assert Solution().replaceElements([400]) == [-1]

# Edge case: two elements
assert Solution().replaceElements([1, 2]) == [2, -1]

# Edge case: strictly decreasing
assert Solution().replaceElements([5, 4, 3]) == [4, 3, -1]

# Edge case: strictly increasing
assert Solution().replaceElements([1, 2, 3]) == [3, 3, -1]

# Edge case: all equal
assert Solution().replaceElements([7, 7, 7]) == [7, 7, -1]

# Brute force gives the same answers
for a in [original, [400], [1, 2], [5, 4, 3], [1, 2, 3], [7, 7, 7], [2, 9, 1, 9, 3]]:

    # Both methods must agree (copy, because the optimal changes its input)
    assert SolutionBrute().replaceElements(a) == Solution().replaceElements(list(a))

# All checks passed
print("All tests passed")
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass from right to left |
| **Space** | `O(1)` | In place, plus two variables |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Updating `max_right` before writing `arr[i]` | Each element counts itself, so `[1, 2]` gives `[2, 2]` | Write `arr[i] = max_right` first, then update |
| Overwriting `arr[i]` without saving it | The old value is lost and `max_right` is wrong | Save `current = arr[i]` first |
| Scanning left to right | Need a fresh right-side scan each time, `O(n^2)` | Scan from the right |
| Starting `max_right` at `0` | Last element becomes `0`, not `-1` | Start at `-1` |
| Loop `range(n - 1, 0, -1)` | Index `0` is never handled | Stop value must be `-1` |

## 7. Interview Follow-ups

### Q1. How is this related to Array Leaders?

**Answer:**
- A leader is an element bigger than everything to its right.
- Same right-to-left running max.
- Leaders are the elements where `arr[i] > max_right` before the update.

### Q2. What if you need the greatest element on the LEFT side?

**Answer:**
- Mirror it: walk left to right with `max_left`.
- The first element gets `-1`.

### Q3. What if you need the next greater element (the first bigger one to the right, not the biggest)?

**Answer:**
- A running max is not enough.
- Use a monotonic stack (LeetCode 496, 503, 739).

### Q4. Can you do it without changing the input?

**Answer:**
- Yes. Write into a new list `result = [0] * n` instead.
- Space becomes `O(n)` for the output.

## 8. Interview Explanation

> Each position needs the max of everything to its right, so I walk from the right end and keep a running max, starting at -1. At each index I first save the current value, then overwrite it with the running max, which is exactly the biggest value to its right, and only then fold the saved value into the running max. The order matters, otherwise an element would count itself. This is one pass, O(n) time and O(1) extra space, done in place.
