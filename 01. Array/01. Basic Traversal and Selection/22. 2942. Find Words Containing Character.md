# 22. 2942. Find Words Containing Character

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [2942. Find Words Containing Character](https://leetcode.com/problems/find-words-containing-character/) | `O(L)` | `O(1)` extra |

`L` = total number of characters in all words.

## 1. Problem Statement

You get a list of strings `words` and a character `x`.

Return a list of the **indices** of the words that contain `x`. The order of the indices can be anything.

### Example

```text
words = ["abc", "bcd", "aaaa", "cbc"], x = "a"

index 0: "abc"   has 'a'  -> keep 0
index 1: "bcd"   no 'a'
index 2: "aaaa"  has 'a'  -> keep 2
index 3: "cbc"   no 'a'

Output: [0, 2]
```

We use this same example in every section below.

### Constraints

- `1 <= words.length <= 50`
- `1 <= words[i].length <= 50`
- `x` is a lowercase English letter
- `words[i]` has only lowercase English letters

## 2. Core Theory

### What the problem really asks

Walk through the list. For each word, ask one yes/no question: "Is `x` inside?" Keep the index if yes.

This is "traverse and select": loop, test, collect.

### The key observation

We only need to know **if** `x` is there, not **how many times**. So for each word we can stop at the first match.

```text
"aaaa", x = 'a'
 ^
 found at the first letter -> stop, no need to read the other 3
```

In Python, `x in word` does exactly this: it scans left to right and stops at the first match.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| No word matches | `["abc", "bcd"], x = "z"` | `[]` | Return an empty list, not `None` |
| Every word matches | `["a", "ba"], x = "a"` | `[0, 1]` | All indices kept |
| One letter words | `["x"], x = "x"` | `[0]` | Smallest match |
| Letter at the end | `["leet", "code"], x = "e"` | `[0, 1]` | `"code"` has `e` only at the end. Scan must reach it |

## 4. Brute Force: Count Every Letter

### Idea

For each word, walk every letter and count how many equal `x`. If the count is more than `0`, keep the index.

### Code

```python
# Import List for type hints
from typing import List


# Count matches in every word, letter by letter
class SolutionBrute:

    # Main method
    def findWordsContaining(self, words: List[str], x: str) -> List[int]:

        # Indices of words that contain x
        result = []

        # Go through every word with its index
        for i, word in enumerate(words):

            # How many times x appears in this word
            hits = 0

            # Look at every letter
            for ch in word:

                # Is this letter x?
                if ch == x:

                    # Count it
                    hits += 1

            # Keep the index if x appeared at least once
            if hits > 0:

                # Save the index
                result.append(i)

        # Return all saved indices
        return result
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(L)` | Every letter of every word is read, always |
| **Space** | `O(1)` extra | Only `hits`. The result list is the output |

It reads the whole word even after finding `x`. That is wasted work.

## 5. Optimal Approach: Stop at the First Match

### Idea

1. For each word with index `i`:
   - If `x in word`, add `i` to the result.
2. Return the result.

`x in word` stops as soon as it finds `x`. Worst case is still `O(L)`, but most of the time it reads less.

### Code

```python
# Import List for type hints
from typing import List


# Solution for 2942. Find Words Containing Character
class Solution:

    # Main method
    def findWordsContaining(self, words: List[str], x: str) -> List[int]:

        # Indices of words that contain x
        result = []

        # Go through every word with its index
        for i, word in enumerate(words):

            # Stop at the first match inside the word
            if x in word:

                # Save the index
                result.append(i)

        # Return all saved indices
        return result
```

| Measure | Complexity | Why |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Returning the words instead of indices | Wrong output type | Append `i`, not `word` |
| Appending `i` once per matching letter | `"aaaa"` adds index 2 four times | Check once per word, or `break` after the first match |
| Returning `None` when nothing matches | Fails the empty case | Return the empty list |
| Using `words.index(word)` to get the index | Wrong index when words repeat, and slow | Use `enumerate` |

## 7. Interview Follow-ups

### Q1. Can you write it in one line?

**Answer:**
- `return [i for i, w in enumerate(words) if x in w]`.
- Same `O(L)` time.

### Q2. What if there are many queries for different letters?

**Answer:**
- Precompute, for each word, the set of its letters (or a 26-bit mask).
- Or build a map from letter to list of word indices once.
- Then each query is a quick lookup.

### Q3. What if we search for a substring, not one letter?

**Answer:**
- `pattern in word` still works.
- For long patterns, KMP makes each word `O(len(word) + len(pattern))`.

### Q4. Why is the brute force slower if both are `O(L)`?

**Answer:**
- Big O is the same, but brute force always reads every letter.
- The optimal version stops at the first match, so it often reads far less.

## 8. Interview Explanation

> I walk through the words with their indices and keep index i if the letter x is inside words[i]. I only need a yes or no per word, so the check can stop at the first match, which is what x in word does. In the worst case every letter is read once, so the time is O(L) for L total letters, and the only extra space is the output list.
