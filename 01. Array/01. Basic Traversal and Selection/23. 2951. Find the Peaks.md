# 23. 2951. Find the Peaks

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [2951. Find the Peaks](https://leetcode.com/problems/find-the-peaks/) | `O(n)` | `O(1)` extra |

## 1. Problem Statement

You get an array `mountain`. Find all the **peaks** in it.

A peak is an element that is **strictly greater** than both of its neighbors.

- The first and last elements are **never** peaks.

Return the indices of all peaks, in any order.

### Example

```text
mountain = [1, 4, 3, 8, 5]

index:     0  1  2  3  4
value:     1  4  3  8  5

               8
         4     |
         |  3  |  5
      1  |  |  |  |
      ----------------
      0  1  2  3  4

index 1: 4 > 1 and 4 > 3  -> peak
index 2: 3 > 4? no        -> not a peak
index 3: 8 > 3 and 8 > 5  -> peak

Output: [1, 3]
```

We use this same example in every section below.

### Constraints

- `3 <= mountain.length <= 100`
- `1 <= mountain[i] <= 100`

## 2. Core Theory

### What the problem really asks

Look at each **inner** element and compare it to its left and right neighbor.

```text
   left   me   right
    [a]  [b]   [c]

b is a peak  <=>  b > a  and  b > c
```

### Why the ends are skipped

- Index `0` has no left neighbor.
- Index `n - 1` has no right neighbor.
- The problem says they are never peaks. So we only check `1` to `n - 2`.

### Strict means strict

`>` not `>=`. A flat top like `[1, 3, 3, 1]` has **no** peak: each `3` is equal to a neighbor.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| Smallest | `[1, 3, 1]` | `[1]` | Only one inner index |
| Big value at an end | `[2, 4, 4]` | `[]` | Index 2 is the last, never a peak. Index 1 ties with index 2 |
| Flat top | `[1, 3, 3, 1]` | `[]` | Equal neighbors fail the strict test |
| Going up only | `[1, 2, 3, 4]` | `[]` | The max is at the end, so it does not count |
| Many peaks | `[1, 5, 1, 5, 1]` | `[1, 3]` | Peaks can be next to the same valley |

## 4. Brute Force: Check Every Index With Bounds

### Idea

Loop over **every** index. For each one, check if it has a left neighbor and a right neighbor. If it has both, compare with them.

### Code

```python
# Import List for type hints
from typing import List


# Check every index, with explicit bound checks
class SolutionBrute:

    # Main method
    def findPeaks(self, mountain: List[int]) -> List[int]:

        # Number of elements
        n = len(mountain)

        # Indices of peaks
        peaks = []

        # Look at every index, ends included
        for i in range(n):

            # Does a left neighbor exist?
            has_left = i - 1 >= 0

            # Does a right neighbor exist?
            has_right = i + 1 < n

            # Ends are never peaks
            if not (has_left and has_right):

                # Skip this index
                continue

            # Strictly bigger than both neighbors
            if mountain[i] > mountain[i - 1] and mountain[i] > mountain[i + 1]:

                # Save the peak
                peaks.append(i)

        # Return all peaks
        return peaks
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass |
| **Space** | `O(1)` extra | The result list is the output |

This is already `O(n)`. It just does extra bound checks that we can remove by choosing the loop range well.

## 5. Optimal Approach: Loop Only Over Inner Indices

### Idea

1. Loop `i` from `1` to `n - 2`.
2. If `mountain[i] > mountain[i - 1]` and `mountain[i] > mountain[i + 1]`, save `i`.
3. Return the saved indices.

Every `i` in this range has both neighbors, so no bound checks are needed.

### Visual Walkthrough (Story Version)

**The story:** a hiker walks along a mountain trail with 5 spots. At each spot she asks: "Am I **higher** than the spot behind me **and** the spot in front of me?" If yes, she plants a flag. She does not ask at the very start or very end of the trail, because there is nothing on one side.

**How to read the pictures:** boxes are heights. `^` is the hiker. `F` is a flag.

**Step 1: spot 1 (height 4)**

|:---|:---|

### Step-by-Step Example

```text
mountain = [1, 4, 3, 8, 5], n = 5
Loop: i = 1, 2, 3
peaks = []
```

**Step 1: `i = 1`**

1. `mountain[1] = 4`, left `mountain[0] = 1`, right `mountain[2] = 3`.
2. `4 > 1` is `True`.
3. `4 > 3` is `True`.
4. Peak. `peaks = [1]`.

**Step 2: `i = 2`**

1. `mountain[2] = 3`, left `mountain[1] = 4`, right `mountain[3] = 8`.
2. `3 > 4` is `False`. The `and` stops here.
3. Not a peak. `peaks = [1]`.

**Step 3: `i = 3`**

1. `mountain[3] = 8`, left `mountain[2] = 3`, right `mountain[4] = 5`.
2. `8 > 3` is `True`.
3. `8 > 5` is `True`.
4. Peak. `peaks = [1, 3]`.

The loop ends (`i = 4` is the last index, not checked).

**Answer: `[1, 3]`.**

### Code

```python
# Import List for type hints
from typing import List


# Solution for 2951. Find the Peaks
class Solution:

    # Main method
    def findPeaks(self, mountain: List[int]) -> List[int]:

        # Indices of peaks
        peaks = []

        # Only inner indices can be peaks
        for i in range(1, len(mountain) - 1):

            # Strictly bigger than both neighbors
            if mountain[i] > mountain[i - 1] and mountain[i] > mountain[i + 1]:

                # Save the peak
                peaks.append(i)

        # Return all peaks
        return peaks


# The example input

# Trace: peaks start empty

# Step 1: i = 1, 4 > 1 and 4 > 3
assert m[1] > m[0] and m[1] > m[2]

# Step 1: save index 1
peaks.append(1)

# Check after step 1
assert peaks == [1]

# Step 2: i = 2, 3 > 4 is false
assert not (m[2] > m[1])

# Check after step 2, nothing added
assert peaks == [1]

# Step 3: i = 3, 8 > 3 and 8 > 5
assert m[3] > m[2] and m[3] > m[4]

# Step 3: save index 3
peaks.append(3)

# Check after step 3
assert peaks == [1, 3]

# Full solution on the example
assert Solution().findPeaks(m) == [1, 3]

# LeetCode example 1
assert Solution().findPeaks([2, 4, 4]) == []

# Smallest input
assert Solution().findPeaks([1, 3, 1]) == [1]

# Flat top
assert Solution().findPeaks([1, 3, 3, 1]) == []

# Going up only
assert Solution().findPeaks([1, 2, 3, 4]) == []

# Many peaks
assert Solution().findPeaks([1, 5, 1, 5, 1]) == [1, 3]

# Import random for brute force comparison
import random

# Try many random mountains
for _ in range(300):

    # Make a random mountain with small values so ties happen
    arr = [random.randint(1, 5) for _ in range(random.randint(3, 30))]

    # Brute force and optimal must agree
    assert SolutionBrute().findPeaks(arr) == Solution().findPeaks(arr)

# All checks passed
print("All tests passed")
```

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | One pass over the inner indices |
| **Space** | `O(1)` extra | The result list is the output |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Looping `range(n)` and reading `i - 1` | At `i = 0`, `mountain[-1]` is the **last** element in Python. No error, wrong answer | Loop `range(1, n - 1)` |
| Looping to `n` and reading `i + 1` | `IndexError` at the end | Stop at `n - 2` |
| Using `>=` | Flat tops are counted as peaks | Strictly `>` |
| Counting the ends as peaks | `[1, 2, 3]` would return `[2]` | Ends are never peaks |

## 7. Interview Follow-ups

### Q1. How is this different from LeetCode 162, Find Peak Element?

**Answer:**
- 162 asks for **any one** peak, and ends **can** be peaks (outside is treated as minus infinity).
- That lets you use binary search in `O(log n)`.
- Here we need **all** peaks, so we must look at every element: `O(n)`.

### Q2. Can we skip an index right after a peak?

**Answer:**
- Yes. If `i` is a peak, then `mountain[i + 1] < mountain[i]`, so `i + 1` cannot be a peak.
- You can jump to `i + 2`. Same Big O, a little less work.

### Q3. What about valleys?

**Answer:**
- Flip the signs: `mountain[i] < mountain[i - 1]` and `mountain[i] < mountain[i + 1]`.

### Q4. What if plateaus should count as one peak?

**Answer:**
- Walk through equal runs as one block.
- The block is a peak if the value before it is smaller and the value after it is smaller.

### Q5. Can we do it in one line?

**Answer:**
- `return [i for i in range(1, len(m) - 1) if m[i - 1] < m[i] > m[i + 1]]`.
- Python lets you chain the two comparisons.

## 8. Interview Explanation

> A peak must be strictly greater than both neighbors, and the first and last elements never count. So I loop only over indices 1 to n - 2, where both neighbors always exist, and keep i when mountain[i] is greater than mountain[i - 1] and mountain[i + 1]. Using strict greater-than means flat tops are not peaks. It is one pass, O(n) time and O(1) extra space. Unlike Find Peak Element, I need every peak, so binary search does not apply.
