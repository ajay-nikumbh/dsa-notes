# 17. 2176. Count Equal and Divisible Pairs in an Array

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Basic Traversal and Selection | [2176. Count Equal and Divisible Pairs in an Array](https://leetcode.com/problems/count-equal-and-divisible-pairs-in-an-array/) | `O(n²)` worst | `O(n)` |

## 1. Problem Statement

You get an integer array `nums` and an integer `k`.

Count the pairs `(i, j)` with `0 <= i < j < n` where:

- `nums[i] == nums[j]`, and
- `i * j` is divisible by `k`.

### Example

```text
nums = [3, 1, 2, 2, 2, 1, 3], k = 2

index:  0  1  2  3  4  5  6
nums:   3  1  2  2  2  1  3

Pairs with equal values:
(0, 6): 3 == 3, 0 * 6 = 0,  0 % 2 = 0  -> counts
(1, 5): 1 == 1, 1 * 5 = 5,  5 % 2 = 1  -> no
(2, 3): 2 == 2, 2 * 3 = 6,  6 % 2 = 0  -> counts
(2, 4): 2 == 2, 2 * 4 = 8,  8 % 2 = 0  -> counts
(3, 4): 2 == 2, 3 * 4 = 12, 12 % 2 = 0 -> counts

Output: 4
```

We use this same example in every section below.

### Constraints

- `1 <= nums.length <= 100`
- `1 <= nums[i], k <= 100`

## 2. Core Theory

### What the problem really asks

Look at pairs of positions. A pair counts only if **both** tests pass:

1. Same value.
2. Product of the two **indices** (not values) is a multiple of `k`.

### Why `n <= 100` matters

There are at most `100 * 99 / 2 = 4950` pairs. Checking all of them is fast. So the plain double loop is a fine answer.

### A small speed-up

Test 1 (same value) fails for most pairs. So first **group indices by value**. Then only check pairs inside the same group.

```text
value 3 -> indices [0, 6]
value 1 -> indices [1, 5]
value 2 -> indices [2, 3, 4]

Pairs to check: (0,6), (1,5), (2,3), (2,4), (3,4)
That is 5 checks instead of 21.
```

Worst case (all values equal) is still `O(n²)`, but usually it does much less work.

### Index 0 is special

`0 * j = 0`, and `0` is divisible by every `k`. So index `0` passes test 2 with anyone.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| One element | `[5], k = 1` | `0` | No pairs at all |
| All different | `[1, 2, 3, 4], k = 1` | `0` | Test 1 never passes |
| `k = 1` | `[7, 7, 7], k = 1` | `3` | Every product is divisible by 1, so all equal pairs count |
| Index 0 in a pair | `[4, 4], k = 100` | `1` | `0 * 1 = 0` is divisible by any `k` |
| Equal but not divisible | `[9, 5, 5], k = 4` | `0` | Values match at `(1, 2)`, but `1 * 2 = 2` is not a multiple of 4. Both tests must pass |

## 4. Brute Force: Check Every Pair

### Idea

Two loops: `i` from `0`, `j` from `i + 1`. Count the pair if both tests pass.

### Code

```python
# Import List for type hints
from typing import List


# Check every pair i < j
class SolutionBrute:

    # Main method
    def countPairs(self, nums: List[int], k: int) -> int:

        # Number of elements
        n = len(nums)

        # Number of good pairs
        count = 0

        # Pick the first index
        for i in range(n):

            # Pick a second index after it
            for j in range(i + 1, n):

                # Both tests must pass
                if nums[i] == nums[j] and (i * j) % k == 0:

                    # Count this pair
                    count += 1

        # Return the total
        return count
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n²)` | All `n(n-1)/2` pairs |
| **Space** | `O(1)` | Only a counter |

## 5. Optimal Approach: Group by Value, Then Check

### Idea

1. Build a dictionary: value -> list of indices with that value.
2. For each list, check every pair `(a, b)` inside it with `a < b`.
3. Count the pair if `(a * b) % k == 0`.

Pairs of different values are never even looked at.

### Code

```python
# Import defaultdict to build groups easily
from collections import defaultdict

# Import List for type hints
from typing import List


# Solution for 2176. Count Equal and Divisible Pairs in an Array
class Solution:

    # Main method
    def countPairs(self, nums: List[int], k: int) -> int:

        # Map from value to the list of its indices
        groups = defaultdict(list)

        # Go through every index
        for i, x in enumerate(nums):

            # Put the index in its value's group
            groups[x].append(i)

        # Number of good pairs
        count = 0

        # Look at one group at a time
        for idx in groups.values():

            # Pick the first index of the pair
            for p in range(len(idx)):

                # Pick a later index in the same group
                for q in range(p + 1, len(idx)):

                    # Check the product of the two indices
                    if (idx[p] * idx[q]) % k == 0:

                        # Count this pair
                        count += 1

        # Return the total
        return count


# The example input
nums = [3, 1, 2, 2, 2, 1, 3]

# Trace phase 1: build groups by hand
groups = defaultdict(list)

# Add every index to its group
for i, x in enumerate(nums):

# Count starts at zero
count = 0

# Check 1: pair (0, 6) passes
count += (0 * 6) % 2 == 0

# Count after check 1

# Check 2: pair (1, 5) fails
count += (1 * 5) % 2 == 0

# Count after check 2

count += (2 * 3) % 2 == 0

# Count after check 5

# Full solution on the example

# LeetCode example 2

# One element
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n + P)`, worst `O(n²)` | `P` = number of equal-value pairs. If all values are equal, `P = n(n-1)/2` |
| **Space** | `O(n)` | The groups store every index once |

## 6. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| Using `nums[i] * nums[j]` | The rule is about **indices**, not values | Use `i * j` |
| Starting `j` at `0` or at `i` | Counts pairs twice, or pairs a kid with himself | Start `j` at `i + 1` |
| Skipping index `0` | `0 * j = 0` always divides, so you miss pairs | Use 0-based indices as given |
| Writing `i * j % k == 0` without thinking | Works in Python (`*` and `%` go left to right), but is easy to misread | Write `(i * j) % k == 0` |

## 7. Interview Follow-ups

### Q1. Is the grouping version really faster?

**Answer:**
- In the worst case (all values equal), both are `O(n²)`.
- When values are mixed, grouping skips most pairs.
- With `n <= 100`, the plain double loop is completely fine.

### Q2. Can we beat `O(n²)` when all values are equal?

**Answer:**
- Yes, with a gcd trick. For each `j`, we need earlier `i` where `k / gcd(j, k)` divides `i`.
- Keep a count, per value, of how many earlier indices are divisible by each divisor of `k`.
- This is about `O(n · d(k))`, where `d(k)` is the number of divisors of `k`. It is overkill for this problem.

### Q3. What if they ask for `i + j` divisible by `k` instead?

**Answer:**
- Then we need `i % k` and `j % k` to add up to `0` or `k`.
- Per value, count how many earlier indices have each remainder. Look up the needed one.

### Q4. What if they only wanted equal pairs (no `k`)?

**Answer:**
- That is LeetCode 1512, Number of Good Pairs.
- A group of size `c` gives `c * (c - 1) / 2` pairs. No pair loop needed.

## 8. Interview Explanation

> A pair counts only if the values match and the product of the indices is a multiple of k. With n at most 100, checking all pairs in O(n²) is fine. A simple improvement is to first group indices by value, so I only look at pairs that already have equal values, and then test (a * b) % k for each pair inside a group. The worst case is still O(n²) when everything is equal, with O(n) space for the groups. The key thing to get right is that the rule uses indices, not values, and index 0 always passes because 0 is divisible by any k.
