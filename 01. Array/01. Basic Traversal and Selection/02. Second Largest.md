# 02. Second Largest

| Difficulty | Pattern | Source | Time | Space |
|:---:|:---:|:---:|:---:|:---:|
| **Easy** | Linear Scan / One Pass | [Second Largest](https://www.geeksforgeeks.org/problems/second-largest3735/1) | `O(n)` | `O(1)` |

## 1. Problem Statement

You get an array of **positive** integers `arr[]`.

Return the **second largest** element.

If it does not exist, return `-1`.

The second largest must **not be equal** to the largest.

### Example

```text
Input:  arr = [12, 35, 1, 10, 34, 1]
Output: 34

Why: the largest is 35. The biggest value smaller than 35 is 34.
```

We use this same example in every section below.

### Constraints

- `2 <= arr.size() <= 10^5`
- `1 <= arr[i] <= 10^5`

## 2. Core Theory

### What the problem really asks

"Second largest" here means: **the biggest value that is strictly smaller than the largest**.

- `[10, 5, 10]` -> largest `10`, second largest `5` (not `10`).
- `[10, 10, 10]` -> no smaller value exists -> `-1`.

### Why two variables are enough

Keep two variables: `largest` and `second`.

For every number `num` there are only three cases:

```text
num > largest            ->  second = largest, largest = num   (old champion moves down)
second < num < largest   ->  second = num                      (better runner-up)
anything else            ->  do nothing                        (too small, or equal to largest)
```

The key idea: when a new champion arrives, the old champion is **not thrown away**. It becomes the runner-up.

```text
before:  largest = 12, second = -inf
num = 35
after:   largest = 35, second = 12     <- 12 moved down, not lost
```

### Why strict `>` and `<`

- Using `>=` would let a copy of the largest become `second`.
- `[10, 5, 10]` would return `10`. Wrong.
- Strict comparisons keep the two answers **different values**.

### Start values

- Start both at `float("-inf")`, a value smaller than everything.
- If `second` is still `-inf` at the end, no answer exists. Return `-1`.

## 3. Edge Cases

| Case | Input | Expected | Why it matters |
|:---|:---|:---:|:---|
| All same | `[10, 10, 10]` | `-1` | `second` never changes. The `-inf` check returns `-1` |
| Largest repeated | `[10, 5, 10]` | `5` | `>=` would wrongly return `10` |
| Exactly two values | `[10, 20]` | `10` | Smallest case with an answer |
| Largest at the end | `[1, 2, 3, 90]` | `3` | The move-down must work on the last element |
| Falling order | `[90, 3, 2, 1]` | `3` | Only the "better runner-up" branch sets `second` |
| Many copies | `[5, 5, 5, 1]` | `1` | Distinct values matter, not counts |
| Negatives (outside GfG limits) | `[-10, -3, -20, -7]` | `-7` | Starting with `0` or `-1` would break this |

## 4. Brute Force: Sort

### Idea

Sort a copy. The largest is at the end. Walk left and return the first value smaller than it.

### Code

```python
# Import List for type hints
from typing import List


# Brute force: sort and walk from the right
class SolutionBrute:

    # Main method
    def getSecondLargest(self, arr: List[int]) -> int:

        # Sort a copy so the input does not change
        nums = sorted(arr)

        # The largest is the last element
        largest = nums[-1]

        # Walk from the second last element to the front
        for i in range(len(nums) - 2, -1, -1):

            # First value smaller than the largest is the answer
            if nums[i] < largest:

                # Return it
                return nums[i]

        # Every value equals the largest
        return -1
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n log n)` | Sorting |
| **Space** | `O(n)` | The sorted copy |

## 5. Better Approach: Two Passes

### Idea

1. Pass 1: find `largest`.
2. Pass 2: find the biggest value that is `< largest`.

### Code

```python
# Better: two simple passes
class SolutionBetter:

    # Main method
    def getSecondLargest(self, arr: List[int]) -> int:

        # Start the largest with the first element
        largest = arr[0]

        # Pass 1: look at every number
        for num in arr:

            # Found a bigger number
            if num > largest:

                # Update the largest
                largest = num

        # No second largest found yet
        second = -1

        # Pass 2: look at every number again
        for num in arr:

            # Must be smaller than largest and bigger than current second
            if second < num < largest:

                # Update the second largest
                second = num

        # Return the answer, -1 if none was found
        return second
```

### Complexity

| Measure | Complexity | Why |
|:---|:---:|:---|
| **Time** | `O(n)` | Two scans of the array |
| **Space** | `O(1)` | Two variables |

This is already linear. The optimal version does the same work in **one** scan, which also works on a stream you can read only once.

## 6. Optimal Approach: One Pass

### Idea

1. `largest = second = -inf`.
2. For each `num`:
   - If `num > largest`: `second = largest`, then `largest = num`.
   - Else if `second < num < largest`: `second = num`.
3. If `second` is still `-inf`, return `-1`. Else return `second`.

### Visual Walkthrough (Story Version)

**The story:** a race has a **gold** podium and a **silver** podium. Runners arrive one by one. Each runner has a speed number.

**The rules:**

- At the start, both podiums are empty (`-`).
- If a new runner beats the gold runner, the gold runner **steps down to silver**, and the new runner takes gold.
- If a new runner does not beat gold, but beats silver (and is not tied with gold), the new runner takes silver.
- Otherwise the runner just goes home.

### Code

```python
# Import List for type hints
from typing import List


# Optimal: one pass with two variables
class Solution:

    # Main method
    def getSecondLargest(self, arr: List[int]) -> int:

        # Largest value seen so far
        largest = float("-inf")

        # Second largest distinct value seen so far
        second = float("-inf")

        # Look at every number once
        for num in arr:

            # New champion found
            if num > largest:

                # Old champion moves down to second
                second = largest

                # New number becomes the largest
                largest = num

            # Not the largest, but better than the current second
            elif second < num < largest:

                # Update the second largest
                second = num

        # Second was never set, so it does not exist
        if second == float("-inf"):

            # GfG wants -1 in this case
            return -1

        # Return the second largest
        return second


# Helper that records (largest, second) after every step, to check the trace
def trace_second(arr):

    # Start values
    largest = float("-inf")

    # Start value for second
    second = float("-inf")

    # List of states after each step
    states = []

    # Same loop as the solution
    for num in arr:

        # New champion
        if num > largest:

            # Old champion moves down
            second = largest

            # New champion
            largest = num

        # Better runner-up
        elif second < num < largest:

            # Update second
            second = num

        # Save the state after this step
        states.append((largest, second))

    # Return every state
    return states


# Negative infinity, used in the trace checks
NEG = float("-inf")

# Example from this note
arr = [12, 35, 1, 10, 34, 1]

# Step 1 to Step 6
assert trace_second(arr) == [(12, NEG), (35, 12), (35, 12), (35, 12), (35, 34), (35, 34)]

# Final answer on the example
assert Solution().getSecondLargest(arr) == 34

# GfG example 2
assert Solution().getSecondLargest([10, 5, 10]) == 5

# GfG example 3
assert Solution().getSecondLargest([10, 10, 10]) == -1

# Edge case: exactly two values
assert Solution().getSecondLargest([10, 20]) == 10

# Edge case: largest at the end
assert Solution().getSecondLargest([1, 2, 3, 90]) == 3

# Edge case: falling order
assert Solution().getSecondLargest([90, 3, 2, 1]) == 3

# Edge case: many copies
assert Solution().getSecondLargest([5, 5, 5, 1]) == 1

# Edge case: negatives
assert Solution().getSecondLargest([-10, -3, -20, -7]) == -7

# Brute force and better agree with optimal on positive inputs
for case in [arr, [10, 5, 10], [10, 10, 10], [10, 20], [1, 2, 3, 90], [90, 3, 2, 1], [5, 5, 5, 1]]:

    # Compare all three
    assert SolutionBrute().getSecondLargest(case) == SolutionBetter().getSecondLargest(case) == Solution().getSecondLargest(case)

# All checks passed
print("All tests passed")
```

## 7. Common Mistakes

| Mistake | What goes wrong | Fix |
|:---|:---|:---|
| `second = 0` at the start | With negatives, `0` is returned but is not in the array | Start with `float("-inf")` |
| Using `>=` for the new champion | `[10, 5, 10]`: the second `10` pushes `10` into `second`. Returns `10` | Use strict `>` |
| `largest = num` before `second = largest` | Both become the new value. The old champion is lost | Move the old one down first |
| `elif num > second` with no upper bound | A copy of the largest can slip into `second` if other code changes | Write `second < num < largest` |
| Returning `second` with no check | `[10, 10, 10]` returns `-inf` | Return `-1` when `second` is still `-inf` |

## 8. Interview Follow-ups

### Q1. What if "second largest" means the second item after sorting, copies allowed?

**Answer:**
- Then `[10, 10, 5]` should return `10`, not `5`.
- Use `>=` for the champion check and drop the "not equal" rule.
- Always ask which meaning they want before coding.

### Q2. How do you find the k-th largest distinct value?

**Answer:**
- Small `k`: keep a sorted list of the best `k` distinct values. `O(n·k)`.
- Bigger `k`: a min-heap of size `k` plus a set to skip copies. `O(n log k)`.

### Q3. The array is a stream you can read only once. Does this still work?

**Answer:**
- Yes. The one-pass version keeps only two numbers.
- The sort and two-pass versions need the whole array.

### Q4. Can you do it with fewer comparisons?

**Answer:**
- Yes, with a tournament. The winner needs `n - 1` comparisons.
- The second best must be one of the about `log n` runners the winner beat.
- Total about `n + log n` comparisons, but it needs extra memory.

### Q5. What if you also need the second smallest?

**Answer:**
- Run the same idea with two more variables, `smallest` and `second_small`, and flip the signs.
- Still one pass. See note 07 in this folder.

## 9. Interview Explanation

> I keep two variables, `largest` and `second`, both starting at negative infinity. For each number, if it is bigger than `largest`, the old largest moves down to `second` and the number becomes `largest`. Otherwise, if it is strictly between `second` and `largest`, it becomes the new `second`. Strict comparisons stop a copy of the largest from becoming the answer. If `second` is still negative infinity at the end, I return -1. This is one pass, O(n) time and O(1) space.
